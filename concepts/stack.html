Stacks & Monotonic Stacks, Explained

Last in, first out for matching brackets, and the monotonic variant for "next greater element" problems.

The core idea

Think of a stack of plates by the sink. You can only put a plate on top, and you can only take the top one off. The plate you washed most recently is the first one you pick up again. Nobody reaches into the middle. That rule has a name: LIFO, last in, first out. 

    push 'c'  ─┐        ┌─  pop  →  'c'
               ↓        │
             ┌───┐    ┌───┐
             │ c │    │ c │  ← top: the only plate you can touch
             ├───┤    ├───┤
             │ b │    │ b │
             ├───┤    ├───┤
             │ a │    │ a │  ← bottom: pushed first, comes out last
             └───┘    └───┘

In Python you do not need a special class. A plain list is a stack: lst.append(x) pushes onto the top, lst.pop() removes and returns the top, and lst[-1] peeks at the top without removing it. All three are O(1).

A stack is the right tool whenever the thing you care about is the most recent unfinished thing. An open bracket waiting to be closed. A folder you opened on the way down and still have to come back out of. A number that has not yet met anything bigger than itself.

Why it's fast: the stack remembers the pending items in the exact order you will need them, so you never search. Each element is pushed once and popped at most once, which is why even the loop-inside-a-loop shape of a monotonic stack is still O(n) overall, not O(n²).

How to recognise it

Reach for a stack when a problem has any of these shapes:

  • Things nest inside other things — brackets, tags, folders, function calls. Nesting is LIFO by definition: the innermost thing must close first.
  • "Match each X with the most recent unmatched Y." The word recent is the tell.
  • "Next greater / next smaller element", "days until a warmer day", "how far can I see". These want a monotonic stack — one whose contents always go one way, all increasing or all decreasing.
  • Undo, back button, or "reverse the order" — pushing everything and popping it all reverses it for free.
  • You want recursion but without recursion. Every recursive function already runs on a stack (the call stack). Making that stack explicit turns recursion into a loop, which dodges Python's recursion limit.

The naive way first

Valid Parentheses: given a string of brackets, decide whether every one is closed by the right kind, in the right order. A common first idea is to keep deleting adjacent matching pairs until nothing changes, then see if the string is empty. 

def is_valid_slow(s):
    prev = None
    while s != prev:                 # keep going until a pass changes nothing
        prev = s
        s = s.replace("()", "").replace("[]", "").replace("{}", "")
    return s == ""

It works, and it is genuinely O(n²) — a string like "((((((...))))))" peels off only one pair per full pass, and each pass rebuilds the whole string. The wasted work is the rescanning: on every pass you walk past hundreds of characters you have already inspected, just to reach the one innermost pair. What you actually needed to remember was a single thing at a time — which bracket is still open and most recent — and that is precisely a stack.

The pattern

Walk the string once. Push every opener. When you hit a closer, the only bracket it is allowed to close is the one on top of the stack. 

def is_valid(s):
    pairs = {")": "(", "]": "[", "}": "{"}   # closer -> the opener it needs
    stack = []

    for ch in s:
        if ch not in pairs:                  # an opener
            stack.append(ch)                 # remember it as "still open"
        else:                                # a closer
            if not stack or stack.pop() != pairs[ch]:
                return False                 # nothing open, or the wrong thing was
    return not stack                         # true only if nothing is left open

The line that matters is stack.pop() != pairs[ch]. Read it as a challenge: "a closer just arrived; the most recent thing still open had better be its partner." There is no searching and no backtracking, because nesting guarantees the partner is on top or the string is invalid.

Both guards on that line earn their keep. not stack catches a closer with nothing open at all, like ")". And the final return not stack catches the opposite — openers that never got closed, like "(" — which the loop alone would happily accept.

The stack grows and shrinks with the nesting depth, and ends empty, so the string is valid.

Notice what happened at step 3. The ] did not go hunting for its partner — it just took whatever was on top, and that was guaranteed to be the innermost open bracket. Now imagine the input were "([)]" instead. At step 3 the character is ), which needs (, but the top of the stack is [. Mismatch, return False immediately. That one comparison is the whole algorithm.

Variations

The monotonic stack

A monotonic stack is one you deliberately keep in sorted order — every value in it is smaller than the one below (or larger, depending on the problem). You maintain that by popping anything that would break the order before you push. It solves the whole family of "next greater element" questions in one pass. 

def next_greater(nums):
    """For each element, the first larger value to its right (-1 if none)."""
    res = [-1] * len(nums)
    stack = []                       # indices; values shrink as you go UP the stack

    for i, x in enumerate(nums):
        # x is bigger than the values waiting on top: it is their answer
        while stack and nums[stack[-1]] < x:
            res[stack.pop()] = x
        stack.append(i)              # x now waits for its own bigger value

    return res                       # anything still on the stack keeps -1

Store indices, not values, so you know where to write the answer. On [2, 1, 5, 6, 2, 3] this gives [5, 5, 6, -1, 3, -1]:

The while inside the for looks like O(n²), but it is not. Each index is pushed exactly once and popped at most once, so across the whole run the while body executes at most n times in total. That accounting trick — charge the work to the element being removed — is called an amortised argument, and it is worth being able to say out loud in an interview.

Carrying extra information: a min stack

"Give me the smallest value currently in the stack, in O(1)" sounds impossible until you notice you can push a pair: the value, and the minimum of everything at or below it. Popping throws the stale minimum away automatically. 

class MinStack:
    def __init__(self):
        self.stack = []              # (value, min so far including this value)

    def push(self, x):
        smallest = x if not self.stack else min(x, self.stack[-1][1])
        self.stack.append((x, smallest))

    def pop(self):
        return self.stack.pop()[0]

    def top(self):
        return self.stack[-1][0]

    def get_min(self):
        return self.stack[-1][1]

Turning recursion into a loop

Depth-first search is naturally recursive, but you can run it with an explicit stack instead. Push the start, then repeatedly pop a node and push its unvisited neighbours. This is a depth-first traversal: it reaches the same nodes as the recursive version, though not always in the same order. Your list plays the role of Python's call stack — handy when the graph is deep enough to blow the default recursion limit of about 1000 frames. See Graph Traversal and Tree Traversal for the full versions. 

def dfs_iterative(graph, start):
    seen, order, stack = {start}, [], [start]
    while stack:
        node = stack.pop()           # pop, not pop(0): that's what makes it depth-first
        order.append(node)
        for nb in graph[node]:
            if nb not in seen:
                seen.add(nb)
                stack.append(nb)
    return order

Common mistakes

Popping an empty stack. [].pop() raises IndexError: pop from empty list. Every pop needs a guard — if not stack: return False, or while stack and .... In bracket problems this is the input ")", and it is the most common crash on this pattern.
Forgetting to check the stack at the end. A loop that never fails is not the same as a valid string. "(((" survives every iteration and leaves three openers behind. The answer is return not stack, not return True.
Storing values instead of indices in a monotonic stack. Once you have popped a value you usually need to know where it came from, to write the result or to measure a distance. Push i and read nums[i]. Getting this wrong makes "Daily Temperatures" style problems unsolvable rather than merely buggy.
Using pop(0) when you meant pop(). pop(0) takes from the front, which makes the list a queue (first in, first out) and quietly turns a depth-first search into a breadth-first one. It is also O(n) per call because everything shifts down. If you really want a queue, use collections.deque and popleft().

Complexity

  • Time: O(n). Each element is pushed at most once and popped at most once, and both operations are O(1) — so even the monotonic stack's inner while loop cannot push the total past 2n steps.
  • Space: O(n) in the worst case — a fully nested string like "(((((", or a strictly decreasing array, puts every element on the stack at the same time.
