Two Pointers, Explained

Two index variables walking toward each other, and why that one trick turns a nested loop into a single pass.

The core idea

Imagine two people standing at opposite ends of a long line of numbered boxes, one at the far left and one at the far right. Each of them can only step toward the other. Every time they look at the two boxes they are standing on, they learn something, and that something tells them which one of them should take a step. They keep going until they meet in the middle.

That is the whole pattern. Two index variables, usually called left and right, walk toward each other through an array or string. At each step you compare the two elements they point at, and the comparison decides which pointer moves.

Why it's fast: each pointer only ever moves in one direction, so between them they take at most n steps in total. You look at every element about once instead of pairing every element with every other element.

How to recognise it

Reach for two pointers when a problem says, or quietly implies, one of these:

  • The input is sorted, or you are allowed to sort it. Sorting is what makes "move left to get bigger, move right to get smaller" work.
  • You need a pair (or a triple) of elements that satisfy a condition: two numbers that sum to a target, two walls that hold the most water.
  • Something is symmetric: palindromes, reversing in place, comparing the front of a string with the back.
  • You are about to write a nested loop that compares every element with every other element, and the input is ordered enough that most of those pairs are obviously pointless.

The naive way first

Take this problem: given a sorted array and a target, find two numbers that add up to the target. The instinctive answer is to try every pair: 

def two_sum_sorted_slow(nums, target):
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:
                return [i, j]
    return []

That is O(n²): for 10,000 numbers it checks about 50 million pairs. The wasted work is easy to see once you look for it. If nums[i] + nums[j] is already too big, every j further right is also too big, because the array is sorted. The inner loop keeps checking them anyway.

The pattern

Start one pointer at each end. Compare. Move the pointer that can still fix the problem.

def two_sum_sorted(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:
        total = nums[left] + nums[right]
        if total == target:
            return [left, right]
        elif total < target:
            left += 1      # too small: only moving left can make the sum bigger
        else:
            right -= 1     # too big: only moving right can make the sum smaller
    return []

The line that matters is the if/else in the middle. Read it as a question: "the sum is wrong, and which pointer is the only one that can move it in the right direction?"

Notice what happened at step 1. The sum 12 was too big, so we moved right. That single move threw away every pair involving 11, because if 1 + 11 is too big then 3 + 11, 4 + 11, and so on are all too big as well. That is where the speed comes from.

Variations

Mirror check (palindromes)

Same two pointers, but instead of a sum you compare the characters for equality. Both pointers move every step, unless one of them is on a character you want to skip. 

def is_palindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        if s[left] != s[right]:
            return False
        left += 1
        right -= 1
    return True

Fix one, two-pointer the rest (3Sum)

When you need three numbers, loop over the first one with a normal for loop and run the two-pointer pair search on everything to its right. That turns O(n³) into O(n²).

Expand from the centre

Sometimes the pointers start together and move apart. Longest Palindromic Substring picks a centre and grows left leftward and right rightward while the characters still match.

Same-direction pointers (read and write)

Not every two-pointer problem uses opposite ends. "Remove duplicates from a sorted array in place" uses a slow pointer for where to write and a fast pointer for where to read. The fast pointer visits every element; the slow one only advances when it finds something worth keeping. 

def remove_duplicates(nums):
    if not nums:
        return 0
    write = 1                          # nums[0] is always kept
    for read in range(1, len(nums)):
        if nums[read] != nums[write - 1]:
            nums[write] = nums[read]   # keep it: copy into the write slot
            write += 1
    return write                       # length of the de-duplicated prefix

Two other same-direction flavours have their own pages: sliding window, where the two pointers bracket a contiguous chunk, and fast and slow pointers, where they move at different speeds through a linked list.

Common mistakes

Moving the wrong pointer. In Container With Most Water, people move the taller wall. Only moving the shorter one can possibly raise the water level. Always ask "which pointer can still improve the answer?" and move only that one.
Moving both when only one should move. In the sum search, moving both pointers at once skips pairs you never checked. Only the equality case moves both.
< versus <= in the loop condition. When left == right the two pointers are on the same element, and an element cannot pair with itself. Use while left < right for pair problems.
Forgetting to sort. The "too big, move right" logic only holds on sorted input. If the problem asks for the original indices, sort a copy of (value, index) pairs instead.

Complexity

  • Time: O(n) for the two-pointer sweep itself, since each pointer moves at most n times. If you had to sort first, that adds O(n log n).
  • Space: O(1). Two integers, no copies of the input.
