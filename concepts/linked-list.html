Linked Lists, Explained

What a linked list actually is, why it exists next to arrays, and how reversing one works — for the reversal walkthrough itself, see Reverse Linked List.

The core idea

Instead of storing items in one contiguous block of memory (like an array), a linked list is a chain of separate objects called nodes. Each node knows exactly two things:

  1. its own value
  2. where the next node lives

That's the entire idea. Here's a node in code:

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val    # the data, e.g. 5
        self.next = next  # a pointer to the next node, or None if it's the last one

A list holding [1, 2, 3] isn't one object — it's three separate ListNodes, daisy-chained together:

Each box is a node — left side is val, the dot on the right is next, and the arrow is where that pointer leads. A variable called head just points at the first node. The last node's next is None — that's how code knows it has reached the end.

Why not just use an array?

Array

  • Items sit next to each other in memory
  • Jumping to index i is instant
  • Inserting/removing in the middle means shifting every item after it

Linked list

  • Items are scattered, connected by pointers
  • Reaching index i means walking from the head, node by node
  • Inserting/removing is just rewiring a couple of pointers — nothing shifts
Why this trade-off matters: pick a linked list when you're constantly inserting and removing (queues, undo history, LRU caches) and rarely need "give me item #47" directly. Pick an array when you need random access or cache-friendly iteration.

Walking the list

This pattern — starting at the head and following .next until you fall off the end — shows up constantly:

curr = head
while curr:
    print(curr.val)
    curr = curr.next   # step to the next node

Notice you can't skip ahead. To read the 3rd node you must first visit the 1st and 2nd.

The trick: three pointers

Walk through the list once. At each node, flip its arrow to point backward instead of forward. To do that safely without losing the rest of the list, track three things at once:

  1. prev — the part of the list already reversed. Starts at None, because node 1 must eventually point at nothing.
  2. curr — the node being rewired right now. Starts at head.
  3. next_node — a bookmark for "what used to come next," saved before curr.next gets overwritten. Skip this and the rest of the list becomes unreachable the instant you flip the arrow.

prev = None,  curr = node(1),  next_node = node(2)

curr.next = prev      # node 1 now points at None instead of node 2
prev = curr            # prev slides up to node 1
curr = next_node       # curr slides up to node 2

Repeat that same block for node 2, then node 3. When curr finally becomes None, the loop stops — and prev is sitting on the last node that got flipped, which is the new head.

The full function

def reverse_list(head):
    prev = None
    curr = head
    while curr:
        next_node = curr.next   # save it before overwriting curr.next
        curr.next = prev        # flip the arrow backward
        prev = curr             # prev advances
        curr = next_node        # curr advances
    return prev                 # prev is the new head
The one line everyone forgets: next_node = curr.next. If you flip curr.next before saving where it used to point, you lose the rest of the chain — there's no way to get back to node 3 once node 2's arrow has been overwritten.
