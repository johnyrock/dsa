Tries, Explained

A tree of characters for prefix lookups, autocomplete, and word search.

The core idea

Think about the keyboard on your phone. You type c, then a, then r, and it instantly offers car, card, care, carpet. It is not reading a dictionary of 100,000 words after every keystroke. It walked three steps down a structure that was already sorted by letter, and now it is standing on a branch where every word underneath it starts with "car".

A trie (say "try", from retrieval; some people say "tree") is that structure. It is a tree where the edges are letters, not the nodes. The path you walk from the root spells out a string, and the node you land on represents that string. Two words that start the same way share the same path until they differ, and only then does the tree branch.

One extra piece is needed. The path spelling "ca" exists inside a trie holding "cat", but "ca" is not itself a word. So every node carries a flag, usually called is_word, meaning "a real word ends right here". 

class TrieNode:
    def __init__(self):
        self.children = {}        # one letter -> the node you reach by using it
        self.is_word = False      # does a word END here?
Why it's fast: looking up a word of length L costs L dict lookups, no matter how many words the trie holds. The size of the dictionary does not appear in the cost at all. Scanning a list of n words costs O(n × L); a trie costs O(L). With a hundred thousand words and a five-letter query, that is five steps instead of a hundred thousand comparisons.

How to recognise it

  • The word "prefix" appears in the problem. That is the loudest possible signal. Tries are the prefix data structure.
  • Autocomplete, typeahead, spell-check, dictionary, word search. All prefix problems in disguise.
  • Many queries against one fixed set of words. Building the trie costs something up front, so it only pays off when you look things up repeatedly. For one lookup, just use a set.
  • You need to prune a search early. In grid word-search problems the trie lets you abandon a path the moment the letters so far are not a prefix of anything — that turns an impossible backtracking search into a fast one.
  • Wildcards in the query, like matching c.t against a dictionary. A hash set cannot do that; a trie can, by branching at the dot.
A trie is not a replacement for a set. If all you ever ask is "is this exact word in the list?", a Python set is faster and one line long. Reach for a trie when the question is about prefixes.

The naive way first

"Given a dictionary, find every word starting with a prefix." Python makes the obvious version very short, which is why it is easy to stop here: 

def words_with_prefix_slow(words, prefix):
    return [w for w in words if w.startswith(prefix)]

For one call on a small list this is completely fine. The problem is repeated calls. Every call touches all n words and compares up to L characters of each, so it is O(n × L) per query. Type six characters into a search box with a 100,000-word dictionary and you have done 600,000 word scans to render one dropdown.

Look at where the waste is. On the query "car" you compare the c of "car" against the first letter of every one of those 100,000 words, and you did the same thing for the query "ca" one keystroke ago. All the words beginning with d are re-rejected on every single query. A trie does that letter comparison once, ever, at build time, and stores the answer as the shape of the tree.

The pattern

Every trie operation is the same walk: start at the root, and step down one node per character. What you do when a letter is missing is the only thing that differs between insert and search. 

class Trie:
    def __init__(self):
        self.root = TrieNode()          # the root spells the empty string

    def insert(self, word):
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()   # missing letter: carve a new branch
            node = node.children[ch]             # step down one letter
        node.is_word = True                      # plant the flag at the end

    def _walk(self, prefix):
        """Return the node this prefix lands on, or None if the path breaks."""
        node = self.root
        for ch in prefix:
            if ch not in node.children:
                return None                      # missing letter: the path just stops
            node = node.children[ch]
        return node

    def search(self, word):
        node = self._walk(word)
        return node is not None and node.is_word   # path exists AND a word ends here

    def starts_with(self, prefix):
        return self._walk(prefix) is not None      # path exists, that is all

The two lines that matter sit at the end of search and starts_with, and the difference between them is the entire point of the is_word flag. starts_with("ca") is True because the path exists. search("ca") is False because although the path exists, no word ends there. Same walk, different final question.

The other habit to build: node = self.root is the first line of every operation. A trie method that forgets to start at the root will happily carry on from wherever the last call left off.

One example, traced by hand

Start with a trie holding cat, car, dog. A star marks a node where is_word is True.

Start. Eight nodes for three words, not ten, because "cat" and "car" share the c-a path.

Now insert card. One row per character.

End. A four-letter word cost exactly one new node.

Notice what happened at steps 3 and 4. Three of the four characters walked over nodes that already existed, because "car" is a prefix of "card". Only the final d needed memory. That is the compression a trie gives you: a dictionary of 100,000 English words does not need 500,000 nodes, because the common beginnings are stored once.

Notice too that the r node keeps its star. "car" is still a word, and "card" is also a word, and one lives on the path to the other. The flag is per node, so both facts coexist without any special handling.

Variations

Autocomplete: collect everything below a node

Walk to the prefix node, then run a depth-first traversal of everything under it, building the string up as you descend. Sorting the children at each step gives you alphabetical output. 

def collect(node, prefix, out):
    if node.is_word:
        out.append(prefix)
    for ch, child in sorted(node.children.items()):
        collect(child, prefix + ch, out)
    return out

def autocomplete(trie, prefix):
    node = trie._walk(prefix)
    if node is None:
        return []
    return collect(node, prefix, [])

The cost is O(L) to walk down plus the size of the answer — you never touch a word that does not start with the prefix, which is exactly what the naive scan could not promise.

Wildcards: branch at the dot

Design Add and Search Words (#211) allows . to mean "any single character". A concrete letter follows one child; a dot has to try them all, so the walk becomes a recursive search that can backtrack. 

def search_wildcard(trie, word):
    def go(node, i):
        if i == len(word):
            return node.is_word
        ch = word[i]
        if ch == ".":
            return any(go(child, i + 1) for child in node.children.values())
        if ch not in node.children:
            return False
        return go(node.children[ch], i + 1)
    return go(trie.root, 0)

Counting: store a number at every node

"How many words start with this prefix?" does not need the words themselves, only the count. Keep a counter on each node and bump it for every word that passes through during insertion. The query is then a walk and a single read. 

class CountingTrieNode:
    def __init__(self):
        self.children = {}
        self.is_word = False
        self.count = 0            # how many words pass through this node

class CountingTrie:
    def __init__(self):
        self.root = CountingTrieNode()

    def insert(self, word):
        node = self.root
        node.count += 1
        for ch in word:
            if ch not in node.children:
                node.children[ch] = CountingTrieNode()
            node = node.children[ch]
            node.count += 1
        node.is_word = True

    def count_prefix(self, prefix):
        node = self.root
        for ch in prefix:
            if ch not in node.children:
                return 0
            node = node.children[ch]
        return node.count

This is the general trick: anything you can accumulate per node — a count, the smallest word id, the full word string itself — turns a traversal into a lookup.

Longest common prefix

Insert every word, then walk down from the root while there is exactly one way to go and no word has ended yet. Where the trie first branches, the shared prefix ends. 

def longest_common_prefix(words):
    trie = Trie()
    for w in words:
        trie.insert(w)
    node, prefix = trie.root, ""
    while len(node.children) == 1 and not node.is_word:
        ch, node = next(iter(node.children.items()))
        prefix += ch
    return prefix

not node.is_word is doing real work here: for ["abc", "abcd"] the answer is "abc", and without that condition you would keep walking to "abcd".

Common mistakes

Forgetting is_word. Without the flag, a trie holding "cat" reports that "ca" and "c" are words too, because their paths exist. Every wrong answer of the form "it says everything is a word" is this bug.
Confusing search with starts_with. They walk identically and differ only in the last line. search needs the flag; starts_with needs only the path. Mixing them up passes the small tests and fails the real ones.
Assuming 26 lowercase letters. A fixed [None] * 26 array of children is fast, but it breaks the moment the input has an uppercase letter, a digit, or a space, usually with a silent out-of-range index. A dict costs a little more memory and never has that problem. Use the dict unless the problem promises you the alphabet.
Not restarting at the root. Every insert and every search begins node = self.root. Leave it out and the second call continues from wherever the first one stopped, which produces a trie full of nonsense that is very hard to read back.

Complexity

  • Time: O(L) for insert, search, and starts_with, where L is the length of the word — one dict lookup per character, and the number of stored words never enters the cost. Autocomplete is O(L + k) where k is the total length of the words returned. Building the trie from n words is O(total characters).
  • Space: O(total characters) nodes in the worst case, when no two words share a prefix; much less in practice because shared prefixes are stored once. Each node also carries a dict, so the constant factor is heavier than a plain list of strings.
