Time & Space Complexity, Explained

What Big O actually measures, why constants get dropped, and how to read time and space off a piece of code without guessing.

What Big O actually measures

Big O describes how the cost of an algorithm grows as the input grows — not how fast it runs on your laptop today. "This function is O(n)" means: if you double the size of the input, the amount of work roughly doubles. It says nothing about whether it takes 2ms or 2 seconds for a given n — that depends on hardware, language, constants. Big O is about the shape of the growth curve, not a single measurement.

Why drop constants: an algorithm that does 3n + 100 operations is still called O(n), not O(3n + 100). For small n the +100 might dominate, but as n grows toward infinity, only the fastest-growing term matters — the constants become noise. This is also why O(n) beats O(n²) eventually, even if the O(n²) version has a smaller constant and wins for tiny inputs.

How to read time complexity off code

Ask one question at each loop or recursive call: how many times does the innermost line run, as a function of n?

for x in items:          # runs n times
    print(x)              # O(1) work each time
# total: O(n)

for x in items:          # runs n times
    for y in items:      # runs n times, for each x
        print(x, y)
# total: O(n * n) = O(n²)

mid = len(items) // 2    # binary search: each step halves what's left
# total: O(log n)
Sequential loops add, nested loops multiply. Two separate for loops one after another, each over n items, is O(n) + O(n) = O(n), still linear. A loop inside another loop is O(n) × O(n) = O(n²). Mixing these up is the single most common Big O mistake.

Space complexity

Space complexity counts the extra memory the algorithm allocates beyond the input itself. The input is given, not created, so it isn't charged. This extra memory is called auxiliary space, and it's what interviewers usually mean by "what's the space complexity?"

The counting rule

Look at every variable and container the function creates, and ask: does its size depend on n, the length of the input?

  1. A single number, boolean, or fixed-size variable takes the same memory whether n is 6 or 6 million — O(1).
  2. A list, set, or dict that can grow to hold up to n items — O(n).
  3. A 2D grid sized n by n — O(n²).
  4. Recursion costs space too: every unfinished call sits on the call stack, so recursion n levels deep is O(n) even with no explicit list anywhere.

Worked example

Take the classic "best time to buy and sell stock" one-pass solution:

def max_profit(prices):
    min_price = float("inf")
    best = 0
    for price in prices:
        min_price = min(min_price, price)
        best = max(best, price - min_price)
    return best
VariableSize depends on n?Space
min_priceNo — always one floatO(1)
bestNo — always one intO(1)
priceNo — one value at a time, overwritten each iterationO(1)

Three small values regardless of input size, so the whole function is O(1) space. Reusing a variable is not growth — price changes n times over the loop, but only ever holds one value at once.

Now contrast it with a version that stores the running minimum for every day instead of just the latest one:

def max_profit(prices):
    mins = []
    lowest = float("inf")
    for p in prices:
        lowest = min(lowest, p)
        mins.append(lowest)          # grows with n
    best = 0
    for i, p in enumerate(prices):
        best = max(best, p - mins[i])
    return best

Same answer, same O(n) time, but mins holds one entry per price, so this version is O(n) space. The tighter solution above keeps only the latest minimum instead of the whole history. Replacing "store all of them" with "store only what the next step needs" is the most common way to shrink space from O(n) down to O(1).

Modifying the input in place is usually counted as O(1) extra space, since nothing new is allocated — you're reusing memory that already existed. Say this explicitly in an interview; don't let it go unstated.

Quick checklist for any solution

  1. Time: how many times does the innermost line run? One loop over n is O(n). A loop inside a loop is O(n²). Sorting is O(n log n). Halving the input each step is O(log n).
  2. Space: what did the function create that isn't the input, and can it grow with n? Only scalars means O(1). A list or map sized off the input means O(n). Recursion n deep means O(n) from the call stack alone, even with zero explicit data structures.

Run through both questions for every solution you write — it's the two-line summary interviewers are listening for at the end of your answer.
