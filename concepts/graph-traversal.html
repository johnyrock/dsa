Graph Traversal, Explained

Representing a graph, BFS for shortest paths, DFS for connectivity, and union-find for grouping.

The core idea

Think of a map of five towns joined by roads. You are standing in town A and you want to know which towns you can reach, or how few roads it takes to get to town E. You cannot see the whole map at once; all you can do at each town is read the signpost listing the roads out of it.

That map is a graph. The towns are nodes (also called vertices) and the roads are edges. If a road can be driven both ways the graph is undirected; if it is one-way it is directed. Unlike a tree, a graph can have loops — you can leave A, drive around, and end up back at A — and there can be more than one route between two towns. That single difference is what makes graph code look the way it does.

Graph traversal is a systematic way to visit every town reachable from where you started, without ever visiting one twice. There are two ways to do it, and they differ by exactly one line of code.

Why it's fast: a set of visited nodes means each node is expanded exactly once and each edge is looked at a fixed number of times. That is O(V + E) — the number of towns plus the number of roads. Without the visited set the same traversal never finishes at all, so the set is not an optimisation, it is the algorithm.

First: how you store a graph

Before you can traverse anything you have to decide how the graph lives in memory. Problems usually hand you an edge list: a list of pairs saying which nodes are joined. 

edges = [("A", "B"), ("A", "C"), ("B", "D"), ("C", "D"), ("D", "E")]

An edge list is useless for traversal, because answering "what is next to D?" means scanning the whole list. So the first thing you do, almost every time, is convert it into an adjacency list: a dict mapping each node to the list of its neighbours. That is the signpost at each town. 

from collections import defaultdict

graph = defaultdict(list)
for u, v in edges:
    graph[u].append(v)
    graph[v].append(u)      # drop this line if the edges are one-way

Which gives you:

{
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A", "D"],
    "D": ["B", "C", "E"],
    "E": ["D"],
}

Now graph[node] is an instant lookup of the neighbours. defaultdict(list) just means "if this key is missing, pretend it maps to an empty list", which saves you a pile of if node not in graph checks. Everything from here on assumes you have built this dict.

How to recognise it

  • The input is a list of pairs — edges, connections, prerequisites, friendships, flights. Pairs almost always mean "build an adjacency list".
  • The input is a 2D grid and you move up/down/left/right. A grid is a graph: each cell is a node, its in-bounds neighbours are the edges. You just never build the dict.
  • The question says "reachable", "connected", "region", "island", "province", "group". That is a connectivity question: DFS, BFS, or union-find.
  • The question asks for the fewest steps / shortest path and every step costs the same. That is BFS, and only BFS.
  • The question asks whether an ordering exists under dependencies. That is topological sort, which is a traversal in a hat.

The naive way first

Here is the code a beginner writes for "is there a path from start to goal?" It is the obvious recursive idea: I am at a node, so try each neighbour in turn. 

def has_path_broken(graph, start, goal):
    if start == goal:
        return True
    for nxt in graph[start]:
        if has_path_broken(graph, nxt, goal):
            return True
    return False

On a tree this is correct. On a graph it never returns. Follow it on our map: from A we go to B, from B the neighbours are ["A", "D"], so we go straight back to A, which goes to B, which goes to A. Python gives up with RecursionError: maximum recursion depth exceeded.

The wasted work is not a slow loop, it is an infinite one. Every undirected edge is a two-way street, and any cycle in a directed graph does the same thing. The fix is one set.

The pattern

Both traversals are the same five lines: take a node out of a container, record it, and put its unseen neighbours in. The container decides everything.

BFS — a queue, closest nodes first

A queue is first-in-first-out: the node that has been waiting longest comes out next. collections.deque gives you that with append (add to the back) and popleft (take from the front). 

from collections import deque

def bfs(graph, start):
    visited = {start}                 # mark BEFORE you enqueue
    queue = deque([start])
    order = []
    while queue:
        node = queue.popleft()        # oldest node first
        order.append(node)
        for nxt in graph[node]:
            if nxt not in visited:
                visited.add(nxt)
                queue.append(nxt)
    return order

The line that matters is visited.add(nxt) sitting next to queue.append(nxt), not later. Read it as "the moment I decide to visit you, you are spoken for." If you instead mark nodes when you pop them, a node with three neighbours can be pushed three times before any of those copies comes out, and the queue blows up. Mark on push.

BFS gives shortest paths for free

Because BFS finishes every node one step away before touching anything two steps away, the first time it reaches a node is by the shortest route. Carry the step count along with the node: 

def shortest_path_length(graph, start, goal):
    if start == goal:
        return 0
    visited = {start}
    queue = deque([(start, 0)])       # (node, steps taken to get here)
    while queue:
        node, dist = queue.popleft()
        for nxt in graph[node]:
            if nxt == goal:
                return dist + 1
            if nxt not in visited:
                visited.add(nxt)
                queue.append((nxt, dist + 1))
    return -1                         # goal is not reachable

This only holds when every edge costs the same. Weighted edges need Dijkstra's algorithm, which is BFS with a heap instead of a queue.

DFS — a stack, one branch to the end

Swap the queue for a stack (last in, first out) and you get depth-first search: it charges down one branch as far as it goes before backing up. Usually you write it with recursion, which uses the call stack instead of a list. 

def dfs(graph, node, visited, order):
    visited.add(node)
    order.append(node)
    for nxt in graph[node]:
        if nxt not in visited:
            dfs(graph, nxt, visited, order)
    return order

Or with your own stack, which never hits Python's recursion limit:

def dfs_iterative(graph, start):
    visited, order, stack = set(), [], [start]
    while stack:
        node = stack.pop()            # newest node first
        if node in visited:
            continue                  # a duplicate copy; skip it
        visited.add(node)
        order.append(node)
        for nxt in graph[node]:
            if nxt not in visited:
                stack.append(nxt)
    return order

Compare that with bfs above. Same loop, same pushes; stack.pop() instead of queue.popleft(). That is the entire difference between the two algorithms. (The two DFS versions above visit our map in different orders — A, B, D, C, E recursively versus A, C, D, E, B iteratively — because a stack hands back the last neighbour you pushed. Both are valid depth-first orders.) DFS does not find shortest paths — it finds a path — so use it when you only care whether things are connected, and BFS when you care how far apart they are.

End. Visit order was A, B, C, D, E — and it is grouped by distance from A, which is exactly why BFS answers shortest-path questions.

Notice what happened at step 3. C looked at D and did nothing, because B had already claimed it at step 2. Both of those are genuine one-road routes from a neighbour of A, and both would have found D at distance 2 — but only the first one counts, and the visited check is what enforces that. Delete the check and step 3 pushes a second copy of D, step 4 pops one D and pushes E, step 5 pops the other D and pushes a second E, and on a bigger graph that doubling never stops.

Variations

Grids are graphs

For a 2D grid you skip the adjacency list entirely. A cell's neighbours are the four cells around it that are still inside the grid, so you compute them on the spot: 

def neighbours(r, c, grid):
    for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
        nr, nc = r + dr, c + dc
        if 0 <= nr < len(grid) and 0 <= nc < len(grid[0]):
            yield nr, nc

The visited set holds (row, col) tuples instead of node names. Everything else is unchanged. That is the whole of Number of Islands.

Counting connected components

One traversal only reaches the nodes connected to where you started. To count the separate clumps of a graph, start a fresh traversal from every node you have not seen yet, and count how many times you had to start. 

def count_components(graph):
    visited = set()
    count = 0
    for node in graph:
        if node not in visited:
            count += 1                       # a brand new clump
            dfs(graph, node, visited, [])    # swallow the whole clump
    return count

The visited set is shared across all the traversals — that is what stops you counting the same clump twice. This one function is Number of Islands, Number of Provinces, and half a dozen others.

Union-find, for grouping without traversal

Sometimes you do not need to walk the graph at all; you only need to know which nodes ended up in the same group. Union-find (also called disjoint set union, or DSU) does that directly.

The idea is a chain of command. Every node starts as its own boss. find(x) follows the chain up until it reaches someone who is their own boss — that person's name is the group's name. union(a, b) takes the two bosses and makes one report to the other, merging two groups into one. Two nodes are in the same group exactly when find returns the same boss. 

class UnionFind:
    def __init__(self, items):
        self.parent = {x: x for x in items}   # everyone starts as their own boss
        self.size = {x: 1 for x in items}

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]   # path compression
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                       # already in the same group
        if self.size[ra] < self.size[rb]:      # hang the smaller tree off the bigger
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        return True

Two small tricks keep the chains short. Path compression is the line inside find: as you climb, you re-point each node at its grandparent, so the next climb is shorter. Union by size always hangs the smaller group under the bigger one, so the chain never gets tall in the first place. With both, find and union are effectively constant time.

Counting components becomes a subtraction — start with one group per node and drop one for each merge that actually did something:

def count_components_uf(nodes, edges):
    uf = UnionFind(nodes)
    groups = len(nodes)
    for u, v in edges:
        if uf.union(u, v):
            groups -= 1
    return groups

Reach for union-find when the edges arrive one at a time and you have to answer "connected?" as you go, or when you only care about the grouping and never about the paths. Reach for BFS or DFS when you need the route, the distance, or the order of visits.

Common mistakes

No visited set. The single most common graph bug. Any cycle — including the trivial one made by an undirected edge — sends you round forever. If your graph code hangs or throws RecursionError, this is why.
Marking visited on pop instead of on push. The traversal still terminates, but a node can sit in the queue several times, so the queue can grow to the number of edges rather than nodes, and nodes get expanded again and again. The distances stay correct, but the cost does not. Add to visited in the same breath as the append.
Only adding one direction of an undirected edge. If the problem says "a road between u and v", you need both graph[u].append(v) and graph[v].append(u). Forget one and half the graph silently becomes unreachable.
Using DFS for a shortest path. DFS finds a path, not the short one. If the question says "minimum number of steps" and the steps all cost the same, it must be BFS.

Complexity

  • Time: O(V + E) for BFS and DFS — every node comes off the container once, and each of its edges is inspected once. For an m × n grid that is O(m × n), since each cell has at most four neighbours. Union-find is O(E α(V)), where α grows so slowly it is under 5 for any input you will ever see; treat it as O(E).
  • Space: O(V + E) to hold the adjacency list, plus O(V) for the visited set and the queue or stack. DFS recursion can stack V frames deep on a long chain.
