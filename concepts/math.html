Math Tricks, Explained

Fast exponentiation, schoolbook multiplication on digit arrays, and reversing an integer without overflowing.

The core idea

Some interview problems are pure arithmetic, but with a catch: the obvious way is too slow, the numbers are too big for a machine word, or the language's built-in shortcut is off limits. The fix is always to go back to how you did arithmetic by hand in school, and then to notice one structural trick that cuts the work.

Three of those tricks come up again and again. To compute xn, square the base and halve the exponent instead of multiplying n times. To multiply two huge numbers, multiply digit by digit into an array of slots and carry afterwards. To reverse or rebuild an integer, peel digits with % 10 and // 10, and check the overflow bound before the step that would cross it.

Why it's fast: halving the exponent turns n multiplications into about log₂ n. The digit loops are O(number of digits), which is the size of the input, so nothing is wasted.

How to recognise it

Reach for these techniques when a problem says, or quietly implies, one of these:

  • A huge exponent or repeat count: n up to 231, "compute x to the power n", "apply this operation n times" where the operation composes.
  • Numbers given as strings because they will not fit in 64 bits. The problem is asking you to be the big-integer library.
  • "Assume a 32-bit signed integer" and "return 0 if it overflows". You must detect the overflow without ever producing an out-of-range value.
  • "Do not use built-in int(), str(), pow". The one-liner exists; the interviewer wants the loop.

The naive way first

Take this problem: compute x raised to the integer power n. The instinctive answer multiplies n times: 

def power_slow(x, n):
    result = 1.0
    for _ in range(abs(n)):
        result *= x
    return result if n >= 0 else 1 / result

That is O(n). For n = 231 − 1, the largest allowed input, it is two billion multiplications. The waste is that x8 is being computed as x·x·x·x·x·x·x·x when it is also ((x²)²)², three multiplications instead of seven.

The pattern

Read n in binary. Each set bit says "multiply x2k into the answer". You get those powers for free by squaring x once per bit. 

def power(x, n):
    if n < 0:
        x, n = 1 / x, -n           # x^-n is (1/x)^n
    result = 1.0
    while n:
        if n & 1:                  # lowest bit set: this power of x belongs in the answer
            result *= x
        x *= x                     # x, x^2, x^4, x^8, ...
        n >>= 1                    # drop the bit we just handled
    return result

The line that matters is x *= x. After k iterations, x holds x2k, and bit k of n decides whether that factor is used. The loop runs once per bit of n, so about 31 times for the worst case instead of two billion.

Variations

Schoolbook multiplication on digit arrays

To multiply two numbers given as strings, do exactly what you did in primary school, but skip the "shift left one column per row" ritual by computing the slot directly. Digit i of a times digit j of b lands in slot i + j + 1, and its carry goes to slot i + j. The product of an m-digit and an n-digit number has at most m + n digits, so that is the array size. 

def multiply(a, b):
    if a == "0" or b == "0":
        return "0"
    digits = [0] * (len(a) + len(b))
    for i in range(len(a) - 1, -1, -1):
        for j in range(len(b) - 1, -1, -1):
            total = int(a[i]) * int(b[j]) + digits[i + j + 1]
            digits[i + j + 1] = total % 10         # ones digit stays here
            digits[i + j] += total // 10           # carry moves one slot left
    k = 0
    while digits[k] == 0:                          # strip leading zeroes
        k += 1
    return "".join(map(str, digits[k:]))

It is O(m · n), which is fine for the string lengths interviews use. The += on the carry line matters: that slot may already hold a carry from an earlier pair.

Digit-by-digit reversal with an overflow check

x % 10 is the last digit; x // 10 drops it. Rebuild the number from the other end with result * 10 + digit. The overflow question is: will result * 10 + digit exceed 231 − 1? Rearranged so nothing overflows, that is result > (INT_MAX − digit) // 10. 

def reverse(x):
    INT_MAX = 2 ** 31 - 1
    sign = -1 if x < 0 else 1
    x = abs(x)                               # Python's % is floor-based; keep it positive
    result = 0
    while x:
        digit = x % 10
        x //= 10
        if result > (INT_MAX - digit) // 10:
            return 0                         # the next step would overflow
        result = result * 10 + digit
    return sign * result

Python integers never actually overflow, so you could check result > INT_MAX at the end. In C, Java or Go the damage would already be done by then, which is why the interview wants the pre-check.

Recursive fast power

The same idea reads naturally as recursion: xn = (xn/2)², times one extra x when n is odd. Compute the half once and store it; calling power(x, n // 2) twice brings back the O(n) you were trying to avoid. 

def power_rec(x, n):
    if n == 0:
        return 1.0
    if n < 0:
        return 1 / power_rec(x, -n)
    half = power_rec(x, n // 2)              # once, not twice
    return half * half * (x if n % 2 else 1)

Modular arithmetic

When the answer is asked "modulo 109 + 7", apply the modulus after every multiply in the fast power loop. The squaring trick is also how pow(x, n, mod) is implemented under the hood.

Common mistakes

Negative exponent handled halfway. Flipping the sign of n without also replacing x with 1/x gives x|n|. Do both, at the top, before the loop.
Recursing on the half twice. power(x, n//2) * power(x, n//2) is O(n) calls. Store the half in a variable and square it.
Negative numbers and %. In Python -123 % 10 is 7, not −3. Work on abs(x) and reapply the sign at the end.
Assigning the carry instead of adding it. digits[i + j] = total // 10 throws away a carry that an earlier digit pair already put there. Use +=.
Checking overflow after the fact. Compare against (INT_MAX − digit) // 10 before result * 10 + digit, not after.
Leading zeroes. "0" times anything should return "0", not "00" or an empty string. Handle the zero case up front and strip zeroes at the end.

Complexity

  • Fast power: O(log n) multiplications, O(1) space iteratively or O(log n) stack recursively.
  • String multiplication: O(m · n) time for m- and n-digit inputs, O(m + n) space for the digit array.
  • Digit reversal: O(d) time for a d-digit number (d ≤ 10 for 32-bit), O(1) space.
