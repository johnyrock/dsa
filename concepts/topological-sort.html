Topological Sort, Explained

Ordering tasks that depend on each other with Kahn's algorithm, and detecting when a cycle makes it impossible.

The core idea

You are planning a course of study. You cannot take Recursion until you have done both Loops and Functions, you cannot take either of those until you have done Intro, and Trees comes after Recursion. Nobody hands you a schedule. All you have is a pile of index cards, each saying "X must come before Y". You need a single order to work through, and it has to respect every card.

Here is how a person actually does it. Look at the pile and find any course with nothing blocking it. Take it. Now cross that course off every card that mentioned it, which may free up some other courses. Repeat until the pile is empty.

That is topological sort: given a directed graph whose edges mean "must come first", produce an order of all the nodes such that every edge points forward. The version of it above, driven by a count of how many things are still blocking each node, is Kahn's algorithm.

Why it's fast: instead of rescanning the whole pile of cards to find what is free, you keep a running count per node of how many blockers remain. Finishing a node decrements only its direct successors, so across the whole run each edge is touched exactly once. That is O(V + E) instead of the O(V2 × E) you get from rescanning.

One thing can go wrong, and it is not a bug in the algorithm. If A must come before B and B must come before A, there is no valid order at all. That is a cycle, and detecting it is half of what these problems ask for.

How to recognise it

  • The words "prerequisite", "dependency", "must come before", "blocked by", "build order". These are the same problem wearing different clothes: courses, package installs, task schedules, recipe steps.
  • The input is a list of pairs and the pairs are one-way. Two-way pairs are plain graph traversal; one-way pairs that mean "before" are topological sort.
  • The question asks "is it possible?" rather than for the order itself. That is a cycle check, and the cycle check falls out of Kahn's algorithm for free.
  • The question asks for the minimum number of rounds / semesters / parallel steps. That is the level-by-level variation below.
  • The answer is allowed to be any valid order. A dead giveaway: topological orders are usually not unique, and the problem statement will say so.

The graph must be a DAG — a directed acyclic graph, meaning one-way edges and no cycles. If it is not a DAG, no topological order exists.

The naive way first

Translate the index-card method literally: scan every remaining node, and for each one scan every edge to see whether anything unfinished still points at it. 

def topo_slow(nodes, edges):
    remaining = set(nodes)
    order = []
    while remaining:
        for node in sorted(remaining):
            blocked = any(v == node and u in remaining for u, v in edges)
            if not blocked:
                order.append(node)
                remaining.remove(node)
                break
        else:
            return []          # nothing was free: there is a cycle
    return order

This is correct, and it is the right thing to write first. But look at the cost. The outer while runs once per node. Inside it you may scan every remaining node, and for each of those you scan every edge. That is roughly O(V2 × E) — for a thousand courses with ten thousand prerequisites, on the order of ten billion comparisons to produce a thousand-item list.

The wasted work is the rescanning. Taking one course changes the blocked-ness of only the handful of courses it pointed at, yet this code recomputes it for everything. Cache that number instead of recomputing it and the whole algorithm collapses to one pass.

The pattern

The cached number is called indegree: for each node, how many edges point at it, counting only edges from nodes not yet placed. Indegree 0 means "nothing is blocking this, take it now". 

from collections import deque, defaultdict

def topo_sort(nodes, edges):
    # edges are (before, after) pairs
    graph = defaultdict(list)
    indegree = {n: 0 for n in nodes}
    for before, after in edges:
        graph[before].append(after)
        indegree[after] += 1              # 'after' has one more thing blocking it

    queue = deque(n for n in nodes if indegree[n] == 0)
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for nxt in graph[node]:
            indegree[nxt] -= 1            # one blocker cleared
            if indegree[nxt] == 0:        # nothing left blocking it
                queue.append(nxt)

    if len(order) != len(nodes):
        return []                          # a cycle: some nodes never reached 0
    return order

The line that matters is if indegree[nxt] == 0. Read it as a gate that only opens on the last blocker. A node with three prerequisites gets decremented three times and pushed exactly once, on the third. Beginners often push whenever the count drops, which puts the node in the queue too early and produces an order that violates the very constraints you were given.

The second line that matters is if len(order) != len(nodes) at the bottom. It is not a sanity check bolted on, it is the cycle detector. Nodes inside a cycle each have a blocker that is also inside the cycle, so none of their counts ever reaches 0, so none of them ever enters the queue and none of them makes it into order. A short output means a cycle. Never omit this check.

End. Every original arrow points forward in this line, which is exactly what "topological order" means.

Notice what happened at step 2. recur went from 2 to 1 and was not pushed. It had Loops out of the way but still needed Functions. Had we pushed on any decrement, recur would have landed in the queue ahead of funcs, and the output would have told you to take Recursion before Functions — a schedule that breaks the one rule you were given. The gate at exactly zero is the whole algorithm.

Also notice that [intro, funcs, loops, recur, trees] would have been just as correct. Once two nodes are both free, nothing in the problem prefers one over the other, so most of these problems accept any valid order.

Variations

Just asking "is it possible?"

Course Schedule (#207) does not want the order, only whether one exists. Run the same function and compare lengths. Watch the direction of the pairs: LeetCode gives [course, prerequisite], which is after then before, the reverse of what the template expects. 

def can_finish(num_courses, prerequisites):
    nodes = list(range(num_courses))
    edges = [(before, after) for after, before in prerequisites]   # flip each pair
    return len(topo_sort(nodes, edges)) == num_courses

The smallest valid order

When several nodes are free at once and the problem wants the lexicographically smallest answer, take the smallest free node rather than the oldest. Swap the queue for a min-heap; nothing else changes. 

import heapq

def topo_smallest(nodes, edges):
    graph = defaultdict(list)
    indegree = {n: 0 for n in nodes}
    for before, after in edges:
        graph[before].append(after)
        indegree[after] += 1

    heap = [n for n in nodes if indegree[n] == 0]
    heapq.heapify(heap)                   # a min-heap instead of a queue
    order = []
    while heap:
        node = heapq.heappop(heap)        # always the smallest free node
        order.append(node)
        for nxt in graph[node]:
            indegree[nxt] -= 1
            if indegree[nxt] == 0:
                heapq.heappush(heap, nxt)
    return order if len(order) == len(nodes) else []

Level by level: how many rounds?

"What is the fewest semesters if I can take any number of unblocked courses at once?" Drain the queue one full level at a time, the same snapshot trick as BFS level order in tree traversal. On our example this gives [[intro], [loops, funcs], [recur], [trees]] — four semesters, with two courses in the second. 

def topo_levels(nodes, edges):
    graph = defaultdict(list)
    indegree = {n: 0 for n in nodes}
    for before, after in edges:
        graph[before].append(after)
        indegree[after] += 1

    queue = deque(n for n in nodes if indegree[n] == 0)
    levels, placed = [], 0
    while queue:
        level = []
        for _ in range(len(queue)):       # exactly the nodes free right now
            node = queue.popleft()
            level.append(node)
            placed += 1
            for nxt in graph[node]:
                indegree[nxt] -= 1
                if indegree[nxt] == 0:
                    queue.append(nxt)
        levels.append(level)
    return levels if placed == len(nodes) else []

The DFS version

There is a second, quite different way: run a depth-first search, and append a node to a list only once every node it points at is completely finished. Reverse that list at the end. Cycle detection needs a third state — a node currently on the recursion stack — because walking into one of those means you have gone in a circle. 

def topo_dfs(nodes, edges):
    graph = defaultdict(list)
    for before, after in edges:
        graph[before].append(after)

    state = {n: 0 for n in nodes}         # 0 = unseen, 1 = on the stack, 2 = done
    order = []

    def visit(node):
        if state[node] == 1:
            return False                  # walked into something still in progress
        if state[node] == 2:
            return True                   # already placed, nothing to do
        state[node] = 1
        for nxt in graph[node]:
            if not visit(nxt):
                return False
        state[node] = 2
        order.append(node)                # finished: everything after it is placed
        return True

    for node in nodes:
        if not visit(node):
            return []
    return order[::-1]                    # reverse the finish order

Both are O(V + E). Kahn's is easier to get right and gives you levels for free, so prefer it unless a problem specifically wants the DFS finishing order.

Common mistakes

Building the edges backwards. prerequisites = [[1, 0]] on LeetCode means "to take course 1 you must first take course 0", so the edge runs 0 → 1 and it is course 1 whose indegree goes up. Getting this backwards produces a perfectly plausible-looking order that is exactly reversed. Say the sentence out loud before you write the loop.
Skipping the cycle check. Without len(order) != len(nodes) a cyclic input silently returns a partial order, and it looks fine on the small test cases. The check is two lines and it is the difference between correct and wrong.
Pushing on every decrement instead of only at zero. A node with several prerequisites then enters the queue as soon as the first one clears, and lands in the output ahead of its own blockers. The condition is == 0, never <= 0 and never unconditional.
Forgetting the isolated nodes. Nodes that appear in no edge at all still belong in the output. Seed indegree from the full node list — {n: 0 for n in nodes} — not from the nodes you happen to see while scanning edges.

Complexity

  • Time: O(V + E). Every node enters and leaves the queue once, and each edge is decremented once, when its source node is popped.
  • Space: O(V + E) — the adjacency list holds one entry per edge, and the indegree dict, queue, and output are each O(V).
