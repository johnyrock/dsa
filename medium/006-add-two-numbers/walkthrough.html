Add Two Numbers, narrated

Scroll through the thinking, from converting to integers and back to a single pass of schoolbook addition with a carry, with the state of the algorithm shown alongside.

Pattern used Linked List dummy head, walk both lists with a carry, loop while anything is left

STEP 1

The problem

Two linked lists, each holding a non-negative integer one digit per node, least significant digit first. Add the numbers and return the sum in the same format.

Running example: l1 = [2, 4, 3] is 342 and l2 = [5, 6, 4] is 465. Their sum is 807, returned as [7, 0, 8].

The reversed order sounds like an obstacle. It is the opposite. Addition works from the ones digit upward, and the ones digits are the heads, so both lists are already in the order we need.

STEP 2

First instinct: turn them into integers

Walk each list, rebuild the integer, add them with +, then split the result back into digits and link them up.

a = 0; mult = 1while l1: a += l1.val * mult; mult *= 10; l1 = l1.next# same for b, then total = a + b# then peel digits off total with % 10 and // 10

In Python this passes, because integers never overflow. It is still the wrong answer in an interview: it throws away the structure the question is about, it does three passes where one will do, and in most languages a 100-digit number does not fit in any integer type.

STEP 3

Reframe: do it the way you learned in school

Column by column from the right: add the two digits and the carry from the previous column. Write down the ones digit, carry the tens digit to the next column.

Because the lists are stored least-significant first, "the next column" is simply .next on both lists. Walk them together, one node each per step, and each step is one column of the addition.

Column: total = carry + l1.val + l2.val. Keep total % 10, carry total // 10. Both come from one call to divmod.
STEP 4

The key idea: one loop that survives unequal lengths and the last carry

Three details make the loop clean:

  • A dummy head in front of the result, so appending the first digit is not a special case. Return dummy.next at the end.
  • Loop while l1 or l2 or carry. When one list runs out it just stops contributing, as if padded with zeros. When both run out but a carry remains, one more iteration emits it.
  • Guard each list with if l1: before reading its value or advancing it.

That is the whole algorithm. No pre-pass to measure lengths, no padding, no post-loop fix-up.

STEP 5

Trace it: the first two columns

Column 1: carry 0 + 2 + 5 = 7. divmod(7, 10) is (0, 7). Append 7, carry stays 0.

Column 2: carry 0 + 4 + 6 = 10. divmod(10, 10) is (1, 0). Append 0, and now carry = 1.

The result so far is 7 → 0, and the two list pointers have each moved twice.

STEP 6

Trace it: the last column and the exit

Column 3: carry 1 + 3 + 4 = 8. divmod(8, 10) is (0, 8). Append 8, carry back to 0.

Now l1 and l2 are both None and carry is 0, so the loop condition is false and we stop. dummy.next is 7 → 0 → 8: 807.

Three nodes in, three iterations, three nodes out. The loop never asked how long either list was.
STEP 7

The pitfall: stopping before the last carry

Take l1 = [9, 9] and l2 = [1], which is 99 + 1 = 100. Column 1: 9 + 1 = 10, append 0, carry 1. Column 2: l2 is gone, so 1 + 9 = 10, append 0, carry 1. Both lists are now empty.

A loop that runs only while l1 or l2 stops here and returns [0, 0]. The carry is the hundreds digit. Including carry in the condition gives one more iteration: 1 + nothing = 1, append 1, carry 0, done: [0, 0, 1].

The same condition handles the two-lists-of-different-lengths case: once l2 runs out, l1 keeps the loop alive on its own.

STEP 8

Time and space

One iteration per column, and there are max(m, n) columns plus at most one for the final carry: O(max(m, n)) time.

The result list has that many nodes and the problem requires it, so O(max(m, n)) space for the output and O(1) beyond it: a dummy, a tail pointer and a carry.

ApproachTimeExtra space
Convert to integers and backO(m + n), three passesO(1) in Python, overflows elsewhere
Column-by-column with carryO(max(m, n)), one passO(1)
STEP 9

The final solution

Sixteen lines. Every one of them maps to a step above.

  • dummy = ListNode(); tail = dummy removes the first-node special case.
  • while l1 or l2 or carry handles unequal lengths and the trailing carry.
  • total = carry then the two guarded if blocks add whatever digits exist and advance those pointers.
  • carry, digit = divmod(total, 10) splits the column.
  • tail.next = ListNode(digit); tail = tail.next appends in least-significant-first order.
  • return dummy.next skips the dummy.
One-line summary to remember: walk both lists in step, one column per node, and loop while anything is left, including the carry.
