Medium · Dynamic Programming · LeetCode #198

House Robber, narrated

I will first recurse on rob-or-skip choices, then remember the best answer for each starting house.

Pattern used Dynamic Programming best[i] = max(best[i-1], best[i-2] + nums[i]), kept in two variables

STEP 1

The problem

Houses stand in a row, and nums[i] is the cash in house i. You can rob any set of houses, with one rule: two adjacent houses cannot both be robbed. Maximise the total.

There is no requirement to alternate. Skipping two or three houses in a row is fine if the numbers say so. The only forbidden pattern is two robbed houses side by side.

Running example: nums = [2, 7, 9, 3, 1]. Robbing houses 0, 2 and 4 yields 2 + 9 + 1 = 12. The tempting 7 + 3 = 10 from houses 1 and 3 is worse. The answer is 12.

We are asked only for the amount, not the set of houses. That is a hint that we can keep running totals rather than sets.

STEP 2

First instinct: recurse on rob-or-skip

I can either rob the current house and skip the next, or skip the current one, then take the better result.

def rob(nums):    def best_from(i):        if i >= len(nums): return 0        return max(nums[i] + best_from(i + 2), best_from(i + 1))    return best_from(0)

This is correct. The recursion branches repeatedly over the same suffixes, giving O(2ⁿ) time complexity. Its call stack has O(n) space complexity.

Keeping the result for each suffix removes repeated choices. There are only n starting indices, and the final version needs only the previous two values.

STEP 3

The key insight: the best haul up to house i needs only the two before it

I define best[i] as the most I can rob from houses 0..i. If I rob house i, I must leave house i - 1 alone, so the total is best[i-2] + nums[i]. If I skip it, the total is best[i-1]. Hence:

best[i] = max(best[i-1], best[i-2] + nums[i])

Filling that table left to right computes each entry once: O(n). And since only best[i-1] and best[i-2] are ever read, the table collapses to two variables. Call them take (best up to the previous house) and skip (best up to two houses back).

This is the Climbing Stairs shape exactly, with max where that problem had +. The base cases are even simpler: with no houses considered, both totals are 0.

STEP 4

The approach: one tuple assignment per house

  • skip, take = 0, 0 — before any house, the best totals two back and one back are both 0.
  • for money in nums — visit each house once.
  • skip, take = take, max(take, skip + money) — the new "one back" is max(leave it, rob it); the old "one back" slides into "two back".
  • return take — after the last house, take is the best over the whole street.

The tuple assignment evaluates its whole right-hand side before rebinding either name, so skip + money uses the old skip. That single detail is what step 8 is about.

STEP 5

Trace it: houses 0 and 1

House 0, money = 2: max(take, skip + money) = max(0, 0 + 2) = 2. Now skip = 0, take = 2. Best from the first house alone is 2, obviously.

House 1, money = 7: max(2, 0 + 7) = 7. Rob house 1 instead of house 0. Now skip = 2, take = 7. Note that skip still remembers the 2, because the next house may want to combine with house 0 rather than house 1.

STEP 6

Trace it: houses 2 and 3

House 2, money = 9: max(7, 2 + 9) = 11. Robbing house 2 on top of house 0 beats keeping house 1. Now skip = 7, take = 11.

House 3, money = 3: max(11, 7 + 3) = 11. Robbing house 3 would force us back to the house-1 total of 7, and 10 < 11, so leave it. skip = 11, take = 11. Both variables holding the same value means "the best total does not include the latest house".

STEP 7

Trace it: house 4, the answer

House 4, money = 1: max(11, 11 + 1) = 12. Because house 3 was skipped, skip already equals the full best of 11, and adding house 4 costs nothing in conflicts. skip = 11, take = 12.

The loop ends and return take gives 12, matching 2 + 9 + 1.

The exponential recursion would have made dozens of calls for five houses. The loop made five max calls.
STEP 8

Where this goes wrong: splitting the assignment, forcing alternation

Two statements instead of one tuple. Writing skip = take and then take = max(take, skip + money) looks equivalent. It is not: the second line now reads the new skip, which equals take, so it computes take + money every time and simply sums the street. On the example the totals run 2, 9, 18, 21, 22 and the function returns 22 instead of 12, robbing every house. The panel shows that run.

Forcing alternation. take = skip + money without the max always robs the current house. It happens to return 12 here, which is what makes it dangerous, but on [4, 1, 1, 4, 1] it returns 6 (houses 0, 2, 4) instead of 8 (houses 0 and 3).

Returning skip. After the loop skip is the best total excluding the last house: 11 instead of 12.

I keep the update as one tuple assignment so its right-hand side sees the old values, and I keep the max so skipping any number of houses stays allowed.
STEP 9

Time and space

One pass over nums with a constant amount of work per house: O(n) time. Two integers regardless of input size: O(1) space.

ApproachTimeSpace
Plain recursion, rob or skipO(2ⁿ)O(n) call stack
Recursion + memo / full dp tableO(n)O(n)
Two rolling variablesO(n)O(1)

The memoised recursion already fixes the exponential blow-up. The two-variable loop is the final step, noticing that best[i] reads only best[i-1] and best[i-2].

STEP 10

The final solution

Four lines of logic. Every one of them maps to a step above.

  • skip, take = 0, 0 — with no houses, the best totals are 0.
  • for money in nums — one decision per house.
  • skip, take = take, max(take, skip + money) — leave it (keep take) or rob it (skip + money), and slide the window.
  • return take — the best total over the whole street.
One-line summary to remember: for each house, the best haul is the better of "skip it" and "rob it plus the best from two houses back".
