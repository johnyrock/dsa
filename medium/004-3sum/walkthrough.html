Medium · Two Pointers · LeetCode #15

3Sum, narrated

Scroll through the thinking, from the triple loop through sorting to fixing one number and closing two pointers on the rest, with the state of the algorithm shown alongside.

STEP 1

The problem

You get an integer array. Return every triplet of values, taken from three different positions, that adds up to zero. The catch is in the second sentence: no duplicate triplets. [-1, 0, 1] and [0, 1, -1] are the same answer and may appear only once.

Running example: nums = [-1, 0, 1, 2, -1, -4]. The answer is two triplets: [-1, -1, 2] and [-1, 0, 1].

Notice that -1 appears twice in the input and both copies are used in the first triplet, while [-1, 0, 1] can be built from either copy but is reported once. Getting the duplicates right is most of the difficulty.

STEP 2

First instinct: three nested loops

Try every i < j < k, check whether the three values sum to zero, and drop the sorted triplet into a set to kill duplicates.

found = set()for i in range(n):    for j in range(i + 1, n):        for k in range(j + 1, n):            if nums[i] + nums[j] + nums[k] == 0:                found.add(tuple(sorted((nums[i], nums[j], nums[k]))))

Correct, but O(n³). With n = 3000 that is roughly 4.5 billion triples. And the duplicate handling is bolted on with a set rather than understood.

Two Sum turned O(n²) into O(n) by remembering complements in a hash map. The same trick here gives O(n²), but deduplicating hash-map hits is messy. Sorting gives a cleaner O(n²).

STEP 3

Reframe: sort, then fix one number

Sort the array: [-4, -1, -1, 0, 1, 2]. Order is not part of the answer, so nothing is lost, and two things are gained.

  • For a fixed first value nums[i], the remaining question is "find two numbers in the sorted suffix that sum to -nums[i]". That is Two Sum on sorted input, which two pointers solve in one linear pass.
  • Equal values are now neighbours, so "have I used this value already?" is a comparison with the previous element.
The plan: loop i over possible first values, and for each one run a two-pointer sweep over i+1 … n-1.
STEP 4

The key idea: two pointers closing inward

With i fixed, put left = i + 1 and right = n - 1 and look at total = nums[i] + nums[left] + nums[right].

  • Too small? The only way up is a bigger left value: left += 1.
  • Too big? The only way down is a smaller right value: right -= 1.
  • Exactly zero? Record it, then move both pointers, because the current left cannot pair with any other right to hit zero again.

Each step discards one element from consideration for good, so the sweep is O(n). Sorted order is what makes the "only way up / only way down" argument valid.

STEP 5

Trace it: i = 0, the −4

Fix nums[0] = -4. Pointers at left = 1 (−1) and right = 5 (2). Total −3, too small, so left moves right: −1 again, total −3; 0, total −2; 1, total −1. Now left = 5 = right and the sweep ends with nothing found.

Nothing pairs with −4 here. That is fine: the outer loop simply moves on.

STEP 6

Trace it: i = 1, the first −1

Fix nums[1] = -1, pointers at 2 (−1) and 5 (2). Total 0: hit, record [-1, -1, 2]. Move both: left = 3 (0), right = 4 (1). Total 0 again: hit, record [-1, 0, 1]. Move both and the pointers cross.

Next, i = 2 is also −1, equal to nums[1]. Every triplet starting with −1 has already been found, so continue skips it. Then i = 3 is 0; its sweep compares 0 + 1 + 2, too big, and ends. The outer loop stops there, since the last two slots can only ever be the second and third members of a triplet. (The nums[i] > 0 break would fire first on inputs whose positives start earlier.)

Two triplets, exactly the expected answer, with no set needed.
STEP 7

The pitfall: skipping the wrong copy

The outer skip must compare with the previous element: nums[i] == nums[i - 1]. Compare with the next one instead and you skip the first −1 in the example, which is the only i that produces [-1, -1, 2].

Skip forward, and [-1, -1, 2] disappears. Skip backward, and the first copy does its work while later copies are ignored.

The inner sweep has the same rule after a hit: advance left past values equal to the one just used, guarded by left < right so the pointers cannot run past each other. On [0, 0, 0, 0] this is what keeps the answer to a single [0, 0, 0].

STEP 8

Time and space

Sorting costs O(n log n). Then there are up to n choices of i, each followed by a two-pointer sweep that is O(n) because every step retires one element. Total O(n²) time, and the sort disappears under it.

Beyond the output, only a few indices are held: O(1) extra space, ignoring the sort's own working memory.

ApproachTimeExtra space
Three nested loops + setO(n³)O(number of triplets)
Fix i, hash map for the pairO(n²)O(n) per i, plus dedup set
Sort, fix i, two pointersO(n²)O(1)
STEP 9

The final solution

Twenty lines. Every one of them maps to a step above.

  • nums.sort() enables both the pointer argument and neighbour-based duplicate skipping.
  • if nums[i] > 0: break is the early exit once the smallest value is positive.
  • if i > 0 and nums[i] == nums[i - 1]: continue skips repeated first values, looking backward.
  • The while left < right loop is Two Sum on sorted input, with the three-way comparison on total.
  • On a hit, both pointers move and the inner while hops over duplicate second values.
One-line summary to remember: sort, fix the smallest, two-pointer the rest, and skip a value you just used.
