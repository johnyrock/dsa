Design Twitter, narrated

I will first filter and sort every tweet for each feed request, then merge only the newest tweets from the relevant users.

Pattern used Heap Each user's tweet list is already sorted by time, so a news feed is a k-way merge: a max-heap seeded with each followee's newest tweet, popped 10 times.

STEP 1

The problem

Build a tiny Twitter. Users post tweets with unique ids, follow and unfollow each other, and ask for their news feed: the 10 most recent tweets by themselves and by everyone they follow, newest first. Four methods: post_tweet, get_news_feed, follow, unfollow.

Running example: post_tweet(1, 5), get_news_feed(1) → [5], follow(1, 2), post_tweet(2, 6), get_news_feed(1) → [6, 5], unfollow(1, 2), get_news_feed(1) → [5].

This is a design problem, so the question is not one algorithm but a set of data structures that make all four operations cheap. The hard one is get_news_feed: it must combine tweets from several authors, order them by time, and cut off at 10. Tweet ids say nothing about time (a user could post id 100 before id 3), so recency has to be recorded separately.

STEP 2

First instinct: one global list, filter and sort each feed

I can keep every tweet in one global list. For a feed, I filter to the user and their followees, I sort the visible tweets by time, and return ten IDs.

def getNewsFeed(self, userId):    authors = self.following[userId] | {userId}    visible = [tweet for tweet in self.all_tweets if tweet[1] in authors]    visible.sort(reverse=True)    return [tweet_id for _, _, tweet_id in visible[:10]]

This is correct. If there are N tweets, filtering takes O(N) time and sorting takes O(N log N) time per feed request. The visible-tweet list uses O(N) space.

Each author's tweet list is already ordered by time, and I only need ten feed items. A heap can merge the newest tweet from each relevant author and stop after ten pops.

STEP 3

The key insight: per-author lists are already sorted, so merge them

I store tweets per user: self.tweets[user_id] is a list of (stamp, tweet_id), appended in posting order. A global counter self.time supplies the stamp, so within any one author's list the stamps strictly increase. Each list is sorted by time for free.

A feed is then the classic problem of merging k sorted lists, newest first, but only for the first 10 results. That is a heap job: seed a heap with the newest tweet of each author (the user plus their followees), I pop the newest overall, and replace it with that same author's next-older tweet. Every pop yields the next feed entry, and after 10 pops I stop.

The heap holds at most one entry per author. It never sees an author's older tweets until the newer ones have been emitted, so a feed of 10 does at most 10 pops and 10 pushes regardless of how many tweets exist.

heapq is a min-heap, so the entry is (-stamp, tweet_id, uid, idx): the negated stamp puts the newest at the root, and uid, idx say where to find the next-older tweet. Following is a set per user, so follow, unfollow and "who do I follow" are O(1).

STEP 4

The approach: three structures, four methods

  • self.time = 0, self.tweets = defaultdict(list), self.following = defaultdict(set): the clock, per-user tweet lists, per-user follow sets.
  • post_tweet: self.tweets[user_id].append((self.time, tweet_id)) then self.time += 1.
  • get_news_feed: for each uid in self.following[user_id] | {user_id} with tweets, seed (-stamp, tweet_id, uid, idx) for their newest; heapq.heapify(heap); then while heap and len(feed) < 10: I pop, I append tweet_id, and if idx > 0 I push the author's tweet at idx - 1.
  • follow: self.following[follower_id].add(followee_id).
  • unfollow: self.following[follower_id].discard(followee_id), which is silent if the pair was never followed.

The panel shows the three structures empty, before any operation. Each trace below runs a few operations of the running example and shows what the structures look like afterwards.

STEP 5

Trace it: post_tweet(1, 5), get_news_feed(1)

post_tweet(1, 5) appends (0, 5) to self.tweets[1], stamp 0 because the clock starts at zero, and then advances the clock to self.time = 1.

get_news_feed(1): the author set is self.following[1] | {1}. User 1 follows nobody yet, so that is just {1}. User 1 has one tweet at idx = 0, so the heap is seeded with the single entry (0, 5, 1, 0), the stamp 0 negated being still 0. I pop it: feed = [5]. idx > 0 is false, so nothing is pushed back, the heap is empty, and the loop ends. Result [5].

STEP 6

Trace it: follow(1, 2), post_tweet(2, 6), get_news_feed(1)

follow(1, 2) makes self.following[1] = {2}. post_tweet(2, 6) appends (1, 6) to self.tweets[2] and advances the clock to 2. Tweet 6 has stamp 1, tweet 5 has stamp 0, so 6 is newer.

get_news_feed(1) now iterates {2} | {1} = {1, 2}. Both have tweets, so the heap is seeded with (0, 5, 1, 0) for user 1 and (-1, 6, 2, 0) for user 2. After heapify the layout is [(-1, 6, 2, 0), (0, 5, 1, 0)]: the more negative stamp, i.e. the newer tweet, is the root.

I pop the root: feed = [6]. User 2 has no older tweet (idx = 0), so nothing is pushed. I pop again: feed = [6, 5]. Heap empty, loop ends. Result [6, 5], newest first, even though the two tweets came from different authors' lists.

STEP 7

Trace it: unfollow(1, 2), get_news_feed(1)

unfollow(1, 2) calls discard(2) on self.following[1], which becomes the empty set. User 2's tweets are untouched: they still exist in self.tweets[2], they simply will not be seeded into user 1's heap any more.

get_news_feed(1): the author set is back to {1}. The heap is seeded with only (0, 5, 1, 0), one pop yields feed = [5], and the loop ends. Result [5].

Nothing was deleted or re-sorted on unfollow. The feed is computed from the follow set at request time, so changing who I follow is a single set operation.
STEP 8

Where this goes wrong: the sign, the self, and the guard

Forgetting to negate the stamp. Seed (stamp, tweet_id, uid, idx) and the min-heap's root is the oldest tweet. On the running example the second feed comes back as [5, 6]: tweet 5 (stamp 0) before tweet 6 (stamp 1). Oldest first is the opposite of a news feed.

Leaving out the user. I iterate self.following[user_id] without | {user_id} and users never see their own tweets: the first feed is [] and the second is [6].

Dropping if idx > 0. After popping an author's oldest tweet, idx - 1 is -1, which Python reads as "the last element", i.e. that author's newest tweet again. It is pushed and emitted a second time, [6, 6, …], until idx - 1 = -2 falls off a one-element list with an IndexError.

Newest first means the largest stamp must be the smallest heap key. Negate it, and include the user in their own feed.
STEP 9

Time and space

post_tweet, follow and unfollow are each one append or one set operation: O(1). get_news_feed seeds one entry per author with tweets, O(f) for f followees, heapifies in O(f), and then does at most 10 pops and 10 pushes at O(log f) each: O(f + 10 log f), independent of how many tweets exist.

Approachpost_tweetget_news_feedSpace
Global list, filter + sortO(1)O(N log N), N = all tweetsO(N + edges)
Per-user lists, heap mergeO(1)O(f + 10 log f)O(N + edges)
Pre-merged feed per user (fan-out on write)O(followers)O(10)O(N · followers)

The third row is what real systems do for most users: I push each new tweet into every follower's stored feed at post time, so reads are trivial. It is the wrong trade for an account with millions of followers, which is why production systems mix both strategies. In an interview, the heap merge is the expected answer.

STEP 10

The final solution

One class, three fields, four methods.

  • self.time, self.tweets, self.following: clock, per-user tweet lists, per-user follow sets.
  • post_tweet: I append (self.time, tweet_id), then self.time += 1.
  • get_news_feed: seed the heap with each author's newest tweet as (-stamp, tweet_id, uid, idx), heapify, then I pop up to 10 times, pushing the popped author's idx - 1 tweet if idx > 0.
  • follow: add to the set. unfollow: discard from the set.
One-line summary to remember: tweets live in per-author lists that are sorted by construction; a feed is a heap merge of those lists that stops after 10.
