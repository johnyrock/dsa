Reorder List, narrated

I will first store the nodes in an array to reach both ends, then reproduce that ordering in place by splitting, reversing, and weaving the list.

Pattern used Linked List find the middle, reverse the second half, merge the halves alternately

STEP 1

The problem

You get the head of a singly linked list L0 → L1 → … → Ln. Rewire it so it reads L0 → Ln → L1 → Ln-1 → L2 → Ln-2 → …: one node from the front, one from the back, alternating until they meet in the middle. Only the next pointers may change — the values stay on their nodes — and nothing is returned; the caller's head is still the first node.

Running example: head = [1, 2, 3, 4, 5]. The result is [1, 5, 2, 4, 3]: front 1, back 5, front 2, back 4, and the middle node 3 is what is left.

The catch is that a singly linked list only goes forward. Reaching "the back" means walking to the end, and once you have taken the last node you have no pointer to the new last node. Any solution that repeatedly walks to the tail is O(n²).

STEP 2

First instinct: copy the nodes into an array

I can walk the list once, I put every node in an array, then I use indices from both ends to rewire the nodes in the required order.

def reorderList(head):    nodes = []    node = head    while node: nodes.append(node); node = node.next    i, j = 0, len(nodes) - 1    while i < j:        nodes[i].next = nodes[j]; i += 1        if i == j: break        nodes[j].next = nodes[i]; j -= 1    if nodes: nodes[i].next = None

This is correct. Building the array and rewiring the list both take O(n) time. The array uses O(n) extra space.

I avoid the extra space by making the list itself provide a backward-moving second half. I will find the middle, reverse that half, and alternate nodes from the two halves.

STEP 3

The key idea: reverse the second half, then zip

I write the target next to the input. [1, 5, 2, 4, 3] is [1, 2, 3] and [5, 4] interleaved — the first half of the list, and the second half backwards. The reversed second half is exactly the "walk the back toward the front" the array gave us, and reversing a linked list in place is a standard loop I already know.

Three phases, each a well-known linked-list move: I find the middle with slow/fast pointers (slow stops at 3), reverse everything after it (4 → 5 becomes 5 → 4), and merge the two halves by alternating one node from each.

One detail decides whether the merge is clean: the first half has to be cut from the second with slow.next = None. After that, both halves end in None, and the merge loop can run while second is not None — the first half is never shorter than the second, so when the second runs out the first half's remaining node (the middle, if any) is already in place and already terminated.

STEP 4

The approach, line by line

  • if head is None or head.next is None: return — zero or one node is already reordered, and the loop below would dereference None on an empty list.
  • slow = fast = head, then while fast.next is not None and fast.next.next is not None — advance slow one hop and fast two. The double-.next guard leaves slow on the last node of the first half for even lengths, so [1, 2, 3, 4] splits as [1, 2] / [3, 4].
  • second = slow.next, slow.next = None — detach the second half.
  • prev = None, while second is not None: nxt = second.next; second.next = prev; prev = second; second = nxt — reverse the second half; prev is its new head.
  • first, second = head, prev, then while second is not None: — merge.
  • first_next, second_next = first.next, second.next — save both successors before touching any pointer.
  • first.next = second, second.next = first_next — splice one back node after one front node.
  • first, second = first_next, second_next — advance both cursors.

The panel shows phase 1 about to start: slow and fast both on node 1.

STEP 5

Trace it: find the middle and cut

Iteration 1: fast.next is node 2 and fast.next.next is node 3, both non-None, so slow moves to 2 and fast to 3. Iteration 2: fast.next is 4 and fast.next.next is 5, so slow moves to 3 and fast to 5. Now fast.next is None and the loop stops.

slow is on node 3, the middle. second = slow.next is node 4, and slow.next = None cuts the list: the first half is now 1 → 2 → 3 → None and the second half is 4 → 5 → None. Two independent lists.

The panel shows the moment just before the cut, with slow on 3 and fast on 5, and the link that is about to be severed drawn faded.

STEP 6

Trace it: reverse the second half

Standard three-pointer reversal on 4 → 5. I start prev = None, second = 4. First pass: nxt = 5, point 4.next = None (the old prev), then prev = 4, second = 5. Second pass: nxt = None, point 5.next = 4, then prev = 5, second = None. The loop ends.

prev is node 5, the head of the reversed half 5 → 4 → None. The first half is untouched: 1 → 2 → 3 → None.

I compare with the target [1, 5, 2, 4, 3]: it is exactly these two lists read alternately, first-half node, second-half node, first-half node, and so on, with the first half's leftover 3 at the end.

STEP 7

Trace it: merge, the answer

I set first = 1 and second = 5. For the first splice, I save first_next = 2 and second_next = 4, then set 1.next = 5 and 5.next = 2. The list becomes 1 → 5 → 2 → 3 → None, and I advance the cursors to first = 2 and second = 4.

For the second splice, I save first_next = 3 and second_next = None, then set 2.next = 4 and 4.next = 3. I now have 1 → 5 → 2 → 4 → 3 → None. After advancing to first = 3 and second = None, my loop condition second is not None fails.

Nothing else to do. Node 3 was already the end of the first half with 3.next = None from the cut, so the merged list is properly terminated. head still points at node 1, which is why the function returns nothing.

Three passes, each over roughly half the list, and never more than a handful of pointers alive at once.
STEP 8

Where this goes wrong: the missing cut and the lost successor

Forgetting slow.next = None. Without the cut, the "first half" is still 1 → 2 → 3 → 4 → 5 when the merge starts — and after the reversal, node 4's next is None and node 5's is 4, so it is really 1 → 2 → 3 → 4 → None. Merging then splices 5 after 1 and 4 after 2, setting 4.next = 3. But 3's own next is still 4. Result: 1 → 5 → 2 → 4 → 3 → 4 → 3 → …, a cycle. Printing it never ends; the test helper's length cap is the only thing that makes the failure visible.

Rewiring before saving. I write the splice as first.next = second followed by second.next = first.next. By the time the second line runs, first.next is second, so node 5 gets pointed at itself: 1 → 5 → 5 → 5 → …. Both successors must be read into first_next and second_next before either pointer is written.

No guard for the empty list. With head = None, the middle-finding loop evaluates fast.next on None and raises AttributeError. A single node happens to work without the guard, which is why it is easy to forget.

Cut the halves apart before I reverse, and save every successor before I overwrite a next.
STEP 9

Time and space

Finding the middle is n/2 hops for slow and n hops for fast; reversing is n/2 pointer flips; merging is n/2 splices. All together O(n) time. The only extra state is a fixed handful of node references — slow, fast, prev, first, second, and two saved successors — so O(1) space.

ApproachTimeSpace
Walk to the tail for every back nodeO(n²)O(1)
Copy nodes into an array, two indicesO(n)O(n)
Find middle, reverse second half, mergeO(n)O(1)

The array version is not wrong, and in an interview it is a good thing to say first. The in-place version is what the follow-up is really asking for, and it is built entirely from loops I have already written for other problems.

STEP 10

The final solution

Three loops. Every line maps to a step above.

  • if head is None or head.next is None: return — nothing to reorder.
  • while fast.next is not None and fast.next.next is not None — slow lands on the last node of the first half.
  • second = slow.next; slow.next = None — cut.
  • nxt = second.next; second.next = prev; prev = second; second = nxt — reverse the second half; prev is its head.
  • first, second = head, prev — set up the merge.
  • first_next, second_next = first.next, second.next — save before writing.
  • first.next = second; second.next = first_next — one splice.
  • first, second = first_next, second_next — advance; the loop ends when the reversed half is used up.
One-line summary to remember: the reordered list is the first half zipped with the reversed second half — find the middle, cut, reverse, merge.
