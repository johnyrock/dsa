Medium · Dynamic Programming · LeetCode #91

Decode Ways, narrated

I will first recurse over one-digit and two-digit choices, then store the number of ways for each suffix.

Pattern used Dynamic Programming dp[i+1] = dp[i] if the digit is a code, plus dp[i−1] if the pair is a code; Climbing Stairs with switches

STEP 1

The problem

Letters were encoded as numbers, A = 1 through Z = 26, and the numbers were glued together into one digit string s. Count how many ways the string can be cut back into codes. Every piece must be a number from 1 to 26 with no leading zero, so "0", "06" and "27" are all illegal pieces.

Running example: s = "226". The answer is 3: 2 | 26 (BZ), 22 | 6 (VF), and 2 | 2 | 6 (BBF).

We are asked for a count, not the decodings themselves. That is the hint that a table of counts will do, and that we never need to build a single decoded string.

STEP 2

First instinct: recurse on one digit or two

I can decode a valid first digit alone, optionally decode a valid first two-digit number, and recurse on the remaining suffix.

def numDecodings(s):    def count(i):        if i == len(s): return 1        if s[i] == "0": return 0        ways = count(i + 1)        if i + 1 < len(s) and int(s[i:i+2]) <= 26: ways += count(i + 2)        return ways    return count(0)

This is correct. The same suffix is reached through many choices, so the time complexity is O(2ⁿ). The recursive call stack has O(n) space complexity.

Keeping each suffix count once removes the repeated recursion. The next count depends only on the previous two counts and whether the one- and two-digit choices are valid.

STEP 3

Reframe: look at the last code, not the first

I call dp[k] the number of decodings of the first k digits. Looking at a prefix ending at digit i, its last code has one of two forms:

  • the single digit s[i], in which case the rest is a decoding of s[:i], and there are dp[i] of those, but only if s[i] != "0";
  • the pair s[i-1]s[i], in which case the rest is a decoding of s[:i-1], and there are dp[i-1] of those, but only if the pair is 10 through 26.
Exactly two numbers feed each new count, and each is gated by a condition on the digits. It is Climbing Stairs where the 1-step and the 2-step can each be switched off.

The recursion is the same recurrence walked downward. Walking upward from the empty prefix evaluates each dp[k] once.

STEP 4

The key idea: two rolling counts and two switches

Seed with dp[0] = 1, the empty prefix, which has exactly one decoding (do nothing), and dp[1] = 1, the first digit as one code, after rejecting a leading zero up front with if not s or s[0] == "0": return 0.

  • two_back, one_back = 1, 1 holds dp[i-1] and dp[i].
  • for i in range(1, len(s)) fills dp[2] through dp[n].
  • if s[i] != "0": ways += one_back is the single-digit switch.
  • if 10 <= int(s[i - 1:i + 1]) <= 26: ways += two_back is the pair switch; the lower bound is what rejects "06".
  • two_back, one_back = one_back, ways slides the window.

The dp row in the panel is drawn so the shape is visible, but the code only ever holds the two most recent cells.

STEP 5

Trace it: i = 1, the second "2"

Before the loop: two_back = dp[0] = 1, one_back = dp[1] = 1. The prefix "2" has one decoding, B.

Digit s[1] = "2" is not zero, so the prefix "22" can end with the code 2: ways = 0 + 1 = 1. The pair s[0:2] = "22" is between 10 and 26, so it can also end with the code 22: ways = 1 + 1 = 2.

dp[2] = 2: B B and V. Slide: two_back = 1, one_back = 2.

STEP 6

Trace it: i = 2, the "6", the answer

Digit s[2] = "6" is not zero, so every decoding of "22" extends with an F: ways = 0 + one_back = 2. The pair s[1:3] = "26" is Z, in range, so every decoding of "2" extends with a Z: ways = 2 + two_back = 2 + 1 = 3.

dp[3] = 3, and the loop is done. one_back now holds 3, which is what return one_back gives back.

I can match this against the list: BBF and VF come from the single-digit switch (2 decodings of "22", each plus F); BZ comes from the pair switch (1 decoding of "2", plus Z). 2 + 1 = 3.
STEP 7

Trace it: what a zero does

Change the example to s = "10". s[0] = "1" passes the guard, seeds are 1 and 1. At i = 1, digit s[1] = "0" is zero, so the single-digit switch is off: ways stays 0. The pair "10" is J, in range, so ways = 0 + two_back = 1.

dp[2] = 1: the only decoding is J. A zero can never stand alone; it survives only by pairing with the 1 or 2 before it. With s = "100" the second zero has nothing to pair with ("00" is below 10), so ways = 0 and the answer is 0.

The panel returns to "226" from here on.

STEP 8

Where this goes wrong: the seed and the bounds

Seeding the empty prefix with 0. two_back, one_back = 0, 1 feels natural ("no ways to decode nothing") but is wrong. On "226" the pair switch at i = 1 adds two_back = 0 instead of 1, so dp[2] = 1 and then dp[3] = 1 + 1 = 2, not 3. The decoding 22 | 6 was thrown away. The empty prefix has exactly one decoding.

Dropping the lower bound. int(pair) <= 26 alone accepts "06" as a code, so "106" returns 2 instead of 1.

Counting a lone zero. Writing ways += one_back without the s[i] != "0" guard gives "10" an answer of 2 (J, and the illegal A | 0) instead of 1.

The two switches are the whole problem. Single digit: not zero. Pair: 10 to 26 inclusive. And dp[0] = 1, always.
STEP 9

Time and space

One pass over the digits with two comparisons and one two-character slice each: O(n) time. Two integers regardless of length: O(1) space.

ApproachTimeSpace
Plain recursion, one or two digitsO(2ⁿ)O(n) call stack
Recursion + memoizationO(n)O(n) cache + stack
Full dp tableO(n)O(n)
Two rolling variablesO(n)O(1)

Memoization fixes the exponential blow-up; going bottom-up with two variables removes the table and the stack.

STEP 10

The final solution

Twelve lines. Every one of them maps to a step above.

  • if not s or s[0] == "0": return 0 rejects the two inputs that cannot start a code.
  • two_back, one_back = 1, 1 seeds dp[0] (empty prefix) and dp[1] (first digit).
  • for i in range(1, len(s)) visits each digit after the first.
  • if s[i] != "0": ways += one_back ends the prefix with a one-digit code.
  • if 10 <= int(s[i - 1:i + 1]) <= 26: ways += two_back ends it with a two-digit code.
  • two_back, one_back = one_back, ways slides the window without a temporary.
  • return one_back is dp[n].
My rule is: a decoding ends with one digit or two, so I add the count for each legal ending and keep only the last two counts.
