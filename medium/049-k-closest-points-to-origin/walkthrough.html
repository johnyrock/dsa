K Closest Points to Origin, narrated

I will sort every point by distance first, then I keep only the closest candidates needed for the answer.

Pattern used Heap Keep the k closest points seen so far in a max-heap on distance; the root is the farthest of them, which is exactly the one to drop when a closer point arrives.

STEP 1

The problem

You are given a list of points on the plane and an integer k. Return the k points nearest to the origin (0, 0), measured by ordinary Euclidean distance. The answer is guaranteed to be unique as a set, and you may return it in any order.

Running example: points = [[3,3],[5,-1],[-2,4]], k = 2. The squared distances are 3² + 3² = 18, 5² + 1² = 26, 2² + 4² = 20. The two smallest are 18 and 20, so the answer is [[3,3],[-2,4]].

Two details simplify the task. First, "closest" only needs a comparison of distances, never the distance itself, so the square root can be skipped: if a² < b² then a < b for non-negative numbers. Second, the output is a set of k points, so a structure must hold k candidates while deciding what to keep.

STEP 2

First instinct: sort by distance, take the first k

I can calculate each point's squared distance, I sort every point by it, and return the first k points.

def kClosest(points, k):    ordered = sorted(points, key=lambda point: point[0] * point[0] + point[1] * point[1])    return ordered[:k]

This is correct. Sorting all n points takes O(n log n) time, and the sorted copy uses O(n) space.

I only need the closest k points, not the full ordering. A max-heap of size k discards the farthest current candidate as I scan.

STEP 3

The key insight: a max-heap capped at k

I keep a heap holding the k closest points seen so far. When a new point arrives, I push it, so the heap briefly holds k + 1 entries, then throw away the farthest of those. That is the one at the root of a max-heap on distance. Every eviction discards a point that is farther than k others, so it can never belong to the answer.

Python's heapq is a min-heap, so the distance is stored negated: (-(x * x + y * y), x, y). The most negative number, i.e. the largest distance, sits at the root. The coordinates ride along in the tuple so the point can be rebuilt at the end.

The root of the heap is always the point most likely to be evicted next. Nothing below it needs to be in order, which is why a push or pop costs only O(log k).

Because the heap never grows past k + 1, each operation costs O(log k) rather than O(log n). For small k that is nearly constant.

STEP 4

The approach: push, then pop if over k

The whole algorithm is one loop over the points:

  • heap = []: starts empty, will hold at most k entries between iterations.
  • heapq.heappush(heap, (-(x * x + y * y), x, y)): negated squared distance first so the tuple orders by distance, farthest at the root.
  • if len(heap) > k: heapq.heappop(heap): after the push there may be k + 1 entries; I drop the farthest.
  • return [[x, y] for _, x, y in heap]: the survivors are the answer, in heap order, which is allowed.

I push then I pop, in that order. The new point must be compared against the current root, and the only way a heap does that comparison is by having both inside it. The panel shows the empty heap and the three tuples about to be pushed.

STEP 5

Trace it: push (3,3), then (5,-1)

Point (3, 3): distance 3·3 + 3·3 = 18, so I push (-18, 3, 3). The heap is [(-18, 3, 3)], size 1, which is not more than k = 2, so nothing is popped.

Point (5, -1): distance 25 + 1 = 26, I push (-26, 5, -1). Because -26 < -18 it sifts up past the first entry, and the heap becomes [(-26, 5, -1), (-18, 3, 3)]. The root is now the farthest point kept so far, which is exactly what the max-heap promises. Size is 2, still not over k, so again no pop.

STEP 6

Trace it: push (-2,4), heap overflows

Point (-2, 4): distance 4 + 16 = 20, I push (-20, -2, 4). It lands at index 2 as the right child of the root: [(-26, 5, -1), (-18, 3, 3), (-20, -2, 4)]. Its parent -26 is already smaller, so it stays put.

Now len(heap) = 3 > 2, so the guard fires and heappop removes the root (-26, 5, -1). That is the point at distance 26, the farthest of the three, and it is gone for good. The heap re-settles to [(-20, -2, 4), (-18, 3, 3)] with the new farthest survivor, distance 20, at the root.

The eviction never had to look at the whole list. It compared the new point against the current worst survivor, and the heap did that in O(log k).
STEP 7

Trace it: the loop ends, read the survivors

There are no more points, so the loop exits with the heap holding exactly k = 2 entries: (-20, -2, 4) and (-18, 3, 3). The comprehension [[x, y] for _, x, y in heap] throws away the negated distances and rebuilds the pairs: [[-2, 4], [3, 3]].

That is the answer. The order differs from the expected [[3,3],[-2,4]], but the problem accepts any order, and the tests compare as sets. If a sorted result were required, sorting the final k entries would cost only O(k log k).

STEP 8

Where this goes wrong: the sign, and the tuple order

Forgetting the negation. I push (x * x + y * y, x, y) with a positive distance and the heap is a min-heap on distance, so its root is the closest point. The overflow pop then evicts the best candidate every time. On the example, pushing (-2, 4) makes the heap [(18, 3, 3), (26, 5, -1), (20, -2, 4)], the pop removes (18, 3, 3), and the function returns [[-2,4],[5,-1]], which contains the farthest point of all. The sign of the key decides which end of the ranking the heap exposes.

Distance not first in the tuple. I push (x, y, -dist) and tuples compare on x first: the root becomes the point with the largest x, and distance is only a tiebreaker. Always put the sort key in position 0.

Trimming with >=. if len(heap) >= k pops as soon as the heap reaches k, so at most k - 1 points can ever survive and the result is one short.

The root is what gets evicted. I store whatever should be evicted first as the smallest tuple, which for "keep the closest" means the negated distance.
STEP 9

Time and space

Each of the n points is pushed once and popped at most once, on a heap that never exceeds k + 1 entries. That is O(n log k) time. The heap itself is O(k) space.

ApproachTimeSpace
Sort all points by distanceO(n log n)O(n) or in place
Max-heap of all n, pop k timesO(n + k log n)O(n)
Max-heap capped at kO(n log k)O(k)
Quickselect on distancesO(n) average, O(n²) worstO(1) extra

When k is close to n the sort and the heap converge, and quickselect wins on average. When k is small, or the points arrive one at a time, the capped heap is the natural fit because it never needs the whole input in memory.

STEP 10

The final solution

Seven lines, one loop.

  • heap = [] holds the current best k candidates.
  • for x, y in points visits each point once.
  • heapq.heappush(heap, (-(x * x + y * y), x, y)) pushes the negated squared distance so the farthest kept point is the root.
  • if len(heap) > k: heapq.heappop(heap) evicts that farthest point whenever the heap overflows.
  • return [[x, y] for _, x, y in heap] rebuilds the surviving pairs.
One-line summary to remember: I keep the k best in a heap whose root is the worst of them, and evict the root whenever a newcomer makes it k + 1.
