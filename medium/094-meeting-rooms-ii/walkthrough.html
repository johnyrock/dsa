Meeting Rooms II, narrated

I’ll start by counting meetings at every instant, then use a min-heap of room end times to reuse rooms.

Pattern used Intervals Sorted by start, a meeting can reuse a room only if the room that frees up soonest is free; a min-heap of end times keeps that room at the top.

STEP 1

The problem

Given [start, end] meetings, find the minimum number of rooms needed. Meetings that overlap need different rooms, while one may start exactly when another ends.

Running example: intervals = [[0, 30], [5, 10], [15, 20]]. The answer is 2: [0, 30] holds one room for the whole span, while [5, 10] and [15, 20] take turns in a second room.

The answer is really "how many meetings are running at the busiest moment". At t = 5 two meetings are live, at t = 15 two again, never three. The question is how to find that peak without checking every moment.

STEP 2

First instinct: count meetings at every instant

My first instinct is to count the meetings running at every start time and keep the largest count. A meeting [s, e] is running at t when s <= t < e.

rooms = 0for start, _ in intervals:    live = 0    for s, e in intervals:        if s <= start < e:            live += 1    rooms = max(rooms, live)

Checking starts is enough because the live count only rises at a start. This takes O(n²) time and O(1) extra space, but at 10^4 meetings it makes a hundred million comparisons.

I repeatedly scan meetings that already ended, but I only need to know which occupied room frees first.

STEP 3

The key idea: reuse the room that frees up first

I sort the meetings by start time and hand out rooms in that order. When a meeting starts, every earlier meeting already has a room, so I ask only whether any is free yet. The room worth checking has the smallest end time; if it is still busy, every room is.

I keep one end time per room in a min-heap, end_times. Its top, end_times[0], is the earliest-freeing room. If end_times[0] <= start, I reuse that room by swapping in the new meeting's end time. Otherwise I open a room by pushing the new end time.

Rooms are never closed, so the heap only grows. Its final size is the peak number of meetings running at once, which is exactly the minimum number of rooms.
STEP 4

The approach, line by line

  • intervals.sort(key=lambda interval: interval[0]) puts the meetings in start order.
  • end_times = [] is the min-heap, one end time per room in use.
  • for start, end in intervals: assigns rooms one meeting at a time.
  • if end_times and end_times[0] <= start: asks whether the earliest-freeing room is free. The <= lets a meeting start exactly when another ends.
  • heapq.heapreplace(end_times, end) pops that end time and pushes the new one in a single sift: same room, new occupant.
  • else: heapq.heappush(end_times, end) opens a new room.
  • return len(end_times): the number of rooms ever opened.
STEP 5

Trace it: the first meeting opens a room

After sorting, the order is [0, 30], [5, 10], [15, 20]; the input was already sorted, so nothing moves.

[0, 30] arrives with end_times empty. The condition end_times and ... is false on an empty list, so there is no room to reuse: I push 30. Now end_times = [30], one room, busy until 30.

The dashed line on the timeline marks end_times[0], the moment the earliest room frees up. For the next meeting to reuse a room it would have to start at or after that line.

STEP 6

Trace it: a second room

[5, 10] arrives. The earliest-freeing room is end_times[0] = 30, and 30 <= 5 is false: that room is still busy, and since it is the soonest to free up, so is every room.

I push 10. The heap sifts it to the top: end_times = [10, 30]. Two rooms are open, and the earliest-freeing one is now the [5, 10] room, at 10, which is where the dashed line moves.

This is the busiest the example gets: two meetings live at t = 5.

STEP 7

Trace it: reusing a room

[15, 20] arrives. end_times[0] = 10, and 10 <= 15 is true: the room that held [5, 10] has been empty since 10. Reuse it: heapreplace pops the 10 and pushes 20, giving end_times = [20, 30]. The heap size stays 2.

The loop ends and len(end_times) = 2 is returned. Two rooms were opened, at t = 0 and t = 5, and none after that.

Each meeting looked at exactly one room, the one at the top of the heap, and either reused it or opened a new one. The heap's size only ever went up, so it records the peak.
STEP 8

Where this goes wrong: losing a room

Popping without pushing back. Writing the reuse branch as heapq.heappop(end_times) and then forgetting heappush(end_times, end) makes the freed room vanish instead of being reused. On the example, [15, 20] pops the 10 and adds nothing, so end_times = [30] and the function returns 1, not 2. The room count must never go down; heapreplace keeps the size fixed on a reuse.

Using < instead of <=. With end_times[0] < start, a meeting that starts exactly when another ends is treated as a conflict. [[1, 2], [2, 3]] then returns 2 instead of 1.

Checking the most recent room instead of the earliest-freeing one. A single prev_end variable, as in Meeting Rooms I, compares against whichever meeting was assigned last. On [[1, 5], [1, 10], [5, 8]], prev_end is 10 when [5, 8] arrives, so a third room is opened even though the [1, 5] room is free: 3 instead of 2. Only the minimum end time answers "is any room free".

I sort by start, check the heap top with <=, and replace rather than pop: the heap size is the answer only if rooms are never closed.
STEP 9

Time and space

Sorting is O(n log n). Each meeting then does one heap operation, heappush or heapreplace, at O(log n), so the sweep is O(n log n) as well. The heap holds at most one entry per meeting, so O(n) space in the worst case where every meeting overlaps every other.

ApproachTimeSpace
Count live meetings at every startO(n²)O(1)
Sort + min-heap of end timesO(n log n)O(n)
Two sorted arrays, two pointersO(n log n)O(n)

The two-pointer version sorts starts and ends separately and walks them together; same bound, no heap, but the room count has to be tracked as a running maximum rather than read off a structure.

STEP 10

The final solution

Nine lines. Every one of them maps to a step above.

  • intervals.sort(key=lambda interval: interval[0]) — start order.
  • end_times = [] — one end time per open room, min-heap.
  • for start, end in intervals: — one meeting at a time.
  • if end_times and end_times[0] <= start: — is the earliest-freeing room free?
  • heapq.heapreplace(end_times, end) — yes: reuse it.
  • heapq.heappush(end_times, end) — no: open another.
  • return len(end_times) — rooms opened, which is the peak.
One-line summary to remember: in start order, reuse the room that frees up soonest if it is free, else open one; the heap size is the answer.
