Implement Trie (Prefix Tree), narrated

Scroll from a set of strings plus prefix scans to a tree of characters with an end-of-word flag, with the trie's contents shown after every operation.

Pattern used Trie One node per character along a path; words that share a prefix share the path, and a flag marks where a word ends.

STEP 1

The problem

Design a class Trie with three methods: insert(word) stores a word, search(word) reports whether exactly that word was stored, and starts_with(prefix) reports whether any stored word begins with prefix. All strings are lowercase letters.

Running example, the sequence of operations from LeetCode: insert("apple"), search("apple") → true, search("app") → false, starts_with("app") → true, insert("app"), search("app") → true.

The two middle answers are the whole problem in miniature. After only "apple" is stored, "app" is a prefix of a stored word but is not itself stored, so search says no while starts_with says yes. Storing "app" afterwards flips search("app") to yes without changing anything about "apple".

The constraint that matters is the call count: up to 3·10⁴ operations on strings up to 2000 characters. Each operation should cost time proportional to its own argument, not to how many words are already stored.

STEP 2

First instinct: a set of words

A Python set gives insert and search for free: self.words.add(word) and word in self.words, both O(L) for the hash. The trouble is starts_with, which has to look at every stored word:

class Trie:    def __init__(self):        self.words = set()    def insert(self, word):        self.words.add(word)    def search(self, word):        return word in self.words    def starts_with(self, prefix):        return any(w.startswith(prefix) for w in self.words)

That any scans all n stored words and compares up to L characters of each: O(n · L) per prefix query. With 10⁴ stored words and 10⁴ queries it is 10⁸ character comparisons, and it gets worse the more you store, which is the opposite of what a data structure should do.

You could patch it with a second set holding every prefix of every inserted word, which makes starts_with O(L) but turns insert into O(L²) and stores 2000 strings for a single 2000-character word. The scan moved, it did not go away.

STEP 3

The key insight: store the characters as a tree

Words that share a prefix should share the storage for it. Lay each word out as a path from a root node, one character per edge: "apple" becomes root → a → p → p → l → e. Then "app" is not a separate string anywhere; it is simply the first three edges of that same path.

Each TrieNode holds a dict children from a character to the next node, and a boolean is_word that is True only where an inserted word ends. Every node is a prefix of something; only the flagged nodes are words.

This makes the three operations three variations of one walk. insert walks the path, creating missing nodes, and flags the last one. starts_with walks the path and asks only "did I reach the end?". search walks the path and asks "did I reach the end, and is that node flagged?". That single flag is the difference between the two middle answers in the running example.

The panel shows the trie after insert("apple"): five nodes in a chain, with a thick ring on e and nowhere else.

STEP 4

The approach: one walk helper, three thin methods

  • self.root = TrieNode() — the empty prefix; never a word, parent of every first letter.
  • insert: for each ch, if ch not in node.children: node.children[ch] = TrieNode(), then node = node.children[ch]. After the loop, node.is_word = True.
  • _walk(s): for each ch, node = node.children.get(ch); if node is None: return None. Return the node reached.
  • search(word): node = self._walk(word), then return node is not None and node.is_word.
  • starts_with(prefix): return self._walk(prefix) is not None.

Notice that insert creates nodes only when they are missing. That is what lets a later insert("app") reuse the a-p-p nodes that "apple" built instead of overwriting them.

STEP 5

Trace it: insert("apple"), then search("apple")

The trie starts as a lone root. insert("apple") walks a, p, p, l, e. At each step the character is missing from node.children, so a new TrieNode is created and the walk moves into it. After the loop node is the e node, and node.is_word = True flags it. Five nodes were created; the root's dict now has one key, "a".

search("apple") calls _walk("apple"). Each children.get finds its letter, so the walk reaches the e node. It is not None, and is_word is True, so search returns true.

The panel highlights the whole a-p-p-l-e path in green and shows the flag on the last node as a thick ring.

STEP 6

Trace it: search("app") vs starts_with("app")

search("app"): _walk("app") follows a, p, p and stops on the second p node. That node exists, so the walk returns it rather than None. But its is_word is False: nothing was ever inserted that ends here. So node is not None and node.is_word is True and False, and search returns false.

starts_with("app"): the very same walk reaches the very same node. This method asks only self._walk(prefix) is not None, which is True, so it returns true.

Same path, same node, opposite answers. The panel shows the a-p-p path in amber for the failed search: reached, but the ring on the second p is thin.
STEP 7

Trace it: insert("app"), then search("app")

insert("app") walks a, p, p again. This time every character is already in node.children, so the if ch not in node.children test is false at each step and no node is created. The walk ends on the existing second p node and sets node.is_word = True. The trie still has exactly five nodes; only one boolean changed.

search("app") now walks to that node, finds is_word is True, and returns true. And search("apple") would still be true: the l and e nodes below were never touched.

The panel shows two thick rings, on the second p and on e, which is the whole content of the trie: the words "app" and "apple", sharing three nodes.

STEP 8

Where this goes wrong

Forgetting the flag in search. Write return self._walk(word) is not None for search, the same body as starts_with. After insert("apple"), search("app") reaches the second p node and returns true instead of false. Every prefix of every stored word now counts as a word. The panel shows that state: the walk lands on an unflagged node and the method says yes anyway.

Overwriting children in insert. Write node.children[ch] = TrieNode() without the if ch not in node.children guard. Then insert("app") replaces the root's a node with a fresh one, and the p-p-l-e chain under the old one is gone; search("apple") returns false after the second insert.

Flagging every node on the path. Move node.is_word = True inside the loop and after insert("apple"), search("a"), search("ap"), and search("app") all return true.

Reaching a node means "this is a prefix". Only the flag means "this is a word". search needs both; starts_with needs only the first.
STEP 9

Time and space

Each operation does one dict lookup (or one insertion) per character of its argument, so insert, search, and starts_with are all O(L), where L is the length of that one string. The number of stored words never appears.

Space is at most one node per inserted character, O(total characters), and less when words share prefixes: "app" cost zero new nodes.

Approachinsertsearchstarts_withSpace
Set of wordsO(L)O(L)O(n · L)O(total chars)
Set of words + set of all prefixesO(L²)O(L)O(L)O(total chars · L)
TrieO(L)O(L)O(L)O(total chars), shared prefixes free
STEP 10

The final solution

A node class with a dict and a flag, and a Trie with one walk helper. Line by line:

  • self.root = TrieNode() — the empty prefix.
  • if ch not in node.children: node.children[ch] = TrieNode() — create a branch only when missing, so prefixes are shared.
  • node = node.children[ch] — step down.
  • node.is_word = True — after the loop, mark the last node and nothing else.
  • node = node.children.get(ch) / if node is None: return None — the shared walk stops at the first missing letter.
  • return node is not None and node.is_word — search: reached and flagged.
  • return self._walk(prefix) is not None — starts_with: reached is enough.
One-line summary to remember: a trie is a tree of characters where reaching a node means "prefix" and a flag on the node means "word".
