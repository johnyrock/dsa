Medium · Backtracking · LeetCode #39

Combination Sum, narrated

I will first try every possible count for every candidate, then stop a partial combination as soon as its sum exceeds the target.

Pattern used Backtracking choose a candidate, recurse from the same index so it can repeat, undo; sorted input lets a break prune the rest

STEP 1

The problem

You are given an array candidates of distinct positive integers and a target. Return every combination of candidates that sums to target. A candidate may be used any number of times, and two combinations are the same if they use the same candidates the same number of times, so [2, 2, 3] and [3, 2, 2] count once.

Running example: candidates = [2, 3, 6, 7], target = 7. The answer is [[2, 2, 3], [7]]: 2 + 2 + 3 = 7 and 7 = 7. Nothing else works.

The problem guarantees fewer than 150 answers for any input, which is a hint that the constraints are small (at most 30 candidates, target at most 40) and that the intended solution explores the space directly. What separates a good solution from a bad one is how much of the space it visits without producing an answer, and whether it can accidentally produce the same answer twice in different orders.

STEP 2

First instinct: pick a count for every candidate

I choose a count for each candidate, build the corresponding combination, and retain it when its sum equals the target.

from itertools import productdef combinationSum(candidates, target):    result = []    ranges = [range(target // value + 1) for value in candidates]    for counts in product(*ranges):        if sum(count * value for count, value in zip(counts, candidates)) == target:            result.append([value for count, value in zip(counts, candidates) for _ in range(count)])    return result

This is correct. It examines O(∏(target / cᵢ)) count vectors, so the time complexity is O(∏(target / cᵢ)). Storing the candidate combinations gives it space complexity of O(∏(target / cᵢ) · target).

I build one combination incrementally. Once its running sum exceeds target, I can stop that branch before choosing counts for every remaining candidate.

STEP 3

Key insight: spend in index order, reuse by not advancing, prune by sorting

I build a combination in a shared list path, tracking remaining = target − sum(path). Three rules make it both complete and duplicate-free.

  • I only pick from start onward. The loop is for i in range(start, len(candidates)). Once a 3 has been placed, 2 is never offered again, so [3, 2, 2] cannot be built and [2, 2, 3] is produced exactly once.
  • I recurse with i, not i + 1. The candidate just placed stays available, which is how 2 gets used twice. This is the one-character difference from Subsets.
  • I sort, then break when candidates[i] > remaining. In sorted order, if this candidate overshoots, so does everything after it. The loop ends instead of recursing into dead ends.
A combination is complete exactly when remaining == 0. That is the base case, checked on entry: I record a copy of path and return.

The panel is standing on [2, 2] with remaining = 3: its children will be [2, 2, 2] (remaining 1, a dead end) and [2, 2, 3] (remaining 0, an answer), and then 6 > 3 breaks the loop before 6 or 7 is tried.

STEP 4

The approach, line by line

  • candidates = sorted(candidates): required for the break to be safe.
  • result = [], path = []: the answers and the combination under construction.
  • backtrack(start, remaining): extend path with candidates at index ≥ start, still needing remaining.
  • if remaining == 0: I record path[:] and return.
  • for i in range(start, len(candidates)), and inside it if candidates[i] > remaining: break.
  • I choose with path.append(candidates[i]), recurse with backtrack(i, remaining − candidates[i]), undo with path.pop().
  • I start with backtrack(0, target) and return result.

The sorted break means I never need a remaining < 0 check: I only choose a candidate when candidates[i] <= remaining.

STEP 5

Trace it: 2, 2, 2 is a dead end; 2, 2, 3 is an answer

backtrack(0, 7): 2 <= 7, I push 2, call backtrack(0, 5). Again 2 <= 5, I push, call backtrack(0, 3). Again 2 <= 3, I push, call backtrack(0, 1) with path = [2, 2, 2].

Now remaining = 1, not zero, so the loop runs: candidates[0] = 2 > 1, and the very first iteration breaks. This call returns having done nothing. I pop the third 2. Back in backtrack(0, 3) the loop moves to i = 1: 3 <= 3, I push 3, call backtrack(1, 0).

remaining == 0: I record [2, 2, 3]. The first answer, found after five calls. I pop the 3; the loop in backtrack(0, 3) reaches i = 2, 6 > 3, break. Candidates 6 and 7 were never pushed under [2, 2].

STEP 6

Trace it: back up to [2], then the [3] subtree

I pop the second 2; back in backtrack(0, 5) with path = [2], the loop moves to i = 1: 3 <= 5, I push, call backtrack(1, 2). Its loop starts at i = 1, and 3 > 2 breaks immediately. It never looks at 2: start = 1 forbids it, which prevents [2, 3, 2]. I pop, I return to [2], then break when i = 2 gives 6 > 5.

I pop the first 2. At the root, i = 1: I push 3, call backtrack(1, 4). 3 <= 4, I push, call backtrack(1, 1) with path = [3, 3]: 3 > 1, break, dead end. I pop; at [3] the loop hits 6 > 4, break.

Three dead ends so far, and each of them cost a single comparison. The tree is thin because the break refuses to grow branches that cannot finish.

STEP 7

Trace it: 6 fails, 7 succeeds, done

Back at the root with i = 2: 6 <= 7, I push, call backtrack(2, 1). Its loop starts at 6: 6 > 1, break. I pop. Then i = 3: 7 <= 7, I push, call backtrack(3, 0). remaining == 0, I record [7]. I pop. The root's loop is finished.

result is [[2, 2, 3], [7]]. Count the calls: ten in total, of which two recorded answers and four were dead ends that broke on their first comparison. I compare that with the 48 count vectors the brute force summed.

Every answer appears once and in non-decreasing order, because the loop never goes back to an earlier index.
STEP 8

Where this goes wrong: i + 1, missing start, missing sort

Recursing with backtrack(i + 1, …). That is the Subsets habit, and it forbids reuse. 2 can then be used only once, so [2, 2, 3] is never built and the output is [[7]]. The panel shows that tree: the [2] branch has no [2, 2] child and dies at [2, 3]. Reuse means the child starts at the same index, not the next one.

Looping from 0 instead of start. Now the same multiset is built in every order: [2, 2, 3], [2, 3, 2], [3, 2, 2], [7], four answers instead of two. The start index is not an optimisation; it is what makes "combination" mean combination and not sequence.

Keeping the break but forgetting sorted. With candidates = [5, 2] and target = 4, the first candidate 5 > 4 breaks the root loop before 2 is ever seen, and the output is [] instead of [[2, 2]]. Either sort, or replace break with continue and accept the extra work.

Reuse means backtrack(i, …), no duplicates means range(start, …), and break is only legal after a sort.
STEP 9

Time and space

The recursion tree's depth is at most target / min(candidates), because every level spends at least the smallest candidate. Its branching factor is at most n. The usual bound quoted is O(n^(target / min)); the real count is far smaller because the start index and the break cut most branches, but no tighter closed form is standard.

ApproachTimeSpace (beyond output)
Every count vector, then filterO(∏ (target / cᵢ) · n)O(n)
Backtracking with remaining < 0 return, no sortO(n^(target/min))O(target / min)
Backtracking, sorted + breakO(n^(target/min)), far fewer calls in practiceO(target / min)

Space is the depth of the recursion plus path, both bounded by target / min(candidates). The output list is the only other memory, and its size is what the problem is really asking us to enumerate.

STEP 10

The final solution

One sort, one nested function, one loop with a break.

  • candidates = sorted(candidates) so that overshooting once means overshooting for the rest of the loop.
  • if remaining == 0: I record path[:] and return.
  • for i in range(start, len(candidates)): never look back at earlier candidates.
  • if candidates[i] > remaining: break: the prune.
  • path.append(candidates[i]), backtrack(i, remaining − candidates[i]), path.pop(): I choose, recurse from the same index, undo.
  • backtrack(0, target) starts with everything owed; return result.
One-line summary to remember: I walk the candidates in order, let each one repeat by recursing from its own index, and break as soon as one is bigger than what is left.
