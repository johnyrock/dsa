Kth Largest Element in an Array, narrated

I will first sort the entire array, then I keep only the largest values that can affect the kth answer.

Pattern used Heap A min-heap capped at k keeps the k largest values seen so far; its root is the smallest of them, which is the kth largest.

STEP 1

The problem

Given an integer array nums and an integer k, return the kth largest element. "Largest" is in sorted order, not distinct order: if the array has two 5s and k = 2, the answer is 5 twice over.

Running example: nums = [3, 2, 1, 5, 6, 4], k = 2. Sorted descending that is 6, 5, 4, 3, 2, 1, so the 2nd largest is 5.

The obvious solution sorts, and the problem explicitly asks whether you can avoid that. The tension is that we need rank information, which sorting gives in full, but we only care about one rank: position k from the top. Everything below it is irrelevant, and everything above it only matters as a count.

STEP 2

First instinct: sort, then index

I can sort the values and read the value at index len(nums) - k.

def findKthLargest(nums, k):    ordered = sorted(nums)    return ordered[len(ordered) - k]

This is correct. Sorting takes O(n log n) time, and the sorted copy uses O(n) space.

Values below the largest k never affect the result. A min-heap capped at k keeps only the values that still matter.

STEP 3

The key insight: keep only the k largest, in a min-heap

Imagine a box that can hold k numbers. I walk the array; every time I see a number, I put it in the box. If the box now has k + 1 numbers, throw out the smallest. When I reach the end, the box holds exactly the k largest values of the array, and the smallest of those is the kth largest.

The box needs two fast operations: insert, and remove-the-smallest. That is precisely what a min-heap offers, in O(log k) each. Python's heapq is already a min-heap, so unlike the max-heap problems there is no negation at all: heapq.heappush(heap, num) and heapq.heappop(heap) do exactly what the box needs.

After every step, heap[0] is the smallest of the largest k values seen so far. At the end of the array, that is the answer: return heap[0].

The heap never grows beyond k + 1, so every operation costs O(log k) rather than O(log n). With k = 2 the heap in the panel has at most three nodes.

STEP 4

The approach: push, trim, read the root

  • heap = []: starts empty, holds at most k values between iterations.
  • for num in nums: heapq.heappush(heap, num): every number goes in, so it is compared against the current survivors by the heap itself.
  • if len(heap) > k: heapq.heappop(heap): after a push the heap may hold k + 1; evict the root, the smallest.
  • return heap[0]: the root of the final heap is the smallest of the k largest.

The order of push and pop matters. I push first, and the newcomer competes against the current root inside the heap. I pop first, and the newcomer walks in unchallenged even if it is smaller than everything that was just evicted. The panel shows the empty heap and the six numbers waiting to be pushed.

STEP 5

Trace it: 3, 2, 1

I push 3: heap [3], size 1, no pop. I push 2: it is smaller than 3 so it sifts up, heap [2, 3], size 2, still not more than k, no pop.

I push 1: it sifts to the root, heap [1, 3, 2]. Now len(heap) = 3 > 2, so I pop the root. The 1 is gone, and the heap re-settles to [2, 3]. That is right: of the three numbers seen, the two largest are 2 and 3, and the smaller of those, heap[0] = 2, is the 2nd largest so far.

STEP 6

Trace it: 5, then 6

I push 5: it is larger than everything, so it lands at index 2 as a leaf, heap [2, 3, 5]. Size 3 again, so I pop the root 2. The heap re-settles to [3, 5]: the two largest so far are 3 and 5.

I push 6: heap [3, 5, 6], size 3, then I pop the root 3, leaving [5, 6]. Each of those two pushes evicted the previous root because the newcomer was bigger than every survivor. The heap does not need to know that 6 > 5; it only needs to know that 3 is the smallest of the three.

The values 1, 2, 3 were each evicted the moment a third value outranked them. They were never sorted against each other.
STEP 7

Trace it: 4, and the answer

I push 4: it is smaller than both survivors, so it sifts up to the root, heap [4, 6, 5]. Size 3, I pop the root, and the 4 is evicted straight back out. Heap: [5, 6].

That was the last number. The heap holds the two largest values of the array, 5 and 6, and its root heap[0] = 5 is the smaller of them: the 2nd largest. return heap[0] gives 5.

Note that 4 cost one push and one pop and changed nothing, which is the common case once the heap is full of large values: most numbers bounce straight off.

STEP 8

Where this goes wrong: the wrong heap, the wrong bound

Negating out of habit. Many heap problems store -num to fake a max-heap. Do that here, with the same size-k cap, and the heap keeps the k smallest values instead: on the example it ends as [-2, -1], i.e. values 2 and 1, and -heap[0] returns 2, the 2nd smallest. The eviction always removes the root; the root must be the value I want gone, and here that is the smallest survivor, which a plain min-heap already exposes.

Trimming with >=. if len(heap) >= k pops as soon as the heap reaches k, so it can never hold k survivors. On the example the heap ends as [6] and the function returns 6, the 1st largest.

Reading the wrong slot. heap[-1] is just the last leaf, not the maximum; after the last step it is 6, which is wrong for k = 2. Only heap[0] has a guaranteed meaning in a heap.

Decide what should be evicted, then I make that the root. To keep the k largest, evict the smallest, so I use a min-heap and do not negate.
STEP 9

Time and space

Each of the n numbers is pushed once and popped at most once, on a heap that never exceeds k + 1 entries: O(n log k) time, O(k) space.

ApproachTimeSpace
Sort and indexO(n log n)O(1) extra if in place
Min-heap capped at kO(n log k)O(k)
QuickselectO(n) average, O(n²) worstO(1) extra
Counting (values bounded by 10⁴)O(n + range)O(range)

For small k the heap is close to linear. Quickselect is the theoretical winner on average and works in place, but its worst case is quadratic unless the pivot is randomised, and it does not survive a streaming input. The heap does: it is the same structure as Kth Largest Element in a Stream, just fed by a loop instead of by add calls.

STEP 10

The final solution

Six lines.

  • heap = [] holds the k largest values seen so far.
  • for num in nums visits each number once.
  • heapq.heappush(heap, num) inserts it, no negation.
  • if len(heap) > k: heapq.heappop(heap) evicts the smallest whenever the heap overflows.
  • return heap[0] is the smallest of the k largest, which is the kth largest.
One-line summary to remember: I keep the k largest in a min-heap; the root is the kth largest.
