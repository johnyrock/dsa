Search a 2D Matrix, narrated

I will first scan every cell, then I use the matrix's global ordering to search its flattened indices.

Pattern used Binary Search treat the matrix as one sorted array; mid // cols and mid % cols pick the cell

STEP 1

The problem

You get an m × n matrix and a target. Each row is sorted left to right, and the first number of each row is larger than the last number of the row above. Say whether target appears anywhere, in O(log(m · n)) time.

Running example: matrix = [[1, 3, 5, 7], [10, 11, 16, 20], [23, 30, 34, 60]], target = 3. The answer is true: it is at row 0, column 1.

The two ordering properties together are stronger than they look. Row 0 ends at 7, row 1 starts at 10; row 1 ends at 20, row 2 starts at 23. Reading the matrix row by row therefore gives 1, 3, 5, 7, 10, 11, 16, 20, 23, 30, 34, 60, a single sorted list of twelve numbers.

The required complexity, O(log(m · n)), is the complexity of a binary search over exactly that many elements. That is the hint.

STEP 2

First instinct: check every cell

I can compare target with each cell and return as soon as one matches.

def searchMatrix(matrix, target):    for row in matrix:        for value in row:            if value == target:                return True    return False

This is correct. For m rows and n columns, its time complexity is O(m · n), and it uses O(1) extra space.

I treat all cells as one sorted sequence. A comparison at the middle tells me which half of the remaining cells cannot contain target.

STEP 3

Key insight: the matrix is a sorted array in disguise

Number the cells row by row from 0. With cols = 4, cell (r, c) gets flat index r · cols + c: (0, 0) is 0, (0, 3) is 3, (1, 0) is 4, (2, 3) is 11. Going the other way, flat index k lives at row k // cols and column k % cols.

Because the flat order is sorted, an ordinary binary search on indices 0 .. rows · cols − 1 works unchanged. The only new line is the translation matrix[mid // cols][mid % cols].

Nothing is actually flattened. The "array" is a formula, so there is no copy and no extra memory.

I check the translation on the example: flat index 5 is row 5 // 4 = 1, column 5 % 4 = 1, and matrix[1][1] = 11, which is indeed the sixth number in the sorted reading.

STEP 4

The approach, line by line

  • rows, cols = len(matrix), len(matrix[0]): the shape.
  • lo, hi = 0, rows * cols − 1: an inclusive window over flat indices.
  • while lo <= hi: I keep going while at least one candidate remains.
  • mid = (lo + hi) // 2, then value = matrix[mid // cols][mid % cols].
  • value == target: found, I return True.
  • value < target: the answer is to the right, lo = mid + 1. Otherwise hi = mid − 1.
  • Window empty: I return False.

For the running example the window starts as lo = 0, hi = 11: twelve candidates.

STEP 5

Trace it: first probe, flat index 5

mid = (0 + 11) // 2 = 5. Translate: row 5 // 4 = 1, column 5 % 4 = 1, so value = matrix[1][1] = 11.

11 == 3 is false, and 11 < 3 is false, so target is to the left: hi = mid − 1 = 4.

One comparison discarded seven cells: index 5 itself and everything after it in the flat order, which is the rest of row 1 and all of row 2.

STEP 6

Trace it: second probe, flat index 2

mid = (0 + 4) // 2 = 2. Row 2 // 4 = 0, column 2 % 4 = 2, so value = matrix[0][2] = 5.

5 < 3 is false, so again go left: hi = 1. The window is now flat indices 0 and 1, the first two cells of row 0.

I see that the window crossed a row boundary without any special handling. Flat indices do not know about rows; only the translation does.

STEP 7

Trace it: indices 0 and 1, then the hit

mid = (0 + 1) // 2 = 0. matrix[0][0] = 1, and 1 < 3, so go right: lo = mid + 1 = 1.

Now lo = hi = 1. The condition lo <= hi still holds, so one more probe: mid = 1, row 1 // 4 = 0, column 1 % 4 = 1, matrix[0][1] = 3. That equals target: I return True.

Four probes for twelve cells. The brute force would have needed two comparisons here, but for a 100 × 100 matrix the binary search needs at most 14 probes against up to 10,000.
STEP 8

Where this goes wrong: the loop condition and the divisor

while lo < hi. The window is inclusive, so lo == hi is a live candidate. With <, the trace above stops as soon as lo = hi = 1, never examines cell 1, and returns False for target = 3 even though it is right there. Any target that ends up as the last survivor of the window is missed, including the last cell, 60.

Dividing by rows instead of cols. The row length is what I divide by. With matrix[mid // rows][mid % rows] on this 3 × 4 matrix, flat index 5 becomes (1, 2) and reads 16 instead of 11; the probes land on the wrong cells and the search is no longer over a sorted sequence. On a 1 × 6 matrix it indexes row 5 and raises IndexError.

hi = rows * cols. An exclusive upper bound with an inclusive loop: searching for 61 pushes lo up until mid = 12, and matrix[3] does not exist.

Inclusive window, <= in the loop, mid ± 1 when moving a bound, and divide by cols.
STEP 9

Time and space

Every probe halves the window of m · n flat indices, so at most log₂(m · n) probes: O(log(m · n)), which is the same as O(log m + log n). Three integers of state: O(1) space.

ApproachTimeSpace
Scan every cellO(m · n)O(1)
Scan first column, then the rowO(m + n)O(1)
Two binary searches (row, then column)O(log m + log n)O(1)
One binary search on the flat indexO(log(m · n))O(1)

The two-search version has the same complexity but two loops and two sets of boundary cases. The flat version has one loop and one translation line.

STEP 10

The final solution

Twelve lines. Every one of them maps to a step above.

  • rows, cols = len(matrix), len(matrix[0]).
  • lo, hi = 0, rows * cols - 1: inclusive flat window.
  • while lo <= hi: a one-cell window is still a candidate.
  • mid = (lo + hi) // 2 and value = matrix[mid // cols][mid % cols]: the only line that knows this is a matrix.
  • if value == target: return True.
  • lo = mid + 1 when value < target, else hi = mid - 1.
  • return False once the window is empty.
One-line summary to remember: a row-sorted matrix whose rows chain together is one sorted array; binary search the flat index and translate with // cols and % cols.
