Walls and Gates, narrated

I will first search outward from each empty room, then let every gate spread outward together in one breadth-first search.

Pattern used Graph Traversal I seed a multi-source BFS with every gate and fill each room on its first arrival

STEP 1

The problem

A grid holds three kinds of cell: -1 is a wall, 0 is a gate, and INF (2147483647) is an empty room. Fill every empty room with the number of steps to its nearest gate, moving up, down, left or right and never through a wall. A room that cannot reach any gate keeps INF.

The work is in place: the function returns nothing and overwrites the rooms in the grid it was given.

Running example: a 4 × 4 grid with gates at (0, 2) and (3, 0) and five walls. The room at (0, 0) ends up 3: the wall at (0, 1) blocks the way right, so its nearest gate is the one at the bottom-left, reached down the left column.

"Nearest" is the whole difficulty. Every room has to compare all the gates it can reach and keep the closest, and there may be hundreds of gates.

STEP 2

First instinct: search from every room

I can run a fresh breadth-first search from each empty room until I reach a gate, then write that distance.

def wallsAndGates(rooms):    for r in range(len(rooms)):        for c in range(len(rooms[0])):            if rooms[r][c] == 2147483647:                rooms[r][c] = nearest_gate(rooms, r, c)

This is correct when nearest_gate performs BFS through non-wall cells. Up to m · n rooms can each scan the grid, so the time complexity is O((m · n)²); each BFS uses O(m · n) space.

Reversing the searches removes the repeated room-by-room traversals. Starting from all gates at once means the first time I reach a room is already its shortest distance.

STEP 3

Reframe: search from the gates instead

Distance is symmetric. The distance from a room to its nearest gate is the distance from the nearest gate to that room. So flip the direction: instead of asking each room "where is a gate?", let the gates announce "here I am" and spread outward.

A breadth-first search from a gate visits rooms in order of distance: everything 1 step away, then everything 2 steps away, and so on. If several gates spread at the same time, in lockstep, then the first gate to reach a room is the closest one, and its arrival time is the answer.

I put every gate into the queue before the loop starts. They all sit at distance 0, so they form the first layer together, and one BFS does the work of all of them.
STEP 4

The key idea: multi-source BFS, fill on first touch

The code is the plain BFS template with a different seed:

  • queue = deque((r, c) for … if rooms[r][c] == 0): every gate, all at once.
  • while queue: r, c = queue.popleft(): I process cells in discovery order, which is non-decreasing distance.
  • For each in-bounds neighbour whose value is INF, I set rooms[nr][nc] = rooms[r][c] + 1 and append it.

The == INF test does three jobs. It skips walls (-1), it skips gates (0), and it skips rooms that were already filled by an earlier, shorter arrival. Writing the distance is the visited mark; no separate set is needed.

The panel shows the queue as a row of cells. Two gates are queued before a single room has been looked at.

STEP 5

Trace it: the two gates spread one step

I pop (0, 2), the first gate, with value 0. I write 0 + 1 = 1 at (1, 2) and append it, then write and append 1 at (0, 3). The remaining neighbours are out of bounds or a wall.

I pop the second gate, (3, 0), and write and append 1 at its only empty neighbour, (2, 0).

The queue is now [(1, 2), (0, 3), (2, 0)]: every room at distance 1, from either gate, in one batch. The panel marks them as the frontier.

STEP 6

Trace it: distance 2, where the gates meet

I pop (1, 2) with value 1, then write and append 2 at (2, 2) and (1, 1). Its other neighbours are a wall and the gate.

I pop (0, 3) and find nothing to fill. Then I pop (2, 0) and write and append 2 at (1, 0).

Now the two searches touch. (1, 1) was filled with 2 from the top gate, and (1, 0) with 2 from the bottom gate. When (1, 1) is popped later it will look at (1, 0), see 2 rather than INF, and leave it alone. Neither gate can overwrite the other's claim, and neither needs to: both arrivals happened in the distance-2 layer.

STEP 7

Trace it: the far corners, and the answer

I pop (2, 2) and set (3, 2) to 3. After (1, 1) yields nothing new, I pop (1, 0) and set (0, 0) to 2 + 1 = 3. That room gets its answer from the bottom gate because the wall at (0, 1) blocks the shorter route from the top gate.

I pop (3, 2) and set (3, 3) to 4. The final pops at (0, 0) and (3, 3) have no empty neighbours, so my queue drains.

Eleven pops for eleven non-wall cells. Every room was written exactly once, at the moment the closest gate reached it.
STEP 8

Where this goes wrong: one gate at a time

Looping over the gates and running a BFS from each. It looks like the same algorithm, and it uses the same == INF test, but the gates no longer spread in lockstep. The first gate, (0, 2), floods every reachable room before the second gate starts, so (2, 0) is written as 4 (down through (1, 2), (1, 1), (1, 0)) and (0, 0) as 4. When the gate at (3, 0) finally runs, its neighbour (2, 0) is no longer INF, so it is skipped. The panel shows the result: 4 at (2, 0) where the answer is 1, and (1, 0) and (0, 0) off by one and two.

Testing != -1 instead of == INF. Now gates and already-filled rooms get rewritten with a larger distance and re-queued, the queue never drains, and the loop runs forever.

Using a stack instead of a queue. Depth-first order reaches a room by whatever path it stumbles on first, not the shortest. Distances come out too large, and fixing it with rewrites brings back the quadratic cost.

All sources in the queue before the first pop, one queue, first write wins. Each of those three clauses rules out one of the bugs above.
STEP 9

Time and space

A cell is appended only while it is INF, and the append is what makes it not INF, so every cell enters the queue at most once. Each pop checks four neighbours in constant time. Total: O(m × n) time. The queue can hold a whole BFS layer, which is at most m × n cells: O(m × n) space. The distances live in the input grid, so nothing else is allocated.

ApproachTimeSpace
BFS from every roomO((m × n)²)O(m × n)
BFS from each gate in turn, keeping the minO(g × m × n)O(m × n)
One BFS seeded with all gatesO(m × n)O(m × n)

The middle row is correct only if each gate's BFS is allowed to lower an existing value; with g gates it is g times slower than seeding them together, for the same answer.

STEP 10

The final solution

The BFS template with the seed changed. Every line maps to a step above.

  • if not rooms or not rooms[0]: return guards the empty grid before rooms[0] is indexed.
  • INF = 2147483647 names the sentinel that means both "empty room" and "unvisited".
  • queue = deque(… if rooms[r][c] == 0) loads every gate as a distance-0 source.
  • r, c = queue.popleft() takes cells in discovery order, which is distance order.
  • 0 <= nr < rows and 0 <= nc < cols and rooms[nr][nc] == INF admits only unvisited rooms, skipping walls, gates and filled cells alike.
  • rooms[nr][nc] = rooms[r][c] + 1 is the answer for that room and its visited mark, in one write.
  • queue.append((nr, nc)) lets the room spread to its own neighbours one layer later.
One-line summary to remember: seed the queue with every gate, BFS once, and the first arrival at each room is its distance.
