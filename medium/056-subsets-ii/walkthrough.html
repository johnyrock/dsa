Subsets II, narrated

Scroll through the thinking, from generating every subset and deduplicating afterwards to a recursion that never builds a duplicate in the first place, with the path, the recursion tree, and the answers shown alongside.

Pattern used Backtracking sort, then at each level skip a value equal to the previous sibling choice; every node is an answer

STEP 1

The problem

You are given an array nums that may contain duplicates. Return every distinct subset of it, the power set with repeated subsets removed. The output may be in any order, but no two entries may be the same multiset: [1, 2] built from the first 2 and [1, 2] built from the second 2 are the same subset and must appear once.

Running example: nums = [1, 2, 2]. The answer is the six lists [], [1], [1,2], [1,2,2], [2], [2,2]. Plain Subsets would produce eight, with [1, 2] and [2] each appearing twice.

The tricky part is that [2, 2] is a legitimate subset, using both copies, while a second [2] is not. So the rule cannot be "never pick a value you have seen before". It has to distinguish picking the second copy after the first (allowed) from picking the second copy instead of the first (a duplicate).

STEP 2

First instinct: generate everything, then deduplicate

Run the ordinary Subsets recursion, which treats the two 2s as different elements, and throw the results into a set of sorted tuples:

seen = set()for subset in all_subsets(nums):        # 2^n of them    seen.add(tuple(sorted(subset)))return [list(t) for t in seen]

It works. It is also O(n log n · 2ⁿ) for the sorting plus the memory of a set holding up to 2ⁿ tuples, and for an input like [2, 2, 2, 2, 2] it builds 32 subsets to keep 6. The duplicates are not a rare edge case; when values repeat, most of the work is producing things that will be thrown away.

The better question is: at which moment does the recursion first commit to building something it has already built? If we can name that moment, we can skip it with one continue.

STEP 3

Key insight: a repeated value is only a duplicate as a sibling choice

Sort first, so equal values are adjacent: [1, 2, 2]. Now look at one level of the recursion, the loop for i in range(start, len(nums)) inside a single call. Each iteration is a sibling branch: "extend the current path with nums[i]". If two consecutive iterations offer the same value, the second one would rebuild exactly the subtree the first one already built, with the same prefix. That is the duplicate, and it is safe to skip.

  • The condition is if i > start and nums[i] == nums[i − 1]: continue.
  • nums[i] == nums[i − 1] says the value repeats. i > start says index i − 1 was a sibling choice at this level, not the element the parent call just placed.
When i == start, nums[i − 1] was chosen by the parent, so this is the second copy stacked after the first: [2, 2]. Allowed. When i > start, nums[i − 1] was tried and fully explored as a sibling: a second [2]. Skipped.

The panel is standing on [1] with start = 1. Its loop tries i = 1 (value 2, fine) and then i = 2, where 2 == nums[1] and 2 > 1, so that sibling is skipped. Everything else is the Subsets algorithm unchanged, including recording path[:] on entry.

STEP 4

The approach, line by line

  • nums = sorted(nums): equal values must be neighbours for the check to see them.
  • result = [], path = []: the answers and the subset under construction.
  • backtrack(start) records path[:] on entry, because every prefix is a subset.
  • for i in range(start, len(nums)): only later elements.
  • if i > start and nums[i] == nums[i − 1]: continue: skip a repeated sibling.
  • path.append(nums[i]), backtrack(i + 1), path.pop(): choose, recurse past it, undo.
  • backtrack(0) and return result.

Two lines differ from Subsets: the sort and the continue. Everything the panel shows in the next three steps is the ordinary recursion tree with two branches pruned off.

STEP 5

Trace it: down the left edge to [1, 2, 2]

backtrack(0) records []. i = 0: no previous sibling to compare with (0 > 0 is false), push 1, call backtrack(1), record [1]. i = 1: 1 > 1 is false, so no skip; push 2, call backtrack(2), record [1, 2].

Now i = 2 with start = 2: nums[2] == nums[1] is true, but 2 > 2 is false, so the check does not fire. This is the second copy stacked after the first. Push 2, call backtrack(3), record [1, 2, 2], empty loop, return.

Four calls, four answers, all distinct, and the i > start half of the condition has just earned its keep by letting [1, 2, 2] through.

STEP 6

Trace it: the first skip, under [1]

Pop back to [1, 2]; its loop is done. Pop back to [1], whose loop continues with i = 2 and start = 1. Now nums[2] == nums[1] and 2 > 1: both halves true, continue.

What was skipped? Pushing the second 2 onto [1] would give [1, 2] again, and its subtree would be a copy of the one just explored from index 1, minus the branches that index 1 could reach. Everything it could produce, [1, 2] and nothing more, is already in result. The panel draws that pruned branch dashed.

Pop back to the root: path = [], the loop moves on to i = 1.

STEP 7

Trace it: [2], [2, 2], and the second skip

At the root, i = 1: nums[1] = 2, nums[0] = 1, different, no skip. Push 2, call backtrack(2), record [2]. Inside, i = 2 == start: the second copy after the first, allowed. Push, record [2, 2], return, pop.

Back at the root, i = 2 with start = 0: nums[2] == nums[1] and 2 > 0, skip. That would have been a second [2] and, under it, nothing new. The loop ends.

result is [[], [1], [1,2], [1,2,2], [2], [2,2]]: six calls, six answers, two skips. The brute force made eight calls and then threw two away.

Every skipped branch is a sibling that repeats the value of the sibling just before it. Never a child that repeats its parent.
STEP 8

Where this goes wrong: i > 0, no sort, no skip

Writing i > 0 instead of i > start. The check now also fires when i == start, so the second copy is never placed, not even after the first. [1, 2, 2] and [2, 2] vanish and the output is [[], [1], [1, 2], [2]], four subsets instead of six. The panel shows the tree with those two branches missing. The comparison must be against start, because that is what separates "sibling" from "child".

Dropping the sort. With input [2, 1, 2] the two 2s are not adjacent, the neighbour check never sees them, and the output has eight entries including [2] twice and both [2, 1] and [1, 2].

Dropping the skip entirely. That is plain Subsets: eight entries for [1, 2, 2], with [1, 2] and [2] duplicated.

Sort, then skip only when i > start: a repeated value is a duplicate as a sibling, never as a child.
STEP 9

Time and space

There is one call per distinct subset, plus one O(1) skip per pruned sibling, and each call copies a path of up to n elements. In the worst case (all values distinct) that is O(n · 2ⁿ), the same as Subsets, and the sort adds O(n log n) up front. When values repeat the tree is smaller than 2ⁿ, and the algorithm only ever does work proportional to what it outputs. Space beyond the output is O(n) for path and the call stack.

ApproachTimeSpace (beyond output)
All 2ⁿ subsets, then a set of sorted tuplesO(n log n · 2ⁿ)O(n · 2ⁿ) for the set
Sort + skip repeated siblingsO(n log n + n · 2ⁿ)O(n)

The asymptotic bounds look close, but the second row never builds a subset it does not return, and it needs no hash set. On [2, 2, 2, 2, 2] it makes 6 calls instead of 32.

STEP 10

The final solution

Subsets, plus a sort and a one-line skip.

  • nums = sorted(nums): bring equal values together.
  • result.append(path[:]) on entry: every node is a subset.
  • for i in range(start, len(nums)): only later elements.
  • if i > start and nums[i] == nums[i − 1]: continue: a repeated sibling would rebuild an explored subtree.
  • path.append(nums[i]), backtrack(i + 1), path.pop(): choose, recurse past it, undo.
  • backtrack(0); return result.
One-line summary to remember: sort, and at each level skip a value equal to the one the previous sibling already tried.
