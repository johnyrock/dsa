Validate Binary Search Tree, narrated

I’ll start by checking every descendant against each node, then carry inherited low and high bounds down one recursive pass.

Pattern used Tree recursion carries an open interval (low, high) tightened at each step

STEP 1

The problem

Check whether a binary tree satisfies the BST invariant everywhere: every node's value is strictly between the bounds set by all of its ancestors, not just its parent.

Running example: [5,1,4,null,null,3,6]. This looks locally fine at every parent/child pair (1<5, 4<5? no — 4's parent is 5 and 4<5 holds; 3<4 holds) but is invalid, because 3 is in 5's right subtree and must be > 5.
STEP 2

First instinct: check every subtree against its root

My first instinct checks that every node in the left subtree is smaller than its root and every node in the right subtree is larger, then repeats that work recursively.

def all_less(node, value):    return not node or (node.val < value and all_less(node.left, value) and all_less(node.right, value))def all_greater(node, value):    return not node or (node.val > value and all_greater(node.left, value) and all_greater(node.right, value))def valid(node):    if not node: return True    return all_less(node.left, node.val) and all_greater(node.right, node.val) and valid(node.left) and valid(node.right)return valid(root)

On a skewed tree it rescans descendants for each ancestor, so this takes O(n²) time; recursion uses O(h) extra space.

Each node only needs to satisfy the bounds inherited from its ancestors. I carry those bounds down to avoid rescanning whole subtrees.

STEP 3

The key idea: carry bounds down the recursion

Each call receives an open interval (low, high) that the current node must fall strictly inside. Going left tightens high to the current value (nothing in the left subtree can be >= it); going right tightens low.

STEP 4

Trace it: root 5

Root call: bounds (-inf, inf). 5 is inside. Recurse left with bounds (-inf, 5), recurse right with bounds (5, inf).

STEP 5

Trace it: node 4, bounds (5, inf)

4 fails 5 < 4 immediately — False. The check catches it right here, at the node where the inherited ancestor bound is violated, not by comparing to its immediate parent.

STEP 6

Contrast: a valid tree

For [5,3,7]: node 3 gets bounds (-inf, 5), passes; node 7 gets bounds (5, inf), passes. Both children's subtrees would keep tightening bounds the same way, all the way down.

STEP 7

Where this goes wrong

Using <=/>= instead of strict inequalities lets duplicate values sneak through — a BST with equal values on the wrong side is still invalid. Comparing only to the immediate parent (Step 2's naive approach) misses violations from higher ancestors, as shown in Step 5.

STEP 8

Time and space

Every node is visited once — O(n) time. Recursion depth matches the tree height — O(h) space.

STEP 9

The final solution

I start with valid(root, float("-inf"), float("inf")). Each recursive call checks low < node.val < high before it narrows one bound.

  • valid(node.left, low, node.val) tightens the upper bound.
  • valid(node.right, node.val, high) tightens the lower bound.
  • None is always valid — it is the recursion’s base case.
I return False at the first failed bound; otherwise True reaches the root after every subtree passes.
