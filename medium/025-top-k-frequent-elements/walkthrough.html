Top K Frequent Elements, narrated

I’ll first count and sort every frequency, then I keep only the best k counts in a bounded min-heap.

Pattern used Heap count with a Counter, then I keep the k largest counts in a min-heap of size k

STEP 1

The problem

You get an integer array nums and a number k. Return the k values that occur most often. Any order is fine, and the input is built so the answer is unique: there is never a tie that would make the k-th place ambiguous.

Running example: nums = [1,1,1,2,2,3], k = 2. The value 1 appears 3 times, 2 appears twice, 3 appears once. The answer is [1, 2].

Two things are being asked at once. First, how often does each value appear? Second, of those frequencies, which k are the largest? The first half is a counting pass. The second half is a selection problem, and that is where the choice of data structure matters.

The statement adds a hint: your algorithm must be better than O(n log n). That rules out the obvious "sort by count" and points at a structure that only ever looks at k things.

STEP 2

First instinct: count, then sort the counts

My first instinct is to count every value, I sort all (value, count) pairs by frequency, and take the first k.

counts = Counter(nums)pairs = sorted(counts.items(), key=lambda p: p[1], reverse=True)return [value for value, _ in pairs[:k]]

With m distinct values, it takes O(m log m) time and uses O(m) extra space for counts and pairs.

Only the best k frequencies need to survive. A min-heap of size k drops every smaller candidate as it arrives.

STEP 3

The key insight: a min-heap capped at k entries

I want the k largest counts. Picture a small bucket that holds at most k pairs. As each (count, value) pair arrives, I drop it in. If the bucket now holds k + 1 pairs, throw out the one with the smallest count, because it is certainly not among the top k of what I have seen so far.

A min-heap is the structure that makes "find and remove the smallest" cheap: heap[0] is always the smallest entry, and heapq.heappop removes it in O(log k) time. Python's heapq is a min-heap by default, so no negation trick is needed here.

I push the tuple (count, num), count first. Tuples compare element by element, so the heap orders by frequency, and the value simply travels along as the payload.

Because the bucket never holds more than k + 1 entries, every heap operation is O(log k) rather than O(log n). That is the "better than n log n" the problem asked for.

STEP 4

The approach, line by line

  • counts = Counter(nums) — one pass, mapping each value to how many times it appears.
  • heap = [] — an empty list that heapq will keep in heap order.
  • for num, count in counts.items() — loop over the distinct values, not over nums.
  • heapq.heappush(heap, (count, num)) — insert the pair, ordered by count.
  • if len(heap) > k: heapq.heappop(heap) — the heap has k + 1 entries, so evict the root.
  • return [num for _, num in heap] — the survivors are the answer; strip the counts.

The push-then-pop order is deliberate. The new pair must sit in the heap when the eviction happens so that it competes fairly with the current root; if it is the smallest, it is the one that leaves.

STEP 5

Trace it: the first pair, (3, 1)

The counter for [1,1,1,2,2,3] is {1: 3, 2: 2, 3: 1}. The loop takes the first entry, value 1 with count 3, and pushes (3, 1).

The heap is now [(3, 1)]. Its length is 1, which is not greater than k = 2, so nothing is popped. The root is the only entry.

Note the shape of what was pushed: count 3 comes first in the tuple, value 1 second. In the panel each node reads count·value.

STEP 6

Trace it: the second pair, (2, 2)

Next is value 2 with count 2. I push (2, 2). It has the smaller count, so it sifts up past (3, 1) and becomes the root: the heap list is [(2, 2), (3, 1)].

Length is now 2, and 2 > 2 is false, so again no eviction. The heap is full but not overfull. The root, (2, 2), is the current weakest survivor, and that is exactly the entry a newcomer will have to beat.

STEP 7

Trace it: the third pair, (1, 3), and the eviction

Last is value 3 with count 1. I push (1, 3). Count 1 is the smallest so far, so it sifts all the way to the root, and the heap list becomes [(1, 3), (3, 1), (2, 2)].

Now len(heap) = 3 > k = 2, so I pop the root. (1, 3) leaves and the heap settles back to [(2, 2), (3, 1)]. The value 3 is gone for good, which is right: with only one occurrence it could never have been in the top two.

The loop is over. Strip the counts from the survivors: [num for _, num in heap] gives [2, 1]. Order does not matter, so this is the answer [1, 2].

Three pushes, one pop, and the sort never happened. The heap did the selection while the pairs streamed past.
STEP 8

Where this goes wrong: the tuple order and the size check

Pushing (num, count) instead of (count, num). The heap now orders by the values themselves. On the running example the entries are (1, 3), (2, 2), (3, 1), and the root, the one evicted, is (1, 3): the value 1, my most frequent element. The function returns [2, 3] instead of [1, 2]. It runs without error and returns k values, which is what makes it dangerous.

Checking len(heap) >= k instead of > k. The eviction fires as soon as the heap reaches k entries, so it can never keep k survivors. On the running example it returns [1]: one value where two were asked for.

Popping before pushing. Writing "if the heap is full, I pop, then I push" means the newcomer is never compared to the root. A very frequent value that shows up late in counts.items() is dropped without a contest.

Count first in the tuple, I push before I pop, and evict only when the heap is strictly larger than k.
STEP 9

Time and space

Counting is one pass over nums: O(n). Then each of the m distinct values does one push and at most one pop on a heap whose size never exceeds k + 1, so that stage is O(m log k), and m ≤ n. Total O(n log k) time.

The counter can hold up to n entries and the heap holds at most k + 1: O(n) space, dominated by the counter.

ApproachTimeSpace
Count, sort all countsO(n log n)O(n)
Count, min-heap of size kO(n log k)O(n)
Count, bucket by frequencyO(n)O(n)

Bucket sort (an array indexed by count, each slot holding the values with that count) is the theoretical best and worth mentioning. The heap is what interviewers usually expect written out, and it generalises to streams and to "top k by any score".

STEP 10

The final solution

Eight lines. Every one of them maps to a step above.

  • counts = Counter(nums) turns the array into value → frequency.
  • heap = [] is the bucket that will hold at most k pairs.
  • for num, count in counts.items() streams the distinct values through the bucket.
  • heapq.heappush(heap, (count, num)) inserts, count first so the heap orders by frequency.
  • if len(heap) > k: heapq.heappop(heap) evicts the least frequent survivor once there are k + 1.
  • return [num for _, num in heap] hands back the k survivors without their counts.
One-line summary to remember: count everything, then let a min-heap of size k throw away whatever is not in the top k as the pairs stream past.
