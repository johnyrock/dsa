Binary Tree Right Side View, narrated

Scroll through the thinking, from walking down the right spine (which is wrong) to a level-order traversal that keeps the last node of each level, with the state of the algorithm shown alongside.

Pattern used Tree Traversal BFS by level; the node popped at i == size − 1 is the rightmost

STEP 1

The problem

Stand to the right of a binary tree and look left. At every depth, the node nearest you hides everything behind it, so you see exactly one node per level. Return those values from the root downward.

Running example: root = [1,2,3,null,5,null,4]. Node 1 has children 2 and 3; 2 has only a right child 5; 3 has only a right child 4. The levels are [1], [2, 3], [5, 4], and the answer is [1, 3, 4].

The phrase to hold on to is "one node per level". The answer has exactly as many entries as the tree has levels, which means the job is to find the rightmost node at each depth, not the rightmost path.

Those two ideas agree on this example but not in general. The README's second example, [1,2,3,4,null,null,null,5], has its deepest nodes under the left child, yet they are still visible from the right because nothing on their level is further right.

STEP 2

First instinct: walk down the right spine

The tempting shortcut is to start at the root and keep taking .right:

result = []node = rootwhile node:    result.append(node.val)    node = node.right

On the running example this gives 1 → 3 → 4, which happens to be correct. It is O(h) time and looks too good to be true, because it is.

On [1,2,3,4,null,null,null,5] the right spine is just 1 → 3, so it returns [1, 3] and misses 4 and 5 entirely. The panel dims what this approach never visits. Any node that is the only one on its level is visible from the right, whichever subtree it lives in.

A correct brute force is to compute every level separately — for each depth d, traverse the tree collecting nodes at depth d and take the last one — which is O(n · h). We can do it in one traversal.

STEP 3

The key idea: the last node popped in each level

Level-order traversal already visits the tree one depth at a time, left to right, using a queue. If we can tell where each level ends, the node popped just before the boundary is the rightmost node of that level — regardless of which parent it hangs from.

The boundary trick: at the start of each level, record size = len(queue). Exactly size nodes belong to this level; everything appended while popping them belongs to the next. The node popped at i == size - 1 is the one we want.

Two details keep the order right. Children are enqueued left first, then right, so each level is queued left to right. And size must be a snapshot: the queue grows during the loop, so re-reading len(queue) would move the boundary.

This is Level Order Traversal with one change: instead of collecting every node of the level into a list, keep only the last one.

STEP 4

The approach, line by line

  • if root is None: return [] — no levels, nothing visible.
  • queue = deque([root]) — the queue holds one full level whenever the outer loop starts an iteration.
  • size = len(queue) — freeze the level's width before popping.
  • for i in range(size): node = queue.popleft() — pop exactly this level.
  • if i == size - 1: result.append(node.val) — the last pop of the level is its rightmost node.
  • if node.left: queue.append(node.left) then if node.right: queue.append(node.right) — queue the next level, left to right.
  • return result — one value per level.
STEP 5

Trace it: level 0

The queue starts as [1], so size = 1. Pop node 1 with i = 0. Since 0 == size - 1, append 1 to result: it is the only node on its level, so it is also the rightmost.

Enqueue its children, left first: node.left is 2, node.right is 3. The queue is now [2, 3], which is exactly level 1 in left-to-right order.

result = [1]. The root is always the first entry — it is alone on level 0.

STEP 6

Trace it: level 1

size = 2. Pop node 2 (i = 0). It is not the last of the level, so nothing is recorded; 2 has no left child, and its right child 5 is enqueued. Queue: [3, 5].

Pop node 3 (i = 1). Now 1 == size - 1, so append 3. Its only child, 4, is enqueued. Queue: [5, 4].

result = [1, 3]. Notice the queue held [3, 5] mid-level, three items would have been wrong to treat as a level — that is why size was frozen at 2.

STEP 7

Trace it: level 2, the answer

size = 2. Pop node 5 (i = 0): not last, no children. Pop node 4 (i = 1): last of the level, append 4. No children, so the queue is empty and the outer while queue loop ends.

result = [1, 3, 4]. Three levels, three values. Node 5 was on the same level as 4 but sat to its left, so it is hidden.

Had 3 lacked its child 4, node 5 would have been the last pop at this level and the answer would end in 5 — a node reached through the left subtree. The BFS handles that without a special case.

STEP 8

Where this goes wrong: a moving boundary, and the wrong end

Reading len(queue) live. Write the test as if i == len(queue) - 1 inside the loop, after the children have been appended. At level 0: pop 1, enqueue 2 and 3, then 0 == 2 - 1 is false, so the root is skipped. At level 1: pop 2, queue [3, 5], false; pop 3, queue [5, 4], 1 == 1, record 3. At level 2: pop 5, queue [4], 0 == 0, record 5; pop 4, queue empty, 1 == -1 false. Output [3, 5]. Snapshot size before the loop.

Recording the first pop. if i == 0 gives the left side view: [1, 2, 5] on the example.

Enqueuing right before left. Then the last pop of each level is the leftmost node, and the output is again [1, 2, 5].

Freeze size once per level, pop exactly size nodes, and record the one at i == size - 1. Children go in left, then right.
STEP 9

Time and space

Every node is enqueued once and popped once: O(n) time. The queue never holds more than one level plus part of the next, so O(w) space where w is the widest level — up to about n / 2 on a complete tree.

ApproachTimeSpaceCorrect?
Follow the right spineO(h)O(1)no
Collect each depth separatelyO(n · h)O(h)yes
BFS, last node per levelO(n)O(w)yes
DFS right-first, first node per depthO(n)O(h)yes

The DFS alternative visits right before left and records a value the first time it reaches each depth. Same answer, recursion stack instead of a queue.

STEP 10

The final solution

The level-order loop with one if in it.

  • if root is None: return [] — empty tree.
  • queue = deque([root]) — level 0.
  • size = len(queue) — snapshot the level width.
  • node = queue.popleft() — pop this level in order.
  • if i == size - 1: result.append(node.val) — the rightmost node of the level.
  • if node.left: … / if node.right: … — enqueue the next level, left to right.
  • return result — one entry per level.
One-line summary to remember: right side view = the last node of every level in a left-to-right BFS; freeze the level size before popping.
