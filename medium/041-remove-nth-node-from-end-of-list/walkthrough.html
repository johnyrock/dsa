Remove Nth Node From End of List, narrated

Scroll through the thinking, from counting the list twice to one walk with two pointers held exactly n apart, with the state of the algorithm shown alongside.

Pattern used Two Pointers open a gap of n, then walk both pointers until the leader hits the tail

STEP 1

The problem

You are given the head of a singly linked list and an integer n. Delete the n-th node counting from the end of the list, and return the head of what is left.

Running example: head = [1,2,3,4,5], n = 2. Counting from the back, 5 is 1st and 4 is 2nd, so node 4 goes and the answer is [1,2,3,5].

The catch is the direction. A singly linked list only has next pointers, so you can walk forward from the head but never backward from the tail. "Second from the end" is easy to say and awkward to find.

Deleting a node in a linked list also never touches the node itself. You find the node before it and rewire that node's next to skip over the victim. So the real job is: land a pointer on the predecessor of the target.

STEP 2

First instinct: count, then walk again

If you knew the length L, "n-th from the end" becomes "position L - n from the front" (0-based). So walk the list once to count, then walk a second time to that position's predecessor and splice.

length = 0node = headwhile node:    length += 1    node = node.nextprev = dummyfor _ in range(length - n):    prev = prev.nextprev.next = prev.next.next

On the example, length = 5, 5 - 2 = 3, so prev moves three steps from the dummy and stops on node 3, whose next is then pointed at 5. That is correct and already O(L) time, O(1) space.

It is a perfectly good answer. The only thing wrong with it is the second pass: the list is walked twice, and the classic follow-up asks for one pass. The two-pointer version below is the same idea with the counting folded into the walk.

STEP 3

The key idea: two pointers held n apart

Put two pointers on the list and separate them by exactly n nodes. Then move both forward one step at a time. The gap never changes, so when the leading pointer reaches the last node, the trailing pointer is exactly n nodes behind the last node — which is n + 1 from the end, the predecessor of the target.

The one subtlety is where the pointers start. If both start on head, the trailing pointer lands on the target itself, not on its predecessor, and if n equals the length there is no predecessor to land on at all.

Fix both problems with one node: dummy = ListNode(0, head). Start fast and slow on the dummy. Now every real node, including the head, has something before it, and slow stops one node before the victim.

At the end, return dummy.next rather than head: if the head was the node deleted, dummy.next already points past it.

STEP 4

The approach, line by line

  • dummy = ListNode(0, head) — a throwaway node in front of the list.
  • fast = slow = dummy — both pointers start on it, not on head.
  • for _ in range(n): fast = fast.next — open the gap: fast is now n nodes ahead of slow.
  • while fast.next is not None: move both pointers one step. Stop when fast is on the last node.
  • slow.next = slow.next.next — slow is on the predecessor; skip the target.
  • return dummy.next — the real head, whatever it is now.

Two loops, but they do not overlap in work: the first moves only fast through n nodes, the second moves it through the remaining L - n. Together fast touches each node once.

STEP 5

Trace it: opening the gap

With n = 2, the gap loop runs twice. fast moves from the dummy to node 1, then to node 2. slow has not moved: it is still on the dummy.

Count the distance: dummy → 1 → 2 is two steps, so fast is exactly n = 2 nodes ahead of slow. That gap is the whole invariant. Nothing after this line changes it.

Note that fast cannot fall off the end here. The constraints guarantee n <= sz, so after n steps from the dummy fast is on a real node — at worst the tail, when n == sz.

STEP 6

Trace it: walking together

Now the main loop. The test is fast.next is not None: keep going while there is a node after fast.

Iteration 1: fast.next is 3, so move. fast = 3, slow = 1. Iteration 2: fast.next is 4, so move. fast = 4, slow = 2. Iteration 3: fast.next is 5, so move. fast = 5, slow = 3.

Now fast.next is None: fast is on the tail and the loop stops. Check the gap: 3 → 4 → 5 is two steps, still n. And slow is on node 3, whose next node, 4, is exactly the 2nd from the end.

STEP 7

Trace it: the splice

slow.next = slow.next.next. Read the right side first: slow.next is 4, and 4.next is 5. So node 3's next becomes 5, and node 4 is no longer reachable from the head.

Node 4 still exists in memory with its own next pointing at 5, but nothing points at it, so as far as the list is concerned it is gone. Python's garbage collector reclaims it.

return dummy.next gives node 1, and walking from it reads 1 → 2 → 3 → 5. That is the answer, found in one pass with no length computed.
STEP 8

Where this goes wrong: one step too far, or no dummy

Looping on fast instead of fast.next. Write while fast is not None and both pointers take one extra step. On the example fast runs off the end to None and slow ends on node 4 — the target itself, not its predecessor. slow.next = slow.next.next then deletes node 5 and returns [1,2,3,4]. The list is one node shorter, so a lazy length check passes.

Starting on head instead of the dummy. Then slow lands on the target rather than before it, and there is no predecessor at all when the head is the target: for [1,2], n = 2 the gap loop leaves fast = None and the main loop's fast.next raises AttributeError. People patch this with an if fast is None: return head.next branch; the dummy makes the branch unnecessary.

Returning head. Correct for every case except deleting the head, where the old head is returned intact: [1,2], n = 2 gives [1,2]. Always return dummy.next.

The loop stops when fast is on the last node, not past it. Then slow is on the node before the victim, which is the only place a delete can happen from.
STEP 9

Time and space

The gap loop moves fast n times; the main loop moves it L - n more. That is one full walk: O(L) time. There are two pointers and one dummy node, so O(1) space.

ApproachTimeSpacePasses
Count, then walk to L − nO(L)O(1)2
Copy to array, index L − nO(L)O(L)1 + array
Two pointers, gap of nO(L)O(1)1

Big-O does not separate the first and last rows. The two-pointer version wins on the "one pass" follow-up and on not needing to know L — which matters when the list is a stream you cannot rewind.

STEP 10

The final solution

Eight lines, each doing one thing.

  • dummy = ListNode(0, head) — guarantees every real node has a predecessor.
  • fast = slow = dummy — both start before the list.
  • for _ in range(n): fast = fast.next — open a gap of exactly n.
  • while fast.next is not None: — walk until fast sits on the tail.
  • fast = fast.next / slow = slow.next — both advance; the gap is preserved.
  • slow.next = slow.next.next — unlink the target.
  • return dummy.next — the head, even if the old head was the one removed.
One-line summary to remember: two pointers n apart, started on a dummy, walked until the leader is on the tail — the trailer is then the node before the one to delete.
