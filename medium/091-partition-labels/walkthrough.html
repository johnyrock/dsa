Partition Labels, narrated

Scroll through the thinking, from testing every cut against every letter to one pass that carries a "must reach" boundary, with the string and the running boundary shown alongside.

Pattern used Greedy extend end to the last index of every letter seen; cut the moment i reaches it

STEP 1

The problem

You get a string s of lowercase letters. Cut it into contiguous pieces so that no letter shows up in two different pieces, and make as many pieces as you can. Return the piece sizes, in order.

Running example: s = "ababcbacadefegdehijhklij", 24 letters. The answer is [9, 7, 8]: "ababcbaca", "defegde", "hijhklij". Every a, b and c lives in the first piece, every d, e, f, g in the second, and so on.

Two things are fixed by the statement. The pieces are contiguous and in order, so the only freedom is where to cut. And "as many as possible" means that whenever a cut is legal we should take it; a legal cut never becomes illegal by cutting elsewhere as well.

What makes a cut after index i legal? No letter may appear both at or before i and after i. Put differently: every letter seen so far in the current piece must have already had its last appearance.

STEP 2

First instinct: test every cut point against every letter

For each candidate cut after index i, take the letters of the current piece and check that none of them occurs later in the string:

sizes, start = [], 0for i in range(len(s)):    piece = set(s[start:i + 1])    if not any(ch in piece for ch in s[i + 1:]):        sizes.append(i - start + 1)        start = i + 1

Correct: it takes every legal cut, and it takes it as early as possible. But every candidate i rebuilds the piece's letter set and rescans the whole tail, so it is O(n²). On the 24-letter example that is a few hundred operations; on the 500-letter limit it is a quarter of a million, and the waste is that we re-answer the same question, "does this letter appear later?", at every single index.

STEP 3

The key insight: precompute each letter's last index, then carry one boundary

"Does ch appear after i?" has a one-number answer: compare i with the last index of ch. So build that once, last = {ch: i for i, ch in enumerate(s)}. Iterating left to right and overwriting means each letter ends up mapped to its final position. The panel shows the entries that matter for the first piece: a → 8, b → 5, c → 7.

Now the cut test collapses. As we walk the piece, keep end = max(end, last[ch]), the furthest index any letter in the piece still needs to reach. The piece cannot close before end, and once i == end every letter in it is fully spent, so it must close there to keep the count maximal.

The piece is exactly the merged interval of [first, last] spans of the letters it contains. end is that merged interval's right edge, and the walk is the same sweep as Merge Intervals.
STEP 4

The approach: one pass with end and size

  • last = {ch: i for i, ch in enumerate(s)}: the last index of each letter, built in one pass.
  • end = size = 0: the boundary the current piece must reach, and how many letters it holds so far.
  • for i, ch in enumerate(s): walk the string once.
  • size += 1: this letter is in the current piece no matter what.
  • end = max(end, last[ch]): stretch the boundary if this letter reappears further on.
  • if i == end: the boundary has been reached, so sizes.append(size) and reset size = 0.
  • return sizes.

In the panel, the blue cell is i, the dashed blue cell is end, and finished pieces are coloured. The dict holds the last entries for letters already seen plus end and size.

STEP 5

Trace it: the first piece stretches to 8

i = 0, ch = 'a': size = 1, end = max(0, last['a']) = max(0, 8) = 8. Already the piece is committed to reaching index 8. i = 1, 'b': size = 2, end = max(8, 5) = 8. i = 4, 'c': end = max(8, 7) = 8. Nothing pushes past 8.

The panel is paused at i = 4 with size = 5. The b at index 5 and the c at index 7 are the last of their kind, but the piece still cannot close because a has an occurrence at 8 that is not yet consumed.

At i = 8, ch = 'a': size = 9, end = max(8, 8) = 8, and now i == end. Append 9 and reset size = 0.

STEP 6

Trace it: the second piece, "defegde"

i = 9, 'd': size = 1, end = max(8, last['d']) = max(8, 14) = 14. Note that end was never reset; it did not need to be, because the next letter's last is necessarily greater than the old boundary, so the max replaces it.

i = 10, 'e': end = max(14, 15) = 15. i = 11, 'f': last['f'] = 11, so end stays 15. 'e', 'g' (last = 13), 'd' at 14: still 15. i = 15, 'e': i == end, size = 7. Append 7.

The boundary moved twice, 14 then 15, and each move was decided by one dictionary lookup.
STEP 7

Trace it: the last piece runs to the end of the string

i = 16, 'h': end = max(15, 19) = 19. i = 17, 'i': end = 22. i = 18, 'j': end = 23. From here 'h', 'k' (last = 20), 'l' (last = 21), 'i', 'j' all have last indices at or below 23, so the boundary is pinned at 23.

i = 23, 'j': size = 8, i == end. Append 8. The loop ends and sizes = [9, 7, 8], which sums to 24, the whole string.

The last piece always closes at len(s) - 1: the final letter's last is that index, so end reaches it and i meets it. No trailing letters are ever left unreported.

STEP 8

Where this goes wrong: comparing against the wrong boundary

Testing if i == last[ch] instead of if i == end. This checks only whether the current letter is done, ignoring earlier letters in the piece that still need to reach further. On the running example the b at index 5 is the last b, so the piece closes there with size 6, cutting the a at index 8 away from the as before it. The panel shows that first wrong cut; the full output is twelve pieces, [6, 2, 1, 3, 2, 1, 1, 4, 1, 1, 1, 1], not [9, 7, 8]. Writing end = last[ch] without the max is the same bug.

Forgetting to reset size. Leave out size = 0 after the append and each entry is a running total: [9, 16, 24]. Sums to far more than 24, which is the tell.

Storing the first index instead of the last. Build the map with setdefault and end never gets past index 1 on "abab": the output is [1, 1], two pieces covering two of four letters.

The cut condition is about the whole piece, not the current letter: i == end, where end is the max of every last seen since the previous cut.
STEP 9

Time and space

Building last is one pass, and the cutting walk is a second pass with a dictionary lookup, a max, and a comparison per letter: O(n) time. The map holds at most 26 entries, so O(1) extra space beyond the output list.

ApproachTimeSpace
Rescan the tail at every cut pointO(n²)O(1)
Last-index map + one sweepO(n)O(1), 26 keys

The map is the whole speed-up: it turns "does this letter occur later?" from a scan into a lookup.

STEP 10

The final solution

Eleven lines. Every one of them maps to a step above.

  • last = {ch: i for i, ch in enumerate(s)} maps each letter to its final index.
  • end = size = 0 seeds the boundary and the running piece length.
  • size += 1 counts the current letter into the piece.
  • end = max(end, last[ch]) stretches the boundary to wherever this letter last appears.
  • if i == end is the cut: every letter in the piece is spent.
  • sizes.append(size) and size = 0 record the piece and start the next.
  • return sizes.
One-line summary to remember: a piece must reach the last index of every letter it contains, so track that max and cut the instant you arrive.
