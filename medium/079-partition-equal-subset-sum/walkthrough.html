Medium · Dynamic Programming · LeetCode #416

Partition Equal Subset Sum, narrated

I reduce the two-group question to one target sum, then track which totals are reachable as I add numbers.

Pattern used Dynamic Programming 0/1 knapsack on sums: dp[s] |= dp[s − num], sums descending

STEP 1

The problem

Split nums into two groups with the same sum. Every element goes into exactly one group. Return whether that is possible.

Running example: nums = [1, 5, 11, 5]. The total is 22, so each half must sum to 11. {1, 5, 5} and {11} both do — the answer is True.

The first simplification is free: if the total is odd there is no way to halve it, so return False at once. [1, 2, 3, 5] totals 11 and is out immediately.

The second is the reframing. You do not need to build two groups. Find one subset that sums to total // 2; everything you left out is the other group, and it sums to the other half automatically.

STEP 2

First instinct: try every subset

My first instinct is to decide for each element whether it belongs in one target subset, while I track the remaining sum I need.

def reach(i, remaining):    if remaining == 0:        return True    if i == len(nums) or remaining < 0:        return False    return reach(i + 1, remaining - nums[i]) or reach(i + 1, remaining)

Two branches per element mean O(2ⁿ) time and O(n) space for the call stack. At n = 200, that is far too slow.

reach(3, 6) is the same question no matter which earlier choices left me needing 6. I record which sums are reachable and reuse that work.

STEP 3

The key idea: track which sums are reachable

The sums are small: at most 200 × 100 / 2 = 10,000. I keep one boolean per sum. dp[s] means “some subset of the numbers processed so far adds up to exactly s.”

Before any number, only the empty subset exists, so dp[0] = True. Processing a number num creates new reachable sums: every already-reachable s − num now also reaches s.

For each num, I visit each sum s and apply if dp[s − num]: dp[s] = True. After all numbers, I return dp[target].

The subtle part is the direction of the inner loop. I walk s downward from target, so dp[s − num] is read before this same num could have written it. An upward walk would use the number twice, which is fine for unlimited coins and wrong here.

STEP 4

The approach, line by line

  • total = sum(nums); if total % 2: return False — odd totals cannot split.
  • target = total // 2 — the sum one subset must hit.
  • dp = [False] * (target + 1); dp[0] = True — reachable sums, seeded with the empty subset.
  • for num in nums — each element is offered once.
  • for s in range(target, num - 1, -1) — sums from high to low, stopping where s − num would go negative.
  • if dp[s - num]: dp[s] = True — extend every reachable sum by num.
  • return dp[target].
STEP 5

Trace it: after 1 and after 5

total = 22, even, target = 11. The table has 12 slots and only dp[0] is True.

num = 1: s runs 11 down to 1. Only s = 1 finds dp[0] True, so dp[1] = True. Reachable: {0, 1}.

num = 5: s runs 11 down to 5. s = 6 reads dp[1] True → dp[6] = True. s = 5 reads dp[0] True → dp[5] = True. Reachable: {0, 1, 5, 6}.

I pay attention to the order at num = 5: 6 was marked before 5. Had I gone upward, marking 5 first, then s = 10 would read dp[5] and mark 10 — using the single 5 twice.

STEP 6

Trace it: after 11

num = 11: s runs 11 down to 11 — a single iteration. dp[11 − 11] = dp[0] is True, so dp[11] = True.

Reachable: {0, 1, 5, 6, 11}. The target is already hit — {11} alone is one half — but the loop does not know to stop, and running to completion costs nothing extra in the big-O.

STEP 7

Trace it: the second 5, then the answer

num = 5 again: s runs 11 down to 5. s = 11 reads dp[6] True → already True. s = 10 reads dp[5] True → dp[10] = True. s = 6 reads dp[1] → already True. s = 5 reads dp[0] → already True.

Final reachable sums: {0, 1, 5, 6, 10, 11}. dp[11] is True, so I return True. I can read one chain back as 11 ← 6 ← 1 ← 0, giving {1, 5, 5}; {11} also works on its own.

Sixteen subsets were possible; the table marked six sums with four short passes.
STEP 8

Where this goes wrong: the seed and the loop direction

Forgetting dp[0] = True. The condition if dp[s - num] can then never fire, because nothing is reachable to begin with. Every slot stays False and [1, 5, 11, 5] returns False instead of True.

Ascending inner loop. If I write range(num, target + 1), each number can be used more than once. [1, 2, 5] has total 8, target 4, and no subset sums to 4, but an upward loop lets the 1 mark dp[1] through dp[4] and returns True.

Looping all the way to 0. range(target, -1, -1) reads dp[s - num] with a negative index for s < num. Python wraps that to the end of the list, so a reachable high sum can leak into a low slot.

I use descending sums for one use per element. Ascending sums allow unlimited copies, so they solve a different problem.
STEP 9

Time and space

One pass over up to target sums for each of n numbers: O(n × target) time. One row of booleans: O(target) space.

ApproachTimeSpace
Enumerate subsetsO(2ⁿ)O(n) stack
2-D table, rows per elementO(n × target)O(n × target)
1-D table, sums descendingO(n × target)O(target)

At the limits, 200 numbers up to 100 give a target of at most 10,000: two million boolean checks. The 2-D version keeps a row per element so that each row reads the previous one; the descending loop makes the single row behave the same way.

STEP 10

The final solution

Twelve lines. Every one of them maps to a step above.

  • total = sum(nums) and if total % 2: return False — odd totals cannot halve.
  • target = total // 2 — the subset sum I need, as an int.
  • dp = [False] * (target + 1) and dp[0] = True — reachable sums, seeded with the empty subset.
  • for num in nums — offer each element once.
  • for s in range(target, num - 1, -1) — descending, and never below num.
  • if dp[s - num]: dp[s] = True — a reachable sum plus this element is reachable.
  • return dp[target] — half the total reachable means the other half is the rest.
My rule is: I look for half the total and walk the reachable-sums row from the top down so each element is used once.
