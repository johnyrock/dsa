Kth Smallest Element in a BST, narrated

Scroll through an iterative in-order traversal that stops the instant the k-th node is visited.

Pattern used Tree in-order traversal of a BST visits values in ascending order

STEP 1

The problem

Return the k-th smallest value in a BST.

Running example: [3,1,4,null,2], k = 2. Sorted order is 1, 2, 3, 4 — the answer is 2.
STEP 2

The key idea: in-order = sorted

A BST's in-order traversal (left, node, right) visits values in strictly ascending order — that's the BST property restated as a traversal fact. So the k-th value visited in-order is the answer. An explicit stack lets the walk stop as soon as the k-th node pops, instead of collecting everything first.

STEP 3

Trace it: descend left

Push 3, then 1 (its left child). 1 has no left child, so the inner loop stops. Stack: [3, 1].

STEP 4

Trace it: pop 1

Pop 1, k becomes 1 (not 0 yet). 1's right child is 2, descend into it — push 2. Stack: [3, 2].

STEP 5

Trace it: pop 2, done

Pop 2, k becomes 0 — return 2. That's the 2nd smallest value, found without ever visiting node 4.

STEP 6

Where this goes wrong

Decrementing k and checking k == 0 in the wrong order, or resetting the count on each new subtree instead of threading it through the whole traversal, both break the count. A fully-recursive in-order without an early return also can't stop early — a nonlocal counter or the iterative stack version is needed.

STEP 7

Time and space

O(h + k) time — h to reach the first node, then up to k pops. O(h) space for the stack.

STEP 8

The final solution

  • Push every left descendant before visiting anything.
  • Pop, decrement k, return if k hits 0.
  • Otherwise move to the popped node's right subtree and repeat.
