Maximum Subarray, narrated

Scroll through the thinking, from summing every subarray to Kadane's one-pass "extend or restart" rule, with the state of the algorithm shown alongside.

STEP 1

The problem

You get an integer array with positives and negatives mixed in. Find the contiguous slice with the largest sum, and return that sum.

The slice has to be non-empty. That rule decides the answer for all-negative input: you must pick something, so you pick the least negative element.

Running example: nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]. The answer is 6, from [4, -1, 2, 1].

Notice that the winning slice carries a −1 inside it. Absorbing a small loss to connect two gains is the kind of decision the algorithm has to make correctly.

STEP 2

First instinct: sum every subarray

Try every start index and every end index, keep a running sum as the end moves so each subarray costs O(1) to extend, and remember the best.

best = nums[0]for i in range(n):    s = 0    for j in range(i, n):        s += nums[j]        best = max(best, s)

Correct, and already better than the O(n³) version that re-sums from scratch. But there are n² / 2 subarrays, so it is O(n²). At n = 100,000 that is five billion additions.

STEP 3

Reframe: the best subarray ending here

Every subarray ends somewhere. So instead of asking about all subarrays, ask a narrower question at each index i: what is the largest sum of a subarray that ends exactly at i? Call it current. The answer to the whole problem is the largest current over all i.

Now the narrower question has a one-step answer. A subarray ending at i is either just nums[i] on its own, or nums[i] glued onto a subarray ending at i - 1. The best of the second kind is nums[i] plus the best subarray ending at i - 1, which is the previous current.

current = max(nums[i], current + nums[i]). Extend the previous run, or restart fresh.
STEP 4

The key idea: a negative run is dead weight

The max picks the restart exactly when the previous current is negative, because then current + nums[i] < nums[i]. A negative prefix can only drag down whatever follows, so it is dropped.

This is dynamic programming: the subproblem is "best ending at i", it depends only on "best ending at i − 1", and the base case is current = nums[0]. Because each step needs only the previous value, the table shrinks to one variable, and best tracks the maximum entry as it goes.

Seeding both with nums[0] rather than 0 is what makes the all-negative case come out right.

STEP 5

Trace it: restarting

Start: current = best = -2. Index 1, value 1: max(1, -2 + 1) = 1, restart. best = 1. Index 2, value −3: max(-3, 1 − 3) = -2, extend (it is the lesser evil), best stays 1.

Index 3, value 4: max(4, -2 + 4) = 4. The run ending at index 2 was worth −2, so it is dropped and a new run starts at the 4. best = 4.

STEP 6

Trace it: absorbing a dip

Index 4, value −1: max(-1, 4 − 1) = 3. Extending wins even though the element is negative, because the run is still positive. Index 5, value 2: max(2, 3 + 2) = 5. Index 6, value 1: max(1, 5 + 1) = 6. best = 6.

Index 7, value −5: max(-5, 6 − 5) = 1. Extend, but the run is badly hurt. Index 8, value 4: max(4, 1 + 4) = 5. Extend again, but 5 does not beat 6. Loop ends, return 6.

The run that won was [4, -1, 2, 1]. The algorithm never stored it; it only needed its sum.
STEP 7

The pitfall: seeding with zero

Take nums = [-3, -1, -2]. The answer is −1. If best starts at 0, nothing ever beats it, and the function returns 0, which is not the sum of any subarray. The empty subarray is not allowed.

Seed best and current with nums[0], and start the loop at index 1. The common variant current = max(0, current + x) has the same bug for the same reason.

With the correct seed: current goes −3, then max(-1, -4) = -1, then max(-2, -3) = -2. best ends at −1.

STEP 8

Time and space

One pass, two max calls per element: O(n) time. Two integers regardless of input size: O(1) space.

ApproachTimeSpace
Every subarray, re-summedO(n³)O(1)
Every subarray, running sumO(n²)O(1)
Divide and conquerO(n log n)O(log n) stack
Kadane, extend or restartO(n)O(1)

The divide-and-conquer version exists mainly as an exercise. Kadane is the expected answer.

STEP 9

The final solution

Seven lines. Every one of them maps to a step above.

  • best = nums[0] and current = nums[0] seed with a real subarray, not zero.
  • for x in nums[1:] is the single pass from the second element.
  • current = max(x, current + x) is the extend-or-restart recurrence.
  • best = max(best, current) records the best "ending here" seen so far.
  • return best.
One-line summary to remember: at each element, either extend the run or start over; a negative run is never worth keeping.
