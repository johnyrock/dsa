Insert Interval, narrated

Scroll through the three-phase scan: intervals before, the merged block, intervals after.

Pattern used Intervals one linear pass, exploiting that the input is already sorted and non-overlapping

STEP 1

The problem

Insert a new interval into an already sorted, non-overlapping list, merging as needed, keeping the result sorted.

Running example: [[1,2],[3,5],[6,7],[8,10],[12,16]], insert [4,8]. Expected: [[1,2],[3,10],[12,16]].
STEP 2

The key idea: three phases in one pass

Because the input is sorted and non-overlapping, a single scan splits cleanly: intervals entirely before the new one (unchanged), intervals overlapping it (folded into a running min/max), intervals entirely after (unchanged). No re-sorting needed.

STEP 3

Trace it: phase 1

[1,2] ends (2) before new start (4) — append unchanged. [3,5] ends (5) at or after 4 — stop phase 1.

STEP 4

Trace it: phase 2, merging begins

[3,5] starts (3) <= end (8) — overlaps. Merge: start = min(4,3) = 3, end = max(8,5) = 8.

STEP 5

Trace it: phase 2 continues

[6,7] starts (6) <= end (8) — overlaps, folded in (no change: 6 >= start, 7 <= end). [8,10] starts (8) <= end (8) — overlaps, end becomes max(8,10) = 10.

STEP 6

Trace it: phase 2 ends, phase 3

[12,16] starts (12) > end (10) — stop merging. Append the merged [3,10]. Phase 3 appends [12,16] unchanged. Result: [[1,2],[3,10],[12,16]].

STEP 7

Where this goes wrong

Using intervals[i][0] < end instead of <= misses touching intervals — [1,2] and [2,3] share the point 2 and must merge into [1,3], not stay separate.

STEP 8

Time and space

O(n) time, one pass. O(n) space for the output.

STEP 9

The final solution

  • Phase 1: copy intervals ending before the new one starts.
  • Phase 2: fold overlapping intervals into a running [start, end], append once.
  • Phase 3: copy the rest unchanged.
