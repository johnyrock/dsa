Medium · Math · LeetCode #7

Reverse Integer, narrated

Scroll through the thinking, from flipping a string to peeling digits off one end and stacking them on the other while watching for 32-bit overflow, with the digits shown alongside.

Pattern used Math x % 10 reads the lowest digit, x // 10 drops it, result * 10 + digit appends it; check the limit before the append, not after.

STEP 1

The problem

You get a signed 32-bit integer x. Return the number whose decimal digits are those of x in reverse order, with the sign kept in front. If that reversed number does not fit in the signed 32-bit range [-2^31, 2^31 - 1], return 0 instead.

Running example: x = -123. The digits 1, 2, 3 become 3, 2, 1 and the sign stays, so the answer is -321.

The catch is in the second sentence. 1534236469 fits in 32 bits, but its reversal 9646324351 does not, and the problem says to assume you cannot store 64-bit integers. So the overflow has to be spotted before the last digit is appended, using only numbers that fit.

STEP 2

First instinct: reverse the string

Turn the number into text, flip it, and parse it back. The sign needs stripping first so it does not end up at the wrong end, and the range check still has to be done by hand:

sign = -1 if x < 0 else 1r = sign * int(str(abs(x))[::-1])if r < -2**31 or r > 2**31 - 1:    return 0return r

It is O(d) for d digits and gives the right answers in Python. But it only works because Python's int is unbounded: int("9646324351") is built in full and then compared. In a language with 32-bit integers that parse overflows before the if runs, which is exactly what the problem tells you not to rely on. It also allocates two strings to do arithmetic.

STEP 3

The key idea: peel and append, and look one step ahead

Two operations move digits without strings. x % 10 is the lowest digit of x, and x // 10 is x with that digit removed. Going the other way, result * 10 + digit shifts every digit of result one place left and drops digit into the ones column. Peel from x, append to result, and the digits come out reversed.

The overflow test goes before the append. result * 10 + digit exceeds INT_MAX = 2147483647 exactly when result > 214748364, or when result == 214748364 and digit > 7. Both comparisons use numbers that already fit, so nothing overflows while checking.

Work on the magnitude. Python's % and // round toward negative infinity, so -123 % 10 is 7, not 3. Taking abs(x) first and putting the sign back at the end keeps the digit arithmetic honest and lets one overflow threshold serve both signs.
STEP 4

The approach, line by line

  • INT_MAX = 2**31 - 1, so INT_MAX // 10 is 214748364 and its last digit is 7.
  • sign = -1 if x < 0 else 1 and x = abs(x) — remember the sign, keep the magnitude.
  • result = 0 — nothing appended yet.
  • while x: — one round per remaining digit.
  • digit = x % 10 and x //= 10 — peel the lowest digit.
  • if result > INT_MAX // 10 or (result == INT_MAX // 10 and digit > 7): return 0 — would the append overflow?
  • result = result * 10 + digit — append it.
  • return sign * result — restore the sign.
STEP 5

Trace it: the first two digits

x = -123 is negative, so sign = -1 and x becomes 123. result = 0.

Round 1. digit = 123 % 10 = 3, and x = 123 // 10 = 12. Overflow check: result = 0 is not greater than 214748364 and not equal to it, so the append is safe. result = 0 * 10 + 3 = 3. The lowest digit of the input is now the highest digit of the output, which is the whole idea: each round moves one digit from the tail of x to the head of the digits already in result.

Round 2. x = 12, so digit = 12 % 10 = 2 and x = 12 // 10 = 1. Overflow check: 3 > 214748364 is false, so append. result = 3 * 10 + 2 = 32. The multiply by 10 is what shifts the earlier 3 into the tens column so the new 2 can sit in the ones column.

STEP 6

Trace it: the last digit and the sign

Round 3. x = 1, so digit = 1 and x = 1 // 10 = 0. Check: 32 > 214748364 is false. result = 32 * 10 + 1 = 321. Now while x sees 0 and stops.

return sign * result = -1 * 321 = -321. Three rounds for three digits, and the sign that was set aside at the start goes back on at the end.

A trailing zero in the input, as in x = 120, is peeled first and appended as result = 0 * 10 + 0 = 0, which changes nothing; the answer 21 has no leading zero because the number never had one.
STEP 7

Trace it: an overflow caught one step early

Take x = 1534236469. Nine rounds peel 9, 6, 4, 6, 3, 2, 4, 3, 5 and build result = 964632435, with x = 1 left.

Round 10. digit = 1, x = 0. Overflow check: result = 964632435 is greater than INT_MAX // 10 = 214748364, so result * 10 + 1 = 9646324351 would not fit. Return 0 without computing it.

The boundary case works the same way: for x = 1463847412, nine rounds give result = 214748364, exactly INT_MAX // 10, and the last digit = 1 is not greater than 7, so 2147483641 is appended and returned. Had the last digit been 8, the check would have returned 0.

STEP 8

Where this goes wrong: negatives and the threshold

Skipping abs(x). Feed -123 straight into the loop. Python computes -123 % 10 = 7 and -123 // 10 = -13, then -13 % 10 = 7, -13 // 10 = -2, then -2 // 10 = -1, and from there -1 // 10 is -1 forever. while x: never sees 0: the function hangs instead of returning -321. Even a version that terminates would have collected the digits 7, 7, 8, which are nothing like 3, 2, 1.

Testing result >= INT_MAX // 10. The equal case is not automatically an overflow; it depends on the digit. With >=, x = 1463847412 returns 0 instead of the valid 2147483641.

Checking after the append. result = result * 10 + digit followed by if result > INT_MAX: return 0 passes every test in Python, but only because Python integers cannot overflow. In a fixed-width int the product has already wrapped to garbage by the time it is compared, which is the situation the problem describes.

Strip the sign first, compare before you multiply, and treat result == 214748364 as "look at the digit", not as overflow.
STEP 9

Time and space

One round per decimal digit of |x|, so O(log₁₀ x) time: at most 10 rounds for any 32-bit input. Three integers of state, O(1) space. The string version is also linear in the digit count but allocates two strings and relies on unbounded integers for its range check.

ApproachTimeSpace
str, reverse, int, then range checkO(d)O(d) strings, needs big ints
Peel with % and //, check before appendO(d)O(1)

Same asymptotic cost; the difference is that the digit loop never holds a value outside the 32-bit range.

STEP 10

The final solution

Twelve lines. Every one of them maps to a step above.

  • INT_MAX = 2**31 - 1 — the limit, 2147483647.
  • sign = -1 if x < 0 else 1 and x = abs(x) — separate sign from magnitude.
  • result = 0 — the reversed number so far.
  • while x: — until every digit has been peeled.
  • digit = x % 10, x //= 10 — take the lowest digit.
  • if result > INT_MAX // 10 or (result == INT_MAX // 10 and digit > 7): return 0 — would appending overflow?
  • result = result * 10 + digit — append.
  • return sign * result — sign back on.
One-line summary to remember: peel the last digit with % 10 and // 10, append with × 10 + digit, and check the limit before the append.
