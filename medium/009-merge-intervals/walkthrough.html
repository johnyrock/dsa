Merge Intervals, narrated

Scroll through the thinking, from repeatedly scanning for any overlapping pair to sorting by start and merging in one sweep, with the state of the algorithm shown alongside.

Pattern used Merge Intervals sort by start, extend the last output interval or append

STEP 1

The problem

You get a list of closed intervals, each a [start, end] pair, in no particular order. Wherever two intervals overlap, or even just touch, combine them into one. Return the resulting list of separate intervals.

Running example: [[1, 3], [2, 6], [8, 10], [15, 18]]. [1, 3] and [2, 6] overlap, so the answer is [[1, 6], [8, 10], [15, 18]].

The output should be sorted, contain no overlaps, and cover exactly the same points as the input.

STEP 2

First instinct: find any overlapping pair and merge it, repeat

Scan all pairs. If two intervals overlap, replace them with their union and start over. Stop when a full scan finds no overlap.

changed = Truewhile changed:    changed = False    for each pair (a, b):        if a and b overlap:            replace both with [min starts, max ends]            changed = True; break

It terminates and it is correct, but each scan is O(n²) and there can be O(n) merges, so it is O(n³) in the worst case. The waste: after a merge we forget everything we learned and rescan.

STEP 3

Reframe: sort by start, then only neighbours matter

Sort the intervals by their start. Now picture walking left to right along the number line. When you reach an interval, everything that could overlap the region you are currently covering has to start at or before its end, and because of the sort those intervals are the very next ones in the list.

After sorting, an interval either overlaps the last merged interval or it starts a new one. It can never reach back to an earlier merged interval, because there is a gap in between that it would have had to start inside.

So one forward pass is enough, comparing each interval only with the last entry of the output.

STEP 4

The key idea: extend or append

Keep an output list merged. For each interval in sorted order:

  • If merged is non-empty and start ≤ merged[-1].end, they overlap. Extend the last merged interval: merged[-1].end = max(merged[-1].end, end).
  • Otherwise there is a gap. Append [start, end] as a new interval.

The max is essential: the new interval may end before the current merged end, as in [1, 4] followed by [2, 3]. The ≤ is what makes touching intervals merge.

STEP 5

Trace it: the merge

[1, 3]: merged is empty, so append it. [2, 6]: 2 ≤ 3, overlap. Extend: merged[-1].end = max(3, 6) = 6. The output now holds [1, 6].

Note that the comparison was against the merged interval's end, 3, and after extending it the end is 6. If a [5, 7] came next it would compare against 6, not 3, and merge too.

STEP 6

Trace it: the gaps

[8, 10]: 8 ≤ 6 is false. Gap. Append [8, 10]. [15, 18]: 15 ≤ 10 is false. Gap. Append [15, 18].

End of input. merged is [[1, 6], [8, 10], [15, 18]], and it came out sorted because the input was processed in sorted order.

Four intervals, four comparisons, each against only the last output entry.
STEP 7

The pitfall: overwriting instead of taking the max

Take [[1, 4], [2, 3]]. Sorted order is the same. [1, 4] is appended. [2, 3]: 2 ≤ 4, overlap. If the code writes merged[-1].end = 3, the merged interval shrinks to [1, 3] and the point 4 is lost.

Always max(merged[-1].end, end). A contained interval must leave the outer one unchanged.

Two more traps: skipping the sort ([[4, 7], [1, 4]] cannot be merged by a single unsorted pass), and using < instead of ≤, which fails to merge [1, 4] with [4, 5].

STEP 8

Time and space

The sort is O(n log n). The sweep is O(n) with O(1) work per interval, so the sort dominates.

The output can hold up to n intervals, so O(n) space for the answer, and O(1) extra beyond that apart from what the sort uses internally.

ApproachTimeSpace
Merge any pair, rescanO(n³)O(n)
Sort by start, one sweepO(n log n)O(n) output
STEP 9

The final solution

Eight lines. Every one of them maps to a step above.

  • intervals.sort(key=lambda iv: iv[0]) orders by start so only the last output entry can overlap.
  • if merged and start <= merged[-1][1] is the overlap test, with ≤ so touching intervals merge.
  • merged[-1][1] = max(merged[-1][1], end) extends without ever shrinking.
  • merged.append([start, end]) starts a new interval on a gap, as a fresh list.
  • return merged.
One-line summary to remember: sort by start, then each interval either extends the last one or starts a new one.
