Min Cost to Connect All Points, narrated

I will first build and sort every possible edge, then grow the tree by choosing its cheapest outgoing edge on demand.

Pattern used Graph I grow the tree with its cheapest available edge in Prim's algorithm

STEP 1

The problem

You are given points on a grid. Connecting any two costs their Manhattan distance, |x1 - x2| + |y1 - y2|. Pick a set of connections so that every point can reach every other point, and make the total cost as small as possible.

"Every point reaches every other point with exactly one simple path" is the definition of a spanning tree. So we want the cheapest spanning tree of the complete graph whose vertices are the points, the minimum spanning tree.

Running example: points = [[0,0],[2,2],[3,10],[5,2],[7,0]]. The cheapest tree uses edges 0-1 (cost 4), 1-3 (3), 3-4 (4) and 1-2 (9), for a total of 20.

Note that point 2 at (3, 10) is far from everything. It will be the last point absorbed, and its cheapest link, 9 to point 1, is unavoidable.

STEP 2

First instinct: sort every pair and avoid cycles

I can create the complete graph, sort its weighted edges, and use union-find to accept only edges that merge components.

def minCostConnectPoints(points):    edges = sorted((abs(x1-x2) + abs(y1-y2), i, j) for i, (x1,y1) in enumerate(points) for j, (x2,y2) in enumerate(points[:i]))    total, used = 0, 0    for cost, i, j in edges:        if union(i, j): total += cost; used += 1        if used == len(points) - 1: return total

This is correct Kruskal's algorithm. The complete graph has O(n²) edges, so sorting gives O(n² log n) time complexity and materializing edges uses O(n²) space.

For this complete graph, I avoid materializing every edge first. Prim's algorithm grows one tree and asks for its cheapest outgoing edge only when needed.

STEP 3

The key insight: the cheapest edge leaving the tree is always safe

Once I have some points in the tree, the cheapest edge with one endpoint inside and one outside belongs to some minimum spanning tree. This cut property means I never need to reconsider a choice: I absorb that edge's outside endpoint, pay its cost, and repeat.

To find the cheapest outgoing edge quickly, I keep a min-heap of candidate edges as (cost, point). Whenever a point joins the tree, I add an edge from it to every point still outside.

I seed heap = [(0, 0)], so point 0 joins for free. The smallest offered edge remains on top.

An outside point can be offered several times, once by each tree point that saw it. Only the first pop matters. That is what visited is for: a popped point that is already in the tree is a stale entry, and if visited[i]: continue discards it.

STEP 4

The approach: pop, absorb, offer

The loop is the insight written out:

  • while connected < n — stop as soon as every point is in the tree, whatever is left in the heap.
  • cost, i = heapq.heappop(heap) — the cheapest offered edge.
  • if visited[i]: continue — I discard an edge whose endpoint is already in the tree.
  • visited[i] = True; total += cost; connected += 1 — absorb the point and pay for the edge that reached it.
  • for j in range(n): if not visited[j]: heappush(heap, (d, j)) — offer an edge from the new point to every point still outside, with d the Manhattan distance.

The panel's array is the heap in its actual heapq layout, smallest at index 0. The rest is only partially ordered, which is why the cells after index 0 are not sorted.

STEP 5

Trace it: absorb point 0, then point 1

I pop (0, 0), giving total = 0 and connected = 1. I add the four edges from point 0, producing [(4, 1), (7, 4), (7, 3), (13, 2)].

I next pop (4, 1), so total = 4 and connected = 2. Adding point 1's outside edges puts (3, 3) at the top of the heap.

STEP 6

Trace it: absorb points 3 and 4

I pop (3, 3), making total = 7 and connected = 3, then add edges to points 2 and 4. The next cheapest entry is (4, 4).

I pop (4, 4), making total = 11 and connected = 4. Its only outside neighbour is point 2 at cost 14.

At the top now sit three entries for points already in the tree. Point 0 and point 1 offered them before cheaper routes to 3 and 4 were found.

STEP 7

Trace it: skip the stale entries, absorb point 2

I discard (7, 3) and both (7, 4) entries because their points are already visited. None changes total or connected.

I then pop (9, 2), making total = 20 and connected = 5. Every point is now connected, so the loop ends.

The four edges taken were 0-1 (4), 1-3 (3), 3-4 (4), 1-2 (9). 4 + 3 + 4 + 9 = 20.
STEP 8

Where this goes wrong: stale entries and the wrong distance

Dropping the visited check on pop. Without if visited[i]: continue, the fifth pop (7, 3) is treated as a new point: total = 11 + 7 = 18 and connected becomes 5, so the loop stops. Point 2 never joins the tree and the function returns 18 instead of 20, a number that is smaller than the true answer, which is the tell that something was skipped rather than overpaid. The panel shows that moment: point 3 counted twice, point 2 stranded.

Using Euclidean distance. math.hypot(dx, dy) reads naturally for "distance between points", but the problem defines cost as Manhattan. On the example it returns about 16.72, a float, instead of 20. The abs(...) + abs(...) form is the whole definition.

Pushing only the single nearest outside point. Offering just the minimum edge from each absorbed point misses edges that become cheapest only after other points join. Prim's needs every (tree point, outside point) edge on offer, which is why the inner loop pushes all of them.

A point is absorbed on its first pop only. Every later pop of the same point is a stale offer and must be skipped without counting.
STEP 9

Time and space

Each of the n absorbed points pushes up to n - 1 entries, so the heap sees O(n²) pushes and at most O(n²) pops, each O(log n) since the heap holds at most n² entries. That is O(n² log n) time and O(n²) space for the heap in the worst case. The Manhattan distance is an O(1) computation, so the graph is never materialised as an edge list.

ApproachTimeSpace
Kruskal: sort all pairs + union-findO(n² log n)O(n²) edge list
Prim's, min-heap of offered edgesO(n² log n)O(n²) heap
Prim's, O(n) array scan per stepO(n²)O(n)

On a complete graph the array-scan variant of Prim's is asymptotically best, because finding the minimum of n values is cheaper than maintaining a heap of n² entries. The heap version is shorter to write and comfortably fast for n ≤ 1000.

STEP 10

The final solution

Every line maps to a step above.

  • heap = [(0, 0)] — point 0 seeds the tree at no cost.
  • while connected < n — stop once every point is in, ignoring leftover heap entries.
  • cost, i = heapq.heappop(heap) — the cheapest edge currently leaving the tree.
  • if visited[i]: continue — a stale offer for a point already absorbed.
  • visited[i] = True; total += cost; connected += 1 — absorb and pay.
  • d = abs(points[i][0] - points[j][0]) + abs(points[i][1] - points[j][1]) — Manhattan cost to each outside point.
  • heapq.heappush(heap, (d, j)) — offer the edge.
One-line summary to remember: grow the tree by always taking the cheapest edge that leaves it, and ignore any pop whose point is already inside.
