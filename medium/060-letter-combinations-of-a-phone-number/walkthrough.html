Letter Combinations of a Phone Number, narrated

Scroll through the thinking, from enumerating every letter string to a recursion that picks one letter per digit and undoes it, with the state of the algorithm shown alongside.

Pattern used Backtracking one recursion level per digit; push a letter, recurse, pop

STEP 1

The problem

On an old phone keypad each digit from 2 to 9 carries three or four letters: 2 → abc, 3 → def, … 7 → pqrs, 9 → wxyz. Given a string of such digits, return every string that could be typed by choosing one letter from each digit's key, in order.

Running example: digits = "23". The answer is ["ad","ae","af","bd","be","bf","cd","ce","cf"]: 3 choices for the first letter times 3 for the second, nine strings.

There is no constraint to satisfy and nothing to reject. Every combination of one letter per digit is an answer, so the task is purely to enumerate a product of small sets, with the number of factors, len(digits), not known until run time. That is what makes a fixed set of nested loops impossible to write.

One edge case matters: digits = "" must return [], not a list holding one empty string.

STEP 2

Brute force: every string of letters, filtered

The dumbest correct approach ignores the keypad while generating: build every string of length len(digits) over all 26 letters, then keep the ones whose letter at each position sits on the right key.

from itertools import productletters = "abcdefghijklmnopqrstuvwxyz"result = []for s in product(letters, repeat=len(digits)):    if all(s[i] in keypad[digits[i]] for i in range(len(digits))):        result.append("".join(s))

For "23" that is 26^2 = 676 candidates to find 9 answers; for four digits it is 26^4 = 456,976 candidates for at most 256 answers. O(26ⁿ · n), almost all of it spent building strings whose first letter was already off the first key.

The obvious fix is to never generate a letter that is not on the current digit's key. Then every string we build is an answer, and the only remaining question is how to write "one loop per digit" for an unknown number of digits.

STEP 3

Key insight: one recursion level per digit

A recursive function backtrack(index) is responsible for exactly one position. It loops over the letters of keypad[digits[index]], and for each one appends it to path, calls backtrack(index + 1) to fill the rest, and then pops it so the next letter of the same key starts from the same prefix.

Each level of the call stack is one of the nested loops we could not write by hand, and the depth adjusts itself to len(digits).

The base case is index == len(digits): every position has its letter, so "".join(path) is a complete answer. Record it and return. There is no pruning anywhere, because there is nothing to prune.
STEP 4

The approach, line by line

  • if not digits: return [] — the empty input is handled before the recursion can record an empty string.
  • keypad — a dict from digit character to its letters.
  • backtrack(index) — if index == len(digits), append "".join(path) to result and return.
  • for letter in keypad[digits[index]] — the choices for this position, in key order so the output comes out lexicographic.
  • path.append(letter), backtrack(index + 1), path.pop() — choose, recurse, undo.
  • backtrack(0) then return result.

The panel shows the digits with the one being filled in blue, the letters available on that key, the current path, and the strings recorded so far.

STEP 5

Trace: "a" then d, e, f

backtrack(0): digits[0] = "2", so the loop runs over "abc". First letter = "a": path = ["a"], call backtrack(1).

backtrack(1): digits[1] = "3", loop over "def". Push "d", call backtrack(2): 2 == len(digits), so "ad" is recorded. Pop "d". Push "e": "ae" recorded, pop. Push "f": "af" recorded, pop.

The loop in backtrack(1) is finished, so it returns to backtrack(0), which pops "a". The path is empty again, exactly as it was before "a" was chosen.
STEP 6

Trace: "b" then d, e, f

Second iteration of the outer loop: letter = "b". Push it, call backtrack(1), and the inner loop repeats over "def" from the new prefix: "bd", "be", "bf" are recorded, each after a push and before a pop.

Notice that backtrack(1) is the same function with the same argument as before; it only produces different strings because path now begins with "b". The prefix is the only state that changes between calls, and the pop is what keeps it honest.

Six strings so far, three calls to backtrack(2) per outer letter.

STEP 7

Trace: "c" then d, e, f, and done

Third and last iteration: letter = "c". The same inner loop records "cd", "ce", "cf". The outer loop is exhausted, backtrack(0) returns, and result holds nine strings in lexicographic order.

Count the calls: one backtrack(0), three backtrack(1), nine backtrack(2): thirteen in all, and nine of them recorded an answer. Nothing was built and thrown away.

Compare the brute force: 676 candidate strings generated to find the same nine.
STEP 8

Where this goes wrong

Dropping the empty-input guard. Without if not digits: return [], backtrack(0) runs with len(digits) == 0, hits the base case at once, and records "".join([]). The function returns [""] instead of [], a list with one string in it, which fails the problem's second example.

Forgetting path.pop(). Letters pile up across siblings: after "ad" the next push gives "ade", then "adef", and the outer loop's "b" lands on top of all that. The output is ["ad", "ade", "adef", "adefbd", …], nine strings of the wrong lengths.

Stopping one level early. A base case of index == len(digits) - 1 records before the last digit's letter is chosen: "23" returns ["a", "b", "c"].

The base case is index == len(digits), every push has a matching pop, and the empty string is rejected before the recursion starts.
STEP 9

Time and space

Each digit offers at most 4 letters, so there are at most 4^n strings, and each one costs O(n) to join. Every call in the tree is on the path to an answer, so the work is proportional to the output.

ApproachTimeSpace
All 26ⁿ strings, filteredO(26ⁿ · n)O(n) per candidate + output
Iterative product (extend a list per digit)O(4ⁿ · n)O(4ⁿ · n) intermediate lists
Backtracking with push / popO(4ⁿ · n)O(n) for path and stack + output

The iterative version is the same count of strings but keeps every intermediate prefix list alive; the recursion keeps one prefix at a time.

STEP 10

The final solution

  • if not digits: return [] — no digits, no strings.
  • keypad = {"2": "abc", …, "9": "wxyz"} — the letters on each key.
  • if index == len(digits): result.append("".join(path)) — one letter per digit chosen; record.
  • for letter in keypad[digits[index]] — the choices for this position.
  • path.append(letter) — choose.
  • backtrack(index + 1) — fill the remaining positions.
  • path.pop() — undo, so the next letter starts from the same prefix.
  • backtrack(0) and return result.
One-line summary to remember: one recursion level per digit, one loop over that key's letters, push before the call and pop after it.
