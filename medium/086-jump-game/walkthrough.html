Jump Game, narrated

Scroll through the thinking, from exploring every possible jump to a single frontier swept left to right, with the state of the algorithm shown alongside.

Pattern used Greedy keep the farthest reachable index; an index beyond it is unreachable forever

STEP 1

The problem

You stand on index 0 of an array nums. The value at your index is the longest jump you may take forward: from index i you can land anywhere in i + 1 .. i + nums[i]. Shorter jumps are allowed; a 0 means you are stuck.

The question is yes or no: can you reach the last index at all?

Running example: nums = [2,3,1,1,4]. The answer is true: jump 1 step to index 1, then 3 steps to index 4.

Contrast with [3,2,1,0,4], where the answer is false. Every route from index 0 passes through index 3, its value is 0, and from a 0 you never move again. We are not asked for the route, only whether one exists, and that distinction is what lets the solution become a single number.

STEP 2

Brute force: explore every jump

The literal approach is a search. From index i, try every jump length from 1 to nums[i] and recurse; succeed when any call reaches the last index.

def can_jump(nums, i=0):    if i >= len(nums) - 1:        return True    for step in range(1, nums[i] + 1):        if can_jump(nums, i + step):            return True    return False

From index 0 in the example you can land on 1 or 2; from 1 on 2, 3 or 4; from 2 on 3, and so on. The call tree branches at every index and re-explores the same suffixes many times, so this is O(2ⁿ) in the worst case. Memoising i brings it to O(n²), since each index tries up to n jump lengths.

That is a lot of work to answer a yes/no question, and the waste is specific: the search keeps asking "can I reach index 3?" from different places when one fact would settle it.

STEP 3

The key insight: reachable indices form a prefix

Suppose you can reach index 4 somehow. Then you can also reach index 3, because the jump that landed on 4 could have been one shorter. And index 2, and so on down. So the set of reachable indices is never scattered; it is always 0 .. reach for some frontier reach.

One integer describes everything reachable. After processing index 0 of the example, reach = 0 + 2 = 2: indices 0, 1, 2 are reachable and 3, 4 are not (yet).

The frontier only ever moves right, and each index i pushes it to max(reach, i + nums[i]), but only if i is itself reachable. That gives the whole algorithm: sweep i from left to right, refuse to stand on any i > reach, and update the frontier from every index you do stand on.

STEP 4

The approach

  • reach = 0: before any jump, only index 0 is reachable.
  • for i, n in enumerate(nums): visit each index with its jump length.
  • if i > reach: return False: nothing to the left could carry us here, so nothing ever will.
  • reach = max(reach, i + n): standing on i lets us land anywhere up to i + n.
  • return True: the sweep survived to the end, so the last index was inside the frontier when we got there.

The panel colours the current index blue, every index inside the frontier green, and everything past reach dimmed. Watch the dimmed region shrink.

STEP 5

Trace it: index 0

i = 0, n = 2. Is 0 > reach? reach is 0, so no: we may stand here. The frontier becomes max(0, 0 + 2) = 2.

Indices 1 and 2 turn green: they are reachable with a single jump. Indices 3 and 4 stay dimmed. Nothing has been decided about them, but nothing so far can get there either.

STEP 6

Trace it: index 1

i = 1, n = 3. 1 > 2 is false, so index 1 is a legal place to stand. The frontier becomes max(2, 1 + 3) = 4.

That already covers the last index. The whole array is green, and no later index can shrink reach, since it only grows. The rest of the sweep is a formality, but the code keeps going, because the check i > reach is what protects against the case where a 0 was blocking the way.

STEP 7

Trace it: indices 2, 3 and 4

i = 2: 2 > 4 is false; max(4, 2 + 1) = 4. i = 3: max(4, 3 + 1) = 4. i = 4: 4 > 4 is false, so the last index is reachable; max(4, 4 + 4) = 8 pushes the frontier past the array, which is harmless.

The loop ends and we return True. On [3,2,1,0,4] the same sweep would stall at reach = 3 after indices 0 to 3, and at i = 4 the test 4 > 3 fires and returns False without ever using the 4.

The search tried every combination of jumps. The sweep did four comparisons and four max calls.
STEP 8

Where this goes wrong: the frontier test and the max

Off by one on the guard. Write if i >= reach: return False and the very first iteration fails: i = 0, reach = 0, 0 >= 0 is true. The function returns false for [2,3,1,1,4], and in fact for every input. Standing exactly on the frontier is fine; only indices strictly beyond it are unreachable.

Overwriting instead of maxing. Write reach = i + n and the frontier can move backwards. On [2,0,0] it goes 2, then 1, and at i = 2 the test 2 > 1 returns false, though index 0 could have jumped straight to index 2. The frontier is a record of the best jump seen so far, and records never regress.

Two comparisons carry the whole algorithm: i > reach with a strict inequality, and max(reach, i + n) so the frontier only grows.
STEP 9

Time and space

One pass over the array with a comparison and a max per index: O(n) time. One integer of state: O(1) space.

ApproachTimeSpace
Recursive search over jumpsO(2ⁿ)O(n) call stack
Memoised search / DP per indexO(n²)O(n)
Greedy frontierO(n)O(1)

The DP already removes the exponential blow-up. The greedy removes the remaining factor of n by observing that the reachable set is a prefix, so a single frontier replaces the whole boolean table.

STEP 10

The final solution

  • reach = 0 seeds the frontier with the starting index.
  • for i, n in enumerate(nums) sweeps every index once, in order.
  • if i > reach: return False rejects an index that no earlier index could reach.
  • reach = max(reach, i + n) extends the frontier from every reachable index.
  • return True is only reached if the last index passed the guard.
One-line summary to remember: reachable indices are always a prefix, so track its right edge and fail the moment the sweep steps past it.
