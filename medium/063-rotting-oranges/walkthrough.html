Rotting Oranges, narrated

Scroll through the thinking, from simulating the grid minute by minute to a breadth-first search seeded with every rotten orange, where each queue level is one minute, with the state of the algorithm shown alongside.

Pattern used Graph Traversal multi-source BFS by levels: one level of the queue is one minute

STEP 1

The problem

A grid holds empty cells (0), fresh oranges (1) and rotten oranges (2). Every minute, every fresh orange that shares an edge with a rotten one turns rotten. Return how many minutes pass until no fresh orange is left, or -1 if some fresh orange can never be reached.

Rot spreads from all rotten oranges at the same time, in all four directions, one cell per minute. Diagonal contact does nothing. An empty cell is a wall: rot does not cross it.

Running example: a 3 × 3 grid with one rotten orange at (0, 0), six fresh oranges, and two empty cells. The answer is 4: the last orange, at (2, 2), is four steps from the source along the only path the empty cells leave open.

Two answers are asked for at once: how long, and whether it finishes at all. The second needs a way to notice an orange that no wave ever reaches.

STEP 2

First instinct: simulate the whole grid every minute

The rules describe a simulation, so simulate. Each minute, scan the entire grid, collect every fresh orange next to a rotten one, and rot them all together after the scan (not during it, or a single minute would chain across the row):

while True:    to_rot = [(r, c) for every fresh (r, c) with a rotten neighbour]    if not to_rot: break    for r, c in to_rot: grid[r][c] = 2    minutes += 1

It is correct and, at 10 × 10, it is fast enough. But every minute rescans all m × n cells to find the handful that changed, and there can be up to m × n minutes on a snake-shaped path: O((m × n)²).

The waste is the rescan. The only cells that can rot next minute are the neighbours of the cells that rotted this minute. Everything else is either already rotten, empty, or too far away.
STEP 3

Reframe: minutes are BFS levels

Cells are nodes and orthogonal adjacency is an edge. "Rots at minute t" means "is t steps from the nearest rotten orange". That is a shortest-path distance, and breadth-first search computes shortest paths on an unweighted graph by visiting nodes level by level: all nodes at distance 1, then all at distance 2, and so on.

There may be several rotten oranges at the start. Put all of them in the queue before the first pop and they form level 0 together, so a fresh orange is reached by whichever source is closest, at exactly the minute the simulation would rot it.

The answer is the number of levels the BFS runs while there is still something to rot. The queue never rescans anything: it holds exactly the cells that rotted last minute.
STEP 4

The key idea: level-by-level BFS with a fresh counter

  • One scan: every 2 goes into queue, every 1 adds one to fresh.
  • while queue and fresh: run a minute only if there is a frontier and something left to rot.
  • for _ in range(len(queue)): pop exactly the oranges that were rotten at the start of the minute. len(queue) is read once, so the appends made during the minute wait for the next one.
  • For each popped orange, every in-bounds neighbour equal to 1 is set to 2, fresh -= 1, and appended.
  • After the inner loop, minutes += 1.
  • return -1 if fresh else minutes.

Marking grid[nr][nc] = 2 at append time is the visited set. An orange with two rotten neighbours in the same wave is appended once, not twice, and fresh is decremented once.

STEP 5

Trace it: minute 1

The scan finds one rotten orange, so queue = [(0, 0)], and six fresh ones, so fresh = 6. Both are non-zero, so the first minute runs. len(queue) is 1: pop (0, 0).

Below, (1, 0), is fresh: set to 2, fresh = 5, append. Above is out of bounds. Right, (0, 1), is fresh: set to 2, fresh = 4, append. Left is out of bounds.

The inner loop ends after that single pop, so minutes = 1. The queue is [(1, 0), (0, 1)]: the two oranges that rotted this minute, and nothing else. The panel highlights them as the wave.

STEP 6

Trace it: minute 2

len(queue) is 2, so this minute pops two oranges. Pop (1, 0): below, (2, 0), is empty, skipped; above is already rotten; right, (1, 1), is fresh: rot it, fresh = 3, append. Pop (0, 1): below is (1, 1), rotten a moment ago, so the == 1 test skips it and it is not appended a second time; right, (0, 2), is fresh: rot it, fresh = 2, append.

minutes = 2, queue = [(1, 1), (0, 2)]. Notice the order of the queue is the order of discovery, and both were discovered in the same minute, so their order relative to each other does not matter.

STEP 7

Trace it: minutes 3 and 4, the answer

Minute 3, two pops. (1, 1): below, (2, 1), is fresh: rot, fresh = 1, append; right, (1, 2), is empty. (0, 2): below is that same empty cell; everything else is rotten or out of bounds. minutes = 3, queue = [(2, 1)]. The empty cell at (1, 2) is why (2, 2) is not rotten yet: the only way to it goes through (2, 1).

Minute 4, one pop. (2, 1): right, (2, 2), is fresh: rot, fresh = 0, append. minutes = 4.

Back at the top of the loop, queue still holds (2, 2), but fresh is 0, so while queue and fresh stops. fresh is falsy, so return minutes gives 4.

STEP 8

Where this goes wrong: the extra minute

while queue: without and fresh. After minute 4 the queue is [(2, 2)]. The loop runs again, pops (2, 2), finds nothing fresh, and still does minutes += 1. The function returns 5 instead of 4. The panel shows that fifth, empty wave. The tempting patch return minutes - 1 then breaks [[0, 2]], which never enters the loop and must return 0, not -1; the honest fix is to stop as soon as nothing is fresh.

Ticking the clock per pop. Move minutes += 1 inside the inner loop and it counts oranges instead of waves: 6 on this example. One minute is one level of the queue, however many oranges are in it.

Forgetting the -1. Return minutes unconditionally and a grid with a walled-off orange reports the time the reachable ones took, as if the job were done. fresh is the evidence that it is not.

Count the level, not the pop; stop when nothing is fresh; and let the leftover fresh count be the impossibility check.
STEP 9

Time and space

The seed scan touches every cell once. Afterwards a cell is appended only while it is 1, and the append turns it into 2, so every cell is appended and popped at most once, with four constant-time neighbour checks per pop. Total: O(m × n) time. The queue holds at most one full level, which is at most every cell: O(m × n) space.

ApproachTimeSpace
Rescan the grid every minuteO((m × n)²)O(m × n) per minute's to-rot list
BFS from each rotten orange separately, keeping the min timeO(k × m × n)O(m × n)
One BFS seeded with all rotten oranges, by levelsO(m × n)O(m × n)

With m, n <= 10 the simulation also passes. The level-by-level BFS is what an interviewer expects because it shows you recognise "spreads one step per tick from many sources" as a multi-source shortest path.

STEP 10

The final solution

A BFS template with a fixed-size inner loop. Every line maps to a step above.

  • The seed scan fills queue with every 2 and counts every 1 into fresh.
  • while queue and fresh runs a minute only while there is a frontier and something to rot.
  • for _ in range(len(queue)) fixes the size of this minute's wave before any appends happen.
  • 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] == 1 admits only in-bounds fresh oranges.
  • grid[nr][nc] = 2, fresh -= 1, queue.append((nr, nc)) rot it, count it, and make it next minute's source.
  • minutes += 1 after the inner loop ticks once per wave.
  • return -1 if fresh else minutes reports impossibility or the time.
One-line summary to remember: seed the queue with every rotten orange, pop one level per minute, and stop the moment nothing is fresh.
