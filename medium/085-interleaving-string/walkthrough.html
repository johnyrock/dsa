Interleaving String, narrated

Scroll through the thinking, from trying every way to split s3 between the two strings to filling a table of yes/no answers for prefixes, with the state of the algorithm shown alongside.

Pattern used Dynamic Programming 2-D prefix table: the last character of s3's prefix came from s1 (cell above) or from s2 (cell to the left)

STEP 1

The problem

You get three strings. s3 is an interleaving of s1 and s2 if you can colour every character of s3 as "from s1" or "from s2" so that the s1-coloured characters read as exactly s1, the s2-coloured ones read as exactly s2, and nothing is left over. Each string keeps its own order, but the two may be cut into pieces of any size and merged in any way.

Return True if such a colouring exists, False otherwise.

Running example: s1 = "aabcc", s2 = "dbbca", s3 = "aadbbcbcac". The answer is True: split it as aa | d | b | b | c | b | ca | c, taking the pieces from s1, s2, s1, s2, s1, s2, s2, s1.

The tricky part is repeated letters. When the next character of s3 is a b and both strings are waiting on a b, either choice might be the one that works, and the wrong choice only shows up much later.

STEP 2

First instinct: try every split

Walk s3 from the front with two pointers i into s1 and j into s2. At each character, if it matches s1[i] try taking it from s1; if it matches s2[j] also try taking it from s2. Recurse on both and succeed if either succeeds.

def go(i, j):    if i + j == len(s3):        return i == len(s1) and j == len(s2)    ok = False    if i < len(s1) and s1[i] == s3[i + j]:        ok = go(i + 1, j)    if not ok and j < len(s2) and s2[j] == s3[i + j]:        ok = go(i, j + 1)    return ok

Whenever both branches match, the recursion forks. On a string like "aaaa" against "aaaa" and "aaaaaaaa" every character forks, so the number of paths is about C(m + n, m), exponential: O(2^(m + n)) in the worst case. Yet the recursion only ever sees (m + 1)(n + 1) distinct (i, j) pairs; it is re-solving the same pair over and over. That is the signal for a table.

STEP 3

The key idea: yes/no answers for prefixes

Define dp[i][j] as "can the first i characters of s1 and the first j characters of s2 interleave to form the first i + j characters of s3?" The position in s3 is not a third dimension: it is always i + j, because every character used so far went into s3.

Look at the last character of that prefix of s3, which is s3[i + j - 1]. It came from exactly one of the two strings:

  • From s1: then it must equal s1[i - 1], and the rest must have been reachable without it: dp[i - 1][j], the cell above.
  • From s2: then it must equal s2[j - 1], and dp[i][j - 1], the cell to the left, must hold.
dp[0][0] = True: two empty prefixes form the empty prefix. Unlike a counting table, the rest of row 0 and column 0 are not a fixed value; dp[0][j] is true only if s2 alone spells the first j characters of s3. The loops must start at 0 and let the recurrence fill the border.
STEP 4

The approach, line by line

  • m, n = len(s1), len(s2) sizes the table.
  • if m + n != len(s3): return False: an interleaving uses every character once, so the lengths must add up. This also keeps s3[i + j - 1] in range for every cell.
  • dp = [[False] * (n + 1) for _ in range(m + 1)] allocates the table, all False, then dp[0][0] = True.
  • for i in range(m + 1) and for j in range(n + 1) visit every cell, including the border, in row-major order, so the cell above and the cell to the left are final before they are read.
  • if i > 0 and dp[i - 1][j] and s1[i - 1] == s3[i + j - 1]: the last character came from s1. The i > 0 guard keeps row 0 from reading row -1.
  • elif j > 0 and dp[i][j - 1] and s2[j - 1] == s3[i + j - 1]: it came from s2. Either case suffices, so elif is enough; if neither fires the cell stays False.
  • return dp[m][n], the cell for the two full strings.
STEP 5

Trace it: the border and the first real cell

Row 0 asks whether s2 alone spells a prefix of s3. dp[0][1] compares s2[0] = d with s3[0] = a: no match, so it is False, and once a cell in row 0 is False every cell to its right is too, because each only reads its left neighbour.

Column 0 asks the same of s1. dp[1][0]: s1[0] = a equals s3[0] = a and dp[0][0] is True, so True. dp[2][0]: s1[1] = a equals s3[1] = a, True. dp[3][0]: s1[2] = b against s3[2] = d, False, and the rest of the column follows.

Now dp[2][1], the prefixes "aa" and "d" against s3[:3] = "aad". The last character is s3[2] = d. Case 1 needs dp[1][1], which is False. Case 2: dp[2][0] is True and s2[0] = d matches, so dp[2][1] = True. The d came from s2.

STEP 6

Trace it: a repeated letter, and a False cell

Row 2 keeps going: dp[2][2] reads s3[3] = b, and dp[2][1] is True with s2[1] = b, so True. Likewise dp[2][3] (s3[4] = b, s2[2] = b) and dp[2][4] (s3[5] = c, s2[3] = c) are True. dp[2][5] wants s3[6] = b to be s2[4] = a: False.

Now dp[3][2]: prefixes "aab" and "db", last character s3[4] = b. Case 1: the cell above, dp[2][2], is True and s1[2] = b matches, so dp[3][2] = True. Here the b is credited to s1; in dp[2][3] the same position was credited to s2. The table keeps both possibilities alive instead of committing.

Next, dp[3][3]: last character s3[5] = c. Above is dp[2][3] = True but s1[2] = b is not c. Left is dp[3][2] = True but s2[2] = b is not c either. Neither case fires, so dp[3][3] = False: there is no way to spell "aadbbc" from "aab" and "dbb".

STEP 7

Trace it: the last cell is the answer

The rows fill in the same way. Row 4 ("aabc") is True from column 2 onward: each of s3[6..9] = b, c, a, c can be explained either by the cell above with s1[3] = c or by the cell to the left with the next character of s2.

The last cell dp[5][5] is the full strings against all of s3. Its last character is s3[9] = c. Case 1: the cell above, dp[4][5], is True, and s1[4] = c matches, so dp[5][5] = True. The final c came from s1, and everything before it was already accounted for.

Every cell was computed once from at most two neighbours that were already final. The function returns dp[5][5] = True. The green path back through the table (above or left, whichever fired) is one valid split of s3.
STEP 8

Where this goes wrong: the border

Starting the loops at 1. Copying the LCS shape, for i in range(1, m + 1) and for j in range(1, n + 1), skips row 0 and column 0. In LCS those are constant zeros, but here they carry real information: dp[1][0] and dp[2][0] must be True for the aa at the front of s3. With the border left False, no cell can ever become True because every cell needs a True above or to its left. The whole table stays False and the function returns False, not True on the running example.

A greedy scan. Walking s3 once and taking each character from s1 whenever it matches, else from s2, never backtracks. On the running example it spends both of s1's cs on s3[5] and s3[7], then reaches s3[8] = a with s1 exhausted and s2 still waiting on its c, and returns False. The table avoids this by keeping both owners of each repeated letter alive.

Indexing s3[i + j]. Cell (i, j) covers i + j characters, and the last of them is at index i + j - 1. Without the - 1 every comparison is shifted by one and the last cell raises IndexError.

Two owners for the last character, cell above or cell to the left; and the border is computed, not assumed. Check with s1 = "", s2 = "b", s3 = "b": only row 0 exists and the answer must be True.
STEP 9

Time and space

The table has (m + 1)(n + 1) cells and each does at most two comparisons, so O(m × n) time: about ten thousand cells at the constraint limit of 100 characters each. The table is O(m × n) space; since a cell only reads the row above and its left neighbour, a single row of n + 1 booleans updated in place gives O(n).

ApproachTimeSpace
Recursive fork on every matchO(2^(m + n))O(m + n) stack
Recursion + memoizationO(m × n)O(m × n) cache + stack
Bottom-up tableO(m × n)O(m × n)
Bottom-up, one rowO(m × n)O(n)

Memoization fixes the exponential blow-up; the bottom-up loop removes the recursion and makes the one-row version possible.

STEP 10

The final solution

Thirteen lines. Every one of them maps to a step above.

  • m, n = len(s1), len(s2) — the two prefix lengths.
  • if m + n != len(s3): return False — lengths must add up.
  • dp = [[False] * (n + 1) for _ in range(m + 1)] and dp[0][0] = True — the table and its one known cell.
  • The two for loops fill it in row-major order, starting at 0 so the border is computed.
  • if i > 0 and dp[i - 1][j] and s1[i - 1] == s3[i + j - 1] — the last character came from s1.
  • elif j > 0 and dp[i][j - 1] and s2[j - 1] == s3[i + j - 1] — or from s2.
  • return dp[m][n] — the answer for the full strings.
One-line summary to remember: the last character of s3's prefix came from s1 (look up) or from s2 (look left); a cell is true if either owner works.
