Valid Parenthesis String, narrated

I’ll start by trying each reading of every star, then keep the lowest and highest possible open counts as I trace the string.

Pattern used Greedy track the range [lo, hi] of possible open counts; valid if hi never goes negative and lo ends at 0

STEP 1

The problem

A string s holds '(', ')' and '*'. Each star is a wildcard: independently, it can be read as '(', as ')', or as nothing at all. Decide whether some reading of the stars makes the string a valid parenthesis string.

Valid means what it always means: scanning left to right, the number of opens minus the number of closes never dips below zero, and it ends at exactly zero.

Running example: s = "(*))". Read the star as '(' and you get "(())", which is valid. Answer true. Read it as empty and you get "())", which is not; the question only asks whether at least one reading works.

The wildcard is what makes this harder than plain bracket matching. A star early in the string may need to be an open bracket to absorb a close bracket that shows up much later, and you cannot know which until you have seen the rest.

STEP 2

First instinct: try every reading of every star

My first instinct is to recurse through the string with an open count. At each star, I try its three readings and succeed when one branch ends at zero without going negative.

def ok(i, open_count):    if open_count < 0: return False    if i == len(s): return open_count == 0    if s[i] == '(': return ok(i + 1, open_count + 1)    if s[i] == ')': return ok(i + 1, open_count - 1)    return ok(i + 1, open_count + 1) or ok(i + 1, open_count - 1) or ok(i + 1, open_count)

With k stars, this explores O(3ᵏ · n) time in the stated form and uses O(n) space for the recursion stack. A string of 100 stars makes that unusable.

I do not need every reading separately. I only need the range of open counts that remains possible after each character.

STEP 3

The key insight: every open count between the extremes is reachable

Instead of asking “what is the open count?”, I ask “what is the set of open counts some reading could have produced by now?” Two readings bound it: I treat every star as ')' for the lowest count, lo, and as '(' for the highest, hi.

Crucially, every integer in between is also reachable: flipping a single star from ')' to empty raises the count by one, and from empty to '(' by another one. So the reachable set is a contiguous range [lo, hi], and two numbers describe it completely.

After "(*" the panel shows lo = 0 and hi = 2: the star could have closed the bracket (0 open), vanished (1 open), or opened another (2 open). All three counts are live.

With a range instead of a number, validity has two checks. If hi < 0 at any point, even the most generous reading has an unmatched ')', so the answer is false. And at the end, the string is valid exactly when 0 is inside the range, which is lo == 0.

STEP 4

The approach: shift the range with each character

  • lo = hi = 0: before any character, exactly zero brackets are open.
  • '(': lo += 1; hi += 1. A real open bracket shifts the whole range up.
  • ')': lo -= 1; hi -= 1. A real close bracket shifts it down.
  • '*': lo -= 1; hi += 1. The range widens by one on each side.
  • if hi < 0: return False: no reading survives an excess of closes.
  • lo = max(lo, 0): readings whose count went negative are invalid and are discarded from the range.
  • return lo == 0: zero is reachable at the end.

The clamp on lo is the subtle line. A negative lo would mean "some reading has more closes than opens so far", and that reading is dead; keeping it would let it later cancel against opens it never had.

STEP 5

Trace it: '(' then '*'

Index 0 is '(': lo = 0 + 1 = 1, hi = 0 + 1 = 1. One bracket is open in every reading. hi < 0 is false, and max(1, 0) leaves lo at 1.

Index 1 is '*': lo = 1 - 1 = 0, hi = 1 + 1 = 2. The range is now [0, 2]. The panel's number line lights up 0, 1 and 2 as reachable: the star closed, vanished, or opened.

Nothing has been decided about the star yet, and nothing needs to be. The range carries all three possibilities forward at the cost of two integers.

STEP 6

Trace it: the first ')'

Index 2 is ')': lo = 0 - 1 = -1, hi = 2 - 1 = 1. hi is not negative, so I continue.

Now the clamp: lo = max(-1, 0) = 0. The reading that had the star as ')' would now be at -1, meaning "())" with an unmatched close. That reading is dead and the clamp removes it from the range. The live range is [0, 1]: the star was empty (count 0) or the star was '(' (count 1).

The number line shows -1 in amber: a count that some reading would produce, but which is not a real state and is dropped.
STEP 7

Trace it: the second ')' and the verdict

Index 3 is ')': lo = 0 - 1 = -1, hi = 1 - 1 = 0. hi is still not negative; the reading with the star as '(' has just closed its last bracket. Clamp: lo = max(-1, 0) = 0. The range is [0, 0].

At the end of the string, lo == 0, so I return true. Exactly one reading survived, and it is the one where the star was '(', giving "(())".

Four characters, four constant-time updates. The brute force would have explored three branches; on a longer string it would have explored exponentially many, while this pass stays linear.

STEP 8

Where this goes wrong: forgetting the clamp

Dropping lo = max(lo, 0). I can run the same example without it. After '(' and '*' the range is [0, 2] as before. The first ')' gives [-1, 1], and the second gives [-2, 0]. Now lo == 0 is false and the function returns false for a valid string. The dead reading (star as ')') was carried along and dragged lo below zero, even though zero is still reachable via the star-as-'(' reading.

Dropping if hi < 0: return False. On ")**", hi goes -1, 0, 1 while lo is clamped to 0 at every step, so the final test says true. But a leading ')' has nothing before it to match, and no later star can fix that. The hi check catches it at index 0.

Returning hi == 0. hi is the reading where every star opened, the most unbalanced reading there is. On "(*)" it ends at 1 and the code returns false. Validity asks whether zero is reachable, which is a question about the low end of the range.

Two integers, two guards: hi < 0 means no reading survives; lo = max(lo, 0) discards the readings that already died.
STEP 9

Time and space

One pass, and each character does two additions or subtractions, a comparison and a max: O(n) time. The state is the pair (lo, hi): O(1) space.

ApproachTimeSpace
Try every reading of every starO(3ᵏ · n)O(n) stack
Memoized on (index, open count)O(n²)O(n²)
Range of open counts, one passO(n)O(1)

The memoized version already kills the exponential blow-up; the range trick notices that of all the (index, open count) states, only the lowest and highest count at each index matter.

STEP 10

The final solution

Sixteen lines, most of them the three-way branch. Every one of them maps to a step above.

  • lo = hi = 0 starts the range at "nothing open".
  • '(' adds one to both bounds; ')' subtracts one from both.
  • '*' does lo -= 1 and hi += 1, widening the range by one on each side.
  • if hi < 0: return False: even the reading with every star open has an unmatched close.
  • lo = max(lo, 0): readings that went negative are invalid and leave the range.
  • return lo == 0: some reading ends exactly balanced.
One-line summary to remember: carry the range of possible open counts; the string is valid if the range never leaves zero behind and still contains zero at the end.
