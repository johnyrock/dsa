Design Add and Search Words Data Structure, narrated

I will first compare a pattern with every stored word, then I use trie branches to rule out impossible prefixes immediately.

Pattern used Trie A literal letter follows one child; a dot tries every child. Recursion with any() does the branching.

STEP 1

The problem

Design a class WordDictionary with two methods. add_word(word) stores a lowercase word. search(word) reports whether some stored word matches the given string, where a . in the string stands for exactly one arbitrary letter. The match has to cover the whole stored word, not just a prefix of it.

Running example: add_word("bad"), add_word("dad"), add_word("mad"), then search("pad") → false, search("bad") → true, search(".ad") → true, search("b..") → true.

Without dots this is Implement Trie's search. The dot is what makes it a new problem: at a . the search cannot know which letter to follow, so it may have to try several. ".ad" could be "bad", "dad", or "mad", and any one of them is enough.

The constraints keep the fan-out honest: words are at most 25 letters and a search pattern has at most 2 dots, with up to 10⁴ calls in total.

STEP 2

First instinct: keep a list and test each word

I can store the words in a list and compare a search pattern with every same-length word, allowing a dot to match any character.

class WordDictionary:    def __init__(self): self.words = []    def addWord(self, word): self.words.append(word)    def search(self, word):        return any(len(saved) == len(word) and all(p == "." or p == c for p, c in zip(word, saved))                   for saved in self.words)

This is correct. addWord takes O(1) time, and a search can compare L characters for each of n words, so its time complexity is O(n · L). The word list uses O(total characters) space.

I focus the search by grouping words according to their prefixes. A trie lets a literal character follow one edge and a dot branch only among matching prefix candidates.

STEP 3

The key insight: a trie, with the search branching at dots

I put the words in a trie, exactly as in Implement Trie. Now a literal letter in the pattern means "follow this one child, or fail if it is missing", which kills "pad" at the root: there is no p branch. Words that do not share the pattern's prefix are never visited.

A . means "follow every child, and succeed if any of them works". That is a recursion, not a loop: match(node, i) answers whether word[i:] can be matched starting at node, and at a dot it returns any(match(child, i + 1) for child in node.children.values()).

The base case is the part people get wrong. When i == len(word) the pattern is used up, and the answer is node.is_word, not True. Reaching a node only proves a prefix exists; the flag proves a word ends there. For "b." the walk reaches the a under b, which is not flagged, so the answer is false even though "bad" is stored.

The panel shows the trie after the three adds: three branches from the root, each a chain a → d with a flag on the d.

STEP 4

The approach: add_word is a plain insert, search is match(root, 0)

  • add_word: for each ch, if ch not in node.children: node.children[ch] = TrieNode(), step down, and after the loop node.is_word = True.
  • if i == len(word): return node.is_word — pattern consumed; a match only if a word ends exactly here.
  • if ch == ".": return any(match(child, i + 1) for child in node.children.values()) — wildcard: I try every child, stop at the first success.
  • child = node.children.get(ch) then return child is not None and match(child, i + 1) — literal: one child or nothing.
  • return match(self.root, 0) — start at the root with the whole pattern ahead.

Two things fall out for free. any over an empty children dict is False, so a dot at a leaf fails correctly. And and short-circuits, so a missing literal never recurses into None.

STEP 5

Trace it: search("pad") and search("bad")

After the three adds, the root's children dict has keys b, d, m. search("pad") calls match(root, 0). The first pattern character is p, a literal, so child = root.children.get("p") is None, and child is not None and … is false without a single recursive call. The other two letters are never even looked at.

search("bad"): b is found, recurse to match(b, 1); a is found, match(a, 2); d is found, match(d, 3). Now i == 3 == len(word), and the d node's is_word is True, so the whole chain of ands evaluates to true.

The panel shows the b-a-d path in green and the other two branches dimmed: with no dots, exactly one path is ever explored.

STEP 6

Trace it: search(".ad")

match(root, 0) sees ch = ".". So it evaluates any(match(child, 1) for child in root.children.values()). The children are the b, d, and m nodes, in insertion order.

The first candidate is match(b, 1). Pattern index 1 is the literal a: found under b, recurse to match(a, 2). Index 2 is the literal d: found, recurse to match(d, 3). The pattern is consumed and d.is_word is True, so match(b, 1) returns True.

That is the first value the generator hands to any, so any stops right there and returns true. The d and m branches are never explored: the panel shows only b → a → d lit, with the dot's two unused alternatives dimmed. Had "bad" not been stored, the generator would have moved on to match(d, 1) next.

STEP 7

Trace it: search("b..")

match(root, 0): literal b, found, recurse to match(b, 1). Index 1 is a dot, so I try every child of b. It has one, a: match(a, 2). Index 2 is also a dot, so I try every child of a. It has one, d: match(d, 3). The pattern is consumed and d.is_word is True.

So match(a, 2) returns True, match(b, 1) returns True, and the top-level and returns true. Two dots, but each had only one child to try, so the whole search visited four nodes.

The four searches returned false, true, true, true. Every one of them touched only the nodes on paths that could still match; the list scan from step 2 would have compared the pattern against all three words every time.
STEP 8

Where this goes wrong

Returning True at the end of the pattern. I write if i == len(word): return True instead of return node.is_word. Then search("b.") on this dictionary walks b → a, runs out of pattern, and answers true, although no stored word is two letters long. The panel shows that: the walk ends on the unflagged a and the bug says yes anyway. The same bug makes search("ba") true.

Treating the dot as a letter. Leave out the if ch == "." branch, and search(".ad") does root.children.get("."), gets None, and returns false. A dot is never a key in children; it has to be handled before the literal lookup.

all instead of any at the dot. On this dictionary it happens to work, because every branch of ".ad" matches. But search(".") on an empty dictionary returns true, since all() of nothing is True, and any dictionary where one child branch fails turns a valid match into False.

The end of the pattern is not the end of the check: ask node.is_word. And a dot is a branching point, not a character to look up.
STEP 9

Time and space

add_word is one dict operation per letter, O(L). A search with no dots follows one path, also O(L). Each dot can fan out to every child of its node, up to 26, so a pattern with d dots costs up to O(26d · L) in the worst case. The constraint of at most 2 dots keeps that at a few hundred nodes per query.

Space is one node per stored character at most, O(total characters), and less when words share prefixes.

STEP 10

The final solution

A trie insert and a recursive matcher. Line by line:

  • if ch not in node.children: node.children[ch] = TrieNode() / node.is_word = True — the same insert as Implement Trie.
  • def match(node, i): — can word[i:] be matched from node?
  • if i == len(word): return node.is_word — pattern consumed; only a flagged node counts.
  • if ch == ".": return any(match(child, i + 1) for child in node.children.values()) — a dot tries every child and stops at the first success.
  • child = node.children.get(ch) / return child is not None and match(child, i + 1) — a literal follows one child or fails.
  • return match(self.root, 0) — kick off at the root.
One-line summary to remember: a trie search where a literal follows one child, a dot tries them all with any(), and the end of the pattern must land on a flagged node.
