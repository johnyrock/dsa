Subsets, narrated

Scroll through the thinking, from counting in binary to a recursion that grows one subset at a time, with the path, the recursion tree, and the growing answer list shown alongside.

Pattern used Backtracking choose an element, recurse on the indices after it, undo; every node of the tree is an answer

STEP 1

The problem

You are given an array nums of distinct integers. Return every possible subset of it, the power set: every way of picking some, none, or all of the elements. The order of subsets in the output does not matter, and the order inside a subset does not matter either, but no subset may appear twice.

Running example: nums = [1, 2, 3]. The answer is the eight lists [], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3].

The count is fixed before you start: each element is either in or out, so there are exactly 2^n subsets. For n = 3 that is 8; for the largest allowed input, n = 10, it is 1024. Since the output itself has that many entries, no algorithm can beat O(2ⁿ) work. The goal is to spend nothing beyond what it takes to write the answers down, and to never write the same one twice.

Notice that [1, 2] and [2, 1] are the same subset. Whatever we build must produce only one of them, and the cleanest way to guarantee that is to always list elements in increasing index order.

STEP 2

First instinct: count in binary

Three elements, each in or out, is a 3-bit number. Count from 0 to 7, and for each number keep nums[j] whenever bit j is set:

result = []for mask in range(1 << len(nums)):    subset = []    for j in range(len(nums)):        if mask >> j & 1:            subset.append(nums[j])    result.append(subset)

This is correct and it is O(n · 2ⁿ), which is optimal. Mask 5 = 101 gives [1, 3], mask 0 gives [], mask 7 gives [1, 2, 3]. Each subset is rebuilt from scratch, bit by bit, even though mask 101 and mask 111 share their first two decisions.

The reason to learn the recursive version anyway is that the bitmask trick stops working the moment the problem changes shape: subsets with duplicate values, combinations of a fixed size, subsets that must hit a target sum. Backtracking handles all of those with a one-line change, and it is the version interviewers expect you to reach for.

STEP 3

Key insight: every prefix is an answer, and the next pick must come later

Build a subset in a shared list path, one element at a time. Two observations turn that into a complete algorithm.

  • Every state of path is itself a subset. Unlike permutations or parentheses, there is no "complete" check: the moment you enter a call, path is a valid answer, so record it immediately with result.append(path[:]).
  • Only pick from indices after the last pick. The call carries a start index and loops for i in range(start, len(nums)). Once 2 is in the path, 1 is never offered again, so [2, 1] cannot be built and [1, 2] is produced exactly once.
The recursion tree has exactly one node per subset. Its root is [], the children of any node are that subset extended by one later element, and reading the tree in preorder gives the output in order.

The panel is standing on the node [1, 2]: it was recorded on entry, and its only child is [1, 2, 3] because start = 2 leaves just one candidate.

STEP 4

The approach, line by line

  • result = [] and path = []: the answers, and the one subset under construction.
  • backtrack(start) extends path using only nums[start:].
  • On entry, result.append(path[:]): the current prefix is an answer. The [:] copy matters, because path will be mutated after this line.
  • for i in range(start, len(nums)): try each later element as the next member.
  • Choose with path.append(nums[i]), recurse with backtrack(i + 1), undo with path.pop().
  • Kick off with backtrack(0) and return result.

The three-line choose / recurse / undo block is the whole backtracking pattern. The i + 1 is what makes the loop an "index after" rule rather than a "any index" rule.

STEP 5

Trace it: down the leftmost branch to [1, 2, 3]

backtrack(0) records []. Its loop starts at i = 0: push 1, call backtrack(1). That records [1] and starts its own loop at i = 1: push 2, call backtrack(2), which records [1, 2]. Its loop starts at i = 2: push 3, call backtrack(3).

That call records [1, 2, 3], then its loop is range(3, 3), which is empty. Nothing to try, so it returns. Four subsets are in result after four calls, and every one of them was recorded on the way down, before any loop ran.

The panel shows the path filled in all three slots and the recursion tree grown one node per call, straight down the left edge.

STEP 6

Trace it: undo and take the other child, [1, 3]

Back in backtrack(2), the line after the recursive call is path.pop(), so 3 comes off and path is [1, 2] again. Its loop is finished (it started at 2 and there are only three elements), so it returns. Back in backtrack(1), another pop takes 2 off: path = [1], and the loop continues with i = 2.

Push 3, call backtrack(3): it records [1, 3] and its loop is empty. Pop, and backtrack(1) has exhausted i = 1, 2, so it returns. Pop again in backtrack(0): path is [], ready for i = 1.

Look at where [1, 3] hangs in the tree: it is a sibling of [1, 2], a child of [1]. There is no [1, 2] → [1, 3] edge, because from [1, 2] the only candidate is index 2. The pop is what moves us up a level before we branch again.

STEP 7

Trace it: the rest of the tree, [2], [2, 3], [3]

With path = [] and i = 1, push 2 and call backtrack(2): record [2], then its loop offers only index 2, so push 3, record [2, 3], empty loop, pop. Back at the root with i = 2: push 3, backtrack(3) records [3] and returns at once.

The root's loop is done. result holds exactly the eight subsets, in the order they were entered: [], [1], [1,2], [1,2,3], [1,3], [2], [2,3], [3]. Notice that 1 never appears after 2, and 2 never after 3: the start index kept every subset in increasing order.

Eight calls, eight answers. The tree is the output.
STEP 8

Where this goes wrong: the copy, the start, and the i + 1

Appending path instead of path[:]. Every entry in result is then the same list object, the one that keeps being appended to and popped from. By the time the function returns, that list is empty again, so the answer is eight copies of []. The panel shows exactly that. Copy on record, always.

Looping from 0 instead of start. Write for i in range(len(nums)) and the call for [1] pushes 1 again, then 1 again … the path grows forever and Python stops it with a RecursionError. The start bound is not just about ordering; it is also what makes the recursion terminate.

Recursing with backtrack(i) instead of backtrack(i + 1). The same element becomes available again in the child, so [1, 1], [1, 1, 1] … are built and the recursion never bottoms out. That variant is correct for Combination Sum, where reuse is allowed; here it is a bug.

Record a copy, and hand the child i + 1. The child may only see what comes after the element you just placed.
STEP 9

Time and space

There are 2^n calls, one per subset, and each records a copy of path, which is up to n long. That is O(n · 2ⁿ) time, and it is optimal because the output has that size. The recursion depth and path are both bounded by n, so the working space beyond the output is O(n).

ApproachTimeSpace (beyond output)
Bitmask 0 … 2ⁿ − 1O(n · 2ⁿ)O(n)
Backtracking, record on entryO(n · 2ⁿ)O(n)
Iterative doubling (extend every existing subset)O(n · 2ⁿ)O(1)

All three are the same asymptotically; the difference is which one still works when the problem changes. The bitmask cannot skip duplicates, and the doubling trick cannot prune by a target. The recursion does both with one extra line.

STEP 10

The final solution

One nested function, one loop, three lines of choose / recurse / undo.

  • result = [], path = []: answers and the working subset.
  • result.append(path[:]) on entry: every node of the tree is a subset.
  • for i in range(start, len(nums)): only elements after the last pick.
  • path.append(nums[i]), backtrack(i + 1), path.pop(): choose, recurse past it, undo.
  • backtrack(0) starts from the empty subset; return result.
One-line summary to remember: record the path on entry, then extend it with each later element and undo.
