Task Scheduler, narrated

I will first test every distinct task ordering, then I choose the available task with the largest remaining count at each CPU tick.

Pattern used Heap At every tick run the available task with the most copies left; a max-heap on counts finds it, and a FIFO cooldown queue holds tasks until n ticks have passed.

STEP 1

The problem

A CPU is given a list of tasks, each an uppercase letter, and a cooldown n. Every tick it runs one task or idles. Two runs of the same letter must be at least n ticks apart, meaning n other ticks (other letters or idles) sit between them. The order is up to you. Return the fewest ticks needed to finish everything.

Running example: tasks = ["A","A","A","B","B","B"], n = 2. The best schedule is A B idle A B idle A B: 8 ticks. Each A needs two ticks before the next A, and there is only one other letter to fill the gap, so one idle per gap is unavoidable.

The answer is a single number, the length of the schedule, not the schedule itself. Idles count as ticks. Only how many copies of each letter exist matters; the letters themselves are irrelevant, and there are at most 26 distinct letters.

STEP 2

First instinct: try every ordering

I can generate each distinct order of the tasks, simulate the cooldown delays it requires, and keep the shortest resulting schedule.

from itertools import permutationsdef leastInterval(tasks, n):    best = float("inf")    for order in set(permutations(tasks)):        last, time = {}, 0        for task in order:            time = max(time + 1, last.get(task, -n - 1) + n + 1)            last[task] = time        best = min(best, time)    return best

This is correct because it examines every possible task order and calculates the idles forced by its cooldowns. With T tasks, the time complexity is O(T! · T), and storing the generated orderings uses O(T! · T) space.

I choose the available task with the most copies left. A max-heap chooses the available task with the most copies left, while a cooldown queue tells me when a task can return.

STEP 3

The key insight: always run the most-remaining available task

The letter with the most copies left is the one that will force idles at the end if it falls behind, so at every tick it should run if it is allowed to. That is a greedy rule with two halves:

  • Which task has the most copies left? A max-heap of counts answers that in O(log 26). heapq is a min-heap, so I store -count; the root is then the largest pile.
  • Which tasks are allowed right now? A task that ran at tick t may not run again until tick t + n + 1. Between those ticks it must be out of the heap, otherwise the greedy would pick it again immediately. Park it in a queue tagged with the tick it becomes ready: (time + n, remaining).
Every parked task waits exactly n ticks, so the queue is sorted by ready time for free. Only its front ever needs checking: cooldown[0][0] == time.

The panel shows the starting heap: Counter gives {A: 3, B: 3}, negated to [-3, -3]. Both roots are equal, so which letter goes first does not matter.

STEP 4

The approach: one loop iteration per tick

  • heap = [-count for count in Counter(tasks).values()], then heapq.heapify(heap): the negated counts, largest pile at the root.
  • cooldown = deque(), time = 0: an empty parking queue and the clock.
  • while heap or cooldown: I keep ticking while anything is runnable or still cooling down.
  • time += 1: a tick passes whether or not a task runs.
  • if heap: remaining = heapq.heappop(heap) + 1: I run the biggest pile. -3 + 1 = -2 means one copy done, two left.
  • if remaining: cooldown.append((time + n, remaining)): unless that letter is finished, park it until time + n.
  • if cooldown and cooldown[0][0] == time: heapq.heappush(heap, cooldown.popleft()[1]): the oldest parked task, if its ready tick is now, goes back into the heap.
  • return time: when both are empty, the clock is the answer.

If the heap is empty at the top of an iteration the CPU idles: nothing is popped, but time still advanced, and the cooldown check may release a task for the next tick.

STEP 5

Trace it: ticks 1 and 2, A then B

Tick 1. I pop -3 (call it A): remaining = -3 + 1 = -2, nonzero, so I append (1 + 2, -2) = (3, -2) to cooldown. The heap is [-3], B only. Nothing in the queue is ready at tick 1.

Tick 2. I pop -3 (B): remaining = -2, I append (4, -2). The heap is now empty: both letters are cooling down. The queue is [(3, A:-2), (4, B:-2)]. The front is ready at 3, not 2, so nothing comes back yet.

Timeline so far: A B. Two ticks, two tasks run, and the CPU is about to have nothing to do.

STEP 6

Trace it: tick 3 idles, tick 4 runs A again

Tick 3. The heap is empty, so if heap is false and nothing runs: an idle. But the tick still counted, and now cooldown[0][0] == 3 == time, so A's -2 is popped from the front of the queue and pushed back into the heap. Heap [-2], queue [(4, B:-2)].

Tick 4. I pop A's -2: remaining = -1, I append (4 + 2, -1) = (6, -1). Then the front of the queue is B with ready tick 4, which equals time, so B's -2 re-enters the heap. Heap [-2] (B), queue [(6, A:-1)].

Timeline: A B idle A. The idle at tick 3 was forced: A ran at tick 1 and could not run before tick 4, and B ran at tick 2 and could not run before tick 5. The heap being empty is the signal that an idle is unavoidable.

STEP 7

Trace it: ticks 5 to 8, the last copies

Tick 5. I pop B's -2, remaining = -1, I append (7, -1). Heap empty, queue [(6, A:-1), (7, B:-1)]. Tick 6. Idle; A's -1 is released at exactly 6. Tick 7. I pop A's -1: remaining = -1 + 1 = 0, which is falsy, so A is finished and nothing is appended. B's -1 is released. Tick 8. I pop B's -1, remaining = 0, finished.

Now heap is empty and cooldown is empty, so while heap or cooldown ends. return time gives 8, and the timeline reads A B idle A B idle A B.

The last B does not pay a trailing cooldown. Once a letter's count hits zero I simply drop it, so the clock stops the moment the last task runs.
STEP 8

Where this goes wrong: the loop condition, and the ready tick

Looping only while the heap is nonempty. I write while heap: instead of while heap or cooldown:. On the example, after tick 2 the heap is empty while both A and B sit in the queue. The loop exits and returns 2. The heap being empty means "idle this tick", not "done"; done is when the queue is empty too.

Off by one on the ready tick. I append (time + n - 1, remaining) and A that ran at tick 1 is released at tick 2 and runs again at tick 3, with only one tick between: the schedule A B A B A B is produced and 6 is returned, which violates the cooldown. The rule is n ticks between runs, so a task that runs at t is ready at t + n and runs at t + n + 1.

Skipping the queue. Pushing remaining straight back into the heap in the same tick makes every letter eligible every tick; the answer collapses to len(tasks) = 6.

The loop runs while anything is left, in the heap or in the queue. An empty heap is an idle tick, not the end.
STEP 9

Time and space

Each loop iteration is one tick of the answer T, and each does at most one pop and one push on a heap of at most 26 entries. That is O(T · log 26), effectively O(T), where T is at most len(tasks) · (n + 1). Space is the counter, heap and queue, all bounded by 26: O(1).

ApproachTimeSpace
Try every orderingO(T! · T)O(T)
Heap + cooldown simulationO(T · log 26) ≈ O(T)O(26)
Closed form on countsO(len(tasks))O(26)

The closed form max(len(tasks), (max_count - 1) * (n + 1) + count_of_max) is what the simulation computes implicitly: the most frequent letter fixes a frame of max_count - 1 gaps of width n + 1, the other letters fill the gaps, and if there are more tasks than the frame has room for, no idles happen at all. I can derive the simulation live in an interview, then mention the formula afterwards.

STEP 10

The final solution

Thirteen lines, one clock.

  • heap = [-count for count in Counter(tasks).values()] and heapq.heapify(heap): the piles, largest at the root.
  • cooldown = deque(): parked tasks, oldest first, tagged with their ready tick.
  • while heap or cooldown: tick until nothing is runnable or waiting.
  • time += 1 then if heap: I run the biggest pile; remaining = heapq.heappop(heap) + 1.
  • if remaining: cooldown.append((time + n, remaining)): park it unless finished.
  • if cooldown and cooldown[0][0] == time: release the front back into the heap.
  • return time: the clock when everything is done.
One-line summary to remember: each tick, I run the available letter with the most copies left; park it for n ticks; the clock when both containers empty is the answer.
