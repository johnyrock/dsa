Number of Connected Components in an Undirected Graph, narrated

I will first compute the reachable set from every node, then count components as edges merge separate sets.

Pattern used Graph Traversal union-find: count = n, minus one per edge that merges two different roots

STEP 1

The problem

You get n nodes numbered from 0 and a list of undirected edges. Two nodes are in the same component when some chain of edges connects them. Count the components.

A node that appears in no edge at all still counts: it is a component of size one. With no edges the answer is n; with enough edges to reach everything it is 1.

Running example: n = 5, edges = [[0,1],[1,2],[3,4]]. Nodes 0, 1, 2 form a chain and nodes 3, 4 form a pair. Nothing links the two groups, so the answer is 2.

Notice we are asked for a count, not for the groups themselves. That is a hint that we may not need to enumerate the members of each component, only to notice when two of them merge.

STEP 2

First instinct: find every node's reachable set

I can run BFS from every node, store its reachable set, and count the distinct sets.

def countComponents(n, edges):    graph = build_graph(n, edges)    groups = set()    for start in range(n):        groups.add(frozenset(bfs(start, graph)))    return len(groups)

This is correct. Every BFS takes O(n + E) time and runs n times, so the time complexity is O(n · (n + E)). The reachable sets use O(n²) space.

Retaining component information instead of rediscovering it lets union-find start with n components and subtract one whenever an edge joins two different roots.

STEP 3

The key idea: start at n and count the merges

Before any edge is considered, there are n components because every node is alone. I then add edges one at a time and track what each does to the count.

  • If its two endpoints are already in the same component, the edge changes nothing. The count stays.
  • If they are in different components, the edge glues those two components into one. The count drops by exactly 1.
So the answer is n minus the number of edges that merged two different components. I only need to know whether two nodes are currently in the same component.

That question is what union-find is for. I keep a parent array where each component is a small tree of pointers, and find(x) follows them to the root.

STEP 4

The approach, line by line

  • parent = list(range(n)): every node is its own root. rank = [0] * n: an upper bound on each root's tree height, used to keep the trees shallow.
  • In find(x), I set parent[x] = parent[parent[x]] while climbing, which shortens the next path, then return the root.
  • count = n.
  • For each edge [a, b]: ra, rb = find(a), find(b). if ra == rb: continue, because a redundant edge must not touch the count.
  • Otherwise, I union by rank, attach rb to ra, and reduce count.
  • return count.

For the running example the loop starts with parent = [0, 1, 2, 3, 4], rank = [0, 0, 0, 0, 0], and count = 5.

STEP 5

Trace it: edge [0,1]

find(0): parent[0] == 0, so the root is 0 immediately. find(1): root 1. They differ, so this edge merges two components.

Ranks are both 0, so no swap; parent[1] = 0. The ranks were equal, so rank[0] becomes 1. count goes 5 - 1 = 4. Now parent = [0, 0, 2, 3, 4].

Nodes 0 and 1 are one component with root 0. Nodes 2, 3 and 4 are still alone, which is what the four remaining roots in the array say.

STEP 6

Trace it: edge [1,2]

find(1): parent[1] = 0, and parent[0] = 0, so the root is 0. find(2): root 2. Different, so merge.

rank[0] = 1 is not less than rank[2] = 0, so no swap; parent[2] = 0. Ranks differ, so rank[0] stays 1. count goes 4 - 1 = 3. Now parent = [0, 0, 0, 3, 4].

Node 2 was attached directly under root 0, not under node 1, even though the edge said [1, 2]. That is the point of unioning roots rather than endpoints: the tree stays one level deep.

STEP 7

Trace it: edge [3,4], the answer

find(3) is 3 and find(4) is 4. Different, so merge. Ranks are both 0: parent[4] = 3, rank[3] becomes 1. count goes 3 - 1 = 2. Now parent = [0, 0, 0, 3, 3].

No edges remain. return 2. Three edges, three merges, 5 - 3 = 2 components: {0, 1, 2} rooted at 0 and {3, 4} rooted at 3. The two roots are exactly the two indices where parent[i] == i.

Every edge in this example merged something. The next step shows the case where one does not, which is the whole reason for the if ra == rb: continue line.
STEP 8

Where this goes wrong: counting edges instead of merges

Two specific bugs live here, and both pass on the running example.

Decrementing on every edge. If I move count -= 1 above if ra == rb: continue, a redundant edge makes the count too small. With [[0,1],[1,2],[3,4],[0,2]], the correct answer is 2 but the buggy version returns 1.

Counting len(set(parent)) at the end. After unions the array is not flat. On n = 4, edges = [[0,1],[2,3],[1,3]] the third edge points root 2 at root 0, giving parent = [0, 0, 0, 2]. The set has two values but there is one component. Either count the indices with parent[i] == i, or, as here, count merges as they happen and never look at the array again.

I skip redundant edges before touching count. If I read the array at the end, I count roots (parent[i] == i), not distinct values.
STEP 9

Time and space

Initialising parent and rank is O(n). The loop does two find calls and at most one union per edge. With path halving and union by rank, a find costs amortised O(α(n)), the inverse Ackermann function, at most 4 for any realistic input. Total O(n + E × α(n)), effectively linear.

parent and rank are each n integers: O(n) space. No adjacency list, no visited set, no queue.

ApproachTimeSpace
BFS from every node, count distinct reachable setsO(n × (n + E))O(n²)
DFS, count how many starts find an unvisited nodeO(n + E)O(n + E) adjacency + visited + stack
Union-find, count mergesO(n + E × α(n))O(n)

DFS and union-find are both linear in practice. I choose union-find when edges arrive one at a time and I need the count after each one, because DFS would have to start over.

STEP 10

The final solution

Every line maps to a step above.

  • parent = list(range(n)) and rank = [0] * n: every node is its own root at rank 0.
  • find(x) walks up with parent[x] = parent[parent[x]] at each step until parent[x] == x.
  • count = n: with no edges, every node is a component.
  • if ra == rb: continue: a redundant edge merges nothing and must not lower the count.
  • parent[rb] = ra after swapping so ra is the higher rank; rank[ra] += 1 only on a tie.
  • count -= 1 once per successful merge, then return count.
My rule is: I start at n and subtract one for every edge whose endpoints have different roots.
