Copy List with Random Pointer, narrated

Scroll through the thinking, from a copy that quietly points back into the original to a two-pass map from every old node to its new twin, with the state of the algorithm shown alongside.

Pattern used Hash Map old node → new node, so any pointer can be translated in O(1)

STEP 1

The problem

Each node in this linked list has the usual val and next, plus a random pointer that may aim at any node in the list, or at nothing. Build a deep copy: a second list of brand-new nodes with the same values and the same pointer shape, sharing no node with the original.

Running example: [[7,null],[13,0],[11,4],[10,2],[1,0]]. Node 7's random is null; 13's random points to index 0 (node 7); 11's points to index 4 (node 1); 10's to index 2 (node 11); 1's to index 0 (node 7). The answer is a new list that serialises to exactly the same array.

The output looks identical to the input, which is why this problem is about identity rather than values. A copy that returns the same array but whose nodes' random fields point into the original list is wrong, even though printing it would look fine.

Notice in the panel that random pointers go both directions: 13 points backward to 7, but 11 points forward to 1, a node that comes later in the list. That forward pointer is the whole difficulty.

STEP 2

First instinct: copy in one pass, resolve random by searching

Walk the list once, creating a new node per original and linking next as you go. That handles val and next. For random, you need to know which copy corresponds to the target — so first find the target's position in the original list, then walk that many steps in the copy:

for each original node (index i):    j = position of node.random in the original list   # O(n) scan    copy_i.random = j-th node of the copied list          # O(n) walk

Because random can point forward, this has to be a second pass after every copy exists. Each node then costs two linear walks, one to find j and one to reach the j-th copy, so the total is O(n²) time with O(1) extra space. On the example, resolving 11's random means scanning to find that node 1 is at index 4, then walking four steps down the copy.

The repeated work is the "find the position" step. We are doing a linear search to answer a question, "what is the copy of this node?", that a dictionary answers in O(1).

STEP 3

The key idea: a map from old node to new node

Keep a dictionary old_to_new whose keys are the original node objects and whose values are their copies. Once it is filled, translating any pointer is one lookup: the copy of node.random is old_to_new[node.random], whatever direction it points.

Because random can point forward, fill the map completely before wiring anything. That splits the job into two passes:

  • Pass 1: for every original node, create Node(node.val) and store it in the map.
  • Pass 2: for every original node, set its copy's next and random by translating the original's targets through the map.
Seed the map with {None: None}. Then a null next (at the tail) or a null random translates to None through the same lookup, with no special case.

The keys are node objects, not values. Python dicts hash objects by identity by default, so two nodes with equal val are different keys — exactly what a deep copy needs.

STEP 4

The approach, line by line

  • old_to_new = {None: None} — the map, pre-seeded so null pointers translate.
  • while node is not None: old_to_new[node] = Node(node.val) — pass 1 creates every copy, values only.
  • copy = old_to_new[node] — pass 2 picks up the copy made in pass 1.
  • copy.next = old_to_new[node.next] — the copy's next is the copy of the original's next.
  • copy.random = old_to_new[node.random] — same translation, same lookup.
  • return old_to_new[head] — the copy of the head; for an empty list this is old_to_new[None], i.e. None.

Both loops are the same node = head; while node is not None: …; node = node.next walk. Only the body differs.

STEP 5

Trace it: pass 1 creates the copies

Start at 7: old_to_new[7] = Node(7). Its next and random are both still None; we are not wiring anything yet. Move to 13, create Node(13). Then 11, 10, 1.

After the pass the map has six entries: the None → None seed plus five originals, each mapped to a fresh node holding only a value. The panel draws each copy under its original with a dashed line for the map entry.

Nothing about the random pointers has been read yet. That is deliberate: when we get to 11, whose random points forward to 1, the copy of 1 will already exist because pass 1 finished first.

STEP 6

Trace it: pass 2 wires 7 and 13

Back to the head. node = 7, copy = old_to_new[7]. Its next: old_to_new[13], the copy of 13. Its random: node.random is None, and old_to_new[None] is None, courtesy of the seed. So copy.random = None.

node = 13. Next becomes the copy of 11. Random: 13's random is node 7 (index 0), and old_to_new[7] is the copy of 7, so the copy of 13 now points back at the copy of 7 — not at the original 7.

Two copies are fully wired. Both of their random pointers stay inside the bottom row, which is what "deep" means.

STEP 7

Trace it: the forward pointer, and the rest

node = 11. Its random is node 1 at index 4, two positions ahead. In a one-pass design this is where things would break, but the copy of 1 was created in pass 1, so old_to_new[1] returns it and copy.random is set in O(1).

node = 10: random → copy of 11 (index 2). node = 1: next → old_to_new[None] = None, the tail; random → copy of 7 (index 0).

All five copies wired. return old_to_new[head] hands back the copy of 7, and walking it serialises to [[7,null],[13,0],[11,4],[10,2],[1,0]]: identical shape, zero shared nodes.
STEP 8

Where this goes wrong: random into the original, and the missing seed

Copying the pointer instead of translating it. Write copy.random = node.random and every copy's random points into the original list. Serialising the copy by index still finds the right positions if you look up positions in the original, so a careless test prints [[7,null],[13,0],[11,4],[10,2],[1,0]] and passes — but the copy shares five nodes with the input, and mutating one list corrupts the other. The panel shows the crossed pointers.

Forgetting {None: None}. Start with old_to_new = {} and the very first node in pass 2, 7, does old_to_new[node.random] with node.random = None: KeyError: None. Even if every random were non-null, the tail's next would hit the same error.

Keying by value. old_to_new[node.val] collapses equal values into one key. On [[3,null],[3,0],[3,null]] only one copy survives and the result is the single node [[3,null]].

Every pointer on a copy must come out of the map. If a line assigns node.something directly to a copy, the copy is not deep.
STEP 9

Time and space

Two passes over n nodes, with a constant number of dictionary operations each: O(n) time. The map holds one entry per node, O(n) extra space on top of the O(n) output that any solution must produce.

ApproachTimeExtra space
Copy, then resolve random by position searchO(n²)O(1)
Two passes with old → new mapO(n)O(n)
Interleave copies (A → A′ → B → B′), then splitO(n)O(1)

The interleaving trick is the classic follow-up: put each copy right after its original so node.next is the map, then set node.next.random = node.random.next and unzip the two lists. Same idea, with the list itself standing in for the dictionary.

STEP 10

The final solution

Two identical walks and one dictionary.

  • old_to_new = {None: None} — seed so null pointers need no branch.
  • old_to_new[node] = Node(node.val) — pass 1: one fresh node per original, keyed by identity.
  • copy = old_to_new[node] — pass 2: fetch the twin.
  • copy.next = old_to_new[node.next] — translate next.
  • copy.random = old_to_new[node.random] — translate random, forward or backward.
  • return old_to_new[head] — the new head (or None for an empty list).
One-line summary to remember: create all the copies first, then wire every pointer through the old-to-new map — never assign an original node to a copy.
