Container With Most Water, narrated

Scroll through the thinking, from checking every pair of lines to two pointers that start at the ends and always move the shorter line inward, with the state of the algorithm shown alongside.

Pattern used Two Pointers start at the ends, always move the shorter wall

STEP 1

The problem

You get an array of heights. Each one is a vertical line standing at its index. Pick two lines; with the floor they form a container, and it holds water up to the level of the shorter line. Return the largest area any pair can enclose.

The area of the pair at indices i < j is (j - i) · min(height[i], height[j]). Width times the shorter wall. The taller wall is wasted above that level.

Running example: height = [1, 8, 6, 2, 5, 4, 8, 3, 7]. The answer is 49: the 8 at index 1 and the 7 at index 8, width 7, height 7.
STEP 2

First instinct: try every pair

Compute the area for every pair of lines and keep the largest.

best = 0for i in range(n):    for j in range(i + 1, n):        best = max(best, (j - i) * min(height[i], height[j]))

Correct and O(n²). At n = 100,000 that is five billion pairs, too slow. Most of those pairs are hopeless, and there is a way to know which ones without computing them.

STEP 3

Reframe: start wide and only give up width for height

The widest possible container uses the two outermost lines. Every other pair is narrower. So a narrower pair can only win if it is taller, and "taller" means its shorter wall is higher than the current shorter wall.

That points at the shorter wall. Suppose the left line is the shorter one. Any container that keeps the left line and moves the right line inward is narrower and still capped at the left line's height, so it is strictly worse. The left line is finished; nothing it pairs with going forward can beat what it already made.

Retire the shorter line. Keep the taller one, because it might still form a bigger container with something taller further in.
STEP 4

The key idea: two pointers, move the shorter one

Put left = 0 and right = n - 1. Repeat until they meet:

  • Compute the area between them and update best.
  • If height[left] < height[right], move left in. Otherwise move right in.

Each step retires one line for good. After at most n − 1 steps the pointers meet and every pair that could possibly have been the best has been looked at. The pairs that were skipped were all provably beaten by a pair we did compute.

STEP 5

Trace it: the first move

left = 0 (height 1), right = 8 (height 7). Width 8, height min(1, 7) = 1, area 8. best = 8.

The left wall, height 1, is the shorter one. Any container using index 0 and a right wall closer in would be at most 1 tall and less than 8 wide, so index 0 is retired. left becomes 1.

STEP 6

Trace it: the answer appears immediately

left = 1 (height 8), right = 8 (height 7). Width 7, height min(8, 7) = 7, area 49. best = 49.

Now the right wall is shorter, so right moves in to index 7 (height 3). Width 6, height 3, area 18. Still shorter on the right: index 6 (height 8), width 5, height 8, area 40. Tie at 8 and 8, so right moves again, and so on inward. Nothing beats 49, and the loop ends with the pointers meeting.

Eight iterations instead of 36 pairs, and the best pair was among them.
STEP 7

The pitfall: moving the taller line

Run the running example with the opposite rule: always move the taller wall. Index 0, height 1, is never the taller one, so it never moves. right walks in from 8 to 1, and every area it produces is width × 1: 8, 7, 6, and so on down. The rule reports 8. The real answer is 49, and reaching it required retiring index 0.

Moving the taller wall gives up width without any chance of gaining height, because the shorter wall still sets the level. It can only lose. Moving both pointers at once has the same flaw plus skipped pairs.

Two smaller traps: using max instead of min for the height, and looping while left <= right instead of <, since a single line has zero width and is not a container.

STEP 8

Time and space

Each iteration does O(1) work and moves one pointer one step. The pointers start n − 1 apart and stop when they meet, so there are at most n − 1 iterations: O(n) time.

Two indices and one running best: O(1) space.

ApproachTimeSpace
Every pairO(n²)O(1)
Two pointers, move the shorterO(n)O(1)
STEP 9

The final solution

Eleven lines. Every one of them maps to a step above.

  • left, right = 0, len(height) - 1 starts at the widest container.
  • area = (right - left) * min(...) is width times the shorter wall.
  • if area > best keeps the running maximum.
  • if height[left] < height[right]: left += 1 else: right -= 1 retires the shorter line.
  • return best after the pointers meet.
One-line summary to remember: start at the ends and always move the shorter wall.
