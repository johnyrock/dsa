Min Stack, narrated

Scroll through the thinking, from scanning the whole stack on every getMin to a second stack that remembers each minimum as it was set, with the contents of both stacks shown after every operation.

Pattern used Stack a parallel min_stack whose top is always the current minimum

STEP 1

The problem

Build a stack with the usual push, pop, and top, plus one extra query: get_min, the smallest value currently in the stack. All four operations must be O(1).

The ordinary operations are free with a Python list. The whole difficulty is get_min: the minimum changes as values come and go, and after a pop removes the current minimum, the previous minimum has to be recoverable instantly.

Running example: push(-2), push(0), push(-3), get_min() → -3, pop(), top() → 0, get_min() → -2.

The last call is the interesting one. After -3 leaves, the answer goes back to -2, a value that was pushed two operations earlier and never touched since.

STEP 2

First instinct: scan on demand

Keep one list. push, pop, and top are the list's own operations, and get_min just looks through everything.

def get_min(self):    return min(self.stack)

Correct, and O(n) per call. With 30,000 operations and a stack that grows to thousands of entries, the scans dominate everything else. The problem statement rules it out explicitly by requiring O(1).

A single current_min variable is the next thought, and it handles push fine: current_min = min(current_min, val). It fails on pop. When -3 leaves the running example, what should current_min become? The variable has forgotten that -2 was ever the minimum, and the only way to find out again is another scan.

STEP 3

Reframe: remember every minimum, in order

Look at when the minimum actually changes. It goes down only when a value at or below the current minimum is pushed. It goes back up only when that exact value is popped, and at that moment it returns to whatever it was just before that push.

That is last-in, first-out behaviour. The minimums form their own stack: each new minimum sits on top of the one it replaced, and popping it reveals the previous one.

Keep a second list, min_stack. Its top is always the minimum of the main stack. get_min becomes min_stack[-1], one read.

The invariant to hold onto: min_stack[-1] equals min(stack) after every operation. Both push and pop have to preserve it, and nothing else touches it.

STEP 4

The approach

  • push(val): always stack.append(val). Additionally min_stack.append(val) if min_stack is empty or val <= min_stack[-1].
  • pop(): stack.pop(), and if the value that came off equals min_stack[-1], also min_stack.pop().
  • top(): stack[-1].
  • get_min(): min_stack[-1].

The comparison in push is <=, not <. Duplicates of the current minimum must each get their own entry on min_stack, so that popping one copy does not steal the minimum from the other. Step 8 shows what goes wrong otherwise.

STEP 5

Trace it: push(-2), push(0), push(-3)

push(-2): the main stack gets -2. min_stack is empty, so -2 goes there too. Both stacks read [-2].

push(0): stack = [-2, 0]. Is 0 <= -2? No. So min_stack stays [-2]; pushing a larger value cannot change the minimum, and the second stack records nothing.

push(-3): stack = [-2, 0, -3]. Is -3 <= -2? Yes, so min_stack = [-2, -3]. A new minimum has been set, and the old one is preserved underneath it.

STEP 6

Trace it: get_min() → -3, then pop()

get_min() reads min_stack[-1] = -3. No scan, and it agrees with min([-2, 0, -3]).

pop() removes -3 from the main stack, leaving [-2, 0]. Now the check: is the popped value equal to min_stack[-1]? -3 == -3, so min_stack pops too and becomes [-2].

This is the moment the single-variable approach could not handle. Here the previous minimum was never lost; it was just sitting one slot lower.

STEP 7

Trace it: top() → 0, get_min() → -2

top() is stack[-1] = 0. The min_stack is not consulted.

get_min() is min_stack[-1] = -2, and indeed min([-2, 0]) = -2. The value resurfaced automatically because the pop that removed -3 also removed its entry from min_stack.

Seven operations, each a constant number of list reads and writes at the end of a list. The invariant min_stack[-1] == min(stack) held after every one.
STEP 8

Where this goes wrong: pop and the duplicate minimum

Popping only the main stack. If pop is just self.stack.pop(), the running example ends with stack = [-2, 0] but min_stack = [-2, -3]. The final get_min() returns -3, a value that is no longer in the stack, instead of -2. The second stack has to shrink in step with the first.

Strict comparison on push. With val < min_stack[-1], the sequence push(1), push(1), pop(), get_min() puts only the first 1 on min_stack. The pop removes a 1 that equals min_stack[-1], so min_stack empties, and get_min on a stack that still holds a 1 raises IndexError. With <= both copies are recorded and the second survives.

Comparing in pop with < or >. The only correct test is equality: a value that came off the main stack is on min_stack exactly when it equals the top there.

Two rules: push to min_stack on <=, and pop from min_stack on ==. Together they keep min_stack[-1] equal to the true minimum.
STEP 9

Time and space

Every operation touches only the ends of two lists: O(1) time each. The second stack holds at most one entry per pushed value, so the structure is O(n) space, which is what a stack of n elements costs anyway.

Approachget_minpush / popExtra space
Scan with min(stack)O(n)O(1)O(1)
Single current_min variableO(1)pop is O(n) to recover the old minimumO(1)
Parallel min_stackO(1)O(1)O(n) worst case

The worst case for space is values arriving in non-increasing order, when every push lands on min_stack and it mirrors the main stack exactly. Values arriving in increasing order leave it with a single entry.

STEP 10

The final solution

The whole class, line by line.

  • self.stack = [] and self.min_stack = []: the values, and the history of minimums.
  • self.stack.append(val): every push lands on the main stack.
  • if not self.min_stack or val <= self.min_stack[-1]: self.min_stack.append(val): record a new (or tied) minimum.
  • if self.stack.pop() == self.min_stack[-1]: self.min_stack.pop(): retire the minimum when the value that set it leaves.
  • return self.stack[-1] for top, return self.min_stack[-1] for get_min: both single reads.
One-line summary to remember: the minimums change in stack order, so keep them on a stack of their own and read its top.
