Longest Common Subsequence, narrated

Scroll through the thinking, from trying every subsequence to filling a table of prefix answers one cell at a time, with the state of the algorithm shown alongside.

Pattern used Dynamic Programming 2-D prefix table: match extends the diagonal, mismatch takes the better neighbour

STEP 1

The problem

You get two strings. A subsequence keeps some of a string's characters in their original order and deletes the rest; it does not have to be contiguous. "ace" is a subsequence of "abcde" because you can delete the b and the d.

Return the length of the longest subsequence that both strings share. Only the length is asked for, not the characters themselves.

Running example: text1 = "abcde", text2 = "ace". The answer is 3: "ace" appears in both, and nothing longer can, because text2 only has three characters.

The tricky part is that a common subsequence can skip different characters in each string. The c in text1 is at index 2 and the c in text2 is at index 1; they still line up.

STEP 2

First instinct: try every subsequence

Every subsequence of text1 is a choice of which characters to keep, so there are 2^m of them. Generate each one and check whether it is a subsequence of text2 with a single two-pointer scan.

best = 0for mask in range(1 << m):    sub = [text1[i] for i in range(m) if mask >> i & 1]    j = 0    for ch in text2:        if j < len(sub) and sub[j] == ch:            j += 1    if j == len(sub):        best = max(best, len(sub))

That is O(2^m · n). At the constraint limit of 1000 characters, 2^1000 is not a number a computer will ever count to. The recursion that compares last characters, lcs(i, j) branching into lcs(i-1, j) and lcs(i, j-1), has the same problem: it re-solves the same (i, j) pair an exponential number of times.

STEP 3

The key idea: answers for prefixes, in a table

Only (m + 1) × (n + 1) different subproblems exist: "the LCS of the first i characters of text1 and the first j characters of text2". Call that dp[i][j]. Solve each one exactly once, smallest prefixes first.

Look at the last character of each prefix, text1[i - 1] and text2[j - 1]:

  • If they are equal, pair them up as the last character of a common subsequence. Everything before them is a common subsequence of the two shorter prefixes, so dp[i][j] = dp[i - 1][j - 1] + 1.
  • If they differ, they cannot both be in the answer. Drop one of them: dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]).
Row 0 and column 0 are the base case: a prefix of length 0 is empty and shares nothing, so those cells are 0. Building the table with an extra row and column means the recurrence never has to look outside the table.
STEP 4

The approach, line by line

  • m, n = len(text1), len(text2) sizes the table.
  • dp = [[0] * (n + 1) for _ in range(m + 1)] allocates it with the zero row and column already in place.
  • for i in range(1, m + 1) and for j in range(1, n + 1) visit the cells in row-major order, so the cell above, the cell to the left and the diagonal are always filled before they are read.
  • if text1[i - 1] == text2[j - 1] compares the last character of each prefix. The - 1 is the shift between "prefix of length i" and "index of its last character".
  • Match: dp[i][j] = dp[i - 1][j - 1] + 1. Mismatch: dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]).
  • return dp[m][n], the cell for the two full strings.
STEP 5

Trace it: the first row

Row 1 is the prefix "a". Cell dp[1][1] compares text1[0] = a with text2[0] = a: a match, so dp[1][1] = dp[0][0] + 1 = 0 + 1 = 1.

Cell dp[1][2] compares a with c: mismatch, so it takes max(dp[0][2], dp[1][1]) = max(0, 1) = 1. The 1 carries to the right: once you have matched an a, adding more of text2 never makes the answer smaller. dp[1][3] (a vs e) is 1 for the same reason.

Row 2, the prefix "ab", has no b to match in "ace", so every cell is a mismatch and copies the best of above and left: 1, 1, 1.

STEP 6

Trace it: the second match

Row 3 is the prefix "abc". dp[3][1] compares c with a: mismatch, max(dp[2][1], dp[3][0]) = max(1, 0) = 1.

Now dp[3][2] compares text1[2] = c with text2[1] = c. Match: dp[3][2] = dp[2][1] + 1 = 1 + 1 = 2. The diagonal cell dp[2][1] is the LCS of "ab" and "a", which is the 1 from the earlier a; the c extends it to "ac".

Notice the two matches sit in different columns of the two strings (c is index 2 in text1, index 1 in text2). The mismatch rule's max is what carried the 1 across the gap so that the diagonal could pick it up.

STEP 7

Trace it: the last cell is the answer

Row 4, "abcd", adds nothing: d matches no character of "ace", so the row copies 1, 2, 2 from above.

Row 5, the full string "abcde". The last cell dp[5][3] compares text1[4] = e with text2[2] = e: match, so dp[5][3] = dp[4][2] + 1 = 2 + 1 = 3. That diagonal cell is the LCS of "abcd" and "ac", which is 2, and the e completes "ace".

Every cell was computed once from three neighbours that were already final. The function returns dp[5][3] = 3.
STEP 8

Where this goes wrong: the mismatch rule

Moving only along the diagonal. Writing the mismatch branch as dp[i][j] = dp[i - 1][j - 1] looks symmetric and tidy, but it means a cell can only inherit from the cell up-and-left. The 1 earned at dp[1][1] can then never reach dp[2][1], so the c match at dp[3][2] starts from 0 instead of 1, and the whole table degrades into a diagonal of single matches. The final cell comes out as 1, not 3. The max(dp[i - 1][j], dp[i][j - 1]) is what lets the two strings skip different characters.

Indexing the strings with i instead of i - 1. Row i is the prefix of length i, and its last character is text1[i - 1]. Comparing text1[i] == text2[j] shifts every match by one cell and returns 2 on the running example (after a guard is added to stop the IndexError on the last row).

Two transitions, not one: a match extends the diagonal, a mismatch takes the better of the cell above and the cell to the left. Check with "bl", "yby": the answer must be 1, from a b in different positions.
STEP 9

Time and space

The table has (m + 1)(n + 1) cells and each takes constant work, so O(m × n) time. At the limit that is a million cells, which is fine. The table is also O(m × n) space; since a row only reads the row above, two rows of length n + 1 are enough for O(min(m, n)) space if you swap the strings so the shorter one runs along the columns.

ApproachTimeSpace
Every subsequence of text1O(2^m · n)O(m)
Recursion + memoizationO(m × n)O(m × n) cache + stack
Bottom-up tableO(m × n)O(m × n)
Bottom-up, two rowsO(m × n)O(min(m, n))

Memoization fixes the exponential blow-up; the bottom-up loop removes the recursion and makes the space reduction possible.

STEP 10

The final solution

Ten lines. Every one of them maps to a step above.

  • m, n = len(text1), len(text2) — the two prefix lengths.
  • dp = [[0] * (n + 1) for _ in range(m + 1)] — the table with its zero row and column.
  • The two for loops fill it in row-major order, starting at 1.
  • if text1[i - 1] == text2[j - 1] — compare the last character of each prefix.
  • dp[i][j] = dp[i - 1][j - 1] + 1 — a match extends the diagonal.
  • dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]) — a mismatch drops one character.
  • return dp[m][n] — the answer for the full strings.
One-line summary to remember: if the last characters match, extend the diagonal by one; otherwise take the better of dropping either one.
