Medium · Hash Map · LeetCode #2013

Detect Squares, narrated

I’ll start by checking triples of stored points, then use the diagonal corner to determine the other two.

Pattern used Hash Map a counter keyed by (x, y); the diagonal corner fixes the other two, so count = n(diag) × n(x, py) × n(px, y)

STEP 1

The problem

Build a class with two operations. add(point) stores a point on the integer grid, and the same point may be stored several times. count(point) asks: using this query point as one corner, how many axis-aligned squares of positive area can be completed from the stored points?

Copies matter. If a corner was stored twice, every square through it is counted twice, because each copy is a different way of choosing that corner.

Running example: add([3,10]), add([11,2]), add([3,2]), then count([11,10]) → 1, count([14,8]) → 0, then add([11,2]) again and count([11,10]) → 2.

"Axis-aligned" means the sides are horizontal and vertical, so the four corners share x-coordinates in pairs and y-coordinates in pairs. That constraint is what makes the problem tractable.

STEP 2

First instinct: try every triple of stored points

My first instinct is to keep every added point in a list. On count, I pick three stored points and test whether they and the query form a square.

for a in points:    for b in points:        for c in points:            if is_square(query, a, b, c):                total += 1

With k stored points, this takes O(k³) time per query and O(1) extra space beyond the stored list. It is far too slow for thousands of operations.

The corners are not independent. Once I choose the diagonal corner, the other two corners are fixed.

STEP 3

Key insight: the diagonal corner fixes the other two

I take the query (px, py) and suppose its diagonally opposite corner is a stored point (x, y). For an axis-aligned square that diagonal must span the same distance in x as in y, so abs(x - px) == abs(y - py), and that distance must be non-zero, so x != px.

Once those two corners are fixed there is no freedom left: the remaining corners are (x, py), which shares the query's y, and (px, y), which shares the query's x.

On the example with query (11, 10), the stored point (3, 2) is 8 away in x and 8 away in y, so it is a valid diagonal. The other two corners must be (3, 10) and (11, 2), both stored.

So the triple loop collapses to a single loop over candidate diagonals, and each candidate needs two dictionary lookups. Storing the points in a counter count_at[(x, y)] gives both the loop and the lookups.

STEP 4

The approach, line by line

  • self.count_at = defaultdict(int) — copies per point; a missing point reads as 0.
  • add: self.count_at[(point[0], point[1])] += 1.
  • count: I unpack px, py = point and start total = 0.
  • Loop for (x, y), n in self.count_at.items(), treating each stored point as a candidate diagonal.
  • if x == px or abs(x - px) != abs(y - py): continue — reject zero-size and non-square offsets.
  • total += n * self.count_at[(x, py)] * self.count_at[(px, y)] — copies of the diagonal times copies of the two side corners.

The panel shows the counter as chips and the grid as a scatter. After the first three adds the map holds (3,10), (11,2), (3,2), one copy each.

STEP 5

Trace it: count([11, 10]) → 1

The query is px = 11, py = 10. I walk the three stored points as diagonal candidates:

  • (3, 10): abs(3 - 11) = 8 but abs(10 - 10) = 0. They are not equal, so I skip it.
  • (11, 2): x == px, so I skip it.
  • (3, 2): abs(3 - 11) = 8 and abs(2 - 10) = 8. A valid diagonal.

For that diagonal the side corners are (x, py) = (3, 10) and (px, y) = (11, 2). The product is 1 × 1 × 1 = 1, so total = 1.

STEP 6

Trace it: count([14, 8]) → 0

Now px = 14, py = 8. Nothing lines up:

  • (3, 10): abs(3 - 14) = 11, abs(10 - 8) = 2, so I skip it.
  • (11, 2): abs(11 - 14) = 3, abs(2 - 8) = 6, so I skip it.
  • (3, 2): abs(3 - 14) = 11, abs(2 - 8) = 6, so I skip it.

No candidate survives the filter, so I never run the multiplication line and total stays 0. I do not need to look up side corners at all.

STEP 7

Trace it: add([11, 2]) again, then count([11, 10]) → 2

The second add([11, 2]) bumps count_at[(11, 2)] from 1 to 2. The map still has three keys; only a count changed.

Repeat the query (11, 10). The candidates are the same three keys and, as before, only (3, 2) passes. This time the product is n(3,2) × n(3,10) × n(11,2) = 1 × 1 × 2 = 2.

Geometrically it is the same square drawn twice, once with each copy of the corner (11, 2). The counter, not the geometry, is what makes duplicates work.

The loop runs over distinct keys, so duplicates never add iterations. They only scale the product.
STEP 8

Where this goes wrong: sets, and the zero-size square

Storing points in a set. Replace the counter with self.points = set() and duplicates vanish. The example's last query then returns 1 instead of 2, because the second copy of (11, 2) was never recorded.

Dropping the x == px guard. If the query point is itself stored, it passes abs(0) == abs(0) and is counted as its own diagonal, contributing n × n × n squares of side 0. If I add (11, 10) once to the example, count([11, 10]) returns 3 instead of 2.

Checking only that x and y differ. The condition x != px and y != py accepts any rectangle: add([0,0]), add([1,2]), add([0,2]), count([1,0]) returns 1 instead of 0.

A diagonal needs equal, non-zero offsets in both axes: abs(x - px) == abs(y - py) and x != px. And keep counts, not membership.
STEP 9

Time and space

add is a single dictionary increment, O(1). count walks every distinct stored point once and does two O(1) lookups for each survivor, so it is O(k) for k distinct points. Space is the counter, O(k).

ApproachaddcountSpace
List + triple loopO(1)O(k³)O(k)
Counter, diagonal candidatesO(1)O(k)O(k)
Counter indexed by x (follow-up)O(1)O(points sharing x)O(k)

With at most 3000 operations, k is at most 3000 and each count is a few thousand cheap iterations.

STEP 10

The final solution

  • self.count_at = defaultdict(int) — the counter; a missing corner multiplies the term to 0.
  • self.count_at[(point[0], point[1])] += 1 — add is one increment.
  • for (x, y), n in self.count_at.items() — every stored point is a candidate diagonal.
  • if x == px or abs(x - px) != abs(y - py): continue — equal non-zero offsets only.
  • total += n * self.count_at[(x, py)] * self.count_at[(px, y)] — three counts multiplied.
One-line summary to remember: I pick the diagonal corner, the other two are forced, and I multiply the copies of all three.
