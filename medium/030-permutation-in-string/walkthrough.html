Permutation in String, narrated

I’ll start by sorting every candidate window, then slide a fixed-width letter-count window across the text.

Pattern used Sliding Window fixed width len(s1); I add the entering letter, I drop the leaving one, I compare 26 counts

STEP 1

The problem

You get two strings. Return True if some contiguous substring of s2 is a permutation of s1, meaning it uses exactly the same letters the same number of times, in any order.

Two facts fall out of the definition immediately. Any permutation of s1 has exactly len(s1) characters, and order inside it does not matter, only the multiset of letters.

Running example: s1 = "ab", s2 = "eidbaooo". The answer is True, because the substring "ba" at positions 3–4 is a rearrangement of "ab".

The second example, s2 = "eidboaoo", contains both an a and a b but they are never adjacent, so it is False. Presence is not enough; the letters have to fit inside one window.

STEP 2

First instinct: sort every substring

My first instinct is to sort s1, then I sort every same-length slice of s2 and compare the sorted forms.

key = sorted(s1)for i in range(len(s2) - len(s1) + 1):    if sorted(s2[i:i + len(s1)]) == key:        return Truereturn False

With window width k, it takes O(n · k log k) time and uses O(k) extra space for each sorted window.

Neighboring windows differ by one entering and one leaving character. I keep 26 counts and update only those two positions as the window moves.

STEP 3

Reframe: count letters, and slide instead of restarting

Sorting is an expensive way to ask "do these have the same letters?" A 26-slot array of counts answers the same question, and unlike a sorted string it can be updated cheaply.

When the window moves one step right, one character enters on the right and one leaves on the left. Increment one counter, decrement another, and the array is correct again. No re-scan of the middle.

The window's width never changes: it is always len(s1). That is what makes this a fixed-width sliding window, simpler than the grow-and-shrink kind.

Comparing two 26-slot lists is 26 comparisons, a constant, so checking for a match after every slide is essentially free.

STEP 4

The approach

  • k = len(s1), and if k > len(s2) no window can exist, so return False.
  • need: 26 counts filled from s1. For "ab" that is a:1, b:1.
  • window: 26 counts of whatever is currently inside the window, all zero to start.
  • For each index i in s2: window[ord(ch) - ord("a")] += 1 adds the entering character.
  • if i >= k: the character at i - k just fell off the left edge, so decrement its count.
  • if window == need: return True. After the loop, return False.

The panel marks the window in green with the newest character in blue, and shows the two count arrays as chips, non-zero entries only.

STEP 5

Trace it: i = 0 and i = 1, the window fills up

At i = 0 the character is e. It enters: window = {e:1}. Since 0 >= 2 is false, nothing leaves yet. I compare with need = {a:1, b:1}: no match.

At i = 1 the character is i: window = {e:1, i:1}. Still 1 >= 2 is false, so the window has grown to its full width of 2 for the first time. I compare: no match.

From here on, every step will both add and remove one character, so the window stays exactly 2 wide.

STEP 6

Trace it: i = 2 and i = 3, the window slides

At i = 2 the character d enters. Now 2 >= 2 is true, so s2[i - k] = s2[0] = 'e' leaves: window = {i:1, d:1}. No match.

At i = 3, b enters and s2[1] = 'i' leaves: window = {d:1, b:1}. I now have one of the two letters I need, but d is in the way. No match.

Each step was two array updates and one 26-slot comparison, regardless of how long the strings are.

STEP 7

Trace it: i = 4, the counts line up

At i = 4, a enters and s2[2] = 'd' leaves: window = {b:1, a:1}. That is exactly need = {a:1, b:1}, and since both are 26-slot lists indexed by letter, the order the letters arrived in is invisible. window == need is True, so I return True.

The window covering "ba" matched "ab" without any sorting. Five characters examined, five constant-time checks.
STEP 8

Where this goes wrong: the off-by-one on the leaving character

Removing one step late. I write if i > k instead of if i >= k. At i = 2 the e is not removed, so the window holds three characters from then on: at i = 4 it is {a:1, b:1, e:1}, which never equals a two-letter signature. The running example returns False instead of True, and so does every other input where k < len(s2).

Removing the wrong index. s2[i - k + 1] instead of s2[i - k] evicts the character that should stay. The window shrinks to k - 1 letters and can never match either.

Comparing sets instead of counts. set(window) == set(s1) says "abb" is a permutation of "aab". Multiplicity is part of the definition, which is why the panel shows counts rather than letters.

The window at index i covers s2[i - k + 1 .. i], so the character that just left is s2[i - k], and it exists as soon as i >= k.
STEP 9

Time and space

One pass over s2, and each step does one increment, at most one decrement, and a 26-slot comparison: O(26 · n) = O(n) time. Two count arrays of fixed size 26: O(1) space.

ApproachTimeSpace
Sort every windowO(n · k log k)O(k)
Recount every windowO(n · k)O(1)
Sliding counts, compare 26 slotsO(26 · n)O(1)
Sliding counts + matches counterO(n)O(1)

The last row keeps a single integer counting how many of the 26 slots currently agree and adjusts it as letters enter and leave, so the per-step comparison becomes O(1). It is a worthwhile refinement to mention, but the 26-slot compare is already linear and much easier to get right.

STEP 10

The final solution

Every line maps to a step above.

  • if k > len(s2): return False rules out an impossible window before doing any work.
  • need[ord(ch) - ord("a")] += 1 over s1 builds the signature to match.
  • window[ord(ch) - ord("a")] += 1 adds the character entering on the right.
  • if i >= k: window[ord(s2[i - k]) - ord("a")] -= 1 drops the one that fell off the left.
  • if window == need: return True is the constant-time permutation test.
  • return False after the loop: no window ever matched.
One-line summary to remember: a permutation is a multiset of letters, so slide a window of width len(s1) and compare counts, not order.
