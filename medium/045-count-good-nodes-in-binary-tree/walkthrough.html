Count Good Nodes in Binary Tree, narrated

Scroll from re-walking every root-to-node path to a single depth-first pass that carries the path maximum downward, with the running maximum and each node's verdict shown alongside.

Pattern used Tree Pass the largest ancestor value down as a parameter; a node is good when it is at least that large.

STEP 1

The problem

Given the root of a binary tree, a node X is called good if no node on the path from the root down to X has a value greater than X.val. Equal values are allowed: a node that ties the largest ancestor is still good. Return how many good nodes the tree has.

Running example: root = [3,1,4,3,null,1,5] in level order. Node 3 has children 1 and 4; node 1 has a single left child 3; node 4 has children 1 and 5. The answer is 4.

Check it by hand. The root 3 has nothing above it, so it is good. The 4 has only 3 above it, and 4 >= 3, so it is good. The deeper 3 sits under the path 3, 1, whose largest value is 3, and 3 >= 3 holds, so it is good too. The 5 sits under 3, 4 and clears both. The two 1s are the only nodes that fail: each has a 3 (and one of them a 4) above it.

The question is about paths, not siblings or subtrees. A huge value in the left subtree says nothing about whether a node in the right subtree is good, because the two are never on the same root-to-node path.

STEP 2

First instinct: re-walk the path for every node

Take the definition literally. For every node, find the path from the root to it, take the maximum value along that path, and compare. Since a tree has no parent pointers, the easy way to get each path is a DFS that keeps the current path in a list:

def brute(root):    count = 0    def walk(node, path):        nonlocal count        if node is None:            return        if node.val >= max(path + [node.val]):            count += 1        walk(node.left, path + [node.val])        walk(node.right, path + [node.val])    walk(root, [])    return count

This gives the right answer, but look at what each call does: it copies the path list (path + [node.val]) and then re-scans the whole list with max. For a node at depth d that is O(d) work, and on a chain-shaped tree the depths run 1, 2, 3, … n, so the total is 1 + 2 + … + n = O(n²). With 10⁵ nodes that is around five billion list operations for a question that needs one comparison per node.

The panel's [3,1] badge on the deeper 3 is the list this version would rebuild and re-scan just to answer "is anything above me bigger than 3?".

STEP 3

The key insight: the path collapses to one number

The brute force keeps the entire path only to call max on it. But the maximum of a path is easy to maintain incrementally: when you step from a parent to a child, the new maximum is max(old_max, child.val). You never need the list, only its running maximum.

Carry one integer, max_so_far, down the recursion as a parameter. A node is good when node.val >= max_so_far. Before recursing into the children, raise it: max_so_far = max(max_so_far, node.val).

Because it is a parameter, not a shared variable, each branch of the recursion gets its own copy. Raising it on the way into the left subtree does nothing to what the right subtree sees, which is exactly the "paths, not subtrees" rule from step 1. The panel shows the value each child will receive: both children of the root get 3.

The root itself has no ancestors. Seeding the parameter with float("-inf") makes the root's comparison 3 >= -inf succeed automatically, and it keeps working if every value in the tree is negative.

STEP 4

The approach: pre-order DFS with a passed-down maximum

The helper dfs(node, max_so_far) returns the number of good nodes in the subtree rooted at node, given that the largest value above it is max_so_far. Line by line:

  • if node is None: return 0 — an empty subtree contributes nothing; this also stops the recursion under the leaves.
  • count = 1 if node.val >= max_so_far else 0 — decide this node before touching the maximum, using only what the ancestors passed down.
  • max_so_far = max(max_so_far, node.val) — raise the bar for everything below.
  • return count + dfs(node.left, max_so_far) + dfs(node.right, max_so_far) — this node's verdict plus the two subtrees' totals.
  • return dfs(root, float("-inf")) — start with a bar nothing can fail.

The decision at each node is pre-order (made on the way down), but the counting is post-order (summed on the way up). Either way, every node is entered exactly once.

STEP 5

Trace it: the root and its left subtree

Call dfs(3, -inf). The root compares 3 >= -inf, which is true, so count = 1. Then max_so_far = max(-inf, 3) = 3, and both children will be called with 3.

Go left: dfs(1, 3). The check 1 >= 3 fails, so count = 0. The bar stays at max(3, 1) = 3; a small node cannot lower it. Its left child is the deeper 3: dfs(3, 3) checks 3 >= 3, which is true because equality counts, so count = 1. Both of its children are None and return 0, so the deeper 3 returns 1 + 0 + 0 = 1.

Back at the 1, its right child is None (the null in the level-order list), so it returns 0 + 1 + 0 = 1. The root now holds 1 from its left side and turns to the right.

STEP 6

Trace it: the right subtree

Go right from the root: dfs(4, 3). The check 4 >= 3 passes, so count = 1, and the bar rises to max(3, 4) = 4. Note that the deeper 3 on the left side never influenced this call: it received the root's 3, not anything from the sibling branch.

The 4's left child is a 1: dfs(1, 4), and 1 >= 4 fails, so it contributes 0 (its own children are None). The 4's right child is 5: dfs(5, 4), and 5 >= 4 passes, so it contributes 1.

The 4 returns 1 + 0 + 1 = 2. The panel marks the good nodes in green with a check badge and the two failed 1s in amber with a cross.

STEP 7

Trace it: summing up

The root has everything it needs: its own count = 1, 1 from the left subtree (the deeper 3), and 2 from the right subtree (the 4 and the 5). It returns 1 + 1 + 2 = 4, and good_nodes returns that as the answer.

Seven nodes, seven calls to dfs (plus the trivial None base cases), one comparison and one max each. The brute force from step 2 would have built and scanned a path list at every one of those seven nodes.

Compare against the hand check from step 1: good nodes 3, 3, 4, 5 and bad nodes 1, 1. The recursion agreed at every node, which is what you would expect since it evaluates the same definition, only without rebuilding the path.

STEP 8

Where this goes wrong

Using a strict comparison. Write node.val > max_so_far instead of >= and the deeper 3 fails its check: 3 > 3 is false. The root still counts because 3 > -inf, but the answer drops to 3 instead of 4. The problem statement says "no node with a value greater than", and ties are not greater.

Seeding with 0. dfs(root, 0) looks harmless on this example, since every value is positive. On a tree like [-1,-2,-3] the root compares -1 >= 0, fails, and the function returns 0. The root is always good, so 0 is never a valid answer for a non-empty tree. Seed with float("-inf"), or with root.val.

Sharing the maximum instead of passing it. Keeping max_so_far as a single nonlocal variable that is raised but never lowered means the bar set in the left subtree leaks into the right one. On [1,10,2] the 10 raises the bar, and then the 2 is compared against 10 and fails, giving 2 instead of 3. Passing the value as a parameter makes each path independent for free.

The bar a node is measured against must come only from its own ancestors. Decide the node with the inherited value, then raise it for the children, and let the parameter scoping handle the rest.
STEP 9

Time and space

Every node is entered once and does a comparison, a max, and two additions, so the time is O(n). There is no way to do better: a node's verdict depends on its value, so every node must be looked at.

The recursion stack is as deep as the tree is tall, O(h). For a balanced tree that is about log n; for a chain it is n, and with the 10⁵-node constraint Python's default recursion limit of 1000 matters. An explicit stack of (node, max_so_far) pairs gives the same O(n) time without the limit.

ApproachTimeSpace
Rebuild and scan the path at every nodeO(n²) on a chain, O(n log n) balancedO(h) path list + stack
Pass the path maximum downO(n)O(h) call stack
STEP 10

The final solution

One nested helper with a single extra parameter. Line by line:

  • def dfs(node, max_so_far): — returns the good-node count of this subtree given the largest ancestor value.
  • if node is None: return 0 — nothing to count below a missing child.
  • count = 1 if node.val >= max_so_far else 0 — the verdict, with >= so ties count.
  • max_so_far = max(max_so_far, node.val) — raise the bar for the children only; the sibling call keeps its own copy.
  • return count + dfs(node.left, max_so_far) + dfs(node.right, max_so_far) — sum the verdicts on the way back up.
  • return dfs(root, float("-inf")) — the root has no ancestors, so nothing can beat it.
One-line summary to remember: carry the largest ancestor value down the recursion; a node is good when it is at least that large.
