Medium · Two Pointers · LeetCode #3163

String Compression III, narrated

I’ll start by doing literally what the statement says, slicing prefixes off a shrinking string, then replace the slicing with two pointers that measure each run where it sits.

Pattern used Two Pointers same-direction: i marks the run start, j walks to its end

STEP 1

The problem

I am given a string word of lowercase letters and asked to compress it. The rule is mechanical: while the string is not empty, remove the longest prefix made of one repeated character, but never more than 9 copies at once, and append the prefix's length followed by that character to the result.

So this is run-length encoding with two twists. The count comes before the character, and every count is a single digit, because a run longer than 9 is cut into pieces of 9 with a remainder.

Running example: word = "aabbdd". The runs are "aa", "bb", "dd", so the answer is "2a2b2d".

A run of length 1 still gets written with its count: "abcde" becomes "1a1b1c1d1e". The output is the compressed string itself, not its length.

STEP 2

First instinct: do what the statement says

The statement describes a loop, so my first version is that loop. Count how many copies of word[0] sit at the front, capped at 9, append the piece, and slice the prefix off.

def compressed_string(word):    comp = ""    while word:        k = 0        while k < len(word) and k < 9 and word[k] == word[0]:            k += 1        comp += str(k) + word[0]        word = word[k:]    return comp

It returns the right string. The cost is hidden in word = word[k:]: every slice copies the whole remainder. On "aabbdd" that is copies of length 4, then 2, then 0. On a string with no repeated neighbours it is n copies of average length n/2, so the loop is O(n²) time. Building comp with += can copy the growing result too.

The counting part was already right. Only the slicing is wasteful, because I do not need to move the string to remember where the next run starts.

STEP 3

The key insight: measure the run in place with two pointers

Instead of trimming the string, I keep an index i for where the current run starts and a second index j that walks forward while word[j] == word[i]. When it stops, the run is word[i:j] and its length is j - i.

The cap of 9 becomes one more condition on the inner loop: j - i < 9. When a run reaches 9, the loop stops early, I emit the piece, and the next run starts at j with the same character. That is exactly what "remove at most 9 at a time" asks for, without a special case.

Both pointers only move forward, and j visits every index once. The whole scan is one pass.

For the output I collect the pieces in a list parts and call "".join(parts) once at the end, so building the result is linear too.

STEP 4

The approach, line by line

  • parts = [] and i = 0: no pieces yet, first run starts at index 0.
  • while i < len(word): one iteration per emitted piece.
  • j = i, then while j < len(word) and word[j] == word[i] and j - i < 9: j += 1: extend the run while in bounds, same character, and fewer than 9 so far.
  • parts.append(str(j - i) + word[i]): count first, then the character.
  • i = j: the next run starts where this one stopped.
  • return "".join(parts).

The bounds check j < len(word) comes first in the condition, so word[j] is never read past the end.

STEP 5

Trace it: the run of a's

I start with i = 0 and j = 0. word[0] is 'a', which equals word[i], and j - i = 0 < 9, so j becomes 1. word[1] is also 'a' and 1 < 9, so j becomes 2. word[2] is 'b', which is not 'a', so the inner loop stops.

The run is word[0:2] = "aa", length j - i = 2 - 0 = 2. I append str(2) + 'a' = "2a" to parts and set i = j = 2.

Nothing was copied. The two a's are still in the string; I just know I am done with them.

STEP 6

Trace it: b's, d's, and the answer

Now i = 2, word[i] = 'b'. j walks from 2 to 4 over the two b's and stops at word[4] = 'd'. Length 4 - 2 = 2, piece "2b", then i = 4.

From i = 4, j walks over the two d's and reaches 6, which equals len(word), so the bounds check ends the inner loop. Length 6 - 4 = 2, piece "2d", then i = 6.

The outer loop's test i < len(word) is now 6 < 6, false. parts holds ["2a", "2b", "2d"], and the join returns "2a2b2d".

STEP 7

Trace it: a run longer than 9

The cap only shows up on a long run, so switch to word = "aaaaaaaaaaaaaabb": fourteen a's and two b's. From i = 0, j walks over a's until j = 9. Then word[9] is still 'a', but j - i = 9, so 9 < 9 is false and the loop stops early.

I emit "9a" and set i = 9. The character at i is 'a' again, so the next run is the remaining five a's: j walks to 14 and stops at 'b', giving "5a". The last run is "2b".

Result: "9a5a2b". Cutting at 9 needed no extra code path, only the third condition in the inner while.
STEP 8

Where this goes wrong: the order, the cap, and the reset

Three small mistakes, each easy to type and easy to miss.

Writing the character first. LeetCode's String Compression I writes "a2", so the habit is strong. With parts.append(word[i] + str(j - i)) the running example returns "a2b2d2" instead of "2a2b2d". Every test with a repeated character fails.

Dropping the cap. Without j - i < 9, fourteen a's come out as "14a", so "aaaaaaaaaaaaaabb" returns "14a2b" instead of "9a5a2b". The close cousin j - i <= 9 allows runs of 10 and returns "10a4a2b".

Forgetting i = j. Then i stays at 0, the inner loop re-measures the same run forever, and the function never returns.

Say the piece out loud before typing it: count, then character. And check the cap with a run of exactly 9, exactly 10, and 18.
STEP 9

Time and space

j moves forward on every inner-loop step and never moves back, and i jumps to j, so together they touch each index a constant number of times. That is O(n) time. The pieces list holds at most one two-character string per run, so O(n) space for the output, and nothing else grows.

ApproachTimeSpace
Slice the prefix off each runO(n²)O(n) copies
Two pointers, comp += pieceO(n²) worst caseO(n)
Two pointers, list + one joinO(n)O(n) output

The middle row usually runs fast in CPython because += on a string with one reference is resized in place, but that is an implementation detail. The list and single join are linear by contract.

STEP 10

The final solution

Nine lines inside the method. Each one maps to a step above.

  • parts = [] collects the pieces so the result is built once.
  • i = 0 is the start of the current run.
  • while i < len(word) runs once per piece and stops when the runs are used up.
  • j = i starts the second pointer at the run's first character.
  • while j < len(word) and word[j] == word[i] and j - i < 9: j += 1 extends the run: in bounds, same character, fewer than 9.
  • parts.append(str(j - i) + word[i]) writes the count, then the character.
  • i = j hands the next iteration the start of the next run.
  • return "".join(parts).
I remember this as: i marks the run, j measures it, and the cap of 9 is just a third condition on j.
