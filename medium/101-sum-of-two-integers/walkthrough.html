Sum of Two Integers, narrated

I’ll start by incrementing one step at a time, then use XOR and shifted carries to add all bits together.

Pattern used Bit Manipulation a ^ b is the sum without carries, (a & b) << 1 is the carries; repeat until the carry is 0

STEP 1

The problem

Return a + b for two integers, but the operators + and - are off limits. Everything else is allowed: comparisons, loops, and the bitwise operators ^, &, |, ~, <<, >>.

Running example: a = 5, b = 3. The answer is 8. In binary, 101 + 011 = 1000.

The inputs are small, between −1000 and 1000, so the sum always fits comfortably in 32 bits. The negative range is the part that matters: the bitwise trick is easy for positive numbers and needs one extra idea for negatives, especially in Python.

The panel shows the low 8 of 32 bits for each value; the upper 24 bits are zero for the running example.

STEP 2

First instinct: increment one at a time

Incrementing has a bitwise form: I flip trailing 1s to 0 and the first 0 to 1. My first instinct is to add b by incrementing a that many times.

def increment(x):    mask = 1    while x & mask:        x ^= mask        mask <<= 1    return x | maskfor _ in range(b):    a = increment(a)

For b = 3, I do three increments. This takes O(|b|) time and O(1) space, and it needs a matching decrement path when b is negative.

All 32 bit positions can be processed together. I treat addition as a loop over carries, not a loop over b.

STEP 3

Key insight: a sum is XOR plus carries

I look at one bit position. Adding two bits gives 0 + 0 = 0, 0 + 1 = 1, 1 + 0 = 1, and 1 + 1 = 0 carry 1. The result bit is exactly a ^ b. The carry bit is exactly a & b, and it belongs one position to the left, so the carries as a number are (a & b) << 1.

So a + b = (a ^ b) + ((a & b) << 1). That still has a + in it, but the two terms are themselves just numbers, so apply the same identity to them, and again, until the carry term is 0.

On the example: 5 ^ 3 = 6 (101 ^ 011 = 110) and (5 & 3) << 1 = 1 << 1 = 2. Sure enough, 6 + 2 = 8. I then add 6 and 2 the same way.

Why does it terminate? Every round shifts the carry left by at least one bit. In a 32-bit register the carry falls off the top after at most 32 rounds. That last clause is the catch for Python, which is the subject of Step 7.

STEP 4

The approach, line by line

  • MASK = 0xFFFFFFFF — 32 one bits. x & MASK keeps only the low 32 bits, imitating a register.
  • MAX_INT = 0x7FFFFFFF — the largest value whose bit 31 is clear; anything above it is a negative number in two's complement.
  • while b != 0: — keep going while there are carries to add.
  • a, b = (a ^ b) & MASK, ((a & b) << 1) & MASK — the partial sum and the carries, both trimmed to 32 bits.
  • return a if a <= MAX_INT else ~(a ^ MASK) — hand back the register value, converting it to a negative Python int if bit 31 is set.

For the running example, a = 5 = 00000101 and b = 3 = 00000011 at the start.

STEP 5

Trace it: round 1, a = 5, b = 3

Bit by bit: 00000101 ^ 00000011 = 00000110, which is 6. Only bit 0 is set in both, so 00000101 & 00000011 = 00000001, and shifting left gives 00000010, which is 2.

After the assignment a = 6, b = 2. The masks change nothing here because every value is far below 2³².

I check the invariant: a + b is still 6 + 2 = 8. Each round rewrites the pair without changing its sum; only the carry term gets smaller in the sense that it moves left.

STEP 6

Trace it: rounds 2 to 4, the carry marches left

Round 2: a = 6 = 00000110, b = 2 = 00000010. XOR gives 00000100 = 4; both share bit 1, so the carry is 00000010 << 1 = 00000100 = 4. Now a = 4, b = 4.

Round 3: 00000100 ^ 00000100 = 0 and the carry is (4 & 4) << 1 = 8. Now a = 0, b = 8. The entire sum lives in the carry term for a moment.

Round 4: 0 ^ 8 = 8, and 0 & 8 = 0, so the carry is finally 0. The loop condition b != 0 fails and a = 8 = 00001000 is the answer.

Four rounds, because the carry started at bit 1 and had to travel to bit 3. The number of rounds is the distance the longest carry chain has to ripple, at most 32.
STEP 7

The Python catch: negatives and the 32-bit mask

In Java or C++ an int is 32 bits, so a carry shifted past bit 31 simply disappears and the loop always ends. Python integers are unbounded: -3 is conceptually an infinite string of 1s followed by ...11101. Shift a carry left forever and it never falls off, so b never becomes 0.

& MASK fixes that by chopping every value to its low 32 bits. Trace a = -3, b = 1: masked, a is 0xFFFFFFFD (low 8 bits 11111101). Round 1: XOR gives 11111100, the carry is 00000010. Round 2: XOR gives 11111110, carry 0. Done, with a = 0xFFFFFFFE.

But 0xFFFFFFFE is 4294967294 as a Python int, not −2. Bit 31 is set, which in two's complement means negative, so the register value must be translated back. a > MAX_INT detects it, and ~(a ^ MASK) does the conversion: a ^ MASK flips the 32 bits to 00000001, and ~1 is -2.

The mask has two jobs: I keep the loop finite on negative inputs, and I mark the answer as a 32-bit register value that the last line reads back as signed.
STEP 8

Where this goes wrong: the shift, the mask, the unmask

Forgetting << 1 on the carry. If I write b = (a & b) & MASK, the carry is added back into the same bit it came from. On the example, round 1 gives a = 6, b = 1, round 2 gives a = 7, b = 0, and the function returns 7 instead of 8.

Dropping & MASK. Every positive test passes, then get_sum(-2, 3) hangs: the carry 1 << 32, 1 << 33, … never reaches 0 in an unbounded integer.

Returning a unconditionally. get_sum(-3, 1) returns 4294967294, the unsigned reading of 0xFFFFFFFE, instead of −2.

Carries move left, so the shift is not optional. Mask both terms every round, and read the final register back as signed with ~(a ^ MASK), which uses no -.
STEP 9

Time and space

Each round moves the lowest carry bit at least one position left, and the mask caps the register at 32 bits, so the loop runs at most 32 times regardless of the inputs. That is O(1) time, and there are only two integers of state, O(1) space.

ApproachTimeSpace
Increment |b| timesO(|b|)O(1)
XOR / AND-shift loop, fixed-width languageO(1), ≤ 32 roundsO(1)
XOR / AND-shift loop with MASK in PythonO(1), ≤ 32 roundsO(1)

The worst case is a carry that has to ripple all the way, such as -1 + 1: 32 rounds, each shifting a single 1 bit left until it leaves the register.

STEP 10

The final solution

  • MASK = 0xFFFFFFFF and MAX_INT = 0x7FFFFFFF — the register width and the signed/unsigned boundary.
  • while b != 0: — loop while a carry remains.
  • a, b = (a ^ b) & MASK, ((a & b) << 1) & MASK — sum without carries, and the carries, both trimmed to 32 bits.
  • return a if a <= MAX_INT else ~(a ^ MASK) — positive register values pass through; negative ones are converted back.
One-line summary to remember: XOR is the sum without carries, AND-shift is the carries; loop until the carries are gone, inside a 32-bit mask.
