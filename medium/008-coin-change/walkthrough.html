Coin Change, narrated

Scroll through the thinking, from the greedy that fails through the exponential recursion to the bottom-up table over amounts, with the state of the algorithm shown alongside.

STEP 1

The problem

You have coin denominations and a target amount, with unlimited coins of each kind. Return the fewest coins that add up to exactly the target, or −1 if no combination does.

Running example: coins = [1, 2, 5], amount = 11. The answer is 3: 5 + 5 + 1.

Two things make this harder than it looks. Some amounts are unreachable, and the obvious greedy strategy is wrong for some coin sets.

STEP 2

First instinct: greedy, largest coin first

Take as many of the biggest coin as fit, then the next biggest, and so on. For 11 with [1, 2, 5] that gives 5, 5, 1: three coins, correct.

Now try coins = [1, 3, 4], amount = 6. Greedy takes a 4, then cannot fit another 4 or a 3, so it takes 1 and 1: three coins. But 3 + 3 is two coins.

Greedy happens to work for coin systems designed for it, like real currencies. It has no guarantee in general, because grabbing a big coin now can leave a remainder that needs many small coins.
STEP 3

Reframe: the last coin

Look at any optimal pile for amount a. Its last coin is some denomination c. Take it away and what remains must be an optimal pile for a − c; if it were not, we could swap in a better one and beat the "optimal" pile.

fewest(a) = 1 + min over coins c ≤ a of fewest(a − c), with fewest(0) = 0.

Written as plain recursion this is correct but explodes: fewest(11) calls fewest(10), fewest(9) and fewest(6), each of which calls three more, and the same amounts get recomputed over and over. Roughly O(coinsamount) without a cache.

STEP 4

The key idea: fill a table from 0 upward

There are only amount + 1 distinct subproblems: fewest(0) through fewest(amount). Compute them in increasing order and store them in an array dp. When we reach dp[a], every dp[a − c] it needs is already final.

  • Start every slot at a sentinel meaning "unreachable". amount + 1 works: no real answer needs more coins than that.
  • dp[0] = 0: making nothing takes no coins.
  • For each a from 1 to amount, for each coin that fits, dp[a] = min(dp[a], dp[a − c] + 1).
  • If dp[amount] is still the sentinel, return −1.
STEP 5

Trace it: the small amounts

dp[1]: only the 1 fits, dp[0] + 1 = 1. dp[2]: the 1 gives dp[1] + 1 = 2, the 2 gives dp[0] + 1 = 1. Take 1. dp[3]: dp[2] + 1 = 2 or dp[1] + 1 = 2. Either way 2. dp[4]: 2. dp[5]: the 5 gives dp[0] + 1 = 1.

Each slot tries three coins and takes the best. No slot is ever revisited.

STEP 6

Trace it: reaching 11

By the time we get to a = 11 the table reads [0, 1, 1, 2, 2, 1, 2, 2, 3, 3, 2] for amounts 0 to 10. Try each coin as the last one:

  • coin 1: dp[10] + 1 = 3
  • coin 2: dp[9] + 1 = 4
  • coin 5: dp[6] + 1 = 3

The minimum is 3. Following the choices back: 11 → 6 (coin 5) → 1 (coin 5) → 0 (coin 1). That is 5 + 5 + 1.

STEP 7

The pitfall: unreachable amounts

With coins = [2] and amount = 3: dp[1] has no coin that fits, so it stays at the sentinel. dp[2] = dp[0] + 1 = 1. dp[3] = dp[1] + 1, but dp[1] is the sentinel, so dp[3] stays at the sentinel too.

Because the sentinel is amount + 1, adding 1 to it never produces a number that looks like a real answer. Map it back to −1 at the very end, and only there.

Two neighbouring traps: forgetting dp[0] = 0, which makes everything unreachable; and indexing dp[a − c] before checking c ≤ a, which in Python silently reads from the end of the list.

STEP 8

Time and space

The table has amount + 1 slots and each one tries every coin: O(amount × coins) time. The table itself is O(amount) space.

ApproachTimeSpace
GreedyO(coins)O(1), but wrong in general
Plain recursionO(coinsamount)O(amount) stack
Memoised recursionO(amount × coins)O(amount) cache + stack
Bottom-up tableO(amount × coins)O(amount)

At amount = 10,000 and 12 coins that is 120,000 steps, against a recursion that would not finish.

STEP 9

The final solution

Nine lines. Every one of them maps to a step above.

  • INF = amount + 1 is the unreachable sentinel that stays an integer.
  • dp = [INF] * (amount + 1) and dp[0] = 0 set up the table and its base case.
  • The outer loop walks amounts upward so every needed slot is already final.
  • The inner loop tries each coin as the last coin, guarded by c <= a.
  • return dp[amount] if dp[amount] != INF else -1 maps the sentinel back.
One-line summary to remember: fewest for a is one more than the fewest for a minus some coin; build the table upward.
