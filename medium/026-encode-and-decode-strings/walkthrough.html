Encode and Decode Strings, narrated

I’ll first use a complete JSON encoding, then I build a dependency-free length-prefixed format that cannot confuse payload text with framing.

Pattern used Hash Map length-prefix framing: I write <len>#<chars> and let the length, not a separator, delimit each string

STEP 1

The problem

Write two functions. encode takes a list of strings and produces one single string. decode takes that single string and rebuilds the original list, element for element. The strings can contain any character at all, and the list can contain empty strings, so nothing about the content can be assumed.

Running example: strs = ["neet", "code", "love", "you"]. Our encoding is "4#neet4#code4#love3#you", and decoding it must return exactly the four original strings.

There is no single correct output string. Any format works as long as decode(encode(strs)) == strs for every possible list. The problem is really about designing a format that cannot be ambiguous, then writing the parser for it.

Two edge cases are worth writing down before starting: the empty list [] must round-trip to [], not to [""], and a list of empty strings such as ["", ""] must keep its count of two.

STEP 2

First instinct: use a standard structured encoding

I first use JSON, which already records string boundaries and escaping rules.

import jsondef encode(strs):    return json.dumps(strs)def decode(data):    return json.loads(data)

JSON supports arbitrary strings, including separators and empty strings. It takes O(N) time and uses O(N) extra space for the encoded data, where N is the total character count.

I take control of the format by writing each string as its length followed by # and exactly that many payload characters. The decoder then trusts the length, not a separator that could appear in the data.

STEP 3

The key insight: say how long each string is

Instead of marking where a string ends with a character that might be forged, announce up front how many characters it has. I write each string as its length, a #, and then the characters: "neet" becomes "4#neet".

The decoder then reads the digits up to the first #, converts them to a number, and slices exactly that many characters. It never inspects the payload, so a # inside a string is harmless: by the time the decoder is looking for the next #, its index has already jumped past the whole payload.

The # only terminates the digits. Digits never contain #, so that boundary is always unambiguous. The payload boundary comes from the number, which is why the content of the payload does not matter.

The edge cases fall out for free. An empty string is "0#". An empty list is "", which the decoder's while i < len(s) loop never enters, so it returns [].

STEP 4

The approach, line by line

Encoding is one line: "".join(f"{len(s)}#{s}" for s in strs). Decoding is a cursor walk.

  • result = [], i = 0 — the output list and a cursor at the start of the first header.
  • while i < len(s) — one iteration per chunk; stops when the cursor runs off the end.
  • j = s.index("#", i) — find the # that ends this header, searching from i, not from the start.
  • length = int(s[i:j]) — the digits between the cursor and the #.
  • result.append(s[j + 1:j + 1 + length]) — the payload starts one past the # and is exactly length characters.
  • i = j + 1 + length — jump the cursor to the character after the payload, which is the next header.
  • return result.
STEP 5

Trace it: encoding the list

"neet" has length 4, so it becomes "4#neet". "code" and "love" likewise become "4#code" and "4#love". "you" has length 3: "3#you".

Concatenated with no separator between chunks, the result is "4#neet4#code4#love3#you", 23 characters. The panel shows the chunks with the index at which each one starts: headers at 0, 6, 12, 18 and payloads at 2, 8, 14, 20.

I see there is nothing between neet and the next 4. The decoder does not need a gap; it knows the payload is over because it counted four characters.

STEP 6

Trace it: decoding the first chunk

I start with i = 0. s.index("#", 0) finds the # at index 1, so j = 1. The digits are s[0:1] = "4", so length = 4.

The payload is s[j + 1 : j + 1 + length] = s[2:6] = "neet". I append it. I move the cursor: i = j + 1 + length = 1 + 1 + 4 = 6.

Index 6 is the 4 of the second header. The cursor landed exactly on it without ever looking at the letters of neet.

STEP 7

Trace it: the remaining chunks

From i = 6: the # is at j = 7, length = int(s[6:7]) = 4, payload s[8:12] = "code", and i = 7 + 1 + 4 = 12.

From i = 12: j = 13, length = 4, payload s[14:18] = "love", i = 18.

From i = 18: j = 19, length = int(s[18:19]) = 3, payload s[20:23] = "you", and i = 19 + 1 + 3 = 23. That equals len(s), so the loop condition i < 23 fails and I return ["neet", "code", "love", "you"].

Four iterations for four strings, and the cursor visited every character exactly once: the headers to read them, the payloads to slice them.
STEP 8

Where this goes wrong: the +1 for the '#'

Slicing from j instead of j + 1. I write s[j:j + length] and every payload starts on the # and stops one character early. The cursor update is still correct, so the loop runs to completion and returns ["#nee", "#cod", "#lov", "#yo"]. Same list length, every string wrong.

Advancing with i = j + length. The cursor lands on the last character of the payload instead of the next header. On the running example the second "header" is s[5:7] = "t4", and int("t4") raises ValueError. The crash is the friendly version of this bug; with all-digit payloads it would silently decode garbage.

Searching for # from the start. s.index("#") without the i argument always finds index 1, so length is always 4 and i is always reset to 6. The loop never advances past the first chunk.

Three offsets, all of them "one past the #": the payload starts at j + 1, it ends at j + 1 + length, and the next header starts at that same j + 1 + length.
STEP 9

Time and space

Let N be the total number of characters over all strings and m the number of strings. Encoding writes every character once plus a short header per string: O(N + m). Decoding reads every character once (s.index scans only the digits of the current header, and slicing copies only the payload): also O(N + m). Since m ≤ N + m, both are O(N) in practice.

The encoded string and the decoded list each hold all the characters: O(N) space.

ApproachTimeCorrect?
Join with a separator, splitO(N)No: breaks on the separator and on []
Escape the separator inside payloadsO(N)Yes, but decode must scan every character
Length-prefix each stringO(N)Yes, and decode skips payloads in one jump

All three are linear. The difference is correctness and simplicity, not speed, which is why this problem is about the design rather than the complexity.

STEP 10

The final solution

Two methods, twelve lines. Every one of them maps to a step above.

  • "".join(f"{len(s)}#{s}" for s in strs) is the whole encoder: length, hash, characters, no separator between chunks.
  • i = 0 and while i < len(s) I walk the encoded string one chunk at a time; an empty input never enters the loop.
  • j = s.index("#", i) ends the header; searching from i is what makes payload hashes invisible.
  • length = int(s[i:j]) reads the digits, however many there are.
  • result.append(s[j + 1:j + 1 + length]) slices the payload blindly.
  • i = j + 1 + length jumps to the next header.
One-line summary to remember: a separator can be forged, a length cannot; I write <len>#<chars> and let the decoder count instead of search.
