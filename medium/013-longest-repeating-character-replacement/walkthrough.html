Medium · Sliding Window · LeetCode #424

Longest Repeating Character Replacement, narrated

Scroll through growing and shrinking the window, with counts and the running record shown alongside.

Pattern used Sliding Window window valid when window_len - max_count <= k

STEP 1

The problem

Given a string and a budget k of replacements, find the longest substring that can be made all-one-letter by changing at most k characters in it.

Running example: s = "AABABBA", k = 1. Answer: 4 (e.g. "AABA" -> "AAAA" with one swap of the B).
STEP 2

First instinct: check every substring

For each substring, count letters, find the max, check if length - max <= k. That's O(n^2) substrings times O(26) to find the max — too slow for n up to 10^5.

STEP 3

The key idea: a window that only grows

Keep a sliding window and a running count of letters inside it. A window is valid exactly when window_len - max_count <= k — everything except the majority letter must fit in the replacement budget. Grow the window by moving right; when it becomes invalid, shrink by moving left one step, rather than restarting.

The record max_count is never decremented, even when the window shrinks. A window can only beat the current best if its length exceeds the previous best window's length, and that requires a max_count at least as large as before — so a stale, too-high max_count never produces a wrong (too long) answer, it just makes shrinking trigger slightly less eagerly, which is harmless.
STEP 4

Trace it: building up to index 3

A A B A: counts are A:3, B:1. window_len = 4, max_count = 3. 4 - 3 = 1 <= k(1) — valid. best = 4.

STEP 5

Trace it: index 4 breaks it

Add the next B: A A B A B. counts: A:3, B:2. window_len = 5, max_count stays 3 (B's count of 2 doesn't beat it). 5 - 3 = 2 > k(1) — invalid. Shrink: drop the leftmost A, left moves to 1.

STEP 6

Trace it: after shrinking

Window is now A B A B (indices 1-4). counts: A:2, B:2. window_len = 4, max_count = 3 (unchanged, stale from before). 4 - 3 = 1 <= k — valid again, but best stays 4 since it doesn't exceed the record.

STEP 7

Where this goes wrong

Recomputing max_count as the true max of the shrunk window (dropping it to 2 in the trace above) doesn't break correctness, but it's wasted work and easy to get backwards — some implementations mistakenly shrink the window back down after finding a smaller true max, which can turn an O(n) algorithm into O(26n) or, if done wrong, produce an under-count.

The window length itself never needs to shrink below the current best + 1 in net effect — left and right both only move forward, so the window size is monotonically non-decreasing overall.
STEP 8

Time and space

right and left each move forward at most n times total — O(n) time. The counts dict holds at most 26 uppercase letters — O(1) space.

STEP 9

The final solution

  • Track per-letter counts inside the window and the best (possibly stale) max_count seen.
  • A window is valid when window_len - max_count <= k.
  • On invalid, shrink from the left by exactly one — never recompute max_count.
  • Record best only when the window is valid.
