Evaluate Reverse Polish Notation, narrated

I will first reduce the token list in place, then I turn that repeated work into one pass with a stack of pending operands.

Pattern used Stack push numbers; an operator pops two, applies, pushes the result

STEP 1

The problem

You get an arithmetic expression as a list of string tokens in Reverse Polish Notation, also called postfix: each operator comes after its two operands. ["2", "1", "+"] means 2 + 1. The operators are +, -, * and /, and division truncates toward zero.

Return the integer value of the expression. The input is always valid, so an operator always has two operands waiting, and there is never a division by zero.

Running example: tokens = ["4", "13", "5", "/", "+"]. The answer is 6: the / applies to 13 and 5, giving 2 after truncation, and the + applies to 4 and that 2.

Notice there are no parentheses and no precedence rules. Postfix does not need them; the position of each operator already says which values it consumes.

STEP 2

First instinct: rewrite the list in place

I can repeatedly find the first operator, replace it and its two operands with their result, and stop when one token remains.

def evalRPN(tokens):    def apply(op, a, b):        return {"+": a + b, "-": a - b, "*": a * b, "/": int(a / b)}[op]    while len(tokens) > 1:        i = next(k for k, token in enumerate(tokens) if token in "+-*/")        tokens[i - 2:i + 1] = [str(apply(tokens[i], int(tokens[i - 2]), int(tokens[i - 1])))]    return int(tokens[0])

This is correct because the first operator in valid RPN always uses the two tokens before it. Repeated scans and list splices make the time complexity O(n²), and the shrinking token list uses O(n) space.

I keep the values that have not found an operator yet. A stack preserves exactly that pending work and removes the repeated scans and splices.

STEP 3

Reframe: an operator always takes the two most recent values

I read the tokens left to right and think about what an operator needs at the moment it appears: the two values produced most recently before it, whether those are literal numbers or results of earlier operators. Everything older is untouched.

"Most recent first" is a stack. I push each number as it arrives. When an operator arrives, I pop twice, compute, and push the result so it can be an operand for a later operator.

The first pop is the right operand (it was pushed last) and the second pop is the left operand. For + and * the order is irrelevant; for - and / it decides the answer.

When the tokens run out, the stack holds one value, the result. Nothing was ever rescanned.

STEP 4

The approach

  • stack = []: the pending operands.
  • For each token: if it is "+", "-", "*" or "/", do b, a = stack.pop(), stack.pop() and push a op b.
  • For "/" I push int(a / b), which truncates toward zero, rather than a // b, which floors.
  • Otherwise the token is a number, possibly negative like "-11": stack.append(int(token)).
  • After the loop, return stack[-1].

STEP 5

Trace it: three numbers go on the stack

"4" is not an operator, so int("4") is pushed: stack = [4]. "13" is pushed: stack = [4, 13]. "5" is pushed: stack = [4, 13, 5].

Nothing has been computed yet. The 4 at the bottom is waiting for an operator that may be a long way off, and that is fine; the stack holds it for as long as necessary while the newer values are dealt with first.

STEP 6

Trace it: "/" pops 5 then 13

The token is "/". The first pop returns the top, b = 5; the second returns a = 13. The expression is a / b = 13 / 5 = 2.6, and int(2.6) = 2. I push it: stack = [4, 2].

I read the tokens again with that in mind: 13 5 / is 13 / 5, left operand first in the token order, which is exactly why the second I pop is the left operand.

STEP 7

Trace it: "+" pops 2 then 4, the answer

The token is "+". I pop b = 2, then a = 4. I push 4 + 2 = 6: stack = [6].

That was the last token, and one value remains. stack[-1] is 6. The 4 pushed at the very start finally met its operator two tokens later, after the division it depended on was resolved.

Five tokens, five constant-time steps, no rescans and no parentheses.
STEP 8

Where this goes wrong: operand order and floor division

Popping in the wrong order. I write a, b = stack.pop(), stack.pop() and then a / b. Now a is the top (5) and b is the one below (13), so the division computes int(5 / 13) = 0 and the final sum is 4 + 0 = 4 instead of 6. Addition and multiplication hide this bug completely, which is why tests need a - or a /.

Floor division. a // b rounds toward negative infinity, but the problem truncates toward zero. On the third LeetCode example, 6 // -132 is -1 where int(6 / -132) is 0, and the final answer comes out as 12 instead of 22.

Mistaking a negative number for an operator. Testing token[0] == "-" or not token.isdigit() treats "-11" as subtraction and pops two values that were not meant for it. I compare against the four operator strings exactly and let int() parse the rest.

I pop the right operand first, then the left; I use int(a / b) for truncation; and the only operators are the four exact strings.
STEP 9

Time and space

Each token is handled once. A number is one push; an operator is two pops, one arithmetic operation, and one push. That is O(n) time. The stack holds at most the operands pushed so far, so O(n) space; a valid expression with n tokens has at most (n + 1) / 2 operands.

ApproachTimeSpace
Rescan and splice the listO(n²)O(n) (in place, but with string conversions)
Recursive descent from the rightO(n)O(n) call stack
Stack of pending operandsO(n)O(n)

The recursive version reads the expression from the end (an operator's two arguments are the two sub-expressions before it) and is a neat way to see that postfix is a tree in disguise. The explicit stack does the same work without recursion depth limits.

STEP 10

The final solution

Every line maps to a step above.

  • stack = [] holds operands until an operator claims them.
  • b, a = stack.pop(), stack.pop() in every operator branch: right operand first, then left.
  • stack.append(a + b), a - b, a * b: apply and push the result back for later operators.
  • stack.append(int(a / b)) truncates toward zero, matching the problem's definition of division.
  • stack.append(int(token)) parses every non-operator token, negative signs included.
  • return stack[-1]: the single value left after the last token.
One-line summary to remember: numbers wait on a stack; each operator pops right then left, computes, and pushes the result.
