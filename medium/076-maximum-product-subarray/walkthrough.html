Maximum Product Subarray, narrated

Scroll through the thinking, from multiplying out every subarray to a single pass that carries both the largest and the smallest product ending at each index, with the state of the algorithm shown alongside.

Pattern used Dynamic Programming Kadane with two running values, because a negative turns the worst product into the best

STEP 1

The problem

You get an integer array nums. Among all contiguous, non-empty subarrays, find the one whose elements multiply to the largest value, and return that product. Negatives and zeros are allowed.

Running example: nums = [2, 3, -2, 4]. The answer is 6, from [2, 3]. Extending to the −2 gives −12, the 4 alone gives 4, and there is no way to reach the 4 without passing through the −2.

Products behave differently from sums: a negative flips the sign of everything before it, and a zero wipes it out. A single-element subarray always counts, so with [-2] the answer is −2, not 0.

STEP 2

First instinct: multiply out every subarray

Fix a start, extend the end one element at a time, multiply as you go, and keep the largest product seen.

best = nums[0]for i in range(n):    product = 1    for j in range(i, n):        product *= nums[j]        best = max(best, product)

There are n(n + 1) / 2 subarrays and each extension costs one multiplication, so this is O(n²). On [2, 3, -2, 4] it evaluates 10 products: 2, 6, −12, −48, 3, −6, −24, −2, −8, 4. At n = 2 · 10⁴ that is 2 · 10⁸ multiplications, too slow.

STEP 3

Reframe: why Kadane alone is not enough

For sums, Maximum Subarray keeps one value, "best sum ending here", because extending a bad prefix can never help. For products that is false. Ending at the −2, the best product is −2 on its own; but the worst product ending there, 2 · 3 · −2 = −12, would become the best if a negative followed it.

So a subarray ending at index i is built from one of three things: nums[i] alone, nums[i] times the largest product ending at i − 1, or nums[i] times the smallest product ending at i − 1.

Two values per index instead of one: cur_max and cur_min, the largest and smallest products of a subarray ending here. A negative nums[i] swaps their roles.
STEP 4

The key idea: three candidates, take both extremes

Seed all three values with nums[0]: best = cur_max = cur_min = nums[0]. The only subarray ending at index 0 is the element itself.

  • for x in nums[1:] visits each later element.
  • candidates = (x, x * cur_max, x * cur_min) are the three ways a subarray can end at x.
  • cur_max, cur_min = max(candidates), min(candidates) keeps both extremes, computed from the same old pair.
  • best = max(best, cur_max) records the global answer.

A zero needs no special case: all three candidates become 0 or x, so the running products reset to 0 and the next element starts fresh.

STEP 5

Trace it: x = 3

Before the loop, best = cur_max = cur_min = 2.

The candidates are (3, 3 · 2, 3 · 2) = (3, 6, 6). cur_max = max(3, 6, 6) = 6, cur_min = min(3, 6, 6) = 3. best = max(2, 6) = 6.

So far it is plain Kadane: everything is positive, so the largest product ending at the 3 is the whole prefix.

STEP 6

Trace it: x = −2, the sign flip

The candidates are (−2, −2 · 6, −2 · 3) = (−2, −12, −6). cur_max = max(−2, −12, −6) = −2: the best subarray ending here is the −2 by itself. cur_min = min(−2, −12, −6) = −12: the worst is the whole prefix [2, 3, −2].

best = max(6, −2) = 6, unchanged. But that −12 is not garbage: if the next element were negative, x · cur_min would be a large positive. This is the value plain Kadane would have thrown away.

STEP 7

Trace it: x = 4, the answer

The candidates are (4, 4 · −2, 4 · −12) = (4, −8, −48). cur_max = 4, the 4 on its own, and cur_min = −48, the whole array.

best = max(6, 4) = 6. The loop ends and return best gives 6.

The −48 never paid off because the array ended, but the code could not know that in advance. Carrying it costs one extra multiplication per element.
STEP 8

Where this goes wrong: one running value, or the wrong seed

Tracking only cur_max. cur = max(x, x * cur) is Kadane with a product. On [2, 3, −2, 4] it happens to return 6, which is why this bug survives a casual test. On [−2, 3, −4] it returns 3, not 24: at the 3 the running value becomes max(3, −6) = 3, the −6 is discarded, and the final −4 has nothing negative to cancel against. The panel shows that run.

Seeding with 0 or 1. best = 0 with cur_max = cur_min = 1 and a loop over all of nums returns 0 for [−2], but the only subarray is [−2] and the answer is −2. Seed with nums[0] and loop from index 1.

Updating in two statements. cur_max = max(...) followed by cur_min = min(x, x * cur_max, x * cur_min) reads the new cur_max. Both extremes must come from the same old pair; the tuple assignment guarantees it.

A negative number makes the smallest product the most valuable one. Keep both, and take both from the same three candidates.
STEP 9

Time and space

One pass with three multiplications and two comparisons per element: O(n) time. Three integers: O(1) space.

ApproachTimeSpace
Every subarray, running productO(n²)O(1)
Prefix and suffix product passesO(n)O(1)
Kadane with max and minO(n)O(1)

The two-pass version (max over prefix products left to right, then right to left, resetting at zero) is equally fast and a good thing to be able to explain; the max/min scan is the one that generalises to "best subarray ending here" problems.

STEP 10

The final solution

Seven lines. Every one of them maps to a step above.

  • best = cur_max = cur_min = nums[0] seeds all three with the only subarray ending at index 0.
  • for x in nums[1:] scans the rest once.
  • candidates = (x, x * cur_max, x * cur_min): start fresh, extend the best, or extend the worst.
  • cur_max, cur_min = max(candidates), min(candidates) keeps both extremes from the same old pair.
  • best = max(best, cur_max) tracks the global answer.
  • return best.
One-line summary to remember: a negative flips best and worst, so carry the max and the min product ending at each index and take the largest max.
