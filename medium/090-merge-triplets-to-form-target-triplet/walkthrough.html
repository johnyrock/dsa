Merge Triplets to Form Target Triplet, narrated

Scroll through the thinking, from trying every subset of triplets to a single pass that throws out anything too big and merges everything else, with the triplets shown alongside.

Pattern used Greedy max only goes up, so skip any triplet that exceeds target and merge all the rest

STEP 1

The problem

You have a list of triplets, each three integers, and one target triplet. One operation picks two triplets and replaces the second with their element-wise maximum: position by position, keep the larger value. You may do this as many times as you like.

The question is whether some sequence of operations can make one of the triplets equal target exactly, in all three positions.

Running example: triplets = [[2, 5, 3], [1, 8, 4], [1, 7, 5]], target = [2, 7, 5]. Merging [2, 5, 3] with [1, 7, 5] gives [max(2, 1), max(5, 7), max(3, 5)] = [2, 7, 5], so the answer is true.

Note what the operation cannot do. It never lowers a value. Once a position holds a number, every later merge leaves it the same or larger. That single fact is the whole solution.

STEP 2

First instinct: try every subset of triplets

The merge is commutative and associative, so the result of merging a set of triplets does not depend on the order. That means the search space is "which triplets do I include?", and a brute force simply tries every non-empty subset, merges it, and compares against target:

for mask in range(1, 1 << len(triplets)):    merged = [0, 0, 0]    for i, t in enumerate(triplets):        if mask >> i & 1:            merged = [max(a, b) for a, b in zip(merged, t)]    if merged == target:        return Truereturn False

For three triplets that is seven subsets, fine. The constraint allows 10^5 triplets, and 2^100000 subsets is not a number a computer will ever finish counting to. This is O(2ⁿ · n), and the wasted work is obvious once you look at it: most subsets contain a triplet that has already ruined the result.

STEP 3

The key insight: a value above target is poison, everything else is free

Look at [1, 8, 4] in the panel. Its middle value is 8 and the target's middle value is 7. If this triplet is ever merged in, the middle position becomes at least 8, and since max never goes down, it stays at least 8 forever. No subset containing [1, 8, 4] can work, so it should be skipped outright.

Now the flip side. Take a triplet where every value is <= target in its position, like [2, 5, 3]. Merging it in can never push any position past the target, so including it is harmless. And if it is harmless, why be selective? Merge every safe triplet.

The greedy rule: discard any triplet with a value above target in some position, merge all the others, and see whether the result equals target. That is line 3's all(triplet[i] <= target[i] for i in range(3)) test, and the merge is what the found set stands in for.

Merging all safe triplets gives, in each position, the largest safe value seen there. That equals target[i] precisely when some safe triplet has triplet[i] == target[i]. So we do not even need to compute the merged triplet; we only need to know which positions got matched.

STEP 4

The approach: one pass, a set of matched positions

  • found = set() collects the positions (0, 1, 2) where some safe triplet equals the target.
  • for triplet in triplets: look at each triplet exactly once, in any order.
  • if all(triplet[i] <= target[i] for i in range(3)): the safety check. A triplet fails it if any position is above the target.
  • if triplet[i] == target[i]: found.add(i): for a safe triplet, record every position it already matches.
  • return len(found) == 3: all three positions were matched by safe triplets, so merging all of them is exactly target.

The panel shows the target row on top, the three input rows below it, and the found set as the running variable. Green cells are positions that match the target; an amber cell is the value that disqualifies a triplet.

STEP 5

Trace it: [2, 5, 3] is safe and matches position 0

Safety check against [2, 7, 5]: 2 <= 2, 5 <= 7, 3 <= 5. All three hold, so this triplet may be merged.

Now the equality check position by position. 2 == 2 at position 0, so found.add(0). 5 == 7 is false and 3 == 5 is false, so nothing else is added. After the first triplet, found = {0}.

Notice that we did not build a merged triplet anywhere. The set is enough, because the only thing that matters about the eventual merge is whether each position reaches the target.

STEP 6

Trace it: [1, 8, 4] fails the safety check

Safety check: 1 <= 2 holds, but 8 <= 7 is false. all(...) short-circuits to False on the second position, so the inner loop never runs and the triplet is skipped.

It is worth seeing why this is correct rather than merely convenient. If this triplet were merged in, the middle value would become max(5, 8) = 8, and no later merge could bring it back down to 7. The triplet does happen to have nothing useful anyway, since its 1 and 4 match nothing, but even a triplet like [2, 8, 5] with two exact matches would have to be thrown away.

found is still {0}. Skipping never changes it.
STEP 7

Trace it: [1, 7, 5] completes the set

Safety check: 1 <= 2, 7 <= 7, 5 <= 5. Safe. Equality: 1 == 2 is false, 7 == 7 adds 1, 5 == 5 adds 2. Now found = {0, 1, 2}.

The loop ends. len(found) == 3, so the function returns true. Cross-check with the actual merge: [2, 5, 3] and [1, 7, 5] combine to [max(2, 1), max(5, 7), max(3, 5)] = [2, 7, 5], the target.

The answer took three safety checks and nine comparisons. The brute force would have merged seven subsets, and on a large input would never finish.

STEP 8

Where this goes wrong: matching before checking safety

Recording matches from an unsafe triplet. It is tempting to fold the two loops into one: for each position, if triplet[i] == target[i]: found.add(i), with no safety gate. Run that on the panel's input, [[2, 8, 4], [1, 7, 5]] with target [2, 7, 5]. The first triplet's 2 matches position 0 and gets recorded, even though its 8 makes the triplet unusable. The second adds positions 1 and 2, len(found) == 3, and the code says true. The real answer is false: the only triplet with a 2 in front also carries an 8, and nothing can reach [2, 7, 5].

Using < instead of <= in the safety check. Then a triplet that equals the target in some position, which is exactly the one you need, is thrown out. With triplets = [[2, 7, 5]] and the same target, the strict test fails on every position, found stays empty, and the function returns false for an input that is literally the target.

Counting matches instead of collecting positions. A counter matched += 1 reaches 3 on [[2, 1, 1], [2, 1, 1], [2, 1, 1]], three matches all at position 0, and wrongly returns true. The set deduplicates for free.

Safety first, then equality. A triplet is either entirely usable or entirely discarded; it cannot contribute one good position while carrying one bad one.
STEP 9

Time and space

Each triplet costs at most three comparisons for the safety check and three for the equality check, so the pass is O(n) time. found never holds more than three integers: O(1) space.

ApproachTimeSpace
Try every subsetO(2ⁿ · n)O(1)
Merge every safe triplet, compareO(n)O(1)
Track matched positions onlyO(n)O(1)

Merging every safe triplet into an explicit [a, b, c] and comparing at the end is just as fast; the set version simply skips building a value nobody reads.

STEP 10

The final solution

Eight lines. Every one of them maps to a step above.

  • found = set() starts with no position matched.
  • for triplet in triplets visits each triplet once; order is irrelevant.
  • if all(triplet[i] <= target[i] for i in range(3)) discards any triplet that would overshoot.
  • if triplet[i] == target[i]: found.add(i) records which positions this safe triplet already hits.
  • return len(found) == 3 is true exactly when merging all safe triplets yields the target.
One-line summary to remember: max never goes down, so throw away any triplet above the target and check that the rest cover all three positions.
