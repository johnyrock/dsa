Daily Temperatures, narrated

Scroll through the thinking, from scanning forward for every day to a decreasing stack of unresolved days, with the state of the algorithm shown alongside.

Pattern used Stack monotonic stack of indices; today resolves every cooler day on top

STEP 1

The problem

You get a list of daily temperatures. For each day, report how many days pass before a strictly warmer day arrives. If no warmer day ever comes, report 0.

Running example: temperatures = [73, 74, 75, 71, 69, 72, 76, 73]. The answer is [1, 1, 4, 2, 1, 1, 0, 0].

Read a couple of entries by hand. Day 2 is 75; the next warmer day is day 6 at 76, so answer[2] = 6 − 2 = 4. Day 3 is 71; day 4 (69) is cooler, day 5 (72) is warmer, so answer[3] = 2. Days 6 and 7 never see anything warmer and stay 0.

The output is a list of the same length, and the input can be 100,000 days long, which rules out anything quadratic.

STEP 2

First instinct: look ahead from every day

For each day i, walk forward until you find a day j with temperatures[j] > temperatures[i], and record j − i. If the walk falls off the end, leave 0.

answer = [0] * nfor i in range(n):    for j in range(i + 1, n):        if temperatures[j] > temperatures[i]:            answer[i] = j - i            break

Correct, and O(n²) in the worst case: a strictly falling list like [100, 99, 98, …] makes every day scan all the way to the end and find nothing. At n = 100,000 that is five billion comparisons.

The waste is that day 3 walks past day 4, and then day 4 starts its own walk over the same territory. Each day forgets what the previous day already learned about the future.

STEP 3

Key insight: keep the unresolved days on a stack

Flip the direction of the question. Instead of each day looking forward for its answer, let each new day look backward and ask: "which earlier days have I just become the answer for?"

Keep a stack of the indices whose warmer day has not arrived yet. When today's temperature temp arrives, any day on the stack that is cooler than temp is resolved right now: its wait is i − j. Pop it, write the answer, and check the next one.

The stack is always decreasing in temperature from bottom to top. Why: a day only stays on the stack if it was not cooler than every day pushed after it. So the cooler unresolved days are on top, and the popping stops at the first day that today cannot beat.
  • answer = [0] * len(temperatures): everything defaults to "never".
  • for i, temp in enumerate(temperatures): one pass.
  • while stack and temperatures[stack[-1]] < temp: today beats the top, so pop it and set answer[j] = i − j.
  • stack.append(i): today now waits its turn. Push after popping.
  • Whatever remains on the stack at the end keeps its 0.

The stack holds indices, not temperatures, because the answer is a distance in days; the temperature is one lookup away as temperatures[stack[-1]].

STEP 4

Trace it: days 0, 1, 2 — a warming run

Day 0 (73): the stack is empty, nothing to pop. Push 0. Day 1 (74): the top is day 0 at 73, and 73 < 74, so pop it and write answer[0] = 1 − 0 = 1. The stack is empty; push 1.

Day 2 (75): the top is day 1 at 74, 74 < 75, pop and write answer[1] = 2 − 1 = 1. Push 2.

Each rising day resolves the one before it immediately, so the stack never holds more than one entry during this run. The panel shows stack = [2] and answer = [1, 1, 0, 0, 0, 0, 0, 0].

STEP 5

Trace it: days 3 and 4 — a cooling run piles up

Day 3 (71): the top is day 2 at 75, and 75 < 71 is false. Nothing is resolved; push 3. Day 4 (69): the top is day 3 at 71, 71 < 69 is false; push 4.

Now the stack is [2, 3, 4], temperatures 75, 71, 69 from bottom to top, decreasing as promised. All three are waiting, and none of the answers have changed since step 4.

This is where the brute force would have started three separate forward scans. The stack instead just records the three open questions in the order they will be answered.

STEP 6

Trace it: day 5 resolves two days at once

Day 5 (72). Top is day 4 at 69: 69 < 72, pop, answer[4] = 5 − 4 = 1. New top is day 3 at 71: 71 < 72, pop, answer[3] = 5 − 3 = 2. New top is day 2 at 75: 75 < 72 is false, stop. Push 5.

The while ran twice. That is the whole reason it is a while and not an if: one warm day can close out an entire cooling run.

The stack is now [2, 5] (75, 72). Day 2 is still waiting for something above 75.

STEP 7

Trace it: days 6 and 7 — the answer

Day 6 (76). Top is day 5 at 72: 72 < 76, pop, answer[5] = 6 − 5 = 1. Top is day 2 at 75: 75 < 76, pop, answer[2] = 6 − 2 = 4. Empty; push 6.

Day 7 (73). Top is day 6 at 76: 76 < 73 is false; push 7. The loop ends with stack = [6, 7]. Those two days never found a warmer day, and their entries in answer were never written, so they keep the default 0.

Final answer: [1, 1, 4, 2, 1, 1, 0, 0]. Eight pushes, six pops, one pass.
STEP 8

Where this goes wrong: if instead of while, and the comparison

if instead of while. Day 5 pops day 4 and stops. Day 3 is left buried under day 5, and nothing later pops it correctly. Day 6 then pops day 5 only, leaving day 2 buried too. The output for the running example becomes [1, 1, 0, 0, 1, 1, 0, 0]: the two "long wait" answers, 4 and 2, are lost.

<= instead of <. Equal is not warmer. On [70, 70, 70] the correct answer is [0, 0, 0]; with <= each day pops the previous one and the output is [1, 1, 0].

Pushing before popping. Move stack.append(i) above the loop and today compares against itself; temperatures[i] < temperatures[i] is false, nothing is ever popped, and every answer stays 0.

Pop while the top is cooler, then push. The loop must be able to pop more than once per day.
STEP 9

Time and space

It looks like a nested loop, but count the operations globally rather than per day: each index is pushed exactly once, and an index can be popped at most once. So across the entire run the while body executes at most n times, and the whole thing is O(n).

ApproachTimeSpace
Forward scan from every dayO(n²)O(1) extra
Right-to-left with a 71-entry next-occurrence tableO(71 · n)O(71)
Monotonic stackO(n)O(n) stack

The stack is O(n) in the worst case: a strictly falling list never pops, so all n indices end up on it, and the answer stays all zeros.

STEP 10

The final solution

Seven lines. Every one of them maps to a step above.

  • answer = [0] * len(temperatures): the default for days that never resolve.
  • stack = []: indices waiting for a warmer day, temperatures decreasing toward the top.
  • while stack and temperatures[stack[-1]] < temp: pop every waiting day that today beats.
  • answer[j] = i - j: the wait is a difference of indices.
  • stack.append(i) after the loop: today joins the queue of open questions.
  • return answer.
One-line summary to remember: each new day pops and answers every cooler day on top of the stack, then pushes itself.
