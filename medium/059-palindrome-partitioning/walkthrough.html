Medium · Backtracking · LeetCode #131

Palindrome Partitioning, narrated

I will first try every set of cut positions, then reject a cut as soon as the piece it creates is not a palindrome.

Pattern used Backtracking choose where the piece at start ends, recurse from end + 1, I pop

STEP 1

The problem

You are given a string s. Cut it into consecutive pieces so that every piece reads the same forwards and backwards, and return every way of doing so. Each answer is the list of pieces in order; joined together they give back s.

Running example: s = "aab". The answer is [["a","a","b"], ["aa","b"]]. The pieces "ab" and "aab" are not palindromes, so b is always alone at the end.

A partition is decided entirely by where the cuts go. Between three characters there are two gaps, each cut or not, so "aab" has 2^2 = 4 candidate partitions and only two survive. The job is to enumerate partitions without building the ones that are doomed.

STEP 2

First instinct: every cut set, then check every piece

I can use a bitmask over the gaps, I build the resulting pieces, and retain that partition only when every piece is a palindrome.

def partition(s):    result = []    for mask in range(1 << (len(s) - 1)):        pieces, start = [], 0        for i in range(len(s) - 1):            if mask >> i & 1: pieces.append(s[start:i + 1]); start = i + 1        pieces.append(s[start:])        if all(piece == piece[::-1] for piece in pieces): result.append(pieces)    return result

This is correct. There are 2^(n-1) cut sets, and building and checking their pieces takes O(n) work, so the time complexity is O(n · 2ⁿ). The result and built partitions use O(n · 2ⁿ) space.

I choose one piece at a time and test it before making the next cut. A failed early piece then prunes every partition that would extend it.

STEP 3

Key insight: choose the end of the current piece, and only if it is a palindrome

I build the partition left to right. At any moment, path holds palindrome pieces covering s[:start], and the only decision left is where the piece beginning at start ends. I try each end from start to len(s) - 1.

Before recursing, test is_palindrome(start, end) by walking two indices inward. If the test fails, I skip that end: no later cut can repair a piece that is already not a palindrome, so the entire subtree beneath it is gone in one comparison.

When start == len(s), every character is inside some palindrome piece and path is a complete answer. Copy it with path[:], since path keeps changing after the return.
STEP 4

The approach, line by line

  • is_palindrome(left, right) — while left < right, I compare s[left] with s[right]; any mismatch returns False.
  • backtrack(start) — if start == len(s), I record path[:] and return.
  • for end in range(start, len(s)) — every possible end of the piece that begins at start.
  • if is_palindrome(start, end) — prune before recursing.
  • path.append(s[start:end + 1]), backtrack(end + 1), path.pop() — choose, recurse, undo. The + 1 in the slice is because end is inclusive.
  • backtrack(0) then return result.

STEP 5

Trace: single characters all the way, ["a","a","b"]

backtrack(0): end = 0, piece "a". A single character is trivially a palindrome (left < right is false immediately), so I push "a" and call backtrack(1).

backtrack(1): end = 1, piece "a", palindrome. I push it, call backtrack(2). There, end = 2, piece "b", palindrome. I push it, call backtrack(3).

start == 3 == len(s), so ["a", "a", "b"] is copied into result. On the way back, backtrack(2) pops "b"; its loop had only that one end, so it returns too.
STEP 6

Trace: "ab" is rejected

Back in backtrack(1), "a" is popped and the loop moves to end = 2: the candidate piece is s[1..2] = "ab". is_palindrome(1, 2) compares s[1] = "a" with s[2] = "b": not equal, False.

Nothing is pushed and no recursive call is made. The partition ["a", "ab"] that the brute force would have built and then discarded never exists here. backtrack(1) has no more values of end, so it returns, and backtrack(0) pops its first "a".

The panel shows the failed candidate in the blue-and-dashed cells, with path back to just the first "a".

STEP 7

Trace: "aa" then "b", and "aab" rejected

backtrack(0) moves to end = 1: piece s[0..1] = "aa". is_palindrome(0, 1) compares s[0] with s[1], both "a", then left and right cross: True. I push "aa", call backtrack(2), which pushes "b" and reaches start == 3.

["aa", "b"] is recorded. I pop back to backtrack(0), end = 2: piece "aab". s[0] = "a" versus s[2] = "b": False, skipped. The loop is exhausted and the top-level call returns.

Six calls to backtrack and seven palindrome checks, producing exactly the two answers with no filtering step.
STEP 8

Where this goes wrong

Slicing s[start:end] instead of s[start:end + 1]. The palindrome check treats end as inclusive, but a Python slice excludes its stop index, so every piece loses its last character. The recursion still advances correctly, so the answer has the right shape with the wrong contents: "aab" returns [["", "", ""], ["a", ""]].

Forgetting path.pop(). The pieces of the first partition are never removed, so the second one comes out as ["a", "a", "b", "aa", "b"].

Recursing with backtrack(end). For end == start that calls backtrack(start) again with the same argument, and the recursion never terminates.

Dropping the palindrome check. Every cut set is emitted: 4 partitions for "aab", including ["a", "ab"] and ["aab"].

end is inclusive everywhere: the check uses (start, end), the slice uses end + 1, and the next piece starts at end + 1.
STEP 9

Time and space

A string of one repeated letter has every cut set valid, so there can be 2^(n-1) answers, each copied in O(n). Every is_palindrome call is O(n) too, and there are O(2ⁿ) of them across the tree. That bounds the recursion at O(2ⁿ · n); it cannot beat the size of its own output.

ApproachTimeSpace
Every cut set, validate afterO(2ⁿ · n) alwaysO(n) per candidate + output
Backtracking with inline palindrome checkO(2ⁿ · n) worst, prunes dead prefixesO(n) stack + output
Backtracking + precomputed pal[i][j]O(n²) table + O(2ⁿ · n) outputO(n²) table + O(n) stack + output

The table version makes each check O(1), which matters when many partitions share the same substrings. For n <= 16 the inline check is fine.

STEP 10

The final solution

  • is_palindrome(left, right) — two indices walking inward; inclusive on both ends.
  • if start == len(s): result.append(path[:]) — every character is covered; copy the partition.
  • for end in range(start, len(s)) — where might the piece at start end?
  • if is_palindrome(start, end) — only a palindrome may be a piece; prune the rest.
  • path.append(s[start:end + 1]) — choose the piece (inclusive slice).
  • backtrack(end + 1) — continue from the next uncovered character.
  • path.pop() — undo, so the next end starts from the same prefix.
  • backtrack(0) and return result.
One-line summary to remember: for the piece starting at start, I try every end that makes a palindrome, recurse from end + 1, and record when start reaches the end of the string.
