Redundant Connection, narrated

I will first search the current graph before adding each edge, then store its connectivity in a union-find.

Pattern used Graph union-find: an edge whose endpoints already share a root closes a cycle

STEP 1

The problem

A tree with n nodes has exactly n - 1 edges and no cycles. Somebody added one more undirected edge, so the graph now has n edges and exactly one cycle. We are handed the edge list and must return the edge to delete so that what remains is a tree again.

Several edges might do the job, because deleting any edge on the cycle breaks it. The tie-break is fixed by the problem: return the candidate that appears last in the input.

Running example: edges = [[1,2],[2,3],[3,4],[1,4],[1,5]]. The cycle is 1-2-3-4-1. Its edges are [1,2], [2,3], [3,4], [1,4]; the last of those in the input is [1,4]. [1,5] appears even later but is not on the cycle, so it does not qualify.

Nodes are labelled 1 to n, not 0 to n-1. That detail will matter when we size an array.

STEP 2

First instinct: add edges one by one and search

I can ask whether an edge's endpoints already connect through the edges I have added; if so, that edge is redundant.

def findRedundantConnection(edges):    graph = defaultdict(list)    for a, b in edges:        if dfs(graph, a, b, set()): return [a, b]        graph[a].append(b); graph[b].append(a)

This is correct. Each DFS can traverse O(n) edges, and it runs once per input edge, so the time complexity is O(n²). The graph and DFS visited set use O(n) space.

Union-find avoids repeated connectivity checks: each edge either merges two roots or is the first edge whose roots already match.

STEP 3

The key insight: track components, not paths

I never need the path from a to b; I only need to know whether they are in the same component. A union-find (disjoint set) structure answers exactly that: every node stores a parent pointer, following pointers upward ends at a root, and two nodes are connected if and only if they have the same root.

Adding a tree edge is then a merge: point one root at the other. Detecting the redundant edge is a comparison: find(a) == find(b) before merging.

Every node starts as its own root: parent = [0, 1, 2, 3, 4, 5]. Slot 0 is unused padding; there are len(edges) + 1 slots so that node n has one.

The one refinement is path halving inside find: parent[x] = parent[parent[x]] re-points each node at its grandparent as I climb, so chains flatten as they are used. That is what makes each operation effectively constant time.

STEP 4

The approach: find, compare, union

The loop is three lines, and the order of those lines is the whole algorithm:

  • root_a, root_b = find(a), find(b) — climb to each endpoint's representative first.
  • if root_a == root_b: return [a, b] — same representative means an earlier path already joins them; this edge is the extra one.
  • parent[root_b] = root_a — otherwise merge, by hanging root under root, so every node of b's tree follows.

Because edges are processed in input order, the check fires on the last edge of the cycle to appear, which is precisely the tie-break the problem wants. No extra bookkeeping is needed for it.

STEP 5

Trace it: edges [1,2] and [2,3]

Edge [1,2]: find(1) = 1 and find(2) = 2, different roots, so union: parent[2] = 1. The array is now [0, 1, 1, 3, 4, 5].

Edge [2,3]: find(2) climbs 2 → 1 and returns 1; find(3) = 3. Different again, so parent[root_b] = root_a sets parent[3] = 1. Note it is parent[3], the root of 3's component, that gets re-pointed, and it points at 1, the root of 2's component, not at 2 itself.

After two edges: parent = [0, 1, 1, 1, 4, 5]. Nodes 1, 2, 3 form one component with root 1; nodes 4 and 5 are still singletons.

STEP 6

Trace it: edge [3,4]

find(3): parent[3] = 1 and parent[1] = 1, so the climb stops at 1. find(4) = 4, still its own root.

1 != 4, so merge: parent[4] = 1. The component rooted at 1 now holds nodes 1, 2, 3, 4, and parent = [0, 1, 1, 1, 1, 5]. Every node in it points straight at the root, so the next find calls on them take a single step.

In the figure, a path 1-2-3-4 exists, so nodes 1 and 4 are already connected. Any later edge between two of these four nodes will be the answer.

STEP 7

Trace it: edge [1,4] closes the cycle

find(1) returns 1 immediately, since parent[1] == 1. find(4): parent[4] = 1, one step up, and parent[1] == 1, so it returns 1 as well.

root_a == root_b, both are 1. The endpoints were already connected by 1-2-3-4, so adding [1,4] creates the cycle. The function returns [1, 4] without looking at [1,5] at all.

The quadratic version would have run four separate DFS searches to reach this point. Union-find did four constant-time lookups and three pointer writes.
STEP 8

Where this goes wrong: order of union and check, and array size

Merging before comparing. If I write the union first, parent[find(b)] = find(a), and then test if find(a) == find(b), the test is true for every edge because I just made it true. The loop returns on the first iteration: [1, 2] instead of [1, 4]. The panel shows the array after that premature union.

Sizing the array for 0-indexed nodes. parent = list(range(len(edges))) gives five slots, indices 0 to 4. Node 5 exists in the example, and the very last edge [1,5] would evaluate parent[5]: IndexError. In this example the answer is found before that edge, which is exactly why the bug survives a quick test; the last test case in the suite puts node n in the final edge to catch it.

I compare roots first, merge second, and give parent exactly n + 1 slots because the labels start at 1.
STEP 9

Time and space

Each edge costs two find calls and at most one write. With path halving, a find is amortised O(α(n)), the inverse Ackermann function, which is at most 4 for any input that fits in memory. So the loop is effectively O(n) time. The parent array is O(n) space.

ApproachTimeSpace
DFS before every edgeO(n²)O(n) adjacency + stack
Union-find, no compressionO(n log n) typical, O(n²) worstO(n)
Union-find + path halvingO(n α(n)) ≈ O(n)O(n)

Path halving is one extra assignment inside the while loop of find. It is the cheapest way to get the near-constant bound; union by rank would achieve the same guarantee with an extra array.

STEP 10

The final solution

Every line maps to a step above.

  • parent = list(range(len(edges) + 1)) — every node is its own root; n + 1 slots because labels run 1 to n.
  • while parent[x] != x — climb until a node that is its own parent; that is the root.
  • parent[x] = parent[parent[x]] — I use path halving, which skips a level so my next climb is shorter.
  • root_a, root_b = find(a), find(b) — resolve both endpoints before touching anything.
  • if root_a == root_b: return [a, b] — already connected, so this edge is the redundant one.
  • parent[root_b] = root_a — otherwise merge the two components at their roots.
One-line summary to remember: the redundant edge is the first one whose endpoints already share a root.
