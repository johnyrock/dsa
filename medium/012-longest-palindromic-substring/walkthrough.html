Longest Palindromic Substring, narrated

Scroll through the thinking, from testing every substring to expanding outward from each of the 2n − 1 centres, with the state of the algorithm shown alongside.

Pattern used Two Pointers expand outward from each of the 2n - 1 centres while the ends match

STEP 1

The problem

You get a string. Return the longest contiguous piece of it that reads the same forwards and backwards. Ties can be broken any way you like.

Running example: s = "babad". The answer is "bab", and "aba" is equally correct.

A single character is a palindrome, so for a non-empty string the answer is never empty. The interesting part is finding the long ones without checking every substring.

STEP 2

First instinct: test every substring

For every start and every end, check whether that slice is a palindrome, and keep the longest that passes.

best = ""for i in range(n):    for j in range(i, n):        sub = s[i:j + 1]        if sub == sub[::-1] and len(sub) > len(best):            best = sub

There are n² / 2 substrings and each palindrome check is O(n), so this is O(n³). At n = 1000 that is on the order of a hundred million character comparisons, and most of them re-check the same inner characters over and over.

STEP 3

Reframe: every palindrome has a centre

A palindrome is symmetric, so it has a middle. For odd length the middle is a character: "bab" is centred on the a. For even length the middle is the gap between two characters: "bb" in "cbbd" is centred between the two b's.

In a string of length n there are n character-centres and n − 1 gap-centres, so 2n − 1 centres in total. Instead of choosing a start and an end, choose a centre and grow outward.

If s[left+1 .. right-1] is a palindrome and s[left] == s[right], then s[left .. right] is a palindrome too. Each outward step reuses everything already confirmed.
STEP 4

The key idea: expand around each centre

For each index centre, run two expansions: one starting with left = right = centre (odd length) and one with left = centre, right = centre + 1 (even length). In each, move the pointers apart while both are in bounds and s[left] == s[right].

When the loop stops, the pointers have gone one step too far on each side, so the palindrome is s[left+1 : right] and its length is right − left − 1. Compare that with the best so far, remembering only a start and a length, and slice once at the very end.

STEP 5

Trace it: centre 1, the first "a"

Odd expansion from index 1: left = right = 1, s[1] == s[1], so step out to 0 and 2. s[0] = b and s[2] = b match, step out to −1 and 3. Now left is out of bounds, stop.

Length 3 − (−1) − 1 = 3, start −1 + 1 = 0. That is "bab", and best_len becomes 3.

The even expansion from the same centre compares s[1] = a with s[2] = b, which fails immediately: length 2 − 1 − 1 = 0, nothing to record.

STEP 6

Trace it: centre 2, the middle "b"

Odd expansion from index 2: s[1] = a and s[3] = a match, step out. s[0] = b and s[4] = d do not. Stop with left = 0, right = 4. Length 4 − 0 − 1 = 3, which is "aba".

3 is not greater than the current best of 3, so "bab" is kept. The remaining centres produce nothing longer. Return "bab".

The even expansions all fail on the first comparison in this string, which is why there is no even-length palindrome in "babad".
STEP 7

The pitfall: skipping the even centres

Take s = "cbbd". Every odd expansion stops at length 1: no character has matching neighbours on both sides. The answer "bb" is centred on the gap between indices 1 and 2, and only the even expansion with left = 1, right = 2 finds it.

Two expansions per index, not one. Drop the even one and every even-length palindrome is missed. The other classic slip is right − left + 1 for the length, which is off by two because the pointers have already overshot.

Check bounds before comparing characters. In Python s[-1] silently reads the last character instead of raising, which can make a palindrome appear to wrap around the string.

STEP 8

Time and space

2n − 1 centres, and an expansion from any of them takes at most n/2 steps: O(n²) time. In practice most expansions stop after one or two comparisons, so it is fast.

Two pointers, a start and a length: O(1) space. The final slice is the output.

ApproachTimeSpace
Every substring, check eachO(n³)O(1)
DP table is_pal[i][j]O(n²)O(n²)
Expand around centreO(n²)O(1)
Manacher's algorithmO(n)O(n)

Expand-around-centre is the expected interview answer. Manacher's is worth naming, rarely worth writing.

STEP 9

The final solution

Eleven lines. Every one of them maps to a step above.

  • best_start, best_len = 0, 0 records the answer without slicing until the end.
  • for centre in range(len(s)) visits every character-centre.
  • for left, right in ((centre, centre), (centre, centre + 1)) runs the odd and even expansions.
  • The while loop expands with bounds checked first.
  • length = right - left - 1 corrects for the overshoot.
  • return s[best_start:best_start + best_len].
One-line summary to remember: every palindrome has a centre; try all 2n − 1 of them and grow outward.
