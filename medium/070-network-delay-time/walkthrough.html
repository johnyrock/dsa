Network Delay Time, narrated

Scroll through the thinking, from relaxing every edge over and over to Dijkstra's algorithm with a min-heap, with the distances and the heap shown alongside as nodes settle.

Pattern used Graph Dijkstra: pop the closest unsettled node from a min-heap, relax its edges, repeat

STEP 1

The problem

A network of n nodes is wired with directed, weighted edges: [u, v, w] means a signal leaving u arrives at v after w time units. At time 0 a signal is sent from node k, and it spreads along every outgoing edge in parallel. When has every node heard it?

Each node hears the signal at the time of its shortest path from k, since the earliest arrival is what counts. The network is done when the slowest of those shortest paths completes. If some node has no path from k at all, the answer is -1.

Running example: times = [[2,1,1],[2,3,1],[3,4,1]], n = 4, k = 2. Node 2 reaches 1 and 3 at time 1, and 3 passes the signal on to 4 at time 2. The answer is 2.

So the question is really two questions: the shortest time to each node, and then the maximum of those. The second part is one line. The first is single-source shortest paths.

STEP 2

First instinct: relax every edge until nothing changes

Start with dist[k] = 0 and every other distance at infinity. Then sweep over all the edges: if dist[u] + w beats dist[v], lower it. One sweep can only propagate the signal one hop further, so repeat the sweep n - 1 times.

dist = {node: float("inf") for node in range(1, n + 1)}dist[k] = 0for _ in range(n - 1):    for u, v, w in times:        if dist[u] + w < dist[v]:            dist[v] = dist[u] + w

This is Bellman-Ford, and it is correct. It even handles negative weights. But it costs O(n · E): for n = 100 and E = 6000 that is 600,000 relaxations, most of which compare two infinities and do nothing.

The waste has a name. Every sweep re-examines edges leaving nodes whose distance is already final. If we knew which node was "done" next, we could relax its edges exactly once.

STEP 3

The key insight: the closest unsettled node is already final

Weights are non-negative. So among all the nodes we have not settled yet, the one with the smallest tentative time cannot get any better: any other route to it must pass through some node that is at least as far away, then add a non-negative edge. That node is settled, and its outgoing edges need relaxing exactly once.

This is Dijkstra's algorithm. The only data structure question is how to find "the smallest tentative time" quickly, and a min-heap keyed on (time, node) does it in O(log n).

Seed the heap with (0, k): the source is reached at time 0. dist starts empty and only settled nodes are written into it, so node in dist means "already final".

Because we push a new entry every time we find a route to a node, the same node can appear in the heap more than once with different times. The smaller one is popped first and settles the node; when the larger one surfaces later, if node in dist: continue discards it. That single check replaces a decrease-key operation.

STEP 4

The approach: pop, settle, relax

The loop follows the insight line for line:

  • graph[u].append((v, w)) — an adjacency list, so each node's outgoing edges are found without scanning times.
  • d, node = heapq.heappop(heap) — the unsettled node with the smallest tentative time.
  • if node in dist: continue — a stale entry for a node that already settled; skip it.
  • dist[node] = d — settle it. This is the first and only write for this node.
  • heapq.heappush(heap, (d + w, nxt)) for every unsettled neighbour — relax the outgoing edges.
  • max(dist.values()) if len(dist) == n else -1 — all nodes settled means the slowest arrival is the answer; otherwise something was unreachable.

The panel shows the adjacency list built from the example: graph[2] = [(1, 1), (3, 1)], graph[3] = [(4, 1)], and nothing leaves 1 or 4.

STEP 5

Trace it: settle the source

Pop (0, 2). Node 2 is not in dist, so settle it: dist[2] = 0.

Relax its edges. graph[2] holds (1, 1) and (3, 1); neither neighbour is settled, so push (0 + 1, 1) and (0 + 1, 3). The heap is now [(1, 1), (1, 3)]. Two nodes are tied at time 1, and the tuple comparison breaks the tie on the node label, so 1 will come out first.

STEP 6

Trace it: settle nodes 1 and 3

Pop (1, 1). Node 1 is new, so dist[1] = 1. It has no outgoing edges, so nothing is pushed; the heap is [(1, 3)].

Pop (1, 3). Node 3 is new, so dist[3] = 1. Its one edge is (4, 1), and 4 is unsettled, so push (1 + 1, 4). The heap is [(2, 4)].

After this step dist = {2: 0, 1: 1, 3: 1}. Notice that dist is filled in increasing order of time. That is not a coincidence, it is the invariant that makes the first pop of each node final.

STEP 7

Trace it: settle node 4 and take the max

Pop (2, 4). Node 4 is new, so dist[4] = 2. It has no outgoing edges and the heap is now empty, so the while heap loop ends.

len(dist) is 4, equal to n, so every node received the signal. The delay is the slowest arrival: max(0, 1, 1, 2) = 2.

Four pops, three pushes. Bellman-Ford would have done three sweeps of three edges, nine relaxations, and most of them would have been wasted comparisons.
STEP 8

Where this goes wrong: edge direction and the reachability check

Building the edge backwards. Write graph[v].append((u, w)) instead of graph[u].append((v, w)) and every arrow flips. In the example nothing then leaves node 2: after settling the source the heap is empty, dist = {2: 0}, len(dist) is 1, and the function returns -1 instead of 2. The panel shows the flipped graph.

Skipping the len(dist) == n guard. Returning max(dist.values()) unconditionally is right whenever every node is reachable, which is every example that comes to mind first. For times = [[1,2,1]], n = 2, k = 2 only the source settles, and the answer becomes 0 instead of -1.

Dropping if node in dist: continue. With [[1,2,5],[1,3,1],[3,2,1]] node 2 is pushed as (5, 2) and later as (2, 2). The (2, 2) entry pops first and sets dist[2] = 2; without the guard, (5, 2) then overwrites it with 5.

[u, v, w] is u → v. A node is done the first time it is popped, never the second, and the answer is only a max if all n nodes made it into dist.
STEP 9

Time and space

Each edge pushes at most one heap entry, so the heap never holds more than E items and there are at most E pops. Each heap operation is O(log E), giving O(E log E) time, which is the same as O(E log V) since E ≤ V². The adjacency list, heap, and dist take O(V + E) space.

ApproachTimeSpace
Bellman-Ford, n − 1 sweepsO(V · E)O(V)
Dijkstra, scan for the minimumO(V²)O(V + E)
Dijkstra, min-heapO(E log V)O(V + E)

For a dense graph the O(V²) array scan is competitive; for the sparse graphs typical of this problem the heap wins clearly.

STEP 10

The final solution

Every line maps to a step above.

  • graph[u].append((v, w)) — adjacency list in the direction of the signal.
  • heap = [(0, k)] — the source is reached at time 0; dist starts empty.
  • d, node = heapq.heappop(heap) — the closest unsettled node.
  • if node in dist: continue — drop stale duplicates.
  • dist[node] = d — settle; the first pop is final because weights are non-negative.
  • heapq.heappush(heap, (d + w, nxt)) — relax each outgoing edge to an unsettled neighbour.
  • max(dist.values()) if len(dist) == n else -1 — slowest arrival, or unreachable.
One-line summary to remember: Dijkstra settles nodes in increasing time; the network delay is the time of the last one settled.
