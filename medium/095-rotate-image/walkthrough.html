Medium · Matrix · LeetCode #48

Rotate Image, narrated

Scroll through the thinking, from copying into a second matrix to the two-phase swap that rotates the image in place, with the state of the matrix shown alongside.

Pattern used Matrix a clockwise turn is a transpose followed by reversing every row

STEP 1

The problem

You are given an n × n matrix representing an image. Turn it 90 degrees clockwise. The function returns nothing: the input list must be modified in place, without allocating a second matrix.

Running example: matrix = [[1,2,3],[4,5,6],[7,8,9]]. After rotating, it must read [[7,4,1],[8,5,2],[9,6,3]].

Look at what moved. The left column 1, 4, 7 became the top row, but read bottom-up: 7, 4, 1. The top row 1, 2, 3 became the right column, read top-down. In general, cell (r, c) lands at (c, n - 1 - r): its row index becomes its column index, and its column index is flipped.

The in-place requirement is the whole difficulty. Reading from a fresh copy is easy; the interesting question is how to move every cell to its destination while the destination is still holding a value that has not been moved yet.

STEP 2

First instinct: build a second matrix

The formula (r, c) → (c, n - 1 - r) translates directly into a copy loop:

rotated = [[0] * n for _ in range(n)]for r in range(n):    for c in range(n):        rotated[c][n - 1 - r] = matrix[r][c]matrix[:] = rotated

This is correct and O(n²) time, which is optimal since every cell has to move. But it allocates a whole second n × n matrix, so the space is O(n²), and the problem says not to do that. The final matrix[:] = rotated only copies the answer back; it does not make the algorithm in-place.

The fix is not to find a cleverer formula. It is to notice that the rotation can be split into moves that each swap two cells, and a swap never needs more than one temporary.

STEP 3

The key insight: transpose, then reverse each row

Compare the target [[7,4,1],[8,5,2],[9,6,3]] with the transpose of the input, [[1,4,7],[2,5,8],[3,6,9]]. Each row of the transpose is the same numbers as the row of the answer, just in the opposite order. Row 0 of the transpose is 1, 4, 7; row 0 of the answer is 7, 4, 1.

A clockwise rotation is a transpose (swap (r, c) with (c, r)) followed by reversing every row. Both halves are pure swaps inside the matrix, so neither needs extra memory.

Why does it work? The transpose turns column c into row c, read top-to-bottom. The rotation also puts column c into row c, but read bottom-to-top. Reversing the row fixes exactly that difference. Composing the two moves: (r, c) → (c, r) → (c, n - 1 - r), which is the rotation formula from step 1.

STEP 4

The approach: two loops, both in place

  • n = len(matrix) — square, so one dimension serves both loops.
  • for r in range(n): for c in range(r + 1, n): — visit every cell strictly above the main diagonal, once.
  • matrix[r][c], matrix[c][r] = matrix[c][r], matrix[r][c] — swap it with its mirror below the diagonal. Tuple assignment reads both before writing either.
  • for row in matrix: row.reverse() — flip each row end to end, in place.

The inner range starting at r + 1 is the important detail. The pair (0, 1) and (1, 0) is one swap; if the loop also visited (1, 0) it would swap the same pair back. Starting above the diagonal visits each pair exactly once, and the diagonal cells (0,0), (1,1), (2,2) stay put, which is right, since transposing never moves them.

STEP 5

Trace it: transpose, row 0

With r = 0 the inner loop runs c = 1, 2. First swap: matrix[0][1] (the 2) and matrix[1][0] (the 4) exchange, so row 0 becomes 1, 4, 3 and row 1 becomes 2, 5, 6.

Second swap: matrix[0][2] (the 3) and matrix[2][0] (the 7) exchange. Now the matrix is [[1,4,7],[2,5,6],[3,8,9]]. Row 0 already reads 1, 4, 7, which is the original left column: it has been turned into a row.

The dashed diagonal cells 1, 5, 9 were never touched. Every swap pairs one cell above the diagonal with one below it.

STEP 6

Trace it: transpose, row 1, and the phase ends

With r = 1 the inner loop is range(2, 3), a single value c = 2. Swap matrix[1][2] (the 6) with matrix[2][1] (the 8). The matrix is now [[1,4,7],[2,5,8],[3,6,9]], the full transpose.

With r = 2 the inner loop is range(3, 3), which is empty. Nothing to do: the last row has no cells above the diagonal. Three swaps in total for a 3 × 3 matrix, which is n(n - 1) / 2 = 3.

Every original column is now a row, read top-to-bottom. Compare with the target: each row is the right numbers, backwards.
STEP 7

Trace it: reverse every row, the answer

row.reverse() on row 0 turns 1, 4, 7 into 7, 4, 1. Row 1: 2, 5, 8 becomes 8, 5, 2. Row 2: 3, 6, 9 becomes 9, 6, 3.

The matrix now reads [[7,4,1],[8,5,2],[9,6,3]], which is the expected output. Nothing is returned; the caller's list object was mutated through both phases, and at no point did a second matrix exist.

Check one cell against the formula: the 3 started at (0, 2), and (c, n - 1 - r) = (2, 2). It is in the bottom-right corner. Correct.
STEP 8

Where this goes wrong

Transposing with range(n) instead of range(r + 1, n). Now the loop visits (0, 1) and swaps it with (1, 0), then later visits (1, 0) and swaps it with (0, 1) again. Every pair is swapped twice, which is no transpose at all. The matrix is unchanged going into the reverse phase, and the output is [[3,2,1],[6,5,4],[9,8,7]]: a mirror image, not a rotation. On the running example nothing crashes, so this passes a quick eyeball.

Reversing the rows first, then transposing. The two phases do not commute. Reverse first and you get [[3,2,1],[6,5,4],[9,8,7]], transpose that and you get [[3,6,9],[2,5,8],[1,4,7]], which is the counter-clockwise rotation. Same for reversing columns instead of rows after the transpose.

Returning a new list. return [list(col)[::-1] for col in zip(*matrix)] produces the right numbers, but the caller's matrix still holds the original. Any test that inspects the list it passed in sees [[1,2,3],[4,5,6],[7,8,9]].

Each transpose swap must happen once, so only walk the cells above the diagonal. Transpose first, reverse rows second, for clockwise.
STEP 9

Time and space

The transpose performs n(n - 1) / 2 swaps and the reverse phase touches every cell once more, so O(n²) time, which is unavoidable because every cell has to move. The only extra storage is the tuple-swap temporary and the loop indices: O(1) space.

ApproachTimeExtra space
Copy into a new matrixO(n²)O(n²)
Four-way cycle per layerO(n²)O(1)
Transpose + reverse rowsO(n²)O(1)

The four-way cycle (move each cell through (r,c) → (c,n-1-r) → (n-1-r,n-1-c) → (n-1-c,r) one layer at a time) is equally in-place but has four index expressions to get right. Transpose-and-reverse does the same job with two loops anyone can write from memory.

STEP 10

The final solution

Seven lines. Every one of them maps to a step above.

  • n = len(matrix) — the side length.
  • for r in range(n): for c in range(r + 1, n): — each above-diagonal cell once.
  • matrix[r][c], matrix[c][r] = matrix[c][r], matrix[r][c] — the transpose swap.
  • for row in matrix: row.reverse() — flip each row in place.
  • No return: the mutation is the result.
One-line summary to remember: clockwise 90° = transpose, then reverse each row; both are in-place swaps.
