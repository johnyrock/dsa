Medium · Hash Set · LeetCode #36

Valid Sudoku, narrated

Scroll through the thinking, from re-scanning a row, a column, and a box for every cell to one pass over the board with 27 sets, with the state of the algorithm shown alongside.

Pattern used Hash Set one set of seen digits per row, per column, and per 3x3 box; check all three, then record in all three

STEP 1

The problem

You get a 9x9 board. Each cell is a digit '1' to '9' or a '.' for empty. Report whether the filled cells respect the three sudoku rules: no digit repeats in any row, in any column, or in any of the nine 3x3 boxes.

Running example: LeetCode's first board, 30 filled cells, shown in the panel. It is valid, so the answer is true. The same board with the top-left 5 changed to 8 is invalid, because (2, 2) already holds an 8 in the same box.

Only the digits that are present are checked. A board with a single 7 on it is valid; so is a completely empty board. Whether the puzzle can be solved is a different question and not asked here.

The wording says "rows, columns, boxes" three times, and that is the whole structure of the answer: every filled cell belongs to exactly one row, one column, and one box, and it must be the only copy of its digit in each of the three.

STEP 2

First instinct: for each cell, re-scan its groups

For every filled cell, walk its whole row, its whole column, and its whole box looking for the same digit anywhere else.

for r in range(9):    for c in range(9):        v = board[r][c]        if v == ".": continue        for k in range(9):            if k != c and board[r][k] == v: return False            if k != r and board[k][c] == v: return False        br, bc = 3 * (r // 3), 3 * (c // 3)        for i in range(br, br + 3):            for j in range(bc, bc + 3):                if (i, j) != (r, c) and board[i][j] == v: return Falsereturn True

Correct, and on a 9x9 board it finishes instantly: 81 cells times 27 comparisons is about 2 000 operations. The complexity is O(n³) for an n x n board, and every pair of cells in a group is compared twice, once from each side.

The wasted work is the re-scanning. When we reach the 9 at (2, 1), we walk box 0 again even though we already walked it for (0, 0), (0, 1), (1, 0), and (2, 2). What we want is a record of what has already been seen in each group.

STEP 3

The key insight: 27 sets of seen digits

There are 9 rows, 9 columns, and 9 boxes: 27 groups. Give each group a set. As the board is read once in order, each digit is checked against the three sets it belongs to, and then added to those same three sets.

A set membership test is O(1), so the per-cell cost drops from 27 comparisons to 3 lookups and 3 inserts, and every cell is visited exactly once.

The one line that needs thought is the box number. r // 3 is which band of rows (0, 1, 2) the cell is in, c // 3 is which stack of columns. (r // 3) * 3 + c // 3 combines them into 0–8, numbering the boxes like the cells of a 3x3 grid: top row 0 1 2, middle 3 4 5, bottom 6 7 8.

Check it on the running example: (2, 1) is in band 0, stack 0, box 0 * 3 + 0 = 0. (3, 4) is band 1, stack 1, box 1 * 3 + 1 = 4, the centre box. (2, 7) is band 0, stack 2, box 2.

STEP 4

The approach, line by line

  • rows, cols, boxes — three lists of nine empty sets each.
  • for r in range(9): for c in range(9) — visit every cell in reading order.
  • if value == ".": continue — empty cells impose no constraint and must not be recorded.
  • box = (r // 3) * 3 + c // 3 — which of the nine boxes this cell is in.
  • if value in rows[r] or value in cols[c] or value in boxes[box]: return False — any repeat anywhere is a violation.
  • rows[r].add(value), cols[c].add(value), boxes[box].add(value) — record the digit in all three groups.
  • return True — every filled cell was consistent with everything before it.

The check comes before the insert. Each digit is compared against what earlier cells put in the sets, never against itself.

STEP 5

Trace it: the first cell, (0, 0) = 5

All 27 sets start empty. The first cell is board[0][0] = "5". Its box is (0 // 3) * 3 + 0 // 3 = 0.

Check: "5" in rows[0] is false, "5" in cols[0] is false, "5" in boxes[0] is false. No violation, so record it: rows[0] = {5}, cols[0] = {5}, boxes[0] = {5}.

The next cell, (0, 1) = "3", is checked against rows[0] = {5}, cols[1] = {}, and boxes[0] = {5}. Also fine, and all three sets grow. The panel highlights the row, column, and box a cell is being checked against.

STEP 6

Trace it: (2, 1) = 9, where the box set has content

By the time the loop reaches row 2, column 1, the top-left box has already collected the 5, 3, and 6 from rows 0 and 1. Column 1 has the 3 from (0, 1). Row 2 is fresh, since (2, 0) is empty.

So the three lookups are: "9" in rows[2] = {} false, "9" in cols[1] = {3} false, "9" in boxes[0] = {3, 5, 6} false. Record it: boxes[0] becomes {3, 5, 6, 9}.

This is the cell where the brute force would have re-walked nine box cells. Here the whole history of the box is one set lookup.

STEP 7

Trace it: (3, 4) = 6 in the centre box, then the end

Row 3, column 4 holds a 6. Its box is (3 // 3) * 3 + 4 // 3 = 3 + 1 = 4, the centre box, which is empty so far. The row set rows[3] holds {8} from (3, 0), and the column set cols[4] holds {7, 9} from (0, 4) and (1, 4).

There is a 6 at (2, 7) only one row up, but that cell is in row 2, column 7, box 2: none of the groups of (3, 4). The three lookups all return false, and the 6 is recorded.

The remaining 20 filled cells all pass the same way. The loop finishes without ever returning early, and the function returns True.

30 filled cells, 90 lookups, 90 inserts, no re-scanning. Each cell was visited once.
STEP 8

Where this goes wrong: the box index

Writing r // 3 + c // 3 without the * 3. That expression only produces 0 to 4, so nine boxes are squeezed into five buckets, and boxes on the same anti-diagonal are merged. Box 2 (top right), box 4 (centre), and box 6 (bottom left) all get key 2.

On the valid running example this returns False. The 6 at (2, 7) in box 2 is recorded under key 0 + 2 = 2. When the loop reaches the 6 at (3, 4) in box 4, its key is 1 + 1 = 2 too, the lookup finds the earlier 6, and a legal board is rejected.

Not skipping the dots. Drop if value == ".": continue and the second empty cell in row 0, at (0, 3), is a "repeat" of the '.' at (0, 2): False on every real board.

Inserting before checking. Swap the add lines above the if, and the very first digit is found in its own sets: False at (0, 0).

Test the box index on two cells in different boxes that share neither row nor column, such as (0, 6) and (3, 3): they must get different numbers.
STEP 9

Time and space

One visit per cell with a constant amount of work: O(n²) for an n x n board, which for the fixed 9x9 is 81 steps, O(1). The 27 sets hold at most 9 digits each: O(n²) in general, a constant 243 slots here.

ApproachTimeSpace
Re-scan row, column, box per cellO(n³)O(1)
27 hash sets, one passO(n²)O(n²)
27 bitmasks, one passO(n²)27 integers

For a 9x9 board all three are instantaneous. The set version is the one to write because it names the idea clearly; the bitmask version is the same algorithm with 1 << (int(value) - 1) in place of each set.

STEP 10

The final solution

Sixteen lines. Every one of them maps to a step above.

  • rows, cols, boxes = [set() for _ in range(9)] are the 27 groups.
  • The double for loop reads the board once.
  • if value == ".": continue leaves empty cells out of the sets.
  • box = (r // 3) * 3 + c // 3 numbers the boxes 0–8 in reading order.
  • if value in rows[r] or value in cols[c] or value in boxes[box]: return False is the whole rule.
  • Three add calls record the digit, and return True after the loop means nothing ever clashed.
One-line summary to remember: each digit lives in one row, one column, and one box; check its three sets, then join them.
