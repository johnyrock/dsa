Serialize and Deserialize Binary Tree, narrated

Scroll through pre-order encoding with explicit null markers, and why that alone is enough to rebuild the exact shape.

Pattern used Tree pre-order + null markers records every branching decision, so decode replays it exactly

STEP 1

The problem

Encode a binary tree to a string and decode it back to the exact same shape.

Running example: [1,2,3,null,null,4,5] — 1's children are 2 and 3; 3's children are 4 and 5; 2 is a leaf.
STEP 2

First instinct: just write the values

A plain pre-order value list, 1,2,3,4,5, is ambiguous — many different tree shapes share that same pre-order sequence. Something has to record where the None children are.

STEP 3

The key idea: null markers make it unambiguous

Write an explicit token ("N") for every None child during a pre-order walk. Now every branching decision — does this node have a left child? a right child? — is recorded in the stream, in a fixed, replayable order.

STEP 4

Trace serialize

dfs(1): write "1", recurse left into 2 (write "2", its children are None -> "N","N"), recurse right into 3 (write "3", recurse into 4 -> "4","N","N", then into 5 -> "5","N","N"). Stream: 1,2,N,N,3,4,N,N,5,N,N.

STEP 5

Trace deserialize

An iterator over the split tokens lets each recursive call consume exactly its own subtree's tokens. build() reads "1" -> node(1). Its left call reads "2", then its own left/right calls each read "N" -> None, None. Back at node 1, the right call reads "3", and so on — token order exactly mirrors the write order.

STEP 6

Where this goes wrong

Using a manual index instead of an iterator is a common source of off-by-one bugs — forgetting to increment it on one branch desyncs every read after it. Building right before left, or in any order that doesn't mirror how serialize wrote them, reconstructs a different (wrong) tree from the same valid-looking token stream.

STEP 7

Time and space

O(n) time for both directions. O(n) space for the string, plus O(h) recursion depth.

STEP 8

The final solution

  • serialize: pre-order walk, write "N" for every None.
  • deserialize: an iterator lets each recursive call consume exactly the tokens for its own subtree.
  • Reading order (node, then left, then right) must mirror the writing order exactly.
