Word Search, narrated

Scroll through the thinking, from enumerating every path on the board to a depth-first search that marks cells in place and unmarks them on the way back, with the state of the algorithm shown alongside.

Pattern used Backtracking DFS from every cell; mark #, try four neighbours, restore

STEP 1

The problem

You have an m × n grid of letters and a word. Decide whether the word can be spelled by starting on any cell and stepping to a horizontally or vertically adjacent cell for each next letter. No cell may be used twice in one spelling.

Running example: the 3 × 4 board on the right and word = "ABCCED". The answer is true: (0,0) A → (0,1) B → (0,2) C → (1,2) C → (2,2) E → (2,1) D.

There is no arithmetic here, only a search. The question is how to explore paths without exploring the same wrong ones over and over, and how to stop a path from doubling back onto a cell it already used, since "ABCB" must be false even though every letter is next to the previous one.

STEP 2

Brute force: every path of the right length

Enumerate every simple path of len(word) cells, from every start, going in any of the four directions at each step, and compare the letters along it to the word at the end.

def paths(r, c, used, k):          # every simple path of length len(word) from (r, c)    if k == len(word): yield used; return    for nr, nc in neighbours(r, c):        if (nr, nc) not in used:            yield from paths(nr, nc, used + [(nr, nc)], k + 1)any("".join(board[r][c] for r, c in p) == word for start in cells for p in paths(*start, [start], 1))

There are up to m · n starts and up to 4 · 3^(L-1) paths from each, so this is O(m · n · 4 · 3^(L-1) · L) with the final comparison. On a 6 × 6 board with a 15-letter word that is tens of millions of paths, almost all of which have the wrong first or second letter and could have been abandoned immediately.

The wasted work is obvious once named: a path whose second cell is S cannot spell "AB…", yet the brute force keeps walking it for thirteen more steps.

STEP 3

Key insight: check one letter at a time, and mark the board itself

Turn the enumeration into a recursion that fails early: dfs(r, c, k) asks "can word[k:] be spelled starting at (r, c)?". If (r, c) is off the board or board[r][c] != word[k], the answer is False at once; no deeper path is ever built.

To stop the path from reusing a cell, overwrite it: set board[r][c] = "#" before recursing into the neighbours. Because "#" is never a letter of word, any neighbour call that lands back on this cell fails the letter check automatically. No visited set, no extra memory.

The mark must be temporary. After the four neighbour calls return, restore board[r][c] = saved. A cell that sat on a failed path is still perfectly usable by a different path, and the restore is what makes it available again.
STEP 4

The approach, line by line

  • if k == len(word): return True — every letter has been matched. This check comes first, before the bounds check, so a completed word is accepted even when the next cell would be off the board.
  • if r < 0 or r >= rows or c < 0 or c >= cols or board[r][c] != word[k]: return False — out of bounds, wrong letter, or a "#" from the current path.
  • saved = board[r][c]; board[r][c] = "#" — mark.
  • found = dfs(r + 1, c, k + 1) or dfs(r - 1, c, k + 1) or dfs(r, c + 1, k + 1) or dfs(r, c - 1, k + 1) — down, up, right, left. The or short-circuits on the first success.
  • board[r][c] = saved — restore, then return found.
  • Outer loop: dfs(r, c, 0) from every cell; return True on the first hit, False if none.

STEP 5

Trace: A, then B

The outer loop starts at (0, 0), which holds A. dfs(0, 0, 0): k = 0, board[0][0] == "A" == word[0], so mark it # and try the neighbours for k = 1.

Down is (1, 0) = S, not B: False immediately. Up is (-1, 0), off the board: False. Right is (0, 1) = B, which matches word[1], so this call marks (0, 1) and goes on to look for C.

Two of the four directions died on a single comparison each. The brute force would have walked five more cells down both of them.
STEP 6

Trace: C, then the second C

From B at (0, 1), looking for word[2] = "C": down is (1, 1) = F, fail; up is off the board; right is (0, 2) = C, match. Mark it and look for word[3] = "C" again.

From (0, 2), the very first direction, down, is (1, 2) = C. Match on the first try; mark it, and now four of six letters are on the path. Left from here would be (1, 1) = F and up would be (0, 2) = #, but we never get to test them because the successful branch returns first.

The path so far is (0,0) (0,1) (0,2) (1,2), all four showing # on the real board, though the panel keeps the letters visible in green.

STEP 7

Trace: E, D, and the base case

From (1, 2) looking for word[4] = "E": down is (2, 2) = E, match. From (2, 2) looking for word[5] = "D": down is (3, 2), off the board; up is (1, 2), which now reads #, so the path cannot double back; right is (2, 3) = E, wrong letter; left is (2, 1) = D, match.

Inside dfs(2, 1, 5) the cell is marked and the four neighbours are called with k = 6. The first of them, dfs(3, 1, 6), hits k == len(word) and returns True before any bounds check runs, even though (3, 1) is off the board.

True propagates up through every or, each frame restoring its cell on the way, and the outer loop returns true. Fourteen calls to dfs in total.
STEP 8

Where this goes wrong

Forgetting the restore. Drop board[r][c] = saved and every cell touched by a failed attempt stays #. Search the same board for "CCB": the scan reaches (0, 2) = C first, marks it, steps down to (1, 2) = C, marks that, finds no B beside it, and gives up with both cells still #. The real path (1,2) → (0,2) → (0,1) is now unreachable, and exist returns false instead of true. The panel shows the two dead cells struck through.

Not marking at all. Without the #, a path may step back onto a cell it already used. "ABCB" goes A → B → C → B by returning to (0, 1) and the function returns true instead of false.

Bounds check before the base case. If k == len(word) is tested after the bounds check, a word whose last letter sits where every neighbour is off the board or already used can only be confirmed by a call that gets rejected first. Test completion first.

Mark before the neighbour calls, restore after them, and test k == len(word) before anything else.
STEP 9

Time and space

Every cell can be a start: m · n of them. After the first step, a call has at most three unvisited neighbours (it cannot go back where it came from), so a single start explores at most 3^L paths of length L. The letter check cuts almost all of them off early.

ApproachTimeSpace
Enumerate every path, compare at the endO(m · n · 4 · 3^(L-1) · L)O(L) per path
DFS with a separate visited setO(m · n · 3^L)O(L) set + O(L) stack
DFS marking the board in placeO(m · n · 3^L)O(L) stack only

Marking in place removes the set but not the exponential term. Real speedups come from pruning before the search, such as refusing early when the board lacks enough copies of some letter in word.

STEP 10

The final solution

  • if k == len(word): return True — all letters matched.
  • if r < 0 or r >= rows or c < 0 or c >= cols or board[r][c] != word[k]: return False — off the board, wrong letter, or on the current path.
  • saved = board[r][c]; board[r][c] = "#" — mark the cell as used.
  • found = dfs(r + 1, c, k + 1) or dfs(r - 1, c, k + 1) or dfs(r, c + 1, k + 1) or dfs(r, c - 1, k + 1) — four directions, first success wins.
  • board[r][c] = saved and return found — restore and report.
  • for r … for c … if dfs(r, c, 0): return True, then return False.
One-line summary to remember: from every cell, match one letter, mark, try four neighbours, unmark — the board is its own visited set.
