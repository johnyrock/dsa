Combination Sum II, narrated

Scroll through the thinking, from testing every subset to a sorted recursion that skips duplicate values and stops early, with the state of the algorithm shown alongside.

Pattern used Backtracking sort, choose from start onward, recurse with i + 1, skip equal neighbours at the same level

STEP 1

The problem

You are given a list candidates that may contain the same value more than once, and a target. Return every distinct combination of candidates that sums to target. Each position in the list may be used at most once, and two combinations count as the same if they contain the same numbers, in any order.

Running example: candidates = [10,1,2,7,6,1,5], target = 8. The answer is [[1,1,6],[1,2,5],[1,7],[2,6]], four combinations.

Two things make this harder than it looks. The list has two 1s, and they are genuinely different positions, so [1,1,6] is a legal answer. But [1,7] built with the first 1 and [1,7] built with the second 1 are the same combination, and the output must contain it once.

So the job is enumeration with two rules: never reuse a position, and never emit the same multiset twice.

STEP 2

Brute force: every subset, then deduplicate

Seven candidates means 2^7 = 128 subsets. Generate every one with a bitmask, keep those whose sum is 8, sort each survivor, and drop it into a set to squash duplicates.

seen = set()for mask in range(1 << len(candidates)):    chosen = [candidates[i] for i in range(len(candidates)) if mask >> i & 1]    if sum(chosen) == target:        seen.add(tuple(sorted(chosen)))return [list(t) for t in seen]

It is correct, and it takes O(2ⁿ · n) time regardless of the target. At the upper constraint of 100 candidates that is 2^100 masks, which never finishes. Almost all of that work is wasted: most subsets overshoot 8 within their first few elements, and the deduplication happens after the fact instead of being avoided.

The two fixes we want are: stop extending a partial sum the moment it cannot reach target, and never generate the second copy of a combination at all.

STEP 3

Key insight: sort, then walk forward with two prunes

Sort the candidates: [1,1,2,5,6,7,10]. Now build every combination in ascending order by choosing an index i and only ever recursing on indices after it. That one rule, backtrack(i + 1, …), guarantees no position is reused and that [2,6] and [6,2] cannot both appear, because only the ascending one is ever built.

Sorting also unlocks two prunes in the loop:

  • if candidates[i] > remaining: break — every later value is at least as big, so nothing past this index can fit. This is a break, not a continue.
  • if i > start and candidates[i] == candidates[i - 1]: continue — a value equal to its left neighbour, at the same level of the recursion, would rebuild exactly the combinations the neighbour already built. Skip it.
The i > start half is the subtle part. When i == start, the equal value is the first option at this level, so it must be allowed even if it equals the value chosen one level up. That is what lets [1,1,6] exist while [1,7] appears once.
STEP 4

The approach, line by line

  • candidates.sort() puts equal values side by side and in ascending order.
  • backtrack(start, remaining) means: extend path using indices from start onward, with remaining still to fill.
  • if remaining == 0: record path[:] (a copy, since path keeps changing) and return.
  • Loop i from start; break if candidates[i] > remaining; continue on an equal neighbour when i > start.
  • Choose: path.append(candidates[i]), recurse with backtrack(i + 1, remaining - candidates[i]), undo with path.pop().
  • Start from backtrack(0, target) and return result.

STEP 5

Trace: the first answer, [1, 1, 6]

From the root, start = 0, remaining = 8. Index 0 holds 1: choose it, recurse with start = 1, remaining = 7. Index 1 holds another 1; here i == start, so the duplicate skip does not fire and we choose it too: path = [1, 1], remaining = 6.

Now index 2 (2): path = [1, 1, 2], remaining = 4. The next value is 5 > 4, so the loop breaks at once and we pop the 2. Index 3 (5): remaining = 1, then 6 > 1 breaks it. Pop. Index 4 (6): 6 - 6 = 0.

remaining == 0, so [1, 1, 6] is copied into result. Back in the [1, 1] loop, index 5 holds 7 > 6: break.
STEP 6

Trace: [1, 2, 5] and [1, 7]

The second 1 is popped and we are back at path = [1], remaining = 7, scanning from index 2. Choose 2: remaining = 5. Then index 3 holds 5, and 5 - 5 = 0: record [1, 2, 5]. Index 4 is 6 > 5, break, pop the 2.

Index 3 alone: [1, 5] leaves remaining = 2, and 6 > 2 breaks. Index 4: [1, 6] leaves 1, and 7 > 1 breaks. Index 5: [1, 7] gives 7 - 7 = 0, record it. Index 6 is 10 > 7, break.

Notice how short each dead end is. Because the values are sorted, every failed branch dies on its very next comparison rather than scanning to the end of the list.

STEP 7

Trace: the duplicate skip, then [2, 6]

Pop the first 1. We are at the root loop with i = 1, start = 0. candidates[1] == candidates[0] and 1 > 0, so continue. Everything that starts with the second 1 is a repeat of what the first 1 already produced, and we skip it in one comparison.

Index 2 (2): remaining = 6. Choosing 5 leaves 1 and breaks; choosing 6 leaves 0, so [2, 6] is recorded; 7 > 6 breaks. Then [5], [6] and [7] each die on their next value, and 10 > 8 ends the root loop.

Seventeen calls to backtrack in total, against 128 subsets for the brute force, and no deduplication pass at the end.
STEP 8

Where this goes wrong

Skipping with i > 0 instead of i > start. The skip then also fires when the equal value is the first option at its level. After choosing the first 1, the second 1 at index 1 is refused, so [1, 1, 6] is never built. The running example returns 3 combinations, not 4.

Dropping the skip entirely. Both 1s open a branch at the root, and each finds [1, 2, 5] and [1, 7]. The output has 6 lists with two exact duplicates, which the problem forbids.

Recursing with backtrack(i, …) (the Combination Sum I call). Positions get reused, and the example returns 10 combinations, starting with [1,1,1,1,1,1,1,1].

Equal values are skipped only when they are not the first choice at their level: i > start, never i > 0. And always recurse on i + 1.
STEP 9

Time and space

In the worst case every subset is a distinct combination that sums to target, so the tree can still have O(2ⁿ) leaves, each copied in O(n). In practice the break kills most branches after one comparison and the skip removes whole duplicate subtrees.

ApproachTimeSpace
All subsets + set of sorted tuplesO(2ⁿ · n) alwaysO(2ⁿ · n) for the set
Backtracking, no prunes, dedupe at endO(2ⁿ · n)O(n) + output + set
Sorted backtracking with break and skipO(2ⁿ · n) worst, output-bound in practiceO(n) for path and stack + output

The sort costs O(n log n), which is nothing next to the enumeration. path and the call stack never exceed the number of candidates.

STEP 10

The final solution

  • candidates.sort() — equal values adjacent, ascending order for the break.
  • if remaining == 0: result.append(path[:]) — a complete combination; copy it.
  • for i in range(start, len(candidates)) — only look forward, so no position is reused and each combination is built ascending.
  • if candidates[i] > remaining: break — nothing later can fit either.
  • if i > start and candidates[i] == candidates[i - 1]: continue — a repeat value at the same level would rebuild the same combinations.
  • path.append(…), backtrack(i + 1, remaining - candidates[i]), path.pop() — choose, recurse, undo.
  • backtrack(0, target) and return result.
One-line summary to remember: sort, choose forward from start, break when a value is too big, and skip a value equal to its left neighbour unless it is the first choice at this level.
