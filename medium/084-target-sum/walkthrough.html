Target Sum, narrated

Scroll through the thinking, from trying all 2ⁿ sign assignments to a subset-sum reduction and a single dp row walked backwards, with the state of the algorithm shown alongside.

Pattern used Dynamic Programming 0/1 knapsack: P = (total + target) / 2, count subsets that sum to P

STEP 1

The problem

You get an array of non-negative integers and a target. In front of every number you must write either + or -, then evaluate the expression. Count how many of the 2ⁿ sign assignments produce exactly target.

Running example: nums = [1, 1, 1, 1, 1], target = 3. The answer is 5: exactly one of the five ones must get a minus sign (4 − 1 = 3), and there are five ways to choose which one.

Two expressions are different if any sign differs, even when the numbers are equal. That is why the five ones give five expressions, not one. Zeros count too: +0 and −0 are two different expressions with the same value.

STEP 2

First instinct: try every sign

Recurse over the array, branching into +nums[i] and −nums[i] at each index, and count the leaves whose running total equals the target.

def ways(i, running):    if i == len(nums):        return 1 if running == target else 0    return ways(i + 1, running + nums[i]) + ways(i + 1, running - nums[i])

That is O(2ⁿ). With n ≤ 20 it is about a million leaves and actually passes, which is why this problem is famous for having a brute force that works. Memoizing on (i, running) gives O(n × total), but the running total can be negative and ranges over 2 × total + 1 values, so the table is awkward. The reduction in the next step makes it clean.

STEP 3

The key idea: it is subset sum in disguise

Split the numbers into the ones that got a plus, with sum P, and the ones that got a minus, with sum N. Then:

  • P − N = target, because that is what the expression evaluates to.
  • P + N = total, because every number is in one group or the other.

Add the two equations: 2P = total + target, so P = (total + target) / 2. Choosing a sign assignment is exactly the same as choosing which subset gets the plus sign, and that subset must sum to P.

The question becomes: how many subsets of nums sum to goal = (total + target) / 2? For the running example, goal = (5 + 3) / 2 = 4: pick four of the five ones for the plus side. That is a 0/1 knapsack count, every number used at most once.

Two things fall out of the formula. If total + target is odd, P is not an integer and the answer is 0. If |target| > total, no assignment can reach it, and goal would be negative or too large; return 0 before building the table.

STEP 4

The approach, line by line

  • total = sum(nums), then if abs(target) > total or (total + target) % 2: return 0 rejects the impossible cases.
  • goal = (total + target) // 2 — the sum the plus group must reach.
  • dp = [0] * (goal + 1) and dp[0] = 1 — dp[s] counts subsets of the numbers so far that sum to s; the empty subset sums to 0.
  • for num in nums — add one number at a time.
  • for s in range(goal, num - 1, -1) — walk the sums downward, so that dp[s - num] is still the count from before this number was added.
  • dp[s] += dp[s - num] — every subset summing to s − num becomes one summing to s by adding num.
  • return dp[goal].
STEP 5

Trace it: the first number

The row starts as dp = [1, 0, 0, 0, 0] for sums 0 through 4. Add the first 1, walking s from 4 down to 1: dp[4] += dp[3], dp[3] += dp[2], dp[2] += dp[1] all add 0, and finally dp[1] += dp[0] gives 0 + 1 = 1.

After the first number: dp = [1, 1, 0, 0, 0]. One subset sums to 0 (the empty one) and one sums to 1 (just this number). Because the walk went downward, dp[2] read dp[1] before it became 1, so "this number twice" was never counted.

STEP 6

Trace it: the second and third numbers

Second 1, downward again: dp[2] += dp[1] gives 0 + 1 = 1 (both ones), dp[1] += dp[0] gives 1 + 1 = 2 (either one alone). Row: [1, 2, 1, 0, 0].

Third 1: dp[3] += dp[2] gives 1, dp[2] += dp[1] gives 1 + 2 = 3, dp[1] += dp[0] gives 3. Row: [1, 3, 3, 1, 0].

The row is turning into Pascal's triangle: dp[s] after k ones is C(k, s), the number of ways to pick s of them. That is exactly what "subsets summing to s" means when every number is 1.
STEP 7

Trace it: the last number, the answer

After the fourth 1 the row is [1, 4, 6, 4, 1]. The fifth 1 walks down once more: dp[4] += dp[3] gives 1 + 4 = 5, dp[3] += dp[2] gives 4 + 6 = 10, dp[2] += dp[1] gives 10, dp[1] += dp[0] gives 5.

Final row: [1, 5, 10, 10, 5]. Return dp[4] = 5: five subsets of four ones, each one a sign assignment with a single minus.

STEP 8

Where this goes wrong: loop direction and parity

Walking the sums upward. Write the inner loop as for s in range(num, goal + 1) and dp[s - num] has already been bumped by this same number, so the number can be reused any number of times. The row for the running example becomes [1, 5, 15, 35, 70] and the function returns 70, not 5. That is the unlimited-supply row from Coin Change II; here every number is a single physical item that gets exactly one sign.

Skipping the parity check. (total + target) // 2 rounds down silently. For nums = [1, 2, 3], target = 1 the true P would be 3.5, no subset works, and the answer is 0; the floor gives goal = 3 and the function returns 2.

Skipping the range check. nums = [100], target = −200 gives goal = −50, [0] * (goal + 1) is empty, and dp[0] = 1 raises IndexError.

Each number is used once, so the inner loop runs from goal down to num. Check with [1, 1], target = 2: the answer is 1 (both plus), and a 3 means a number was reused.
STEP 9

Time and space

One addition per (number, sum) pair: O(n × goal) time, and goal ≤ total ≤ 1000, so at most 20,000 steps. One row of goal + 1 integers: O(goal) space.

ApproachTimeSpace
Every sign assignmentO(2ⁿ)O(n) call stack
Memoized on (index, running total)O(n × total)O(n × total), offset for negatives
Subset-sum row, downwardO(n × goal)O(goal)

With n ≤ 20 the brute force is about a million leaves and passes; the reduction is what you want when n is 50 and total is still small.

STEP 10

The final solution

Eleven lines. Every one of them maps to a step above.

  • total = sum(nums) — needed for the reduction.
  • if abs(target) > total or (total + target) % 2: return 0 — unreachable or non-integer plus side.
  • goal = (total + target) // 2 — the subset sum to count.
  • dp = [0] * (goal + 1), dp[0] = 1 — the empty subset.
  • for num in nums — one number at a time, each used once.
  • for s in range(goal, num - 1, -1) — downward, so the number is not reused.
  • dp[s] += dp[s - num] — extend every subset that leaves room for num.
  • return dp[goal].
One-line summary to remember: the plus side must sum to (total + target) / 2, so count subsets with that sum, walking the row downward.
