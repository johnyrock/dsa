Pow(x, n), narrated

Scroll through the thinking, from multiplying x by itself n times to reading n one bit at a time while squaring a running base, with the bits of n and the two running values shown alongside.

Pattern used Math Binary exponentiation: x^n is the product of x^(2^k) over the set bits k of n, and repeated squaring produces those factors in order.

STEP 1

The problem

Implement pow(x, n): given a float x and an integer n, return x raised to the power n. The exponent can be negative, in which case the answer is 1 / x^|n|, and it can be as large as 2^31 - 1, about two billion.

Running example: x = 2.0, n = 10. The answer is 1024.0. In binary 10 is 1010, that is 8 + 2, so 2^10 = 2^8 · 2^2 = 256 · 4.

The size of n is the whole difficulty. Two billion multiplications is too slow, so the question is really: how do you raise something to a huge power in far fewer steps than the power itself?

STEP 2

First instinct: multiply n times

Start from 1.0 and multiply by x once per unit of the exponent, after flipping a negative n into a positive one on 1 / x:

if n < 0:    x, n = 1 / x, -nresult = 1.0for _ in range(n):    result *= x

For the example that is ten multiplications, and it gives the right answer. But it is O(n), and n may be 2^31 - 1: over two billion float multiplications, which takes minutes in Python. The exponent is a number, not a collection, and a loop that runs once per unit of a number is almost always the wrong shape.

STEP 3

The key idea: read n in binary

Write n in binary: 10 = 1010, meaning 8 + 2. Then x^10 = x^8 · x^2. In general, x^n is the product of x^(2^k) for every bit k that is set in n.

Those factors are cheap to produce in order: x, then x^2 = x · x, then x^4 = x^2 · x^2, then x^8 = x^4 · x^4. Each is the square of the previous one. So keep a running base that squares once per bit, and multiply it into result only when the current lowest bit of n is 1.

The panel shows the four bits of 10 lined up with the four bases 2, 4, 16, 256. The set bits are bit 1 and bit 3, so the answer is 4 · 256 = 1024.

One iteration per bit of n: n & 1 reads the lowest bit, n >>= 1 drops it. That is about log₂ n rounds, at most 31 for the constraint range, instead of n rounds.
STEP 4

The approach, line by line

  • if n < 0: x = 1 / x; n = -n — a negative power of x is a positive power of 1 / x. After this n is non-negative and the loop can shift it toward zero.
  • result = 1.0 — the empty product. If n is 0 the loop never runs and this is the answer.
  • base = x — the factor for bit 0, x^(2^0) = x.
  • while n: — keep going while any bit is left.
  • if n & 1: result *= base — if the current lowest bit is set, its factor belongs in the answer.
  • base *= base — square, so base becomes the factor for the next bit up.
  • n >>= 1 — drop the bit just handled.
  • return result.
STEP 5

Trace it: rounds 1 and 2

Start: result = 1.0, base = 2.0, n = 10 which is 1010.

Round 1. n & 1 is 0, so result stays 1.0. Square the base: base = 2.0 · 2.0 = 4.0. Shift: n = 10 >> 1 = 5, which is 101.

Round 2. n & 1 is 1, so result = 1.0 · 4.0 = 4.0: the x^2 factor for bit 1 of the original n is in. Square: base = 4.0 · 4.0 = 16.0. Shift: n = 5 >> 1 = 2, which is 10.

Notice the base was squared in round 1 even though nothing was multiplied in. Squaring happens every round regardless; it is the multiplication into result that is conditional.

STEP 6

Trace it: rounds 3 and 4

Round 3. n = 2, n & 1 is 0, result stays 4.0. Square: base = 16.0 · 16.0 = 256.0. Shift: n = 2 >> 1 = 1.

Round 4. n = 1, n & 1 is 1, so result = 4.0 · 256.0 = 1024.0: the x^8 factor for bit 3 is in. Square: base = 65536.0, which will never be used. Shift: n = 1 >> 1 = 0.

The loop condition while n now sees 0 and stops. Four rounds for a four-bit exponent, and result = 1024.0 is exactly x^2 · x^8.

STEP 7

Trace it: a negative exponent

Take x = 2.0, n = -2. The guard fires: x = 1 / 2.0 = 0.5 and n = 2, which is 10 in binary. From here the loop is identical to the positive case.

Round 1. n & 1 is 0; base = 0.5 · 0.5 = 0.25; n = 1.

Round 2. n & 1 is 1; result = 1.0 · 0.25 = 0.25; base = 0.0625; n = 0. The answer is 0.25, which is 2^-2 = 1/4.

Python's integers are unbounded, so -n is safe even for n = -2^31. In a language with 32-bit ints that negation overflows; use a wider type or process n as a negative number.
STEP 8

Where this goes wrong: order and sign

Squaring before checking the bit. Writing base *= base above if n & 1: result *= base means every factor that gets multiplied in is one squaring too far along: bit k contributes x^(2^(k + 1)) instead of x^(2^k). On the example the two set bits pull in 16 and 65536 instead of 4 and 256, and the function returns 1048576, not 1024, which is 2^20, twice the intended exponent.

Forgetting the negative branch. With n = -2 and no guard, while n: never ends: -2 >> 1 is -1 and -1 >> 1 is still -1, so n never reaches 0. Changing the condition to while n > 0: stops the hang but returns 1.0 instead of 0.25.

Starting result at x. Then n = 0 returns x rather than 1.0, and every other answer carries an extra factor of x: 2048.0 on the example.

Check the bit, then square, then shift. The base is the factor for the bit you are looking at now; squaring prepares it for the next bit.
STEP 9

Time and space

The loop runs once per bit of |n|, so O(log n) time: at most 31 rounds for any exponent in the constraint range, each doing at most two float multiplications. The state is result, base and the shrinking n, so O(1) space.

ApproachTimeSpace
Multiply n timesO(n)O(1)
Recursive halving, pow(x·x, n // 2)O(log n)O(log n) stack
Bit loop with squaring baseO(log n)O(1)

The recursive version is the same idea top-down; the loop reads the bits bottom-up and needs no stack.

STEP 10

The final solution

Twelve lines. Every one of them maps to a step above.

  • if n < 0: x = 1 / x; n = -n — fold the sign into the base.
  • result = 1.0 and base = x — the empty product and the factor for bit 0.
  • while n: — one round per remaining bit.
  • if n & 1: result *= base — a set bit contributes its factor.
  • base *= base — prepare the factor for the next bit.
  • n >>= 1 — move on to that bit.
  • return result.
One-line summary to remember: read n's bits from the bottom; square the base every round, multiply it in on a 1.
