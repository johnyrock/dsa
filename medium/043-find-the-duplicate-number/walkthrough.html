Find the Duplicate Number, narrated

I will begin with a legal pairwise comparison, then I use the array's value range to view it as a linked list with a cycle.

Pattern used Fast & Slow Pointers i → nums[i] is a linked list; the duplicate is the cycle's entrance

STEP 1

The problem

You get an array nums of n + 1 integers, every one of them between 1 and n. There are more slots than distinct values, so something must repeat; the problem promises exactly one value repeats (possibly many times). Return it.

Running example: nums = [1,3,4,2,2]. Here n = 4, the values are drawn from 1..4, and 2 appears twice. The answer is 2.

Without the extra rules this is a warm-up: sort it, or throw values into a set. The rules are what make it medium: do not modify the array and use only O(1) extra space. No sorting in place, no set, no visited array.

The constraint that values are in [1, n] while indices run 0..n is not decoration. It is the hint that a value can be used as an index, and that index 0 is never a value.

STEP 2

First instinct: compare every pair

I can compare each value with every later value and return as soon as two positions contain the same number.

def findDuplicate(nums):    for i in range(len(nums)):        for j in range(i + 1, len(nums)):            if nums[i] == nums[j]:                return nums[i]

This is correct and does not modify nums. Its nested loops take O(n²) time, and it uses O(1) extra space.

I follow indices as pointers without using a set: i → nums[i]. Since two indices share the duplicate value, that pointer structure must contain a cycle whose entrance is the duplicate.

STEP 3

The key idea: the array is a linked list in disguise

I read each index as a node and each value as a next pointer: node i points to node nums[i]. Every value is in [1, n], so every pointer lands on a valid index, and starting from index 0 I can follow pointers forever.

On the example: 0 → nums[0] = 1, 1 → nums[1] = 3, 3 → nums[3] = 2, 2 → nums[2] = 4, 4 → nums[4] = 2. And 2 again: a cycle. The panel draws exactly this graph.

A node has two arrows coming into it precisely when two indices hold its value — that is, when the value is the duplicate. Here both index 3 and index 4 hold 2, so node 2 has two incoming arrows, and it is where the path from 0 first re-enters itself. The duplicate is the entrance of the cycle.

Index 0 can never be pointed at, since values are ≥ 1, so 0 is always in the "tail" before the cycle. That matters: Floyd's algorithm needs to start outside the cycle. From here the problem is Linked List Cycle plus "find the entrance", on a list I never build.

STEP 4

The approach: Floyd's two phases

  • slow = fast = 0 — both start at node 0, which is outside the cycle.
  • Phase 1: slow = nums[slow] (one hop) and fast = nums[nums[fast]] (two hops), repeated until slow == fast. They meet somewhere on the cycle.
  • Phase 2: slow2 = 0; then while slow != slow2, I move both one hop. They meet at the entrance.
  • return slow — the entrance index, which equals the duplicate value.

Why phase 2 works: if the tail has length t and the cycle has length c, then when they meet in phase 1 the slow pointer has taken k hops and fast 2k, so the extra k hops are a whole number of laps. The meeting point is therefore t hops short of a lap boundary, exactly as far from the entrance as node 0 is. I walk both at the same speed and they arrive together.

STEP 5

Trace it: phase 1, hops 1 and 2

Hop 1: slow = nums[0] = 1. fast = nums[nums[0]] = nums[1] = 3. Not equal, I keep going.

Hop 2: slow = nums[1] = 3. fast = nums[nums[3]] = nums[2] = 4. Not equal.

I see how fast is computed: the inner nums[fast] is one hop, and the outer lookup is the second. It matches fast.next.next on a real list. I leave the array unchanged and read it twice per iteration.

STEP 6

Trace it: phase 1, hops 3 and 4, they meet

Hop 3: slow = nums[3] = 2. fast = nums[nums[4]] = nums[2] = 4. Still different.

Hop 4: slow = nums[2] = 4. fast = nums[nums[4]] = nums[2] = 4. Equal. Break out of the loop.

They met at node 4, which is on the cycle (2 → 4 → 2). But 4 is not the answer — the array has one 4, not two. The meeting point is only a foothold on the cycle; the entrance is what I want, and phase 2 finds it.

STEP 7

Trace it: phase 2, walk to the entrance

I put slow2 = 0 at the start; slow stays at 4. They differ, so both hop once.

Hop 1: slow = nums[4] = 2, slow2 = nums[0] = 1. Hop 2: slow = nums[2] = 4, slow2 = nums[1] = 3. Hop 3: slow = nums[4] = 2, slow2 = nums[3] = 2. Equal at 2.

Both pointers took exactly 3 hops: slow2 walked the tail 0 → 1 → 3 → 2, and slow went around from the meeting point 4 → 2 → 4 → 2. Same distance, same arrival. return 2, which is the duplicate.
STEP 8

Where this goes wrong: a loop that never starts, and the wrong pointer returned

A pre-checked loop. The natural translation of "until they meet" is while slow != fast:. But slow and fast are both 0 before the first hop, so the condition is false immediately and phase 1 does nothing. Phase 2 then sets slow2 = 0, sees slow == slow2 at once, and returns 0 — a value that is not even in the array. The loop must run at least once: while True: … if slow == fast: break.

Returning the phase-1 meeting point. On the example that is node 4, and the function reports 4 instead of 2. The meeting point is on the cycle but is the entrance only by coincidence.

Restarting phase 2 from the wrong place. slow2 = slow (both on the cycle) or slow2 = nums[0] breaks the equal-distance argument. Only index 0 is guaranteed to be outside the cycle.

Phase 1 is a do-while, not a while: hop first, I compare second. Phase 2 always restarts from 0 and moves both pointers one hop.
STEP 9

Time and space

Phase 1 meets within one lap after slow enters the cycle, so at most t + c ≤ n + 1 slow hops. Phase 2 takes exactly t hops. Total O(n) time, with three integer variables: O(1) space, and the array is never written.

ApproachTimeExtra spaceModifies nums?
Nested loopsO(n²)O(1)no
Sort a copyO(n log n)O(n)no

Only the last row satisfies every rule at once. The binary-search version (count how many values are ≤ mid; the duplicate is on the side with too many) is the runner-up when the linked-list trick does not come to mind.

STEP 10

The final solution

Twelve lines, two loops.

  • slow = fast = 0 — start outside the cycle.
  • while True: — do-while: hop before comparing.
  • slow = nums[slow] / fast = nums[nums[fast]] — one hop and two hops through the implicit list.
  • if slow == fast: break — met somewhere on the cycle.
  • slow2 = 0 — second pointer restarts at the head.
  • while slow != slow2: I move both one hop — same distance to the entrance.
  • return slow — the entrance, which is the duplicate value.
One-line summary to remember: index → value is a linked list; the duplicate is the node with two incoming edges, i.e. the cycle entrance, found by Floyd's two phases.
