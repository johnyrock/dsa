Graph Valid Tree, narrated

I will first remove each edge and test whether its endpoints remain connected, then track connectivity while adding edges once.

Pattern used Graph Traversal union-find: n − 1 edges and every union merges two different roots

STEP 1

The problem

You get n nodes numbered from 0 and a list of undirected edges. Decide whether they form a tree. A tree has two properties at once: it is connected (you can walk from any node to any other) and it is acyclic (there is no closed loop of edges).

Either property can fail on its own. Two separate chains are acyclic but not connected. A triangle with an extra node hanging off it is connected but not acyclic. Both must hold.

Running example: n = 5, edges = [[0,1],[0,2],[0,3],[1,4]]. Node 0 fans out to 1, 2 and 3, and node 4 hangs off 1. Every node is reachable and nothing loops back, so the answer is True.

The edges are undirected, so [0, 1] and [1, 0] would be the same edge. The constraints promise there are no duplicates and no self-loops, which removes two easy ways to smuggle in a cycle.

STEP 2

First instinct: test whether every edge is load-bearing

I can remove each edge in turn, check whether its endpoints still connect through the remaining edges, and finally confirm the graph is connected.

def validTree(n, edges):    for i, (a, b) in enumerate(edges):        if reachable(a, b, edges[:i] + edges[i + 1:]): return False    return reachable_count(0, edges) == n

This is correct when the helper functions run breadth-first search. Each of E tests can traverse O(n + E) graph data, so the time complexity is O(E · (n + E)). The temporary traversal structures use O(n + E) space.

Remembering connected components as I process edges lets a union-find report immediately when an edge joins nodes that already share a component.

STEP 3

The key idea: count the edges, then merge sets

Two facts about trees do all the work.

A tree on n nodes has exactly n - 1 edges. Fewer and it cannot be connected; more and there must be a cycle. So if len(edges) != n - 1: return False is a legitimate first line, not a hack.

Given n - 1 edges, acyclic implies connected. I begin with n isolated nodes, then each edge that joins different components reduces the count by one. If no edge closes a cycle, n - (n - 1) = 1 component remains.

So after the count check, the only remaining question is: does any edge join two nodes that are already in the same component? That is exactly what union-find answers.

Union-find keeps a parent array. Each component is a small tree of pointers, and find(x) follows them to the root. Two nodes are in the same component when they have the same root. Merging two components is one pointer assignment: point one root at the other.

STEP 4

The approach, line by line

  • if len(edges) != n - 1: return False handles both "too few" and "too many" before any traversal.
  • parent = list(range(n)): every node starts as its own root. rank = [0] * n: an upper bound on each root's tree height.
  • In find(x), I use parent[x] = parent[parent[x]] to skip a generation while climbing, then return the root.
  • For each edge [a, b]: ra, rb = find(a), find(b). if ra == rb: return False is the cycle check.
  • Union by rank: if rank[ra] < rank[rb]: ra, rb = rb, ra, then parent[rb] = ra, and bump rank[ra] only when the two ranks were equal.
  • If the loop finishes, every edge merged two different sets: return True.

The running example passes the count check (4 edges, n - 1 = 4) and starts with parent = [0, 1, 2, 3, 4] and rank = [0, 0, 0, 0, 0].

STEP 5

Trace it: edges [0,1] and [0,2]

Edge [0, 1]: find(0) = 0 and find(1) = 1. Different roots, so no cycle. Ranks are both 0, so no swap; parent[1] = 0, and since the ranks were equal, rank[0] becomes 1. Now parent = [0, 0, 2, 3, 4].

Edge [0, 2]: find(0) = 0, find(2) = 2. Different. rank[0] = 1 is not less than rank[2] = 0, so no swap; parent[2] = 0. The ranks were not equal, so rank[0] stays 1. Now parent = [0, 0, 0, 3, 4].

Three nodes share root 0; nodes 3 and 4 are still their own roots. Two components merged into one, two edges used, and the component count went from 5 to 3.

STEP 6

Trace it: edges [0,3] and [1,4], the answer

Edge [0, 3]: roots 0 and 3, different. parent[3] = 0. parent = [0, 0, 0, 0, 4].

Edge [1, 4]: find(1) follows parent[1] = 0 and parent[0] = 0, so the root is 0. find(4) = 4. Different, so parent[4] = 0 (rank 1 beats rank 0, node 4 goes under 0, not under 1). parent = [0, 0, 0, 0, 0].

The loop ends without ever seeing ra == rb. Four merges took five components down to one. return True.

The final parent array is flat: every node points straight at 0. That is union by rank doing its job; find never had to walk more than one step.
STEP 7

Contrast: a cycle is caught by the first repeated root

I can test n = 5, edges = [[0,1],[1,2],[2,3],[1,3],[1,4]]. That is 5 edges on 5 nodes, so the count check already fails. If I skip it for this illustration, the cycle check still shows its own behaviour.

[0, 1]: merge, parent[1] = 0, rank[0] = 1. [1, 2]: find(1) = 0, find(2) = 2, merge, parent[2] = 0. [2, 3]: find(2) = 0, find(3) = 3, merge, parent[3] = 0. Now parent = [0, 0, 0, 0, 4].

[1, 3]: find(1) = 0 and find(3) = 0. Same root. Nodes 1 and 3 were already connected (via 2), so this edge closes the loop 1–2–3–1. return False immediately; edge [1, 4] is never looked at.

STEP 8

Where this goes wrong: cycle-free is not the same as tree

Two specific bugs live here, and both return a confident wrong answer.

Dropping the edge-count guard. Without if len(edges) != n - 1: return False, I can use n = 5 and edges = [[0,1],[1,2],[3,4]]. Every edge merges, yet two components remain and the function incorrectly returns True.

A find that does not loop. Writing return parent[x] returns the immediate parent, not the root. On [[0,1],[2,3],[1,3],[0,3]] the third union points root 2 at root 0, so node 3's parent is still 2 while its root is 0. The cycle-closing edge [0, 3] compares 0 with 2, sees "different", and returns True for a graph with a cycle and an isolated node 4.

I check the count first, then make find walk all the way to a node whose parent is itself.
STEP 9

Time and space

The count check is O(1). The loop does two find calls and one union per edge. With path halving and union by rank, a find costs amortised O(α(n)), the inverse Ackermann function, which is at most 4 for any input that fits in memory. Total O(n + E × α(n)), effectively linear.

parent and rank are each n integers: O(n) space. No adjacency list is ever built.

ApproachTimeSpace
Remove each edge, BFS to test redundancyO(E × (n + E))O(n + E)
One DFS from 0 with parent tracking, then count visitedO(n + E)O(n + E) adjacency + stack
Count check + union-findO(n + E × α(n))O(n)

The DFS version is also linear, but it needs the adjacency list built first and has to remember which node it arrived from so the edge back to the parent is not mistaken for a cycle. Union-find sidesteps both.

STEP 10

The final solution

Every line maps to a step above.

  • if len(edges) != n - 1: return False: a tree has exactly n - 1 edges, and with that many, acyclic means connected.
  • parent = list(range(n)) and rank = [0] * n: every node is its own root at rank 0.
  • find(x) walks up with parent[x] = parent[parent[x]] at each step until parent[x] == x.
  • if ra == rb: return False: the endpoints were already connected, so this edge closes a cycle.
  • parent[rb] = ra after swapping so ra is the higher rank; rank[ra] += 1 only on a tie.
  • return True: every edge merged two sets, so one component is left.
One-line summary to remember: exactly n − 1 edges, and no edge whose endpoints already share a root.
