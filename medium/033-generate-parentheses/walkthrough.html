Generate Parentheses, narrated

I will begin by enumerating every bracket string, then prune impossible prefixes while I build the answer.

Pattern used Backtracking choose a bracket, recurse, undo; two guards prune every invalid prefix

STEP 1

The problem

You are given a number n. Produce every string that uses exactly n opening brackets and n closing brackets and is well-formed: reading left to right, the number of ) seen never exceeds the number of ( seen, and the two counts are equal at the end.

Every answer has length 2n. The order of the list does not matter, but there must be no duplicates and nothing may be missing.

Running example: n = 3. The answer is the five strings ((())), (()()), (())(), ()(()), ()()().

Unlike most problems, the output is not a single number but a whole list, and the size of that list grows fast: 1, 2, 5, 14, 42, 132 … These are the Catalan numbers. The work is unavoidably proportional to the output, so the goal is to spend no time on strings that will not make the cut.

STEP 2

First instinct: generate everything, then filter

I can make every length-2n string of parentheses and keep only the balanced ones.

from itertools import productdef generateParenthesis(n):    result = []    for chars in product("()", repeat=2 * n):        depth = 0        for ch in chars:            depth += 1 if ch == "(" else -1            if depth < 0: break        if depth == 0: result.append("".join(chars))    return result

This produces every valid answer. There are 2^(2n) candidates, each checked in O(n) time, so the time complexity is O(2^(2n) · n). The space complexity is O(2^(2n) · n) for the result and candidate work.

I reject a prefix as soon as it has more closing than opening parentheses. Backtracking with counts avoids constructing strings that can never become valid.

STEP 3

Key insight: only extend a prefix that can still succeed

I build the string one character at a time and ask, before adding each bracket, whether the resulting prefix could still become a valid string. Two counters answer that: open_count and close_count, the number of each bracket placed so far.

  • Adding ( is fine as long as open_count < n. There is no other constraint on openers.
  • Adding ) is fine only if close_count < open_count: there must be an unmatched opener for it to close.
Any prefix that obeys both rules can be completed: close every open bracket and I have a valid string. So no path is ever a dead end, and the recursion never wastes a step.

This is backtracking: I choose a character, recurse into the longer prefix, then undo the choice with path.pop() so the other branch starts from the same prefix. The path list is shared across all calls, which is why the undo matters.

STEP 4

The approach, line by line

  • result = [] and path = []: the answers, and the one string under construction.
  • backtrack(open_count, close_count) extends path from its current state.
  • Base case: if len(path) == 2 * n, join the path into a string, I append it, I return. No validity check is needed.
  • Branch 1: if open_count < n, I push (, recurse with open_count + 1, I pop.
  • Branch 2: if close_count < open_count, I push ), recurse with close_count + 1, I pop.
  • Kick off with backtrack(0, 0) and return result.

Because branch 1 is tried before branch 2 at every level, the output comes out in a fixed order: the most deeply nested string first, ()()() last.

STEP 5

Trace it: the leftmost path, ((()))

From the empty path, branch 1 fires three times in a row: open_count goes 0 → 1 → 2 → 3 and path becomes (((. Now open_count < n is 3 < 3, false, so no more openers.

Branch 2 checks close_count < open_count: 0 < 3, true. I push ). Then 1 < 3, I push again. Then 2 < 3, I push again. The path is ((())) with length 6, which equals 2 * n, so the base case records it as the first answer.

STEP 6

The base case returns, and each frame runs its path.pop(). The three closers come off, then the frame that pushed the third opener pops it too. I am back at (( with open_count = 2, close_count = 0, and that frame's branch 1 is finished, so it tries branch 2: 0 < 2, I push ). The path is (().

From ((), branch 1 first: 2 < 3, I push ( to get (()( with open_count = 3. Openers are exhausted, so two closers follow: (()(), then (()()). Length 6, I record the second answer.

Unwind again to ((), and its branch 2 gives (()), then (())(, then (())(): the third answer. Only after both branches under (( are exhausted does the pop reach (, and the whole right half of the tree, starting (), begins.

STEP 7

Trace it: the () subtree and the full answer

From (, branch 2 pushes ) to make () with both counters at 1. Branch 1 from there: ()(, ()((, then two forced closers give ()(()). Branch 2 from ()(: ()(), then ()()(, then ()()().

Back at the empty path, branch 2 asks close_count < open_count, which is 0 < 0, false. Nothing starts with ). The recursion is done and result holds exactly five strings.

Count the calls: 5 answers of length 6 means the recursion visited 5 leaves plus their shared prefixes, about 25 calls in total. The brute force examined 64 strings.
STEP 8

Where this goes wrong: the close guard

Symmetric guards. It is tempting to write the second guard to mirror the first: if close_count < n. That only limits the total closers, not their position. Every arrangement of three ( and three ) now reaches length 6, so the function returns 20 strings instead of 5, and the last one is )))(((. The guard must compare against open_count, not n.

Forgetting the undo. I drop a path.pop() and the second branch appends to a path that still contains the first branch's characters. Lengths overshoot, the base case fires on garbage, and the list is filled with nonsense or nothing at all.

Reversing the comparison. if open_count < close_count is never true from a fresh start, so the recursion pushes three openers and stops. The result is an empty list.

Say the rule in words before writing it: "I may close only if something is open." That is close_count < open_count, and nothing else.
STEP 9

Time and space

The number of valid strings is the Catalan number C(n) = (2n)! / ((n+1)! n!), which grows like 4^n / n^1.5. Every recursive call lies on the path to at least one answer, so the total number of calls is O(n · C(n)), and joining each answer costs O(n).

ApproachTimeSpace (beyond output)
All 2^(2n) strings, then filterO(2^(2n) · n)O(n)
Recursion with a final validity checkO(2^(2n))O(n)
Backtracking with both guardsO(4^n / √n · n)O(n)

The space that matters is path and the call stack, both bounded by 2n. The output list itself is unavoidable and dominates memory.

STEP 10

The final solution

One nested function, two guards, one shared list.

  • result = [], path = []: answers and the working string.
  • if len(path) == 2 * n: I record "".join(path) and return.
  • if open_count < n: I push (, recurse with open_count + 1, I pop.
  • if close_count < open_count: I push ), recurse with close_count + 1, I pop.
  • backtrack(0, 0) starts from the empty string; return result.
One-line summary to remember: open while I have openers left, close while something is open, and undo after each recursive call.
