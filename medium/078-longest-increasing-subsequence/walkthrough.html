Longest Increasing Subsequence, narrated

Scroll through the thinking, from enumerating every subsequence to a table of "longest run ending here", with the state of the algorithm shown alongside.

Pattern used Dynamic Programming dp[i] = 1 + max(dp[j]) over j < i with nums[j] < nums[i]

STEP 1

The problem

A subsequence keeps some elements of nums in their original order and skips the rest. Find the longest one whose values go strictly up, and return its length.

Running example: nums = [10, 9, 2, 5, 3, 7, 101, 18]. The answer is 4: for instance 2, 3, 7, 101 or 2, 5, 7, 18. There is no increasing pick of five.

Two things to fix in your head. "Strictly" means equal values cannot follow each other, so [7, 7, 7] has answer 1. And "subsequence" means gaps are fine: 2, 3, 7 skips the 5 in between.

We are asked for a count, not the elements. That lets us record a single number per position rather than a list.

STEP 2

First instinct: try every subsequence

Each element is either in or out, so walk the array once per index deciding to take it (if it is bigger than the last taken value) or skip it, and keep the longest length seen.

def longest(i, last):    if i == len(nums):        return 0    skip = longest(i + 1, last)    take = 0    if nums[i] > last:        take = 1 + longest(i + 1, nums[i])    return max(skip, take)

Correct, and it doubles at every index: O(2ⁿ). At n = 2500 that is hopeless. The repeated work is easy to spot — longest(5, 3) ("from index 5 with last value 3") gets asked once for every different way of reaching the 3, even though the answer never changes.

STEP 3

The key idea: anchor on where the run ends

Define dp[i] as the length of the longest increasing subsequence that ends at index i — it must use nums[i] as its last element. That anchor is what makes the subproblem small enough to reuse.

Whatever came right before nums[i] in such a run is some earlier nums[j] with j < i and nums[j] < nums[i]; and the run up to that point is a best run ending at j, which is exactly dp[j].

dp[i] = 1 + max(dp[j]) over every j < i with nums[j] < nums[i], or just 1 if no such j exists. The answer is max(dp), because the best run can end anywhere.

Filling i left to right makes every dp[j] final before it is read. Seeding every slot with 1 encodes "an element on its own is a run of length 1".

STEP 4

The approach, line by line

  • dp = [1] * len(nums) — every element is at least a run of one.
  • for i in range(len(nums)) — the slot being filled.
  • for j in range(i) — every candidate predecessor.
  • if nums[j] < nums[i] — strict, so equal values do not chain.
  • dp[i] = max(dp[i], dp[j] + 1) — extend the best run ending at j.
  • return max(dp) — the longest run wherever it ends.
STEP 5

Trace it: the first four slots

i = 0 (value 10): no earlier index, dp[0] stays 1. i = 1 (value 9): the only earlier value is 10, not smaller, so dp[1] = 1. i = 2 (value 2): 10 and 9 are both bigger, dp[2] = 1.

i = 3 (value 5): look back at 10, 9, 2. Only 2 < 5, at j = 2 with dp[2] = 1, so dp[3] = max(1, 1 + 1) = 2. The run is 2, 5.

The table so far: [1, 1, 1, 2].

STEP 6

Trace it: i = 5, value 7

First i = 4 (value 3): only 2 < 3, so dp[4] = dp[2] + 1 = 2. Note it does not chain off the 5, because 5 < 3 is false.

Now i = 5 (value 7). Earlier values smaller than 7: 2 at j = 2 (dp = 1), 5 at j = 3 (dp = 2), 3 at j = 4 (dp = 2). The best is 2 + 1 = 3, reached through either the 5 or the 3. So dp[5] = 3: 2, 5, 7 or 2, 3, 7.

The table so far: [1, 1, 1, 2, 2, 3].

STEP 7

Trace it: 101 and 18, then the answer

i = 6 (value 101): everything before it is smaller, and the biggest dp[j] among them is dp[5] = 3. So dp[6] = 3 + 1 = 4.

i = 7 (value 18): 101 is excluded (101 < 18 is false), but 7 at j = 5 still gives 3 + 1 = 4. So dp[7] = 4 as well.

Final table: [1, 1, 1, 2, 2, 3, 4, 4], and max(dp) = 4. Here the maximum happens to sit at the last index too, but that is luck — see the pitfalls.

The backtracking explored up to 2⁸ subsequences. The table did 28 comparisons.
STEP 8

Where this goes wrong: the seed, the strictness, the return

Seeding with zeros. Write dp = [0] * len(nums) and no run can ever start: dp[j] + 1 only builds on earlier zeros, and any slot with no smaller predecessor stays 0. On the running example the 2 at index 2 has no predecessor, so its slot is 0, the 5 becomes 0 + 1 = 1, and the chain reaches only 3 instead of 4.

Using <=. Then equal values chain, and [7, 7, 7] returns 3 instead of 1. The running example has no duplicates, which is exactly why this bug hides in it.

Returning dp[-1]. The best run need not end at the last element. [4, 5, 1] has dp = [1, 2, 1], so dp[-1] is 1 when the answer is 2.

dp[i] is the longest run ending at i. Seed it with 1, compare strictly, and take the max over the whole table.
STEP 9

Time and space

Slot i looks back at i earlier slots, so the total is 0 + 1 + … + (n − 1): O(n²) time. The table is O(n) space.

ApproachTimeSpace
Enumerate subsequencesO(2ⁿ)O(n) stack
Table, dp[i] = best run ending at iO(n²)O(n)
Patience sorting with binary searchO(n log n)O(n)

At n = 2500, O(n²) is about three million comparisons — comfortably fast. The O(n log n) version keeps an array of the smallest tail of each run length and binary-searches where each new value lands; it is the follow-up, not the interview baseline.

STEP 10

The final solution

Seven lines. Every one of them maps to a step above.

  • dp = [1] * len(nums) — each element alone is a run of length 1.
  • for i in range(len(nums)) — fill left to right so earlier slots are final.
  • for j in range(i) — every earlier index is a candidate predecessor.
  • if nums[j] < nums[i] — strictly smaller, so the run really increases.
  • dp[i] = max(dp[i], dp[j] + 1) — keep the longest extension.
  • return max(dp) — the run can end anywhere.
One-line summary to remember: the longest run ending at i is one more than the longest run ending at any smaller earlier value; the answer is the biggest slot.
