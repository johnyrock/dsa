Medium · Graph · LeetCode #695

Max Area of Island, narrated

Scroll through the thinking, from counting land cells to a flood fill that measures each island the first time it is touched, with the state of the algorithm shown alongside.

Pattern used Graph Traversal scan cells, on unvisited land flood-fill it, count the pops, keep the max

STEP 1

The problem

You get a grid of 1 (land) and 0 (water). An island is a group of land cells connected up, down, left or right. The area of an island is how many cells it has. Return the largest area, or 0 if there is no land.

Diagonals do not connect. Two blocks that touch only at a corner are two islands, and each is measured on its own.

Running example: a 4 × 5 grid with an L of three cells top-left, an L of four cells bottom-right, and a lone cell at (3, 0). The answer is 4.

Unlike Number of Islands, the count of islands is irrelevant. What matters is the size of each one, and only the biggest survives to the return.

STEP 2

First instinct: count the land, or grow from every cell

Counting 1 cells gives 8 for the example, which is the total land, not the biggest island. The question is about pieces, not the sum.

The next idea is honest but wasteful: from every land cell, run a flood fill on a fresh copy of the grid and measure what it reaches:

best = 0for r in range(rows):    for c in range(cols):        if grid[r][c] == 1:            best = max(best, fill(copy.deepcopy(grid), r, c))

Every cell of a 4-cell island starts its own fill and rediscovers the same 4 cells, so the island is measured four times. With a 50 × 50 grid of all land that is 2,500 fills of 2,500 cells each: O((m × n)²), plus a grid copy per fill.

The waste is that a fill from any cell of an island visits exactly the same cells as a fill from any other cell of it. One measurement per island is enough.
STEP 3

Reframe: components, and their sizes

Every land cell is a node and every orthogonally adjacent pair of land cells is an edge. An island is a connected component. The area of an island is the number of nodes in its component.

Measuring components has the same recipe as counting them: visit cells in scan order; when the scan lands on a cell no traversal has touched yet, that cell starts a new component, so traverse everything reachable from it, marking each cell visited so no later scan step starts a second traversal into the same island.

The only new thing is a counter that goes up by one for every cell the traversal pops. When the traversal ends, the counter is the area, and max keeps the record.
STEP 4

The key idea: sink the island as you measure it

Scan the grid row by row. When the scan lands on a 1:

  • Set grid[r][c] = 0 right away, push the cell, and reset area = 0 for this island.
  • Loop while stack: pop a cell, do area += 1, and for each of its four neighbours that is in bounds and still 1, sink it with grid[nr][nc] = 0 and push it.
  • When the stack empties, best = max(best, area).

Overwriting to 0 is the visited set. It costs no extra memory, and it guarantees the outer scan passes over the rest of this island without starting a second fill. Sink on push, not on pop, so no cell is pushed twice and no cell is counted twice.

Counting on pop is what makes the seed cell count: it is pushed before the loop, popped first, and counted like every other cell.

STEP 5

Trace it: the first island, area 3

The scan crosses (0, 0) and (0, 1), both water, and lands on (0, 2), which is land. Sink it, push it, area = 0.

Pop (0, 2): area = 1. Its neighbours are (1, 2) below (land: sink and push), nothing above, (0, 3) water, (0, 1) water. Pop (1, 2): area = 2. Below is (2, 2), water; above is already sunk; right is (1, 3), water; left is (1, 1), land, so sink and push. Pop (1, 1): area = 3, and all four of its neighbours are water or sunk.

The stack is empty, so best = max(0, 3) = 3. When the scan later reaches (1, 1) and (1, 2) it sees 0 and skips them; this island is never measured a second time.

STEP 6

Trace it: the second island, area 4

More water, then (2, 3). Sink it, push it, reset area = 0. Pop (2, 3): area = 1; only (3, 3) below is land, so sink and push it.

Pop (3, 3): area = 2. Below is out of bounds, above is sunk, right is (3, 4) (land: sink, push), left is (3, 2) (land: sink, push). The stack is now [(3, 4), (3, 2)]; the panel shows both pushed cells sunk and (3, 3) as the cell being explored.

Pop (3, 2): area = 3, no live neighbours. Pop (3, 4): area = 4, no live neighbours. Stack empty, so best = max(3, 4) = 4.

STEP 7

Trace it: the lone cell, and the answer

The scan reaches row 3. (3, 0) is land: sink, push, area = 0. Pop it: area = 1. Every neighbour is water, out of bounds, or already sunk, so the fill ends immediately.

best = max(4, 1) = 4. The record does not move. The scan finishes the row over cells that are all 0 now, and return best gives 4.

Three islands, three fills, eight pops in total. Each land cell was pushed once and popped once, which is the whole cost of the algorithm.
STEP 8

Where this goes wrong: where the counting happens

Counting on push. Move area += 1 into the neighbour loop, next to stack.append. Now the seed cell, which is pushed before the loop, is never counted, and every island is one short: the running example returns 3 instead of 4. The panel shows the second island with three cells counted and its seed (2, 3) left out.

Not resetting the counter. Put area = 0 once before the scan instead of once per island. The fills then share one counter: after the three fills it holds 3 + 4 + 1 = 8, and best ends as 8, the total land, not the largest island.

Sinking on pop instead of push. A cell with two live neighbours is pushed twice before either pop reaches it, so it is popped and counted twice. A 2 × 2 block comes out as 5 or 6.

Mark on push, count on pop, reset per island. Each of the three rules fixes exactly one of the bugs above.
STEP 9

Time and space

The scan visits each of the m × n cells once. A land cell is sunk the moment it is pushed, so it is pushed at most once and popped at most once. Total: O(m × n) time. The stack holds at most every land cell at once, so O(m × n) space in the worst case, and the grid itself is the visited set.

ApproachTimeSpace
Fill from every land cell on a copyO((m × n)²)O(m × n) per copy
Fill once per island, separate visited setO(m × n)O(m × n) set + stack
Fill once per island, sink in placeO(m × n)O(m × n) stack, nothing else

Sinking in place trades the caller's grid for the visited set. If the grid must survive, keep a set of (r, c) instead; the time is unchanged.

STEP 10

The final solution

Number of Islands with a counter and a max. Every line maps to a step above.

  • if grid[r][c] != 1: continue skips water and anything already sunk.
  • grid[r][c] = 0 then stack = [(r, c)] marks the seed before it is pushed.
  • area = 0 starts a fresh count for this island.
  • cr, cc = stack.pop() and area += 1 count each cell exactly once, on its pop.
  • The four-tuple loop with 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] == 1 finds live neighbours.
  • grid[nr][nc] = 0 before stack.append((nr, nc)) is the mark-on-push rule.
  • best = max(best, area) after the loop keeps the record; return best hands it back.
One-line summary to remember: flood-fill each island once, sinking cells as you push them, count the pops, keep the max.
