Medium · Hash Set · LeetCode #128

Longest Consecutive Sequence, narrated

Scroll through the thinking, from sorting the array to a set that lets every run be walked exactly once from its smallest value, with the state of the algorithm shown alongside.

Pattern used Hash Set a value with no predecessor in the set starts a run; walk upward only from those starts

STEP 1

The problem

You get an unsorted array nums. Find the longest run of consecutive integers that are all present, and return its length. The run is about the values, not the positions: the members can be scattered anywhere in the array.

Running example: nums = [100, 4, 200, 1, 3, 2]. The values 1, 2, 3, 4 are all present, so the answer is 4. The 100 and the 200 are runs of length 1 on their own.

The problem insists on O(n) time. That is the whole difficulty: sorting would make this trivial, and sorting is O(n log n), so it is off the table.

Duplicates can appear and must not stretch a run: [1, 1, 2] has a run of length 2, not 3. And the empty array has no run at all, so its answer is 0.

STEP 2

First instinct: sort and scan

Sort the array, then walk it once, extending a counter while each value is exactly one more than the previous and resetting on a gap. Equal neighbours are skipped so duplicates do not count.

nums.sort()best = run = 0for i in range(len(nums)):    if i > 0 and nums[i] == nums[i - 1]: continue    run = run + 1 if i > 0 and nums[i] == nums[i - 1] + 1 else 1    best = max(best, run)

On the running example the sorted array is [1, 2, 3, 4, 100, 200], the counter climbs to 4 and resets at 100. Correct, and easy to get right. But the sort is O(n log n), and the problem said linear.

The sort does more than we need. We do not care about the order of 100 relative to 200; we only care, for each value, whether its immediate neighbours num - 1 and num + 1 exist. That is a membership question, not an ordering question.

STEP 3

The key insight: only walk from the start of a run

Put every value in a set. Now x in seen is O(1), so from any value we can step upward, num + 1, num + 2, and so on, for as long as the next integer is present. That measures the run that contains num from num upward.

Doing that from every value is wasteful: the run 1–4 would be walked from 1, again from 2, again from 3, and again from 4. The fix is to notice that a value is the start of its run exactly when num - 1 is not in the set.

Walk upward only from values whose predecessor is missing. Then every run is walked exactly once, from its smallest member, and each value is stepped over by exactly one walk. The while inside the for is O(n) in total, not O(n²).

In the running example only 1, 100, and 200 have no predecessor in the set. Those are the three runs, and only those three walks happen.

STEP 4

The approach, line by line

  • seen = set(nums) — O(1) membership, and duplicates collapse.
  • best = 0 — the longest run so far; 0 is correct for an empty input.
  • for num in seen — visit each distinct value once.
  • if num - 1 in seen: continue — not the start of its run, skip it.
  • length = 1 — the start itself counts.
  • while num + length in seen: length += 1 — step upward while the next integer exists.
  • best = max(best, length) — record the finished run.
  • return best.

The loop goes over seen rather than nums so that a duplicated start does not trigger the same walk twice.

STEP 5

Trace it: 1 is a start, walk to 4

Python happens to hand the set out as 1, 2, 3, 100, 4, 200, but the order does not matter for correctness. The first value is num = 1. Is 0 in the set? No, so 1 is the start of a run.

Set length = 1. Is 1 + 1 = 2 in the set? Yes, length = 2. Is 3 in? Yes, length = 3. Is 4 in? Yes, length = 4. Is 5 in? No, the walk stops.

best = max(0, 4) = 4. The whole run 1–4 has been measured in a single pass from its bottom.

STEP 6

Trace it: 2, 3, and 4 are skipped

Next is num = 2. Is 1 in the set? Yes, so 2 is in the middle of a run that has already been walked. continue, no work done.

The same happens for 3 (its predecessor 2 is present) and later for 4 (predecessor 3 is present). Three values, three O(1) checks, zero steps of walking.

This is the step that makes the algorithm linear. Without the predecessor check, 2 would walk 2–4, 3 would walk 3–4, and 4 would walk itself: 6 extra membership tests on this small input, and quadratic work on a long run.

STEP 7

Trace it: 100 and 200, then the answer

num = 100: is 99 in the set? No, so it is a start. length = 1; is 101 in? No. The run has length 1. best = max(4, 1) = 4, unchanged.

num = 200: 199 is absent, so it is a start; 201 is absent, so its run is also length 1. best stays 4.

The loop is over and we return 4. Count the membership tests: 6 predecessor checks, plus 4 + 1 + 1 = 6 upward steps. Twelve O(1) operations for six values, which is the linear bound in action.

Each value was stepped over by exactly one walk, the one from its run's start. That is the invariant that makes the nested loop O(n).
STEP 8

Where this goes wrong: which side to check, and where to start counting

Checking num + 1 instead of num - 1. Now the values that survive the skip are the tops of runs, and walking upward from a top finds nothing. On the running example, 1, 2, and 3 are all skipped (each has a successor), 4 walks to 5 and stops immediately, and the function returns 1 instead of 4.

Inverting the skip: if num - 1 not in seen: continue. Now the starts are thrown away and only the non-starts walk. 2 walks to 4 for a length of 3, 3 gets 2, 4 gets 1, and 1, 100, 200 are never measured: 3 instead of 4.

Dropping the skip entirely. The answer is still right, but every member walks its own run: 12 steps instead of 6 here, and O(n²) on one long run, which is a timeout at 10^5 values.

Starting best = 1. The empty array then returns 1 instead of 0.

The start of a run is the value with no predecessor. Check num - 1 in seen and skip when it is present, then walk upward with num + length.
STEP 9

Time and space

Building the set is O(n). The outer loop does one O(1) check per distinct value. The inner while loops look nested, but each value is visited by at most one of them, so their total work is O(n) as well. O(n) time.

The set holds up to n values: O(n) space.

ApproachTimeSpace
Sort, then scanO(n log n)O(1) extra (in place)
Set, walk from every valueO(n²) worst caseO(n)
Set, walk only from run startsO(n)O(n)

The middle row is the same code minus one if. That single line is the difference between passing and timing out.

STEP 10

The final solution

Eleven lines. Every one of them maps to a step above.

  • seen = set(nums) gives O(1) membership and removes duplicates.
  • best = 0 handles the empty input by default.
  • for num in seen visits each distinct value once.
  • if num - 1 in seen: continue is the line that makes it linear.
  • length = 1 then while num + length in seen: length += 1 measures the run from its bottom.
  • best = max(best, length) and return best.
One-line summary to remember: a value with no predecessor starts a run; walk upward only from those, and every run is measured once.
