Medium · Dynamic Programming · LeetCode #139

Word Break, narrated

Scroll through the thinking, from the backtracking that re-explores the same suffixes to a boolean table over prefixes, with the state of the algorithm shown alongside.

Pattern used Dynamic Programming dp[i] = any(dp[j] and s[j:i] in words), table over prefixes

STEP 1

The problem

You get a string s and a dictionary of words. Decide whether s can be cut into pieces, left to right, so that every piece is a dictionary word and nothing is left over. Words may be reused as often as you like.

Running example: s = "leetcode", word_dict = ["leet", "code"]. The answer is True: cut after the 4th character and both halves are words.

The answer is a yes/no. We never have to return the cuts themselves, only whether a valid set of cuts exists — and that is a hint that a table of booleans, not a list of segmentations, is enough.

The catch is that the first word you spot is not always the right one. In "cars" with ["car", "ca", "rs"], grabbing "car" strands the "s"; the real split is "ca" + "rs". Any correct method has to be willing to back up.

STEP 2

First instinct: backtracking over every cut

Try every dictionary word at the current position. If it matches, recurse on the rest of the string. Succeed if any branch reaches the end.

def can_break(rest):    if rest == "":        return True    for w in words:        if rest.startswith(w) and can_break(rest[len(w):]):            return True    return False

This is correct, and it handles the "cars" trap because the loop keeps going when "car" dead-ends. But it is exponential: "aaaaaaab" with ["a", "aa", "aaa"] reaches the same suffix "aab" through dozens of different cut sequences and re-solves it every time. Roughly O(2ⁿ) branches in the worst case.

The waste has a name: the answer for a suffix does not depend on how you got there. can_break("code") is the same question whether the prefix was cut as "leet" or as "le" + "et".

STEP 3

The key idea: decide each prefix once

There are only len(s) + 1 distinct subproblems: the prefixes s[:0], s[:1], …, s[:len(s)]. Give each one a boolean slot, dp[i] = "can the prefix s[:i] be segmented?"

A prefix s[:i] is breakable exactly when its last word is s[j:i] for some cut j, and the part before that cut, s[:j], is itself breakable. That is the recurrence:

dp[i] = True if there is any j < i with dp[j] and s[j:i] in words. Seed with dp[0] = True: the empty prefix needs zero words.

Filling i from 1 upward means every dp[j] a slot consults is already final. Putting the dictionary in a set makes the membership test O(1) instead of a scan of the list.

STEP 4

The approach, line by line

  • words = set(word_dict) — O(1) lookups for every slice.
  • dp = [False] * (len(s) + 1) and dp[0] = True — one slot per prefix length, with the empty prefix seeded.
  • for i in range(1, len(s) + 1) — fill prefixes shortest to longest.
  • for j in range(i) — try every cut point for the last word.
  • if dp[j] and s[j:i] in words — a breakable prefix followed by a dictionary word.
  • dp[i] = True; break — one valid cut is enough.
  • return dp[len(s)] — the whole string is the longest prefix.
STEP 5

Trace it: the first three prefixes stay False

i = 1: the only cut is j = 0. dp[0] is True but s[0:1] = "l" is not a word. dp[1] stays False.

i = 2: j = 0 gives "le", not a word; j = 1 has dp[1] = False, so the slice is not even checked. dp[2] stays False.

i = 3: "lee" is not a word, and dp[1], dp[2] are False. dp[3] stays False.

Notice that only cut points with dp[j] = True ever cost a slice. So far that is just j = 0.

STEP 6

Trace it: i = 4, the first True

i = 4, j = 0: dp[0] is True and s[0:4] = "leet" is in the set. Both halves hold, so dp[4] = True and the inner loop breaks without trying j = 1, 2, 3.

Then i = 5, 6, 7: the candidate cuts with a True prefix are now j = 0 and j = 4. j = 0 gives "leetc", "leetco", "leetcod"; j = 4 gives "c", "co", "cod". None are words, so dp[5], dp[6], dp[7] stay False.

STEP 7

Trace it: i = 8, the answer

i = 8, j = 0: "leetcode" is not a word. j = 1, 2, 3: their dp[j] are False, skipped. j = 4: dp[4] is True and s[4:8] = "code" is in the set. So dp[8] = True.

The table reads [T, F, F, F, T, F, F, F, T]. dp[len(s)] = dp[8] is True, and that is the return value. Reading the True slots back gives the cuts: 0 → 4 → 8, or "leet" + "code".

Backtracking would have explored the same suffixes repeatedly; the table asked each of the nine prefix questions exactly once.
STEP 8

Where this goes wrong: the seed and the slice

Forgetting dp[0] = True. The empty prefix is the base every other True is built from. Leave it False and the condition dp[j] and s[j:i] in words can never fire, because no dp[j] is ever True. Every slot stays False and "leetcode" returns False.

Slicing s[j:i + 1] instead of s[j:i]. With dp[i] meaning "prefix of length i", the last word ends at index i exclusive. Off by one and slot 4 tests "leetc", which is not a word, so the chain never starts and the result is again False.

Returning dp[-2] or dp[len(s) - 1]. That is the prefix of length 7, "leetcod", which is False. The whole string lives at index len(s), which is why the table has one extra slot.

The table has len(s) + 1 slots because it indexes prefix lengths, not characters. Slot 0 is the empty prefix and must start True.
STEP 9

Time and space

There are n + 1 slots and slot i tries up to i cut points, each building a slice and hashing it: O(n² × L) where L bounds the slice length, or O(n³) in the loosest reading. The table is O(n), plus the set of dictionary words.

ApproachTimeSpace
BacktrackingO(2ⁿ)O(n) stack
Memoised backtrackingO(n² × L)O(n) cache + stack
Bottom-up tableO(n² × L)O(n) table

Because no dictionary word is longer than 20 characters, the inner loop can stop at j = i - 20 and the bound drops to O(n × 20 × 20). The version here keeps the plain range(i) for clarity.

STEP 10

The final solution

Ten lines. Every one of them maps to a step above.

  • words = set(word_dict) turns the list into O(1) lookups.
  • dp = [False] * (len(s) + 1) makes one slot per prefix length, including the empty prefix.
  • dp[0] = True seeds the chain.
  • for i in range(1, len(s) + 1) fills prefixes in increasing length so every needed dp[j] is final.
  • for j in range(i) proposes every possible last word s[j:i].
  • if dp[j] and s[j:i] in words checks the prefix and the last word together.
  • dp[i] = True then break: one witness is enough.
  • return dp[len(s)] — the slot for the whole string.
One-line summary to remember: a prefix is breakable if some shorter breakable prefix is followed by a dictionary word; seed the empty prefix as True and fill upward.
