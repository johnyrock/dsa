Construct Binary Tree from Preorder and Inorder Traversal, narrated

Scroll from slicing both arrays at every call to a single preorder cursor plus an inorder index map, with the tree growing node by node alongside.

Pattern used Tree The next preorder value is always the root of the current inorder window; its inorder position splits the window into left and right.

STEP 1

The problem

You are given two arrays that describe the same binary tree: preorder, which lists every node before its two subtrees (root, left, right), and inorder, which lists the left subtree, then the node, then the right subtree. All values are distinct. Rebuild the tree.

Running example: preorder = [3,9,20,15,7], inorder = [9,3,15,20,7]. The answer is the tree [3,9,20,null,null,15,7]: root 3, left child 9, right child 20 with children 15 and 7.

Why two traversals? Preorder alone tells you the root but not where the left subtree ends and the right one begins: [1,2,3] could be a left chain, a right chain, or a root with two leaves. Inorder alone tells you what is left and right of each node but not which node is on top. Put together, and with distinct values, they leave exactly one tree.

The panel shows the target tree, the preorder list with the cursor that will walk it, and the inorder list with the window that will be split. Nothing has been built yet.

STEP 2

First instinct: slice both arrays and recurse

The classic textbook version. The root is preorder[0]. Find it in inorder with index; say it lands at position mid. Then the left subtree has mid nodes, so its preorder is the next mid values and its inorder is everything before mid; the right subtree gets the rest of both arrays:

def build_tree(preorder, inorder):    if not preorder:        return None    root = TreeNode(preorder[0])    mid = inorder.index(preorder[0])    root.left = build_tree(preorder[1:mid + 1], inorder[:mid])    root.right = build_tree(preorder[mid + 1:], inorder[mid + 1:])    return root

It is correct and short, and it is worth knowing. But every call does two O(n) things: inorder.index scans the list, and the four slices copy it. On a chain of 3000 nodes the windows shrink by one each level, so the total is 3000 + 2999 + … = O(n²) time and the same again in copied memory.

The panel marks the scan: on the running example the root 3 is found at inorder index 1, and both arrays are then cut into a 1-element left part and a 3-element right part. That cut is the right idea; the copying and scanning are the waste.

STEP 3

The key insight: one cursor and one map replace all the slicing

Two observations remove both costs. First, the scan: build a dict index_of = {val: i for i, val in enumerate(inorder)} once, and finding mid becomes an O(1) lookup. Values are distinct, so the map is unambiguous.

Second, the slicing. Notice which preorder value each recursive call consumes: the first call takes preorder[0], the left-subtree call takes preorder[1], its left call takes preorder[2], and so on. Because preorder lists the whole left subtree before the right, and the recursion builds left before right, the calls happen in preorder order. A single cursor next_pre that advances by one per call always points at the correct root.

So a call never needs its own copy of preorder: it takes preorder[next_pre] and increments. And it never needs a copy of inorder: it just needs the window bounds lo..hi, which it splits at mid = index_of[val] into lo..mid-1 and mid+1..hi.

The panel shows the cursor sitting on 3 and the map's answer: index_of[3] = 1.

STEP 4

The approach: build(lo, hi)

The helper build(lo, hi) returns the subtree whose inorder values are inorder[lo..hi] inclusive. Line by line:

  • if lo > hi: return None — an empty window is an empty subtree, and the cursor does not move.
  • val = preorder[next_pre] then next_pre += 1 — take the next root and advance, before recursing.
  • node = TreeNode(val) and mid = index_of[val] — create the node and find where it splits the window.
  • node.left = build(lo, mid - 1) — the left window, built first so it consumes its preorder values first.
  • node.right = build(mid + 1, hi) — then the right window, starting wherever the cursor now stands.
  • return build(0, len(inorder) - 1) — the whole tree is the whole inorder list.

The nonlocal next_pre declaration is what lets the nested function mutate the shared cursor rather than shadowing it with a local.

STEP 5

Trace it: the root

Call build(0, 4). The window is all of inorder. The cursor is at 0, so val = preorder[0] = 3 and the cursor moves to 1. Look it up: mid = index_of[3] = 1.

That splits the window into lo..mid-1 = 0..0, holding just [9], and mid+1..hi = 2..4, holding [15, 20, 7]. So the root 3 will have a one-node left subtree and a three-node right subtree, which matches the answer we expect.

The node 3 is created and the panel draws it at the top. The next thing that happens is node.left = build(0, 0), and it is important that this comes before the right call: the cursor currently points at 9, and 9 belongs on the left.

STEP 6

Trace it: the left subtree

Inside build(0, 0): the window is not empty, so take val = preorder[1] = 9 and advance the cursor to 2. The map says mid = index_of[9] = 0.

Both sub-windows are empty: the left is build(0, -1) and the right is build(1, 0), and in each lo > hi so they return None immediately without touching the cursor. Node 9 is a leaf, and it is attached as 3.left.

Back in the root's call, the cursor stands at 2, pointing at 20. Everything preorder listed for the left subtree has been consumed, which is exactly why the next value is the right subtree's root.

STEP 7

Trace it: the right subtree, and the answer

Now node.right = build(2, 4). Take val = preorder[2] = 20, cursor to 3, mid = index_of[20] = 3. The window splits into 2..2 (just [15]) and 4..4 (just [7]).

The left call build(2, 2) takes preorder[3] = 15, cursor to 4, and both of its sub-windows are empty, so 15 is a leaf. Then build(4, 4) takes preorder[4] = 7, cursor to 5, another leaf. Node 20 gets left = 15 and right = 7 and is attached as 3.right.

The cursor ends at 5, the length of preorder, having handed out every value exactly once, in order. The returned tree is [3,9,20,null,null,15,7].
STEP 8

Where this goes wrong

Building the right subtree first. Swap the two recursive lines so node.right = build(mid + 1, hi) runs before the left. The cursor does not know which window asked for a value, so the right window 2..4 is handed preorder[1] = 9, a value that is not even inside it. Every level after that is misaligned: 9 becomes the "root" of [15,20,7], then 20, 15, 7 are consumed as a chain of right children, and when the deferred left calls finally run, preorder[5] does not exist: IndexError: list index out of range. The left-before-right order is not a style choice; it is what makes the cursor correct.

Leaving the root in the left window. Write build(lo, mid) instead of build(lo, mid - 1). The left window now includes the root's own value, so it is one element too wide at every level and consumes one preorder value too many; the cursor again runs off the end with the same IndexError.

Dropping nonlocal. Without nonlocal next_pre, the next_pre += 1 makes the name local to build, and Python raises UnboundLocalError at the first preorder[next_pre].

Left before right, and the left window stops at mid - 1. Both mistakes surface as the cursor overrunning preorder, so an IndexError here almost always means the windows and the cursor have fallen out of step.
STEP 9

Time and space

Building index_of is one pass over inorder. Then each of the n nodes is created by exactly one build call, and that call does a dict lookup, one increment, and two recursive calls: O(1) of its own work. Total O(n).

Space is the map, O(n), plus the recursion stack, O(h), which is up to n on a chain. The slicing version's extra cost was in copied arrays, which this version never makes.

ApproachTimeSpace
Slice both arrays, inorder.index per callO(n²)O(n²) copies on a chain
Index map, still slicingO(n²) from the copiesO(n²) copies on a chain
Cursor + index map + window boundsO(n)O(n) map + O(h) stack
STEP 10

The final solution

One map, one cursor, one recursive helper over window bounds. Line by line:

  • index_of = {val: i for i, val in enumerate(inorder)} — O(1) lookup of where each value sits in inorder.
  • next_pre = 0 — the cursor into preorder, shared by every call via nonlocal.
  • if lo > hi: return None — empty window, empty subtree.
  • val = preorder[next_pre]; next_pre += 1 — this call's root, then advance.
  • mid = index_of[val] — where the root splits the inorder window.
  • node.left = build(lo, mid - 1) — left first, so it consumes its preorder values first.
  • node.right = build(mid + 1, hi) — then the right, from wherever the cursor now is.
  • return build(0, len(inorder) - 1) — the whole tree spans the whole inorder list.
One-line summary to remember: the next preorder value is the root of the current inorder window; split the window at that value, build left, then right.
