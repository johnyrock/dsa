Easy · Two Pointers · LeetCode #125

Valid Palindrome, narrated

Scroll through the thinking, from the cleaned copy you reach for first to the two pointers that need no copy at all, with the state of the algorithm shown alongside.

Pattern used Two Pointers skip non-alphanumerics, compare lowercase

STEP 1

The problem

You get a string s. Decide whether it reads the same forwards and backwards, ignoring everything that is not a letter or a digit, and treating uppercase and lowercase as the same character.

So spaces, commas, colons and apostrophes are invisible, and 'N' and 'n' are the same letter.

Running example: s = "No 'x' in Nixon". The alphanumeric characters spell noxinnixon, which is the same read either way, so the answer is True.

Two inputs that look like trick questions are not: the empty string "" and a string of only punctuation like ".,;'" both return True, because there is nothing left that could disagree.

STEP 2

First instinct: clean it, then reverse it

The obvious move is to do the two rules literally. Build a new string containing only the lowercased alphanumeric characters, then compare it to its own reverse.

cleaned = "".join(c.lower() for c in s if c.isalnum())return cleaned == cleaned[::-1]

This is correct and it is a perfectly good first answer to say out loud. It is also O(n) time, so the time is already optimal.

The cost is memory. cleaned is a copy of the input, and cleaned[::-1] is a second copy, so this is O(n) extra space. For a 200,000-character input that is two more strings held in memory just to answer a yes/no question.

What is the copy actually buying us?

STEP 3

Reframe: what does the comparison really touch?

Comparing a string to its reverse means comparing position 0 with the last position, position 1 with the second-to-last, and so on inward until the two meet in the middle.

That is the entire operation: a sequence of mirrored pairs. The reversed copy exists only so that both halves can be read left to right.

In "No 'x' in Nixon", the first pair is N at index 0 against n at index 14. Nothing in between matters yet.

But we can read a string backwards without reversing it — just walk an index down from the end. And the filtering does not need a new string either; it only needs to decide which positions to skip.

STEP 4

The key idea: two pointers, skipping in place

Put left on the first character and right on the last, and walk them toward each other. At each step:

  • Skip left forward past anything that fails isalnum().
  • Skip right backward past anything that fails isalnum().
  • Compare the two characters they land on, lowercased. A mismatch answers the whole question: False.
  • Step both pointers inward and repeat.

Filtering has turned from a string-building step into a movement rule. Nothing is copied, so the extra space is two integers: O(1).

When the pointers meet or cross, every mirrored pair has agreed, and the answer is True.

STEP 5

Trace it: the outermost pair

Start at left = 0 and right = 14. Both characters are already alphanumeric, so neither skip loop moves.

s[0].lower() is 'n' and s[14].lower() is 'n'. They match, so the pair is settled and both pointers step inward to left = 1, right = 13.

There, 'o' meets 'o' — another match — and the pointers move again, to left = 2 and right = 12.

Note what did not happen: no string was built, and the capital N was handled by .lower() at comparison time rather than by rewriting the input.
STEP 6

Trace it: the skip

Now left = 2, which is a space, and left = 3 is an apostrophe. The inner loop slides left forward twice and stops at index 4, the x.

Meanwhile right = 12 is already the other x, so its skip loop does nothing. The pair matches.

The same thing happens on the way in: the pointers skip ', a space and another space, matching i with i and n with N, until both land on index 9. At that point left < right is false, the loop ends, and the function returns True.

Each pointer only ever moves inward, so between them they visit each position at most once. All that skipping is still one pass.
STEP 7

Where it goes wrong

Take s = "race a car". The first three pairs match: r/r, a/a, c/c. Then left = 3 sits on e, and right = 6 is a space, so the right skip loop backs it up to index 5, an a.

'e' != 'a', so the answer is False and we return immediately — no need to look at the middle.

The off-by-one to watch: both inner skip loops need their own left < right guard. On ".,;'" nothing is alphanumeric, so an unguarded loop walks left straight off the end of the string and raises IndexError. With the guard, the pointers stop against each other and the function correctly returns True.

The empty string is free: right starts at -1, the outer while left < right is false immediately, and the answer is True with no special case.

STEP 8

Time and space

Every iteration of any loop moves left forward or right backward, and they never move apart. So the total number of moves is bounded by the length of the string: O(n) time.

The only storage is the two indices. Nothing scales with the input, so the extra space is O(1).

ApproachTimeSpace
Cleaned copy, compare to reverseO(n)O(n)
Two pointers, skip in placeO(n)O(1)

Unlike most optimizations, this one buys nothing in time — both are O(n). The win is that the answer no longer requires holding a second copy of a 200,000-character string.

STEP 9

The final solution

Twelve lines, and each one is a step above.

  • left, right = 0, len(s) - 1 puts a pointer on each end.
  • while left < right is the meet-in-the-middle stopping rule, and the reason "" works.
  • The two inner while loops are the filter, expressed as movement instead of a copy.
  • s[left].lower() != s[right].lower() is the mirrored-pair comparison, case folded.
  • left += 1 / right -= 1 close the window by one on each side.
  • return True is reached only when the pointers met without a mismatch.
One-line summary to remember: walk inward from both ends, skip what does not count, compare what does.
