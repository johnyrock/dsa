Easy · Fast & Slow Pointers · LeetCode #141

Linked List Cycle, narrated

Scroll through the tortoise-and-hare technique, with both pointers' positions shown alongside.

Pattern used Fast & Slow Pointers slow steps by 1, fast steps by 2 — they meet only if a cycle exists

STEP 1

The problem

Given the head of a linked list, decide whether it has a cycle — some node's next loops back to an earlier node instead of eventually reaching None.

Running example: 3 -> 2 -> 0 -> -4, and -4's next points back to 2 (index 1). No node is ever None, so a naive walk to the end never terminates.
STEP 2

First instinct: remember visited nodes

Keep a set of every node object seen so far. Walk forward; if the current node is already in the set, there's a cycle; if you reach None, there isn't. This works and is O(n) time, but it's O(n) space — and the problem asks for O(1) extra space.

STEP 3

The key idea: two speeds, no memory

Instead of remembering where you've been, run two pointers at different speeds. slow advances one node per step, fast advances two.

If there's no cycle, fast simply reaches the end first — it's just running a race it wins by finishing. If there is a cycle, both pointers are stuck circling inside it, and fast gains on slow by one node every step, so it must eventually land exactly on top of it.
STEP 4

Trace it: step 1

Start: slow = fast = 3. After one iteration: slow moves to 2, fast moves to 0 (two hops from 3). Not equal, keep going.

STEP 5

Trace it: step 2

slow moves to 0. fast moves two hops from 0: to -4, then following its cycling next back to 2. So fast is now at 2. Still not equal — but the gap between them just closed a lot.

STEP 6

Trace it: step 3, they meet

slow moves to -4. fast moves two hops from 2: to 0, then to -4. Both pointers are now on the same node object — slow is fast is true. Return True.

STEP 7

Contrast: no cycle

On a straight list like 1 -> 2 -> 3 -> 4 -> 5, fast reaches the last node (or None) before it ever lines up with slow. The loop condition fast is not None and fast.next is not None catches this and exits cleanly, returning False.

STEP 8

Where this goes wrong

Checking only fast is not None and then evaluating fast.next.next crashes with an AttributeError the moment fast.next is None — which happens on any even-length list with no cycle. Both halves of the guard are required.

Also watch node comparison: use is, not ==, so the check is about identity (same object), not value equality.
STEP 9

Time and space

O(n) time: if there's a cycle of length k, fast closes the gap by one node per step, so it meets slow within k steps of entering the cycle. O(1) space: only two pointers exist, regardless of list length.

STEP 10

The final solution

  • slow = fast = head — both start at the same place.
  • The while guard checks both fast and fast.next before dereferencing twice.
  • slow advances by 1, fast by 2, every iteration.
  • slow is fast after advancing is the only way to detect a cycle — checking before advancing would falsely trigger at the start.
