Maximum Depth of Binary Tree, narrated

I’ll start by listing every root-to-leaf path, then use a recursive depth calculation that returns only the one number each parent needs.

Pattern used Tree A tree is empty at a missing child, so its depth is 0. Every real node contributes one level plus the larger child depth.

STEP 1

The problem

Given the root of a binary tree, return its maximum depth: the number of nodes on the longest path from the root down to a leaf. An empty tree has depth 0; a single node has depth 1.

Running example: root = [3,9,20,null,null,15,7] in level order. Node 3 has children 9 and 20; node 9 has no children; node 20 has children 15 and 7. The answer is 3, because the longest path is 3 → 20 → 15 (or 3 → 20 → 7), three nodes.

The path 3 → 9 is only two nodes, so it is not the one that counts. "Maximum" means we compare all root-to-leaf paths and keep the longest; we never have to say which path it was, only how long.

STEP 2

First instinct: list every path and measure each

My first instinct is to follow the definition literally. I enumerate every root-to-leaf path, record each one at a leaf, and return the largest path length.

paths = []def visit(node, path):    if node is None: return    path.append(node.val)    if not node.left and not node.right: paths.append(path[:])    else: visit(node.left, path); visit(node.right, path)    path.pop()visit(root, [])return max((len(path) for path in paths), default=0)

On the running example that produces three paths, exactly what the panel shows: [3,9] with length 2, [3,20,15] with length 3 and [3,20,7] with length 3. The maximum is 3, and the answer is correct.

This baseline copies a path at each leaf. In the worst case those copies take O(n · h) time and O(n · h) extra space, where h is the tree height.

Neighboring paths repeat their shared prefixes. A parent only needs the larger child depth, so I do not need to keep every full path.

STEP 3

The key insight: an empty tree has depth 0

Forget the paths and ask what the depth of a subtree is in terms of its children. A node adds one level on top of whichever child subtree is taller. So depth(node) = 1 + max(depth(node.left), depth(node.right)).

The recursion needs a floor, and the floor is the empty tree. A missing child is an empty subtree with depth 0. The panel draws that as the ghost 0 under node 9. This one base case, if root is None: return 0, ends every branch of the recursion.

There is no separate leaf case. A leaf is just a node whose two children are both empty: 1 + max(0, 0) = 1, exactly what a single node should measure. Getting the None value right is what makes the whole formula work without special cases.

STEP 4

The approach: post-order recursion

The whole solution is the recurrence written as a function. At any node:

  • if root is None: return 0 — the base case from the previous step.
  • self.max_depth(root.left) — measure the left subtree.
  • self.max_depth(root.right) — measure the right subtree.
  • return 1 + max(...) — add this node's own level to the taller of the two.

This is post-order: a node cannot answer until both children have. The panel shows the root sitting at left = ?, right = ?, waiting. Each node is entered exactly once and does a constant amount of work of its own, so no path or prefix is ever revisited.

STEP 5

Trace it: node 9, a leaf

The root calls self.max_depth(root.left), which is node 9. Node 9 calls max_depth on its left child, gets None, and the base case returns 0. Its right child is also None, so that returns 0 as well.

Now node 9 can compute its own answer: 1 + max(0, 0) = 1. The panel badges it →1. A leaf has depth 1, which matches the definition: a path consisting of just that node has one node on it.

Back at the root, the left result is 1. The root now calls self.max_depth(root.right) and the walk moves to node 20.

STEP 6

Trace it: node 20

Node 20 has two children, and they finish first. Node 15 is a leaf: both its children are None, so it returns 1 + max(0, 0) = 1. Node 7 does exactly the same and returns 1.

Node 20 then has left = 1 and right = 1, and returns 1 + max(1, 1) = 2: the badge →2. Two nodes on the longest path below and including 20, which is right: 20 → 15 or 20 → 7.

The tie between 15 and 7 does not matter. max only needs the larger value, and both children are equally deep.

STEP 7

Trace it: the root, and the answer

Both calls have returned to the root: left = 1 from node 9 and right = 2 from node 20. The root returns 1 + max(1, 2) = 3.

That is the answer: 3. The deepest path is 3 → 20 → 15 (or 3 → 20 → 7), and the function never had to write it down. It only carried one integer up from each subtree.

Five nodes, five real calls plus six trivial None calls, each doing constant work. The path-listing approach walked 3 → 20 twice and built three lists to learn the same number.
STEP 8

Where this goes wrong: the base case

Almost every bug in this problem is a wrong value for the empty tree.

Returning 1 for None. It is tempting to think a node counts as one level and make the bottom return 1. But the bottom of the recursion is the empty child, not the leaf. With if root is None: return 1, leaf 9 computes 1 + max(1, 1) = 2, node 20 computes 3, and the root reports 4 instead of 3.

Special-casing leaves and forgetting empty input. Writing if root.left is None and root.right is None: return 1 as the base case, without a None check first, crashes with AttributeError on an empty tree (root = []), and also on any node with exactly one child, because the recursion is then called on the missing child. The None base case covers all of those at once and makes the leaf case fall out for free.

I test a single node: the answer must be 1. An answer of 2 means the empty tree is being counted as a level.
STEP 9

Time and space

Every node is entered by max_depth exactly once, and beyond its two recursive calls it does one max and one addition. So the time is O(n). The badges in the panel are the five values computed, one per node.

The only extra memory is the call stack, which is as deep as the tree is tall: O(h). For a balanced tree that is about log n; for a chain where every node has one child it is n.

ApproachTimeSpace
Enumerate every root-to-leaf pathO(n · h)O(n · h) for the path lists
Post-order recursionO(n)O(h) call stack

A breadth-first version with a queue, counting levels, is also O(n) time; its extra memory is the widest level rather than the height, which can be better or worse depending on the shape.

STEP 10

The final solution

Three lines of logic. Line by line:

  • if root is None: return 0 — an empty subtree contributes no levels. This is the only base case, and it also handles an empty input tree.
  • self.max_depth(root.left) and self.max_depth(root.right) — depths of the two child subtrees, each computed once.
  • return 1 + max(...) — this node adds one level on top of its taller child.
One-line summary to remember: an empty tree has depth 0, and every node is one more than its taller child.
