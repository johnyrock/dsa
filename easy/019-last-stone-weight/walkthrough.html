Easy · Heap · LeetCode #1046

Last Stone Weight, narrated

Scroll from re-sorting every round to a negated max-heap, with the heap’s layout shown alongside as stones are smashed.

Pattern used Heap Every round needs the two heaviest stones, so a max-heap removes precisely the values the next operation needs.

STEP 1

The problem

You have a pile of stones, each with a positive weight. Every round, take the two heaviest stones, x <= y, and smash them together. If x == y both are destroyed. Otherwise the lighter one is destroyed and the heavier one shrinks to y - x, which goes back on the pile. Repeat until at most one stone is left, and return its weight, or 0 if none remain.

Running example: stones = [2, 7, 4, 1, 8, 1]. Rounds: 8 vs 7 leaves 1; 4 vs 2 leaves 2; 2 vs 1 leaves 1; 1 vs 1 destroys both. One stone of weight 1 survives.

Notice the rule always says the two heaviest. That is the whole difficulty: after every smash the pile changes, and you need the new top two immediately. The answer is a single integer, not the sequence of smashes.

STEP 2

First instinct: sort every round

Simulate it literally. Each round, sort the list descending, pop the first two, push back their difference if it is nonzero:

while len(stones) > 1:    stones.sort(reverse=True)    first, second = stones.pop(0), stones.pop(0)    if first != second:        stones.append(first - second)

It is correct and it is fine for 30 stones. But look at what the sort does: after [8, 7, 4, 2, 1, 1] is sorted, only the top two are touched, yet the next round sorts all remaining values again. Every round removes at least one stone, so there are up to n - 1 rounds, each costing O(n log n): O(n² log n) in total. The pop(0) calls are O(n) each on top of that.

The waste is that a full sort establishes the order of every pair of stones, when all you need each round is "which one is heaviest, and which is next".

STEP 3

The key insight: a max-heap gives you the heaviest in O(log n)

A heap answers exactly one question fast: "what is the extreme element?" Popping it costs O(log n), and pushing a new value costs O(log n), and between operations the rest of the pile stays partially ordered instead of being re-sorted from scratch.

Python's heapq is a min-heap, and there is no max-heap flag. The standard trick is to store each weight negated: heap = [-stone for stone in stones]. The most negative number is then the smallest, so it sits at the root, and the most negative number corresponds to the heaviest stone.

After heapify([-2, -7, -4, -1, -8, -1]) the list is laid out as [-8, -7, -4, -1, -2, -1]. The root is -8, which is stone 8, the heaviest. That is what the panel highlights in green.

Every time you read a value out of this heap, negate it again to get a weight. Every time you put a weight in, negate it first. Keep that rule in your head; it is where the bug in step 8 lives.

STEP 4

The approach: pop two, smash, push the difference

With the negated heap built, the loop on lines 5 to 9 is the smash rule almost word for word:

  • while len(heap) > 1: keep going as long as there are two stones to smash.
  • first = -heapq.heappop(heap): the heaviest stone, as a positive weight.
  • second = -heapq.heappop(heap): the next heaviest. Because the first pop was the largest, first >= second always.
  • if first != second: heapq.heappush(heap, second - first): the surviving weight is first - second, and it must be stored negated, which is second - first.

Each round removes two values and adds back at most one, so len(heap) falls by at least one every round. It starts at 6 in the example, so at most 5 rounds can happen. The panel marks the two amber roots, -8 and -7, as first and second for round 1.

STEP 5

Trace it: round 1, 8 vs 7

The first pop returns -8, so first = 8. The second pop returns -7, so second = 7. After both pops the heap has settled into [-4, -2, -1, -1], with the next heaviest stone, 4, at the root.

8 != 7, so push second - first = 7 - 8 = -1. That represents a stone of weight 1. It is appended at index 4 and stays there, because its parent -2 is already smaller. The heap is now [-4, -2, -1, -1, -1]: four stones, one of them the fresh 1 shown in blue.

STEP 6

Trace it: round 2, 4 vs 2

Five values remain, so the loop continues. Pop -4, so first = 4; pop -2, so second = 2. Only [-1, -1, -1] is left in the heap, three stones of weight 1.

4 != 2, so push 2 - 4 = -2. This time the pushed value is smaller than everything present, so heappush sifts it all the way to the root: [-2, -1, -1, -1]. The stone of weight 2 is now the heaviest, and it will be the next first.

The heap re-established "heaviest on top" with a single O(log n) sift. The sort-based version would have re-sorted all four values to learn the same thing.
STEP 7

Trace it: rounds 3 and 4, the last stone

Round 3: pop -2 and -1, so first = 2, second = 1. They differ, so push 1 - 2 = -1. Two pops and one push on four stones leaves three: [-1, -1, -1].

Round 4: pop -1 and -1, so first = 1 and second = 1. Now first != second is false, so nothing is pushed. Both stones are destroyed and the heap is [-1], a single stone of weight 1, shown in green.

len(heap) is 1, so the loop exits. Line 10 returns -heap[0] = 1. The if heap else 0 guard covers the case where the last round destroyed both stones and the heap is empty, as with [2, 2], which returns 0.

STEP 8

Where this goes wrong: the sign of the pushed difference

Pushing first - second. It reads naturally: the surviving weight is 8 - 7 = 1, so push 1. But this heap holds negated weights, and +1 is larger than every negative value. The panel shows round 1 with this bug: the heap is [-4, -2, -1, -1, 1], and the +1 at index 4 sorts after everything. It is never chosen as first or second while any other stone remains, and when it is finally the only value left, the function returns -heap[0], which is −1 instead of 1. A negative stone weight is the tell.

Forgetting the negation on the way out. Writing first = heapq.heappop(heap) without the leading minus makes first = -8 and second = -7. Then second - first = 1, positive again, and the same corruption follows. Both directions of the conversion must be explicit.

Rule for a negated heap: everything that goes in is negated, everything that comes out is negated back. second - first is -(first - second), which is the negated survivor.
STEP 9

Time and space

heapify is O(n). Each round does two pops and at most one push on a heap of size at most n, so O(log n) per round. Every round permanently removes at least one stone, so there are at most n - 1 rounds. Total: O(n log n) time. The heap holds at most n values: O(n) space.

ApproachTimeSpace
Re-sort every roundO(n² log n)O(n)
Max-heap via negated valuesO(n log n)O(n)

With n <= 30 the brute force also passes. The heap version is what an interviewer expects because it shows you recognise "repeatedly extract the extreme" as a heap problem.

STEP 10

The final solution

Eight lines, each of them a step above.

  • heap = [-stone for stone in stones] negates every weight so that heapq's min-heap behaves as a max-heap of weights.
  • heapq.heapify(heap) arranges them in O(n) so the heaviest stone, -8, is at index 0.
  • while len(heap) > 1 runs a round only when there are two stones to smash.
  • first = -heapq.heappop(heap) and second = -heapq.heappop(heap) extract the two heaviest as positive weights, with first >= second.
  • if first != second skips the push when both stones are destroyed.
  • heapq.heappush(heap, second - first) stores the surviving weight first - second in negated form.
  • return -heap[0] if heap else 0 converts the last value back to a weight, or returns 0 when nothing survived.
One-line summary to remember: "always take the two largest" means a max-heap; in Python, negate on the way in and on the way out.
