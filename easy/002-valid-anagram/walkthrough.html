Easy · Hash Map · LeetCode #242

Valid Anagram, narrated

Scroll through the thinking, from sorting both strings to a single pass of character counting, with the state of the algorithm shown alongside.

STEP 1

The problem

You get two strings s and t. Return True if t is an anagram of s, and False otherwise.

An anagram uses exactly the same letters as the original, exactly as many times, in any order. Order is the one thing that is allowed to change.

Running example: s = "anagram", t = "nagaram". The answer is True: both are one a a a, one n, one g, one r, one m.

Notice the phrase exactly as many times. Not "the same set of letters" — the same letters with the same multiplicities. That distinction is the whole problem.

STEP 2

First instinct: sort both strings

If order is the only thing allowed to differ, then destroying the order should make the two strings identical. Sort each one and compare.

def is_anagram(s, t):    return sorted(s) == sorted(t)

This is correct, it is one line, and it is a perfectly good first answer to say out loud. Sorting also handles the length difference for free: two lists of different lengths are never equal.

The cost is the sort. Comparison sorting is O(n log n) time, and it builds two new lists of characters along the way.

But sorting does more work than we asked for. It puts the letters in order, and we do not care about order at all — we throw the ordering away the moment we compare. What do we actually need?

STEP 3

Reframe: what is an anagram, really?

Two strings are anagrams when they have the same character counts. "anagram" is not a sequence here, it is a tally: a×3, n×1, g×1, r×1, m×1.

So the question is not "do these strings match after sorting?" but "does t have exactly as many of each character as s?"

s has three as. Does t have three as? It has an n, a g, an r, an m — one of each, same as s. So yes.

A tally is a mapping from character to number. That is exactly what a dictionary is, and a dictionary reads and writes in O(1).

STEP 4

The key idea: count, then cancel

Build the tally for s in one pass. Then walk t and cancel one copy of each character against the tally.

  • Count. For each character of s, add one to its entry. counts.get(ch, 0) + 1 treats an unseen character as zero.
  • Cancel. For each character of t, if its count is already 0 there is no copy left to give — return False. Otherwise subtract one.

And before either loop, one guard: if the lengths differ, return False immediately. That check costs nothing and it is what lets the second loop end with a bare return True.

Two passes, each O(n), each doing O(1) work per character. No sorting, no ordering, no comparisons between the strings themselves.

STEP 5

Trace it: count s

Lengths first: both strings are 7 characters, so we continue.

Now sweep "anagram" left to right. The a at index 0 is new, so its count becomes 1. The n becomes 1, the a at index 2 bumps to 2, then g, r, the third a which bumps to 3, and finally m.

One pass later the tally is complete. The string is gone; only the counts matter now.

STEP 6

Trace it: cancel t against the tally

Walk t = "nagaram". The n has a count of 1, so it is not zero — subtract one, leaving 0. The a drops 3 to 2. The g drops to 0. The next a drops to 1.

Then r to 0, the third a to 0, and m to 0. Every lookup found a copy still available, so the loop never returned early.

The loop finishing is the answer. Because the lengths matched, cancelling all of t without running out means every count landed exactly on zero — no leftovers are possible. So return True.
STEP 7

Where it goes wrong

Take s = "rat", t = "car". Same length, so the guard passes. The tally is r:1, a:1, t:1.

The first character of t is c. counts.get("c", 0) is 0, so there is no c to cancel and we return False after looking at one character. We never reach the a or the r.

Use counts.get(ch, 0) == 0, not ch not in counts. Once a character is used up its key is still there with a value of 0, and in would wave it through. That is how s = "aacc", t = "ccac" sneaks past a buggy version.

And the length guard is not decoration. Drop it and try s = "aa", t = "a": the single a in t cancels fine, the loop ends, and the function returns True — leaving an unspent a behind. The guard is what makes "the loop finished" mean "everything balanced".

STEP 8

Time and space

Two loops, each visiting n characters once, each doing an O(1) dictionary read and write. That is O(n) time — strictly better than sorting.

The dictionary holds one entry per distinct character, not per character. For lowercase English letters that is at most 26 entries no matter how long the strings are, so the space is O(k) for an alphabet of size k, which is effectively O(1) here.

ApproachTimeSpace
Sort both, compareO(n log n)O(n)
Character countsO(n)O(k), k = alphabet

Sorting orders n items to answer a question that never needed order. Counting answers it directly.

STEP 9

The final solution

Eleven lines. Every one of them maps to a step above.

  • if len(s) != len(t) is the guard that makes the ending safe.
  • counts = {} is the tally.
  • counts[ch] = counts.get(ch, 0) + 1 is the counting pass over s.
  • if counts.get(ch, 0) == 0 is the O(1) check: does s still have this character to give?
  • counts[ch] -= 1 is the cancellation.
  • return True is reached only when every character of t was paid for.
One-line summary to remember: an anagram is a tally, not a sequence — count s, then spend it on t.
