Kth Largest Element in a Stream, narrated

I’ll start by re-sorting the full stream, then keep only the top k values in a capped min-heap.

Pattern used Heap Keep only the k largest values seen so far. The smallest of those kept values is exactly the k-th largest overall.

STEP 1

The problem

Design a class KthLargest. It is constructed with an integer k and an initial list nums. Then values arrive one at a time through add(val), and after each one you must return the k-th largest value seen so far, counting duplicates as separate values (the 3rd largest of [5, 5, 8] is 5).

Running example: k = 3, nums = [4, 5, 8, 2]. Then add(3) returns 4, add(5) returns 5, and add(10) returns 5.

After adding 3, the values seen are {2, 3, 4, 5, 8}. In descending order they are 8, 5, 4, …, so the 3rd largest is 4. The challenge is answering cheaply as the stream grows, rather than finding the answer once.

STEP 2

First instinct: keep everything sorted

My first instinct is to store every value. On each add, I append, sort the full list, and return index -k.

def __init__(self, k, nums):    self.k, self.values = k, nums[:]def add(self, val):    self.values.append(val)    self.values.sort()    return self.values[-self.k]

Sorting returns the right k-th value, but it touches all n values every time, so each add takes O(n log n) time; storing the whole stream uses O(n) extra space.

bisect.insort would still shift O(n) values. I avoid that work by dropping values that can never affect the top k.

STEP 3

The key insight: only the k largest matter

Values can only arrive, never leave. So once a value is outside the top k, every future stream makes it fall further. In the example, once {4, 5, 8} are the three largest, the 2 is permanently irrelevant and can be dropped.

When I keep exactly the k largest values seen so far, the smallest of those kept values is exactly the k-th largest overall. For kept = {4, 5, 8}, min(kept) = 4, which is the answer.

I need a structure that answers "what is my minimum?" quickly and lets me evict that minimum when something bigger arrives. That is a min-heap: the smallest element is always at the root, self.heap[0], which is why line 13 can simply return self.heap[0].

STEP 4

The approach: heapify, then trim to k

In __init__, I copy the input with nums[:] so the caller's list stays untouched, then call heapq.heapify(self.heap). Python's heapq is a min-heap, exactly what I need. For [4, 5, 8, 2], heapify rearranges the list in place to [2, 4, 8, 5]: the root is the smallest, and each child is no smaller than its parent.

Then trim: while len(self.heap) > k: heapq.heappop(self.heap). The size is 4 and k = 3, so one pop removes the root, 2. The panel marks that root amber, about to be popped.

  • add(val) pushes val, and if the size is now k + 1, pops the smallest.
  • After that, the heap holds the k largest and self.heap[0] is the answer.

Note the constraint 1 <= k <= nums.length + 1: the heap may start with only k - 1 values. That is fine, because the first add brings it up to k.

STEP 5

Trace it: the state after __init__

Popping 2 from [2, 4, 8, 5] works the way heapq always does: the last element, 5, moves to the root, then sifts down past the smaller child 4. The result is [4, 5, 8].

Now len(self.heap) == 3, which equals k, so the while loop on lines 6 to 7 stops. The three values I keep are the three largest of {2, 4, 5, 8}, and the root self.heap[0] = 4 is the 3rd largest. The panel highlights it green: this is already a correct answer, before any add has happened.

STEP 6

Trace it: add(3)

heapq.heappush(self.heap, 3) appends 3 and sifts it up. It is smaller than its parent 5, then smaller than the root 4, so it climbs all the way: the list becomes [3, 4, 8, 5]. The panel colours 3 blue for "just pushed".

Now len(self.heap) is 4, which is greater than self.k = 3, so line 11 pops. The smallest value is the root, 3, the very thing I just inserted. It leaves immediately and the heap is [4, 5, 8] again.

I return self.heap[0] = 4. Adding a value that is not among the top k costs one push and one pop, and changes nothing. That is the invariant doing its job.
STEP 7

Trace it: add(5), then add(10)

When I push 5, the list is [4, 5, 8, 5]. Its size reaches 4, so I pop root 4; the heap settles as [5, 5, 8] and add(5) returns 5. The two fives remain because duplicates count separately.

For add(10), I push to get [5, 5, 8, 10], then pop a 5 and sift 10 down to [5, 10, 8]. The root remains 5, so it returns 5.

STEP 8

Where this goes wrong: the wrong heap, or no trim

Using a max-heap of everything. "K-th largest" tempts me to push negated values so the largest is on top: heapq.heappush(self.heap, -val). But then the largest is at the root and the k-th largest is k pops deep. The panel shows it for the example: to reach 4, I must pop 8 and 5 first, then push them back. Every add costs k pops plus k pushes, O(k log n), and the heap keeps all n values. It returns the right number slowly, which is why it feels fine on small tests.

Forgetting the trim in add. Without lines 10 to 11, I only heappush before returning self.heap[0]. After add(3), the heap is [3, 4, 8, 5] and its root is 3, not 4.

Min-heap, capped at k. The root answers the question only while the size is exactly k, so every push must be paired with a conditional pop.
STEP 9

Time and space

Each add is one heappush and at most one heappop on a heap that never holds more than k + 1 values, so it is O(log k). Space is the heap itself, O(k), no matter how long the stream runs.

Construction is heapify, O(n), plus up to n - k pops at O(log n) each: O(n + (n − k) log n), paid once.

ApproachTime per addSpace
Re-sort the whole listO(n log n)O(n)
Max-heap of every valueO(k log n)O(n)
Min-heap trimmed to kO(log k)O(k)
STEP 10

The final solution

Two methods, and every line maps to a step above.

  • self.k = k stores the cap because add needs it later.
  • self.heap = nums[:] copies the input so the constructor does not mutate the caller's list.
  • heapq.heapify(self.heap) turns the copy into a min-heap in O(n): [4, 5, 8, 2] becomes [2, 4, 8, 5].
  • while len(self.heap) > k: heapq.heappop(self.heap) discards the smallest values until exactly k remain.
  • heapq.heappush(self.heap, val) admits the new value as a candidate.
  • if len(self.heap) > self.k: heapq.heappop(self.heap) evicts the smallest if the cap is exceeded, which may be the value just pushed.
  • return self.heap[0]: the root of a min-heap holding the k largest values is the k-th largest.
I remember this as: I keep the k largest values in a min-heap; its root is the k-th largest, and each add trims back to k.
