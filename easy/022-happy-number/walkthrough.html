Easy · Fast & Slow Pointers · LeetCode #202

Happy Number, narrated

Scroll through the digit-square chain as a linked list, with the slow and fast pointers shown alongside until one reaches 1 or they meet.

Pattern used Fast & Slow Pointers The repeated digit-square transformation is a linked sequence of numbers. It either reaches 1 or loops forever, which makes Floyd's two-speed cycle detection applicable.

STEP 1

The problem

Take a positive integer n and replace it with the sum of the squares of its digits. Repeat. If the process ever reaches 1 it stays there forever, and n is called happy. If it never reaches 1, it must eventually fall into a loop that excludes 1, and n is not happy. Return True or False.

Running example: n = 19. 1² + 9² = 82. Then 8² + 2² = 68, 6² + 8² = 100, 1² + 0² + 0² = 1. It reached 1, so 19 is happy: answer true.

The hard part is not computing the next value, it is knowing when to give up. A happy number announces itself by hitting 1, but an unhappy one just keeps producing new values. You need a way to detect "this is going in circles" without knowing in advance how big the circle is.

STEP 2

First instinct: remember every value

Keep a set of every number seen so far. Transform, check the set, stop on 1 or on a repeat:

seen = set()while n != 1 and n not in seen:    seen.add(n)    n = self._next(n)return n == 1

For 19 the set grows to {19, 82, 68, 100} and then n becomes 1, so it returns True. This is correct, and it is a perfectly good first answer. Its cost is the set: it holds one entry per value in the chain, so the space is O(length of the chain) before it terminates or repeats.

In practice the chain is short, so the set is small. The interview follow-up is still "can you do it in O(1) space?", and the answer is yes, by noticing what kind of structure the chain is.

STEP 3

The key insight: the chain is a linked list

Look at _next on lines 10 to 15. It is a pure function: _next(19) is always 82, _next(82) is always 68. So every number has exactly one successor, which is precisely the shape of a singly linked list where _next(value) plays the role of node.next.

A linked list built this way has only two possible shapes. Either it reaches 1, and since _next(1) = 1 that is a dead end you can treat as the tail. Or it never reaches 1, in which case, because the values are bounded, it must revisit a value and loop forever.

"Does this linked list terminate or does it have a cycle?" is exactly the question Floyd's slow and fast pointers answer with no memory at all. A pointer here is just an integer, and "follow the pointer" is just "call _next".

Why bounded: each digit contributes at most 9² = 81. A 10-digit number maps to at most 810, and anything below 1000 maps to at most 243. The chain plunges into a small range within a step or two and can only wander among a few hundred values after that, so it must repeat if it does not hit 1.

STEP 4

The approach: two speeds, no set

Lines 3 and 4 set up the pointers: slow = n, which is 19, and fast = self._next(n), which is 82. Starting fast one hop ahead means the loop condition slow != fast is meaningful on the very first check instead of trivially true.

The loop on line 5 runs while fast != 1 and slow != fast. Each turn, slow moves one hop with self._next(slow) and fast moves two with self._next(self._next(fast)).

  • If the chain reaches 1, fast gets there first and the loop exits with fast == 1: happy.
  • If the chain loops, both pointers end up circling inside the loop, fast gains one position per turn, and it lands on slow. The loop exits with slow == fast and fast != 1: not happy.

Line 8, return fast == 1, distinguishes the two exits. Only two integers are ever held.

STEP 5

Trace it: turn 1

Check the condition: fast is 82, not 1, and slow is 19, not equal to 82. Enter the loop.

slow = self._next(19) = 82. Then fast takes two hops from 82: _next(82) = 64 + 4 = 68, and _next(68) = 36 + 64 = 100. So after turn 1, slow = 82 and fast = 100. The panel has now discovered the chain up to 100 and shows the fifth value still unknown.

Check again: fast is 100, not 1; slow is 82, not 100. Loop once more.

STEP 6

Trace it: turn 2, fast reaches 1

slow = self._next(82) = 68. Then fast hops twice from 100: _next(100) = 1 + 0 + 0 = 1, and _next(1) = 1 again. So slow = 68 and fast = 1.

Notice that _next(1) = 1 did not hurt: once the chain hits 1 it stays at 1, so a double hop cannot overshoot the target. That is why the loop condition can check fast alone for the happy case.

The panel highlights 1 in green. The full chain is 19 → 82 → 68 → 100 → 1, and the fast pointer covered it in two turns while the slow pointer is still back at 68.
STEP 7

Trace it: the loop stops, answer true

Back to line 5. fast != 1 is now False, so the and short-circuits and the loop ends without evaluating slow != fast. Line 8 returns fast == 1, which is True.

slow never caught up with fast, and it never needed to: the chain terminated before any cycle could form. The set-based version stored four values to reach this conclusion; this version stored two integers and did the same number of _next calls plus a couple more for the double hops.

STEP 8

Where this goes wrong: the unhappy case

The panel switches to n = 2, which is not happy. Its chain is 2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 → …: after the first hop it enters a loop of eight values that never includes 1. Run the real algorithm: slow starts at 2, fast at 4, and after 7 turns both sit on 42. slow == fast ends the loop, and since fast is 42 and not 1, line 8 returns False. Correct.

Bug 1: a fixed step budget. It is tempting to skip cycle detection and write for _ in range(100): n = self._next(n) then return n == 1. It happens to work for small inputs, but it is a guess: you are betting the chain always settles within your budget, and you are doing 100 transformations even for 19, which needs four. Worse, shrink the budget to 4 and n = 7 (7 → 49 → 97 → 130 → 10 → 1) returns False for a happy number.

Bug 2: starting both pointers at n. Write slow = fast = n and keep the loop as is: slow != fast is False on the first check, the loop never runs, and return fast == 1 yields False for 19. If you want both to start at n, you need a do-while shape that advances before comparing, which Python does not have; starting fast one hop ahead is the cleaner fix.

Detect the cycle, do not guess its length. The meeting of slow and fast is the only stopping condition that works for every unhappy input.
STEP 9

Time and space

One call to _next costs one divmod per digit, so O(log n) for the starting value and O(1) once the chain has fallen below 1000. The number of turns is bounded by the length of the chain plus the size of the loop it enters, and since every value below 1000 maps to at most 3 × 81 = 243, that length is a small constant in practice. Space is two integers: O(1).

ApproachTimeSpace
Set of seen valuesO(log n) per step, chain-length stepsO(chain length)
Slow and fast pointersO(log n) per step, chain-length stepsO(1)

The two approaches do essentially the same number of transformations. The pointer version wins only on memory, which is the point of the follow-up.

STEP 10

The final solution

Two methods, each line a step above.

  • slow = n and fast = self._next(n) start the two pointers, with fast one hop ahead so the first comparison is meaningful.
  • while fast != 1 and slow != fast stops on either exit: reached 1, or the pointers met inside a loop.
  • slow = self._next(slow) moves one hop; fast = self._next(self._next(fast)) moves two.
  • return fast == 1 tells the two exits apart: True for happy, False when the loop ended by a meeting on some other value.
  • _next: total = 0, then while value: peel digits with value, digit = divmod(value, 10) and add digit * digit. The loop ends when value reaches 0, and it returns the sum of squared digits.
One-line summary to remember: the digit-square chain is a linked list that either ends at 1 or cycles, so run slow and fast pointers and check whether fast hit 1.
