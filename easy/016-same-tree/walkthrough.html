Same Tree, narrated

Scroll through why flattening to a value list is not enough, and the lockstep recursion that compares values and missing children together, with both trees shown alongside.

Pattern used Tree Corresponding nodes must agree in both value and shape. The missing-child positions are part of the tree, not just formatting.

STEP 1

The problem

Given the roots of two binary trees p and q, decide whether they are the same: identical in shape, with the same value at every corresponding position.

Running example: p = [1,2,3], q = [1,2,3]. Each is a root 1 with a left child 2 and a right child 3. The answer is true.

"Same" is stricter than it sounds. Two trees that contain the same values in the same traversal order are not necessarily the same tree; a child that is missing on the left in one and missing on the right in the other makes them different. So the comparison has two parts at every position: do the values agree, and do the gaps agree?

STEP 2

First instinct: flatten both trees and compare the lists

The obvious shortcut is to turn each tree into a list with a traversal, say preorder, and check the lists for equality. For the running example preorder(p) = [1,2,3] and preorder(q) = [1,2,3]; the lists are equal, and the answer is right.

It is even linear time. The problem is that it is wrong. A traversal records values but not where the missing children were. The tree [1,2] (2 is the left child) and the tree [1,null,2] (2 is the right child) both flatten to [1,2], so this approach calls them the same when they are not.

You can patch it by writing a marker like # into the list for every None, which does make preorder unambiguous. But then you are building two lists of size n just to compare them position by position, when you could compare the trees position by position directly and stop at the first mismatch.

STEP 3

The key insight: walk both trees in lockstep

Instead of flattening, visit the two trees together. At every position you hold a pair (p, q): the node of the first tree and the node in the same position of the second tree. The trees are the same if every pair agrees.

A pair agrees when either both nodes are None, or both are present with equal values and their left pairs and right pairs agree in turn. A None on one side must be matched by a None on the other; that is where the shape is checked.

The highlighted lines are the base case that does the shape check: if p is None or q is None: return p is q. If either side ran out, the pair is fine only when both did, and p is q is true precisely when both are None.

STEP 4

The approach: base case on None, then three conditions

The whole function is two statements:

  • if p is None or q is None: return p is q — if either is empty, they match only when both are.
  • return p.val == q.val and self.is_same_tree(p.left, q.left) and self.is_same_tree(p.right, q.right) — otherwise the values must agree, then the left pair, then the right pair.

The and chain short-circuits: if the values differ, the recursive calls never run; if the left pair fails, the right pair is never examined. The panel shows the starting pair p, q = 1, 1 with p.val == q.val still unknown, and the two children dimmed because they have not been reached.

The base case also guarantees safety: by the time p.val is read, both p and q are known to be real nodes.

STEP 5

Trace it: the root pair (1, 1)

Both roots are present, so p is None or q is None is false and the base case does not fire. Next, p.val == q.val is 1 == 1, true, which the panel marks with = on both roots.

Because the first operand of the and chain is true, evaluation continues to the second: self.is_same_tree(p.left, q.left). That is the pair (2, 2). The right pair, (3, 3), stays dimmed for now; it will only be examined if the left pair passes.

STEP 6

Trace it: the left pair (2, 2)

Both present, values 2 == 2, true. Now the recursion goes one level further, into the children of the 2s, and this is where the shape check happens.

The left pair below is (None, None), drawn as the ghost · under each 2. The base case fires: p is None or q is None is true, and p is q is None is None, which is true. The right pair below is also (None, None), and returns true the same way. The panel shows this as true × 2.

So the pair (2, 2) evaluates true and true and true and returns true: the badge ✓. The missing children agreed on both sides.

STEP 7

Trace it: the right pair (3, 3), and the answer

Back at the root, the second operand was true, so the chain moves to the third: self.is_same_tree(p.right, q.right), the pair (3, 3). Same story as the 2s: values equal, both child pairs are (None, None), returns true.

The root's expression is now fully evaluated: 1 == 1 and true and true, which is true. That is the answer. Every corresponding pair matched, including the four empty ones under the leaves.

Three real pairs and four (None, None) pairs were compared. The flattening approach would have built two lists and compared three values, and would have been unable to tell if any of those four gaps had moved.
STEP 8

Where this goes wrong: gaps in different places

The panel switches to p = [1,2] and q = [1,null,2]. Both have a root 1 and a single node 2, but in p the 2 is the left child and in q it is the right child. The correct answer is false.

Comparing flattened value lists. Preorder gives [1,2] for both, so the step 2 approach returns true. The lockstep walk gets it right: the root pair (1, 1) matches, then the left pair is (2, None). One side is None and the other is not, so p is q is false, and the whole and chain is false.

Treating any None as a match. A base case written as if p is None or q is None: return True (or if p is None and q is None: return True with nothing for the mixed case) breaks in two different ways. The or version returns true for the pair (2, None), and so wrongly reports these two trees as the same. The and version falls through to p.val == q.val with q = None and crashes with AttributeError.

Comparing only one child. Dropping the self.is_same_tree(p.right, q.right) term means the right subtrees are never compared at all, so two trees that differ only somewhere on the right are reported as the same.

The base case must return p is q, not True. It is one expression, and it is the only place the shape is checked.
STEP 9

Time and space

Each pair of corresponding positions is compared at most once, doing one value comparison and two recursive calls. On a full match every node of both trees is visited, so the time is O(n), where n is the number of nodes in the smaller tree; a mismatch ends early because of the short-circuiting and. On the running example n = 3.

The recursion stack is as deep as the trees are tall: O(h). Here h = 2.

ApproachTimeSpace
Flatten to value lists, compareO(n), but wrong without None markersO(n) for two lists
Flatten with None markersO(n)O(n) for two lists
Lockstep recursionO(n)O(h) call stack

The recursive version wins on memory, stops at the first difference, and needs no serialization format to get the shape right.

STEP 10

The final solution

Two statements. Line by line:

  • if p is None or q is None: — at least one side of the pair is empty, so no values can be compared.
  • return p is q — true only when both are None; a gap on one side alone is a shape mismatch.
  • p.val == q.val — both present, so the values must agree.
  • and self.is_same_tree(p.left, q.left) — the left pairs must agree, checked recursively.
  • and self.is_same_tree(p.right, q.right) — and so must the right pairs. Any false along the chain stops the rest.
One-line summary to remember: walk both trees together; every pair must match in value, and a missing child must be missing on both sides.
