Easy · Bit Manipulation · LeetCode #338

Counting Bits, narrated

I’ll first count each number’s bits from scratch, then reuse earlier counts with a right-shift recurrence.

Pattern used Bit Manipulation Right-shifting removes a number's final bit. Its one-bit count is therefore the count of the shifted prefix plus that final bit.

STEP 1

The problem

Given an integer n, return an array counts of length n + 1 where counts[i] is the number of 1 bits in the binary representation of i, for every i from 0 to n.

Running example: n = 5. Writing out the binary: 0 = 000, 1 = 001, 2 = 010, 3 = 011, 4 = 100, 5 = 101. Counting the 1s gives the answer [0,1,1,2,1,2].

This is the popcount problem asked n + 1 times. The follow-up in the original statement is the real question: can you do it in a single O(n) pass rather than counting each number separately?

STEP 2

First instinct: count each number from scratch

My first instinct is to count the bits of each number separately by repeatedly clearing its lowest set bit.

counts = []for value in range(n + 1):    bits, x = 0, value    while x:        x &= x - 1        bits += 1    counts.append(bits)return counts

Each inner loop can take O(log n) rounds, so this baseline takes O(n log n) time. The output list has n + 1 entries, so it uses O(n) space.

Counting 3 recounts the prefix 1, whose answer I already computed. A table lets me reuse those smaller answers directly.

STEP 3

The key insight: drop the last bit and look it up

value >> 1 shifts the number right by one place, which discards its last bit. The result is a smaller number whose count is already in my table when I fill it in increasing order.

The panel shows it for 5. value = 5 is 0101. Its prefix value >> 1 = 2 is 0010, and the bit that was dropped is value & 1 = 1. So the count of 5 is the count of 2, plus 1 for the dropped bit.

counts[value] = counts[value >> 1] + (value & 1). The number of 1 bits in a number is the number of 1 bits in its prefix plus its last bit, and the prefix is always a smaller number.

The same idea in words: 5 is "2, followed by a 1". 4 is "2, followed by a 0". Both share the prefix 2 and differ only in their final bit, so both can be answered from counts[2] in one step.

STEP 4

The approach: fill the table left to right

Allocate the output once with counts = [0] * (n + 1). That also sets the seed, counts[0] = 0, which is correct because 0 has no set bits. The panel shows the table as [0,?,?,?,?,?] at this point.

Then for value in range(1, n + 1): compute counts[value] = counts[value >> 1] + (value & 1). Because value >> 1 < value for every value >= 1, the entry being read is always to the left of the entry being written, so it has already been filled. No number is ever counted from scratch after 0.

STEP 5

Trace it: values 1, 2 and 3

The first two iterations are quick. value = 1 gives counts[0] + (1 & 1) = 0 + 1 = 1. value = 2 gives counts[1] + (2 & 1) = 1 + 0 = 1. The table is [0,1,1,?,?,?].

Now value = 3, which is 0011. 3 >> 1 = 1, and counts[1] = 1 is already there. The dropped bit is 3 & 1 = 1. So counts[3] = 1 + 1 = 2, and the table is [0,1,1,2,?,?].

The panel shows the lookup: the current cell is index 3, and the highlighted cell it reads from is index 1. Two set bits in 3, found with one table read and one AND rather than a loop over its bits.

STEP 6

Trace it: value 4 drops back to one bit

value = 4 is 0100. 4 >> 1 = 2, whose count is counts[2] = 1. The dropped bit is 4 & 1 = 0. So counts[4] = 1 + 0 = 1.

The table is now [0,1,1,2,1,?]. The count went down from 2 to 1 between 3 and 4, which is right: 3 is 011 and 4 is 100. The recurrence does not care that 4 is bigger than 3; it only cares that 4's prefix, 2, has already been filled in.

STEP 7

Trace it: value 5 completes the table

value = 5 is 0101. 5 >> 1 = 2, the same prefix 4 had, so again counts[2] = 1. This time the dropped bit is 5 & 1 = 1, so counts[5] = 1 + 1 = 2.

The loop ends because 5 was the last value in range(1, 6). return counts gives [0,1,1,2,1,2], which matches the hand count from step 1.

4 and 5 share the prefix 2 and differ only in their last bit. The recurrence answered both from the same table entry. That sharing is the entire speed-up.
STEP 8

Where this goes wrong: the table, and operator precedence

The panel shows why my table is worth having: counts[5] reused counts[2], which reused counts[1], which reused counts[0]. Every prefix is counted exactly once. Calling a standalone bit counter for each number is not wrong, but it recounts those prefixes and turns O(n) into O(n log n), which is the exact work I avoid.

A table with n entries instead of n + 1. If I write counts = [0] * n, the range 0 through n needs one more slot than exists. For n = 5 the loop reaches value = 5 and counts[5] = ... raises IndexError. The output includes both endpoints, so the table has n + 1 entries.

Dropping the parentheses around value & 1. In Python + binds tighter than &, so counts[value >> 1] + value & 1 means (counts[value >> 1] + value) & 1. For the running example that produces [0,1,1,0,1,0]: value = 3 computes (1 + 3) & 1 = 0 instead of 2. The parentheses in + (value & 1) are not decoration.

I check n = 0 (answer [0], so the loop must not run) and one small n by hand. The precedence bug gives plausible-looking 0s and 1s, so I compare against a hand count, not just against "it ran".
STEP 9

Time and space

The loop runs n times and each iteration does one table read, one shift, one AND and one addition, all O(1). That is O(n) time. The table has n + 1 entries, so O(n) space, but that space is the required output; nothing beyond it is allocated.

ApproachTimeSpace
Popcount each number separatelyO(n log n)O(n) output
Recurrence counts[v >> 1] + (v & 1)O(n)O(n) output, nothing extra

This is dynamic programming in the most literal sense: a table indexed by the subproblem, filled in an order that guarantees every dependency is ready before it is needed. The "subproblem" of a number is simply the number with its last bit removed.

STEP 10

The final solution

Four lines of body.

  • counts = [0] * (n + 1) allocates the output once, one slot per number from 0 to n, and seeds counts[0] = 0 for free.
  • for value in range(1, n + 1): fills the table in increasing order, so every prefix is ready before it is read.
  • counts[value >> 1] looks up the count of the number with its last bit dropped, a strictly smaller index that is already filled.
  • + (value & 1) adds the dropped bit back in: 1 if value is odd, 0 if even. The parentheses are required.
  • return counts — the completed table is the answer.
One-line summary to remember: the bit count of a number is the bit count of the number shifted right by one, plus its lowest bit.
