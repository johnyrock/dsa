Easy · Bit Manipulation · LeetCode #268

Missing Number, narrated

I’ll start by sorting to find the first gap, then use XOR to cancel the supplied values against the full range.

Pattern used Bit Manipulation XOR cancels equal values. XOR every index and every supplied number against the full range 0 through n, leaving only the absent value.

STEP 1

The problem

You are given an array nums of n distinct integers drawn from the range 0 to n inclusive. That range has n + 1 values and the array holds only n of them, so exactly one is absent. Return it.

Running example: nums = [3,0,1], so n = 3 and the full range is 0, 1, 2, 3. The value 2 never appears, so the answer is 2.

The follow-up asks for O(n) time and O(1) extra space. The panel lists the four range values as 8-bit patterns and highlights 2 = 00000010, the one with no match in the array.

STEP 2

First instinct: sort, or use a set

My first instinct is to sort the array and find the first index whose value does not equal that index.

nums.sort()for i, v in enumerate(nums):    if v != i:        return ireturn len(nums)

Sorting finds the missing value. It takes O(n log n) time and, when done in place, uses O(1) extra space.

I only need one missing value, not the full order. XOR lets equal range and input values cancel without sorting or allocating a set.

STEP 3

The key insight: XOR the range against the input

XOR has the property x ^ x = 0, and it is associative and commutative, so the order of operands is irrelevant. The panel shows the simplest case: 3 ^ 3 = 0.

Now XOR together every value in the full range 0 through n and every value in nums. A value that is present in nums appears twice in that combined expression, once from the range and once from the array, so it cancels to 0. The missing value appears only once, from the range, and survives.

For the example: (0 ^ 1 ^ 2 ^ 3) ^ (3 ^ 0 ^ 1). The 0s, 1s and 3s pair off and vanish. What is left is 2.

No sorting, no set, and unlike the sum-based alternative, the running value never grows larger than the largest input.

STEP 4

The approach: the indices are the range

I do not need to build a second list holding 0 through n. The indices of nums already supply 0 through n − 1, and the one value they do not supply, n itself, is len(nums). So I seed the accumulator with it: missing = len(nums), which for the example is missing = 3 (00000011).

Then a single pass, for index, number in enumerate(nums):, folds in both the range value and the array value at once: missing ^= index ^ number. After the loop every present value has been XORed in twice and the missing one exactly once.

STEP 5

Trace it: index 0, number 3

The accumulator starts at missing = 3. The first element gives index = 0 and number = 3, so the update is 3 ^ 0 ^ 3.

XORing in the index 0 changes nothing (x ^ 0 = x). XORing in the number 3 meets the seed 3 and cancels it: 3 ^ 3 = 0. The panel shows the two 00000011 patterns lining up and the result missing = 0 (00000000).

Two range values have now been accounted for, 3 from the seed and 0 from the index, and one array value, 3. The range value 0 is waiting for its partner.

STEP 6

Trace it: index 1, number 0

Next, index = 1 and number = 0. The update is 0 ^ 1 ^ 0.

The index 1 has no partner yet, so it turns bit 0 on. The number 0 is a no-op. The result is missing = 1 (00000001).

Bookkeeping: the range values seen so far are 3, 0, 1 and the array values are 3, 0. The 3s cancelled in the previous step, and the range 0 and the array 0 have both been XORed in, so they cancel too. Only the range value 1 is unmatched, and that is exactly what the accumulator holds.

STEP 7

Trace it: index 2, number 1, the answer

The last element gives index = 2 and number = 1. The update is 1 ^ 2 ^ 1.

The number 1 meets the index 1 that was left over from the previous step and cancels it. The index 2 has no partner anywhere in nums, so it turns bit 1 on and stays. The result is missing = 2 (00000010).

The loop is finished and return missing gives 2. Every present value paired off; the value that was never in the array is the only survivor.

The whole computation, in the order it ran: 3 ^ (0 ^ 3) ^ (1 ^ 0) ^ (2 ^ 1) = 2. Three iterations, two XORs each, one integer of state.
STEP 8

Where this goes wrong: the sum, the seed, and the index

The panel shows the arithmetic alternative: the range 0 through 3 sums to 0+1+2+3 = 6, the array sums to 3+0+1 = 4, and 6 - 4 = 2. It is also O(n) time and O(1) space, and in Python it is fine. In a fixed-width language, though, n * (n + 1) / 2 grows quadratically and overflows a 32-bit integer for n around 65,000. The XOR accumulator never produces a value wider than its inputs, so it has no such limit.

No seed for n. If I write missing = 0 instead of missing = len(nums), the range value n is never XORed in. For [3,0,1] that computes 0 ^ (0 ^ 3) ^ (1 ^ 0) ^ (2 ^ 1) = 1: the array's 3 now has no partner and pollutes the result. The function returns 1 instead of 2.

Only folding in the numbers. If I write missing ^= number without the index ^, half of the range is missing. For the example that is 3 ^ 3 ^ 0 ^ 1 = 1, again returning 1. Both halves of index ^ number are required: the indices and the seed together are the full range, and the numbers are what gets cancelled against it.

Test the two edge placements: [0,1] (answer 2, the missing value is n) and [1,2] (answer 0, the missing value is the smallest). The seed bug returns 0 and 2 for them; the index bug returns 3 and 1. Neither bug survives both.
STEP 9

Time and space

One pass over the array with two XORs per element: O(n) time. The only state is the single integer missing, so O(1) space.

ApproachTimeSpace
Sort, then scan for the gapO(n log n)O(1) to O(n) depending on the sort
Hash set, then check 0..nO(n)O(n)
Sum formula n(n+1)/2 - sum(nums)O(n)O(1), but the total can overflow
XOR accumulatorO(n)O(1), no overflow

The set already meets the time bound; the sum meets both bounds in Python. XOR is the answer that meets both bounds in every language, which is why it is the one to reach for.

STEP 10

The final solution

Four lines of body.

  • missing = len(nums) seeds the accumulator with n, the one range value the indices cannot supply.
  • for index, number in enumerate(nums): walks the array once, yielding a range value (the index) and an array value (the number) together.
  • missing ^= index ^ number folds both in. Every value present in the array is XORed twice across the run and cancels; the absent one is XORed once.
  • return missing — the lone survivor is the number that was never in nums.
One-line summary to remember: XOR the full range 0..n with every array value; everything present cancels and the missing number is what remains.
