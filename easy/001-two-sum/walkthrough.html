Two Sum, narrated

Scroll through the thinking, from the obvious brute force to the one-pass hash map, with the state of the algorithm shown alongside.

Pattern used Hash Map value -> index, look up the complement

STEP 1

The problem

You get an array of integers nums and an integer target. Return the indices of the two numbers that add up to target.

Two guarantees make life easier: exactly one valid answer exists, and you cannot use the same element twice.

Running example: nums = [2, 7, 11, 15], target = 9. The answer is [0, 1] because 2 + 7 = 9.

Notice the question asks for indices, not the values. That detail shapes what we need to remember later.

STEP 2

First instinct: try every pair

The most direct idea is to pick every possible pair and check whether it sums to the target. For each element, loop over every element after it.

for i in range(len(nums)):    for j in range(i + 1, len(nums)):        if nums[i] + nums[j] == target:            return [i, j]

This is correct, and it is a fine first answer to say out loud. But with n elements there are roughly n² / 2 pairs, so the running time is O(n²). At n = 10,000 that is about fifty million checks.

The inner loop is doing something wasteful: it rescans the whole rest of the array to answer one question. What is that question?

STEP 3

Reframe: what am I looking for?

Stand at one element n. There is exactly one value that would complete the pair: target - n. Call it the complement.

So the inner loop is really asking a yes/no question: "Does the complement exist somewhere else in the array?"

For 2 the complement is 9 − 2 = 7. For 7 it is 2. For 11 it is −2. For 15 it is −6.

The brute force answers that question by scanning, which costs O(n) each time. If we could answer it in O(1), the whole thing collapses to a single pass.

STEP 4

The key idea: remember what you have seen

A dictionary (hash map) answers "have I seen this value?" in O(1) on average. So as we walk the array, we record each value we pass, mapped to its index.

Then at every element we do two things, in this order:

  • Check whether the complement is already in the dictionary. If it is, we are done.
  • Store the current value and its index, so a later element can find it.

Why store the index and not just the value? Because the problem asks for indices. The value is the key we look up by, and the index is what we need back.

STEP 5

Trace it: index 0

Start with an empty dictionary. The first element is 2, so the complement is 9 − 2 = 7.

Is 7 in the dictionary? No, it is empty. So we store 2 → 0 and move on.

Nothing found yet, but the dictionary now knows where a 2 lives.

STEP 6

Trace it: index 1

Next element is 7. The complement is 9 − 7 = 2.

Is 2 in the dictionary? Yes, it maps to index 0. That means the pair is the 2 at index 0 and the 7 at index 1.

We return [seen[2], 1], which is [0, 1]. The earlier index comes first because it is the one we pulled out of the dictionary.

We never looked at 11 or 15. The loop stopped as soon as the answer appeared.
STEP 7

Why check before storing

The order of the two operations matters. Suppose nums = [4, 1, 7] and target = 8. At index 0 the value is 4 and the complement is also 4.

If we stored first and then checked, we would find our own 4 in the dictionary and return [0, 0], using the same element twice. That is exactly what the problem forbids.

Check, then store. The dictionary should only ever contain elements that came before the current one.

With the correct order, the 4 finds nothing, gets stored, and the real answer 1 + 7 is found at index 2.

STEP 8

Time and space

The loop visits each element once. Inside the loop, the dictionary lookup and the dictionary insert are both O(1) on average. So the total is O(n) time.

The dictionary can grow to hold every element if the answer is at the very end, so it uses O(n) extra space.

ApproachTimeSpace
Brute force, all pairsO(n²)O(1)
Hash map, one passO(n)O(n)

This is the classic trade: spend memory to buy time. For n = 10,000 it turns fifty million checks into ten thousand.

STEP 9

The final solution

Seven lines. Every one of them maps to a step above.

  • seen = {} is the memory of values already passed.
  • complement = target - n is the reframed question.
  • if complement in seen is the O(1) check.
  • seen[n] = i is the store, placed after the check on purpose.
  • return [] handles the case where nothing pairs up.
One-line summary to remember: for each number, ask whether its complement has already been seen.
