Easy · Hash Map · LeetCode #1

Two Sum, narrated

I’ll walk through how I move from my first brute-force idea to a one-pass hash map, while the state of the algorithm stays visible alongside.

Pattern used Hash Map values mapped to indices, with complements as lookup keys

STEP 1

The problem

Given an array of integers nums and an integer target, return the indices of the two numbers that add up to target.

There is exactly one valid answer, and the same element cannot be used twice.

Running example: nums = [2, 7, 11, 15], target = 9. The answer is [0, 1] because 2 + 7 = 9.

The answer should contain the indices, not the values themselves. That detail determines what needs to be remembered while scanning the array.

STEP 2

First instinct: try every pair

My first instinct is to try every possible pair. I pick one index, compare it with every index after it, and return as soon as the two values add up to the target.

for i in range(len(nums)):    for j in range(i + 1, len(nums)):        if nums[i] + nums[j] == target:            return [i, j]

This first solution is correct. With n elements, I may check roughly n² / 2 pairs, so it takes O(n²) time. Apart from the returned pair, it needs O(1) extra space. At n = 10,000, that can mean about fifty million checks.

The repeated work is the complement lookup: the inner loop scans values I already considered. A fast record of earlier values removes those repeated pair checks.

STEP 3

Reframe: what am I looking for?

When I stand at one element n, there is exactly one value that would complete the pair: target - n. I call that value the complement.

That means my inner loop was really asking one yes-or-no question: “Have I already seen this complement?”

For 2 the complement is 9 − 2 = 7. For 7 it is 2. For 11 it is −2. For 15 it is −6.

My brute-force version answers that question by scanning, which costs O(n) every time. If I can answer it in O(1), I only need one pass through the array.

STEP 4

The key idea: remember what you have seen

I use a dictionary, or hash map, because it answers “have I seen this value?” in O(1) average time. As I walk through the array, I record each value I pass with its index.

At every element, I do two things in this order:

  • I check whether the complement is already in the dictionary. If it is, I am done.
  • I store the current value and its index, so a later element can find it.

I store the index with the value because the problem asks me to return indices. The value is the key I look up, and the index is what I need to give back.

STEP 5

Trace it: index 0

I start with an empty dictionary. At index 0, the value is 2, so the complement I need is 9 - 2 = 7.

I check whether 7 is in the dictionary. It is not, because the dictionary is empty, so I store 2 → 0 and move on.

I have not found the answer yet, but I now know where the value 2 lives.

STEP 6

Trace it: index 1

At index 1, I see 7. Its complement is 9 - 7 = 2.

I check for 2, and it is already in the dictionary at index 0. That gives me the pair: 2 at index 0 and 7 at index 1.

I return [seen[2], 1], which becomes [0, 1]. The earlier index comes from the dictionary, so it naturally appears first.

I never need to look at 11 or 15; the loop stops as soon as I find the answer.
STEP 7

Why check before storing

The order of my two operations matters. Suppose nums = [4, 1, 7] and target = 8. At index 0, I have 4, and its complement is also 4.

If I stored first and checked second, I would find my own 4 in the dictionary and return [0, 0]. That reuses the same element twice, which the problem forbids.

I check first and store second, so the dictionary contains only elements from earlier positions.

With the correct order, I find nothing for the first 4, store it, and later find the real answer because 1 + 7 = 8 at index 2.

STEP 8

Time and space

I visit each element once. Inside the loop, both the dictionary lookup and dictionary insert take O(1) on average, so my final solution takes O(n) time.

If the answer appears at the end, my dictionary can hold every earlier element, so my final solution uses O(n) extra space.

ApproachTimeSpace
Brute force, all pairsO(n²)O(1)
Hash map, one passO(n)O(n)

I am trading memory for time. For n = 10,000, I replace roughly fifty million pair checks with one pass of ten thousand elements.

STEP 9

The final solution

My final solution is seven lines, and every line comes directly from the reasoning above.

  • seen = {} gives me a place to remember values I have already passed.
  • complement = target - n calculates the partner I need for the current value.
  • if complement in seen gives me the O(1) lookup.
  • seen[n] = i stores the current value only after I check for its complement.
  • return [] covers the case where no pair appears.
What I remember: for each number, I ask whether I have already seen its complement.
