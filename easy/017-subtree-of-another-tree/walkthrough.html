Easy · Tree · LeetCode #572

Subtree of Another Tree, narrated

I’ll start with a shape-preserving serialization search, then walk the tree and test exact matches at candidate roots.

Pattern used Tree A subtree must match all values and all missing-child positions. Search each root position, then perform an exact same-tree comparison only where a match could begin.

STEP 1

The problem

Given the roots of two binary trees root and subRoot, decide whether subRoot appears somewhere inside root as an exact subtree. A subtree of root is some node of root together with all of its descendants; it must match subRoot in every value and in every missing-child position.

Running example: root = [3,4,5,1,2] and subRoot = [4,1,2]. In root, node 3 has children 4 and 5, and node 4 has children 1 and 2. The subtree hanging from node 4 is exactly [4,1,2], so the answer is true.

The word "exact" is what makes this more than a value search. A node of root can have the right value and the right children and still fail, if one of those children has an extra descendant that subRoot does not have. Also note the edge cases: an empty subRoot is a subtree of anything, and a non-empty subRoot is never a subtree of an empty root.

STEP 2

First instinct: flatten both and look for a substring

My first instinct is to serialize both trees in preorder, including a marker for each None, then search for the smaller serialization inside the larger one.

def serialized(node):    values = []    def visit(node):        if node is None: values.append("#"); return        values.append(str(node.val)); visit(node.left); visit(node.right)    visit(node)    return "," + ",".join(values) + ","return serialized(sub_root) in serialized(root)

The null markers make this baseline correct: an extra child changes the serialization. It takes O(n + m) time to build and search the strings and uses O(n + m) extra space.

I do not need to materialize either tree. I can try a same-tree comparison at each node of root and return as soon as one matches.

STEP 3

The key insight: every node is a candidate start

If subRoot is a subtree of root, its root coincides with some node of root. I visit each of the n possible roots and ask whether the tree there is the same tree as subRoot.

That splits the problem into two familiar pieces for me: a tree walk that visits every candidate 3, 4, 5, 1, 2, and an exact same-tree comparison at each candidate, _same_tree(node, sub_root), which checks values and gaps together.

Most candidates die instantly. A node whose value differs from subRoot's root value fails on the very first comparison inside _same_tree, so the expensive full comparison only happens where a match could actually begin.

STEP 4

The approach: DFS through root, exact match at each node

Two functions. is_subtree is the search; _same_tree is the comparison.

  • if sub_root is None: return True — an empty tree is a subtree of everything.
  • if root is None: return False — I ran out of candidates without a match.
  • return self._same_tree(root, sub_root) or self.is_subtree(root.left, sub_root) or self.is_subtree(root.right, sub_root) — try an exact match at this node; if it fails, search the left subtree, then the right.

The or chain short-circuits, so the first successful candidate ends the search and nothing to its right is examined. The panel shows the search at the first candidate, root = 3, with _same_tree(3, 4) not yet evaluated and the rest of root dimmed.

_same_tree is the Same Tree solution: if first is None or second is None: return first is second, and otherwise equal values and matching left and right pairs.

STEP 5

Trace it: candidate 3

sub_root is not None and neither is root, so the guards pass and the chain starts with _same_tree(3, 4). Both nodes exist, so the base case does not fire, and the first comparison is first.val == second.val: 3 == 4, which is false. The and chain inside _same_tree stops right there; the children of 3 and 4 are never compared against each other.

The panel marks both roots with ≠. Back in is_subtree, the first operand of the or chain is false, so evaluation moves to the second: self.is_subtree(root.left, sub_root). The next candidate is node 4.

STEP 6

Trace it: candidate 4

Now root = 4 and the comparison is _same_tree(4, 4). The values agree, 4 == 4, so this candidate survives the first test and the real comparison begins.

_same_tree continues down the and chain: first the left pair, (1, 1), which is _same_tree(first.left, second.left); then, if that passes, the right pair, (2, 2).

Both 1s are leaves and both 2s are leaves, on both sides. So each of those pairs will compare its own children as (None, None), which is where the shape gets checked.

STEP 7

Trace it: the leaves match, and the answer

Pair (1, 1): values equal; the left children are (None, None), so the base case returns None is None, true; the right children likewise. The pair returns true. Pair (2, 2) goes through the same steps and returns true.

So _same_tree(4, 4) is true and true and true, which is true. That was the first operand of the or chain in the is_subtree call for node 4, so that call returns true immediately; and it was the second operand of the chain in the call for node 3, so that call returns true as well.

The answer is true. Because or short-circuited, self.is_subtree(root.right, sub_root) at the root was never evaluated: node 5 was never examined as a candidate.
STEP 8

Where this goes wrong: a matching root is not a matching subtree

The panel switches to comparing the tree [4,1,2,0] against [4,1,2]. On the left, node 1 has a left child 0; on the right, node 1 has none. The correct answer to "is the second the same tree as the first" is false.

Checking only the root value. A shortcut like if root.val == sub_root.val: return True in place of _same_tree accepts [4,1,2,0] as a match for [4,1,2] because the roots are both 4, and returns true. The values match at 4 and at 1, which the panel marks with =, and only then does the pair (0, None) appear. That pair is where first is second is false, and only a full same-tree comparison ever gets there.

Using is_subtree inside the comparison. If _same_tree recurses into self.is_subtree(first.left, second.left) instead of self._same_tree(...), the pair (0, None) hits if sub_root is None: return True and the extra node 0 is quietly accepted. The function returns true for a tree that is not the same. The two functions have different base cases on purpose: "empty pattern matches anything" is right for the search and wrong for the exact comparison.

Swapping the two guards in is_subtree. Checking if root is None: return False before if sub_root is None: return True makes an empty subRoot fail against an empty root. I put the sub_root check first because an empty tree is a subtree of every tree.

Value equality at a node is only permission to start comparing. The match is decided at the None pairs below, and every one of them has to line up.
STEP 9

Time and space

Let n be the number of nodes in root (5 here) and m the number in subRoot (3 here). The search visits each of the n nodes once, and at each one runs _same_tree, which costs up to m comparisons. So the worst case is O(m · n).

In practice most candidates fail on the first value comparison and cost O(1), so the typical cost is far below the bound. The worst case needs a tree full of near-matches, such as every value being the same, where each candidate pays most of m before a gap or a leaf disagrees.

The recursion stack holds the search path plus the comparison path, both bounded by the height of root: O(h) space.

ApproachTimeSpace
Substring search on value traversalsO(m + n), but wrongO(m + n) for the lists
Same-tree check at every nodeO(m · n) worst caseO(h) call stack
Serialize with None markers + KMPO(m + n)O(m + n) for the strings

The serialization approach can be made correct by writing a marker for every missing child and delimiting values, and then a linear-time string search gets O(m + n). For an interview the O(m · n) recursion is the expected answer, and the linear version is a good follow-up to know about.

STEP 10

The final solution

A search and a comparison. Line by line:

  • if sub_root is None: return True — the empty tree is a subtree of anything, so the search succeeds trivially.
  • if root is None: return False — no candidates left; a non-empty pattern cannot be found in nothing.
  • self._same_tree(root, sub_root) — try an exact match starting at this node.
  • or self.is_subtree(root.left, sub_root) or self.is_subtree(root.right, sub_root) — otherwise keep searching below, left first, stopping at the first success.
  • if first is None or second is None: return first is second — in the comparison, a gap on one side must be a gap on the other.
  • first.val == second.val and self._same_tree(first.left, second.left) and self._same_tree(first.right, second.right) — equal values, then matching left pairs, then matching right pairs, all the way down.
I remember this as: I try an exact same-tree comparison at every node of root; values and None positions both finish the match.
