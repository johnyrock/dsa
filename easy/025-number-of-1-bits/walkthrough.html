Easy · Bit Manipulation · LeetCode #191

Number of 1 Bits, narrated

I’ll start by testing all 32 bit positions, then clear one set bit per loop so the work follows the answer.

Pattern used Bit Manipulation Subtracting one flips bits through the lowest set bit, so n & (n - 1) clears exactly that lowest one bit.

STEP 1

The problem

You are given an unsigned 32-bit integer n. Return how many of its bits are 1. This count is called the Hamming weight, or the population count.

Running example: n = 11, which is 1011 in binary. Bits 0, 1 and 3 are set, so the answer is 3.

The panel shows the low 8 of the 32 bits as 00001011; the upper 24 are all zero for this input and are not drawn. The task is purely about the bit pattern, not the numeric value, which is the hint that the solution should work at the bit level too.

STEP 2

First instinct: test every bit position

My first instinct is to walk all 32 positions. I test the lowest bit with n & 1, add it to the count, then shift right.

count = 0for _ in range(32):    count += n & 1    n >>= 1return count

This counts every set bit. The width is fixed, so 32 rounds take O(1) time, and the counter uses O(1) extra space.

For sparse numbers, my loop still tests zeros. Clearing one set bit per round makes the number of rounds equal the number of 1 bits.

STEP 3

The key insight: n & (n - 1) clears the lowest set bit

Think about what subtracting 1 does to a binary number. It borrows through every trailing 0 until it reaches the lowest 1, flips that 1 to 0, and turns all the trailing 0s below it into 1s. Every bit above the lowest 1 is unchanged.

The panel shows it for the example: n = 11 is 00001011, and n - 1 = 10 is 00001010. Only bit 0 changed, because bit 0 was the lowest set bit and there were no trailing zeros below it.

Now AND the two together. Above the lowest set bit, both numbers agree, so those bits survive. At the lowest set bit, n has 1 and n - 1 has 0, so it is cleared. Below it, n has all 0s, so nothing survives. Result: n & (n - 1) = 10, which is n with exactly its lowest 1 removed.

n &= n - 1 removes exactly one set bit per call, always the lowest, and never touches anything else. I count how many times I can do it before reaching 0.
STEP 4

The approach: strip and count

I start with count = 0 and n = 11 (00001011). I loop with while n:, then run n &= n - 1 followed by count += 1. Each pass through the body removes one set bit and records that it did so.

The loop condition is the bits themselves: as long as any bit is still set, n is non-zero and truthy. Once the last bit is stripped, n is 0 and the loop ends. For the example that is three rounds, not 32.

STEP 5

Trace it: round 1 clears bit 0

n = 11 is 00001011. Its lowest set bit is bit 0. n - 1 = 10 is 00001010, and n & (n - 1) = 10, or 00001010.

After n &= n - 1 the variable holds n = 10 (00001010); after count += 1, count = 1. Two bits remain, and the loop condition while n sees 10, which is truthy.

STEP 6

Trace it: round 2 clears bit 1

n = 10 is 00001010. The lowest set bit is now bit 1, and there is one trailing zero below it. So n - 1 = 9 is 00001001: the subtraction borrowed through bit 0 (turning it to 1) and flipped bit 1 to 0.

n & (n - 1) = 8, or 00001000. Bit 0 is 0 in n, bit 1 is 0 in n - 1, and only bit 3, where both agree, survives. Now n = 8 (00001000) and count = 2.

STEP 7

Trace it: round 3 clears the last bit

n = 8 is 00001000, a single set bit at position 3 with three trailing zeros. n - 1 = 7 is 00000111: every bit below position 3 became 1 and bit 3 became 0. The two numbers share no set bits, so n & (n - 1) = 0.

n = 0 and count = 3. Back at the top, while n sees 0, which is falsy, and the loop exits. return count gives 3.

The sequence of values was 11 → 10 → 8 → 0. Three rounds for three set bits. The brute-force loop would have done 32.
STEP 8

Where this goes wrong: the loop condition

Testing n >= 0 instead of n. The panel shows the state after the last strip: n = 0, count = 3. With while n >= 0: the loop does not stop here. It computes n &= n - 1 with n = 0, which is 0 & -1 = 0, so n stays 0, count keeps climbing, and the condition 0 >= 0 stays true forever. The function never returns. The condition must be the truthiness of the remaining bits, while n:, which is false exactly when there is nothing left to count.

A signed 32-bit n > 0 test. In Python, while n > 0 happens to work because the input is a non-negative Python int. In Java or C, the same 32-bit input with bit 31 set is a negative number, so n > 0 is false on the first check and the function returns 0 for an input like 0xFFFFFFFF, whose correct answer is 32. There I use n != 0, which is what Python's while n means.

Test with n = 0 (answer 0, loop must not run) and with the all-ones input (answer 32). Both are one-liners and each catches a different loop-condition bug.
STEP 9

Time and space

The loop runs once per set bit. For k set bits that is O(k) time, at most 32 rounds for a 32-bit input and typically far fewer. The state is two integers, n and count, so O(1) space.

ApproachTimeSpace
bin(n).count("1")O(w), w = 32O(w) for the string
Shift and mask all positionsO(w), always 32 roundsO(1)
n &= n - 1 until zeroO(k), k = set bitsO(1)

All three are constant-bounded because the width is fixed, so on a complexity table they look alike. The difference is the constant: the last one's work is proportional to the answer, which is why it is the one interviewers expect. It is also the building block for related problems such as checking whether a number is a power of two (n & (n - 1) == 0).

STEP 10

The final solution

Five lines of body.

  • count = 0 — nothing stripped yet.
  • while n: keeps going as long as any bit is still set; 0 is the only value that stops it.
  • n &= n - 1 clears exactly the lowest set bit and leaves everything above it intact.
  • count += 1 records that one bit was removed.
  • return count — the number of strips it took to reach zero, which is the number of 1 bits there were.
One-line summary: n & (n - 1) removes the lowest 1 bit; I count how many times I can do it before hitting zero.
