Reverse Linked List, narrated

Scroll through the thinking, from copying the values out into an array to the in-place three-pointer rewiring, with the state of the list shown alongside.

STEP 1

The problem

You get head, the first node of a singly linked list. Each node holds a value and a single link called next. Return the head of the same list, reversed.

Singly linked means there are no backwards links. From a node you can reach everything after it and nothing before it, and you only ever get one pass in that direction for free.

Running example: 1 → 2 → 3 → 4. The answer is 4 → 3 → 2 → 1, and the node holding 4 becomes the new head.

Notice what the answer is: a node, not a list of values. Whatever we do has to leave real nodes wired up in the new order.

STEP 2

First instinct: copy the values out

The most direct idea is to walk the list once, push every value into a Python list, reverse that list, then walk the nodes again writing the values back.

values = []node = headwhile node:    values.append(node.val)    node = node.next# then walk again, writing values[::-1] back in

This works and it is O(n) time. But it allocates an array as big as the list, so it costs O(n) extra space, and it never actually reverses anything — it shuffles payloads between nodes that stay wired the same way.

The links are the thing the problem is really about. So: can we change the links themselves, in place, using only a couple of variables?

STEP 3

Reframe: reversing is just flipping arrows

A reversed list is the same four nodes with every arrow turned around. Node 1 should point at None, node 2 at node 1, node 3 at node 2, node 4 at node 3.

So the whole job is a sequence of single assignments, one per node: curr.next = the node before it.

But there is a catch. The moment you write curr.next = prev, the old value of curr.next is gone — and that was the only way to reach the rest of the list.

Overwrite it blind and the tail becomes unreachable. So the real question is: what do you need to be holding at the instant you flip an arrow?

STEP 4

The key idea: three pointers

Three variables are enough to flip one arrow safely and keep walking:

  • prev — the front of the part already reversed. Starts at None, because the old head must end up pointing at nothing.
  • curr — the node being flipped right now. Starts at head.
  • next_node — a scratch copy of curr.next, saved before the flip so the rest of the list survives it.

Each iteration is the same four moves, always in this order: save next_node = curr.next, flip curr.next = prev, then advance both prev = curr and curr = next_node.

Nothing else is allocated, so the extra space is constant no matter how long the list is.

STEP 5

Trace it: flip node 1

Before the loop: prev = None, curr = node 1. The loop condition while curr is true, so we enter.

Save next_node = curr.next, which is node 2 — that is our lifeline to the rest of the list. Then flip: curr.next = prev makes node 1 point at None, which is exactly right, since node 1 is going to be the tail.

Advance: prev becomes node 1, curr becomes node 2.

The list is now two pieces: the reversed piece None ← 1, and the untouched remainder 2 → 3 → 4 that curr is standing on.
STEP 6

Trace it: flip node 2

Now prev is node 1 and curr is node 2. Same four moves.

Save next_node = node 3. Flip curr.next = prev, so node 2 now points back at node 1. Advance: prev becomes node 2, curr becomes node 3.

The reversed piece has grown to None ← 1 ← 2, and prev is always sitting on its front — which is why prev is the thing we will return.

STEP 7

Trace it: flip node 3

Save next_node = node 4. Flip node 3 to point at node 2. Advance: prev becomes node 3, curr becomes node 4.

One more iteration will flip node 4, save next_node = None, and set curr = None. The while curr test then fails and the loop stops.

At that moment prev is node 4, the front of the fully reversed list. return prev — not head, which is now the tail.
STEP 8

The pitfall: flipping before you save

Swap the first two lines of the body so the flip happens first:

curr.next = prev        # flip first — wrongnext_node = curr.next   # this now reads prev, not the tail

On the very first node, curr.next = prev sets node 1's link to None. The next line then reads that same link back, so next_node is None, curr becomes None, and the loop exits after one iteration. The function returns a one-node list and 2 → 3 → 4 is unreachable — with no error, just silently missing data.

Save the way forward before you destroy it. That single ordering is the whole trick of the problem.

The two boundary cases need no special handling. Empty list: curr = head = None, the loop never runs, and prev is still None — the correct answer. Single node: one iteration sets its link to None and returns the same node.

STEP 9

Time and space

Each node is visited exactly once, and the work at each node is three assignments. So the total is O(n) time.

The only storage is the three pointers, and that does not grow with the list, so it is O(1) extra space.

ApproachTimeSpace
Copy values out, reverse, write backO(n)O(n)
Recursive flipO(n)O(n) call stack
Iterative three pointersO(n)O(1)

The recursive version reverses the tail first, then does head.next.next = head and head.next = None. It is elegant, but it holds one stack frame per node, so at the 5,000-node constraint it is near Python's recursion limit. Say it as an aside, write the iterative one.

STEP 10

The final solution

Nine lines including the node class. Every one of them maps to a step above.

  • prev = None is the empty reversed part, and the None the old head will point at.
  • curr = head starts the walk.
  • while curr stops the moment we fall off the end — and never runs at all for an empty list.
  • next_node = curr.next is the save, and it must come first.
  • curr.next = prev is the flip.
  • prev = curr and curr = next_node step both pointers forward together.
  • return prev returns the new head, because prev always sits on the front of the reversed part.
One-line summary to remember: save the next node, flip the arrow backwards, then move both pointers up one.
