Best Time to Buy and Sell Stock, narrated

Scroll through the thinking, from the obvious brute force to the one-pass minimum tracker, with the state of the algorithm shown alongside.

Pattern used Sliding Window track min price so far, profit = price - min

STEP 1

The problem

You get an array prices where prices[i] is the stock's price on day i. Choose one day to buy and a later day to sell, and return the largest profit.

One rule does all the work: the sell day must come after the buy day. And if prices never rise, you simply do not trade, so the answer is 0 rather than a loss.

Running example: prices = [7, 1, 5, 3, 6, 4]. The answer is 5 — buy on day 1 at 1, sell on day 4 at 6.

Notice the question asks for the profit, not the days. We never have to remember which days won, only how much they were worth.

STEP 2

First instinct: try every buy/sell pair

The direct idea is to test every possible trade: for each buy day i, try every sell day j after it and keep the largest difference.

best = 0for i in range(len(prices)):    for j in range(i + 1, len(prices)):        best = max(best, prices[j] - prices[i])

This is correct, and it is a fine first answer to say out loud. But there are roughly n² / 2 pairs, so the running time is O(n²). At n = 100,000 that is about five billion subtractions.

The inner loop is wasteful in a specific way: for each buy day it rescans the entire future. Flip which loop is in charge and the waste becomes obvious.

STEP 3

Reframe: stand on the sell day

Instead of fixing the buy day and scanning forward, fix the sell day and look backward. Stand on day j and ask: "If I sold today, what is the most I could have made?"

There is only one sensible buy day: the cheapest day anywhere before j. Buying on any other earlier day gives strictly less profit, so no other candidate is worth considering.

On day 4 the price is 6. The cheapest day before it is the 1 on day 1, so selling today is worth 6 − 1 = 5.

The brute force answers that question by rescanning the past, which costs O(n) each time. But the cheapest day so far is something we can just carry along.

STEP 4

The key idea: carry the minimum with you

Walk the array once, left to right, holding two numbers:

  • min_price — the cheapest price seen so far. Start it at infinity so the first day always replaces it.
  • best — the largest profit found so far. Start it at 0, because doing nothing is always an option.

At each day, either the price is a new low (update min_price) or it is a candidate sale (compare price - min_price against best). Both take O(1).

Because we only ever look at a minimum drawn from days already passed, the "buy before you sell" rule is enforced by the direction of the loop itself. There is no ordering check anywhere in the code.

STEP 5

Trace it: days 0 and 1

Day 0, price 7. Infinity is beaten, so min_price becomes 7. No sale is considered — we cannot buy and sell on the same day, and the elif makes sure of that.

Day 1, price 1. That is cheaper than 7, so min_price becomes 1. Again no sale: this is a buy day, not a sell day.

best is still 0. Two days in and we have banked nothing, but we now hold the cheapest buy point of the whole array.

STEP 6

Trace it: day 4, the peak

Days 2 and 3 (prices 5 and 3) are both above min_price, so each is checked as a sale: 5 − 1 = 4 raises best to 4, then 3 − 1 = 2 does not beat it.

Day 4, price 6. It is not below 1, so we take the elif branch: 6 − 1 = 5, which beats 4. best becomes 5.

Day 5, price 4, gives 4 − 1 = 3 and changes nothing. The loop ends and we return 5.

The green cell is the day we conceptually bought on; the blue cell is where the loop is standing. They never cross, because the green one is always in the past.
STEP 7

The pitfall: prices that only fall

Take prices = [7, 6, 4, 3, 1]. Every day is cheaper than the one before, so the if branch fires every single time and the elif never runs.

The correct answer is 0: you decline to trade. A common bug is initialising best to something like -inf or prices[1] - prices[0], which lets a losing trade become the answer and returns −1.

Start best at 0 and never let it go down. Also note the reverse trap: the global minimum here is the last day, and you cannot sell after it. Tracking best separately from min_price is what handles that.

The same reasoning covers a single-day array: the loop runs once, takes the if branch, and returns the untouched 0.

STEP 8

Time and space

The loop visits each day once and does one comparison and at most one subtraction per day, so the total is O(n) time.

We hold two scalars no matter how long the array is, so it is O(1) extra space — strictly better than the hash-map style solutions to other array problems.

ApproachTimeSpace
Brute force, all pairsO(n²)O(1)
One pass, min so farO(n)O(1)

For n = 100,000 this turns about five billion pair checks into one hundred thousand steps, and it costs nothing in memory to do it.

STEP 9

The final solution

Nine lines. Every one of them maps to a step above.

  • min_price = float("inf") is the cheapest buy day so far, primed so day 0 wins.
  • best = 0 encodes "no trade is always allowed".
  • for price in prices is the single forward pass that enforces buy-before-sell.
  • if price < min_price is the new-low branch.
  • elif price - min_price > best is the reframed question, asked on the sell day.
  • return best hands back 0 untouched when prices only fall.
One-line summary to remember: at each day, the best buy is the cheapest day before it.
