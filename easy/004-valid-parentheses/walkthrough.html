Easy · Stack · LeetCode #20

Valid Parentheses, narrated

Scroll through the thinking, from counting brackets to the one-pass stack, with the state of the algorithm shown alongside.

STEP 1

The problem

You get a string s containing only the six bracket characters ( ) [ ] { }. Return True if the brackets are balanced.

Balanced means two things at once: every bracket is closed by the same kind of bracket, and they close in the right order.

Running example: s = "([]{})". The answer is True. Every closer lines up with the opener it belongs to.

That second requirement, the order, is the whole problem. It is what makes this more than a counting exercise.

STEP 2

First instinct: count the brackets

The obvious idea is to count. Walk the string keeping a running balance: add one for every opener, subtract one for every closer. If the balance ever goes negative, a closer arrived with nothing open. If it ends at zero, everything matched.

balance = 0for ch in s:    balance += 1 if ch in "([{" else -1    if balance < 0:        return Falsereturn balance == 0

This is O(n) time and O(1) space, which sounds great. It is also wrong.

Try s = "([)]". Two openers, two closers, the balance goes 1, 2, 1, 0 and never dips below zero. The counter says valid. But ( and ) are interleaved with [ and ] instead of nested, so the string is invalid.

Even three separate counters, one per bracket type, fail on the same input. A count throws away the one thing that matters: which opener each closer is supposed to close.

STEP 3

Reframe: which opener does this closer belong to?

Stop at a closing bracket and ask a precise question: of all the brackets still open right now, which one is this closer responsible for?

There is only one sensible answer. It must be the most recently opened one that is still unclosed. If it were an older one, some newer bracket would be left dangling inside, crossing over the boundary.

In "([]{})", at index 2 the closer is ]. The openers still waiting are ( then [. The most recent is [, and it matches. Valid so far.

So the rule is: last opened, first closed. Now the data structure picks itself.

STEP 4

The key idea: a stack of pending openers

"Last in, first out" is the definition of a stack. In Python a plain list is one: append pushes, pop removes the last item.

Keep on the stack every opener that has not been closed yet. Then each character is one of two cases:

  • An opener — push it. It is now the one that must close next.
  • A closer — pop the top and check it is the matching opener. If the stack is empty, or the popped bracket is the wrong kind, the string is invalid.

To answer "is this the matching opener?" in one comparison, use a dict mapping each closer to its opener: {")": "(", "]": "[", "}": "{"}. Membership in that dict also tells you whether the character is a closer at all, so one lookup does both jobs.

STEP 5

Trace it: the openers go on

Start with an empty stack. Index 0 is (. It is not a key of pairs, so it is an opener: push it.

Index 1 is [. Also an opener, so push it too. The stack is now ( [ with [ on top.

Two brackets are pending, and the stack remembers the order they were opened in. That order is the information the counter threw away.

STEP 6

Trace it: the first closer

Index 2 is ], which is a key of pairs, so it is a closer. Its required partner is pairs["]"], which is [.

The stack is not empty, so pop the top: it is [. That equals the required partner, so this pair is settled and we keep going.

The pop is not just a peek. Removing the [ is what makes ( the top again, ready to be closed later.

Indices 3 and 4 are { and }: push, then pop and match, exactly the same way. The stack is back to just (.
STEP 7

Trace it: the last closer, and the end

Index 5 is ). Its partner is (, and popping the stack gives (. Match. The stack is now empty.

The loop ends. The final line is return not stack: an empty stack means nothing was left waiting, so the answer is True.

Note what that last line is not: it is not return True. Surviving the loop only proves that no closer went wrong; it says nothing about openers that never got closed.

STEP 8

Two ways it goes wrong

The counterexample from step 2, s = "([)]", is the interesting one. Push (, push [. At index 2 the closer is ), so the required partner is ( — but the top of the stack is [. Mismatch, return False immediately.

The other failure is quieter. For s = "((" the loop never hits a closer, so no check ever fires. The string is invalid only because the stack still holds two openers at the end. That is the case return not stack catches.

A third case: a closer with an empty stack, like s = ")". That is why the test is if not stack or stack.pop() != pairs[ch] — check emptiness first, because pop() on an empty list raises IndexError. Python's or short-circuits, so the pop never runs when the stack is empty.

STEP 9

Time and space

The loop visits each character once. Inside it, the dict lookup, the append and the pop are all O(1). Each character is pushed at most once and popped at most once, so the total is O(n) time.

The stack can hold every character if the string is all openers, like "(((((", so it uses O(n) extra space.

ApproachTimeSpace
Count opens and closes (wrong answer)O(n)O(1)
Repeatedly delete "()" "[]" "{}" until stableO(n²)O(n)
Stack, one passO(n)O(n)

The O(n) space is not a trade for speed here, it is the price of correctness. The counter is just as fast and simply gives the wrong answer.

STEP 10

The final solution

Ten lines. Every one of them maps to a step above.

  • pairs = {...} is the closer-to-opener map, and doubles as the "is this a closer?" test.
  • stack = [] holds the openers still waiting to be closed.
  • if ch in pairs splits the two cases from step 4.
  • if not stack or stack.pop() != pairs[ch] is the emptiness guard and the match check, in that order.
  • stack.append(ch) pushes an opener so it becomes the next one due to close.
  • return not stack catches the leftover openers, like "((".
One-line summary to remember: the most recently opened bracket must be the next one closed, and that is a stack.
