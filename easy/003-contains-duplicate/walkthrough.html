Pattern used Hash Set early exit on first repeat

STEP 1

The problem

You get an array of integers nums. Return True if any value appears at least twice, and False if every element is distinct.

That is the whole question. You do not have to say which value repeats, or where it repeats, or how many times. One bit of information comes back.

Running example: nums = [1, 2, 3, 1]. The answer is True because the 1 at index 0 shows up again at index 3.

Notice how little the answer asks for. A yes/no question can often be answered without doing the full bookkeeping a richer question would need.

STEP 2

First instincts: every pair, then sorting

The most direct idea is to take every possible pair of positions and check whether the two values are equal. For each element, compare it against every element after it.

for i in range(len(nums)):    for j in range(i + 1, len(nums)):        if nums[i] == nums[j]:            return True

This is correct, and it is a fine first answer to say out loud. But with n elements there are roughly n² / 2 pairs, so the running time is O(n²). At n = 100,000 that is about five billion comparisons.

The obvious improvement is to sort first. Once the array is in order, equal values sit next to each other, so one sweep comparing each element to its neighbour is enough.

nums.sort()for i in range(1, len(nums)):    if nums[i] == nums[i - 1]:        return True

That is O(n log n) time and O(1) extra space, which is the right answer if memory is tight. But the sort dominates, and it destroys the original order unless you copy the list first.

Sorting to find duplicates does far more work than the question needs. It puts everything in order just to learn whether any two things match. And the brute force rescans the whole tail to answer one small question. What is that question?
STEP 3

Reframe: what am I actually asking?

Stand at one element n. The only thing you need to know is: "have I already walked past this exact value?"

That is a membership question, not a comparison. The brute force answers it by scanning, which costs O(n) each time. Sorting answers it by rearranging, which costs O(n log n) once.

If we could answer "have I seen this value before?" in O(1), the whole thing would collapse to a single pass.

And unlike Two Sum, we do not need to remember where a value was. Only that it happened.

STEP 4

The key idea: a set of what you have seen

A set answers "is this value in here?" in O(1) on average, the same hashing trick a dictionary uses. Since we do not need an index, a set is the right shape: keys with no values attached.

So we walk the array and, at every element, do two things in this order:

  • Check whether the value is already in the set. If it is, we have found a repeat and can return True straight away.
  • Add the current value, so a later element can match against it.

Check before add. If you add first, every element finds itself in the set and the answer is always True.

STEP 5

Trace it: indices 0, 1, 2

Start with an empty set. The first value is 1. Is 1 in the set? No, it is empty, so we add it and move on.

The value 2 is not in the set either, so it gets added. Same for the 3 at index 2.

The set now holds {1, 2, 3}. Each of those checks cost O(1), no matter how big the set has grown. A run of misses is the normal case: the set just keeps growing until a match appears or the array runs out.

STEP 6

Trace it: index 3, the hit

The last value is 1. Is 1 in the set? Yes — we put it there back at index 0.

That settles the question, so we return True immediately. We never add this second 1, and we never look at anything after it.

This early exit is why the explicit loop can beat the one-liner. On [7, 7, …a million more…] the loop stops after two elements; len(set(nums)) != len(nums) builds the entire set first.
STEP 7

The other ending: nothing repeats

Change the input to nums = [1, 2, 3, 4]. Now every check misses. The set fills up completely — one entry per element — and the loop runs off the end of the array.

The return False after the loop is doing real work here. It is not a defensive leftover; it is the answer for every distinct array, which is the common case in practice.

Forgetting the trailing return False makes the function return None for distinct arrays. None is falsy, so casual tests still pass while the return type is wrong.

This is also the worst case for space: the set ends up as large as the input.

STEP 8

Time and space

The loop visits each element at most once. Inside the loop, the membership check and the insert are both O(1) on average. So the total is O(n) time.

When every value is distinct the set holds all n of them, so it uses O(n) extra space.

ApproachTimeSpace
Brute force, all pairsO(n²)O(1)
Sort, then scan neighboursO(n log n)O(1)
Hash set, one passO(n)O(n)

The usual trade: spend memory to buy time. The sorting row is the one to keep in your pocket for when the interviewer says "now do it in O(1) space".

STEP 9

The final solution

Seven lines. Every one of them maps to a step above.

  • seen = set() is the memory of values already passed.
  • if n in seen is the O(1) membership check, the reframed question.
  • return True is the early exit, taken the moment a repeat appears.
  • seen.add(n) is the store, placed after the check on purpose.
  • return False is the answer when the loop finishes untouched.

In real Python you would often just write return len(set(nums)) != len(nums). It is the same idea compressed: build the set of distinct values, and if fewer came out than went in, something collapsed. It is always O(n) time and O(n) space, with no early exit — so it is the better one-liner and the worse loop.

One-line summary to remember: walk once, and ask the set whether this value has already gone by.
